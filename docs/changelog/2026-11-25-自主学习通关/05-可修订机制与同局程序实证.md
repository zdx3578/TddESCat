## 公开机制怎样修订

| 改动 | 条件和证据 | 实际消费者 |
|---|---|---|
| 运动边允许被撤回和恢复 | 同坐标同动作的成功与失败共同约束运动边。从反例前的公开像素和动作历史生成区分候选。候选分歧时返回未知 | 规划器撤回无条件通路，在当前绑定满足区分条件时重新采用通路。测试覆盖关门、开门和证据分歧 |
| 原地动作保留效果 | 同一份确认回执保存帧顺序、视觉信号、计数器读数以及动作和位移次数 | 没有位移的回执仍更新相应观测。旧版通关原始回执中独立查到 16 次角色静止而画面变化 |
| 接触条件允许引入历史 | 固定图案比较无法一致解释时，检查图案签名与当前动作、上次动作、当前绑定的可见候选数。保留全部适用域样本；相同输入仍有相反结果时回到未知 | 同画面、同接触动作的正反例促成历史条件，规划器随后在已支持的历史上下文选择接触 |
| 分开学习准入与晋级 | 受阻、进入、推进来自公开回执。晋级拟合使用实际进入的样本，读取动作前事实 | 同一关系正文用本关绑定生成具体决策。在两个提供公开角色绑定的测试布局中，同一份固定关系分别生成以 ACTION3 和 ACTION4 开头的路线 |
| 签收后的程序参加同局控制 | 连续回执和共享角色生成有类型程序语料。E-Stitch 搜索完成后，在动作之间核对展开、来源和成本，记录可用时点 | 新程序可在下一动作被召回。每一步重新绑定并检查公开结果，反例撤回后缀 |
| 一个回执保留为同一次动作 | 重复帧只贡献证据。超过一次可见变化、角色对应或残差未闭合时保留解释义务 | 后续遇到证据边界时，已完整的前缀可以当局送入程序搜索 |

观察和预测均沿用公共动作与完整回执存储。视觉候选仍使用连通、形状、几何和当前观测到的角色。精确适用域使用 Julia 的有限关系表示，程序结构复用使用 Rust E-Stitch，Python 独立复核回执、训练前缀和评分终态。完整先验清单见 [01-先验设置与架构实际作用.md](01-先验设置与架构实际作用.md)。

## 原版程序语料的实测边界

用同一套程序编译器回读前次原版验收的 764 条动作，只得到 8 段各含两步的合格语料。748 条动作保留待解释义务，其中 736 条的步骤作用域未闭合，12 条缺少已验证的相邻步骤。步骤未闭合的动作中，733 条有像素残差，52 条需要解释实际发生的中间变化。这两项可以重叠。

将这 733 条回执与本轮正式复测逐一对齐，核对动作、状态和全帧一致。271 条动作的全部残差恰好落在视觉控制器已绑定的计数器区域，并对应读数变化，共 894 个像素。其中 251 条只记录像素残差这一项解释义务。视觉控制器已能读取这类计数，通用程序效果的计数当前依据离散组件。计数器的连续变化及真实多帧演化仍需进入统一的效果和程序语义。
