# 对象探测与晋级关系

公开 24 款游戏的旧版冷启动共执行 6,871 个动作，各款均通过回放核验，累计推进 1 关。唯一一次推进来自早期探索动作。ft09 和 sc25 后段各连续 100 步点击不同坐标，却持续停留在首关。

旧实验调度器以一次观测生成对象点和栅格点队列，按原顺序继续派发。对象移动、出现或离开后，队列仍含有旧绑定。日志中的 `observed_color_precondition` 是联合效果候选的拒绝原因，调度队列仍可能派发该坐标。旧版晋级学习从空间接触样本构造关系，点击造成的推进只出现在公共回执。

## 行为与证据

- 每次决策从当前公开帧重建连通支持，取支持内部的代表点，用形状、颜色及其在当前画面的数量提出关系候选。控件或背景也可能响应，仍保留合法的坐标实验。栅格按空间尺度展开，混合动作域定期尝试原子动作。
- 以确认回执记录干预、对象证据和是否推进。至少有两关的同输入正例及对照时，拟合可区分结果的单变量关系。可用解释在当前输入一致时才提交推进预测，预测和来源事件在动作前冻结。相反回执进入同一批拟合并使矛盾解释退出。
- 点击效果模型校验实际支持与形状内偏移。已证实作用只在所点支持上改色时，允许同形支持在新位置绑定，反馈和整帧投影均核对本次绑定。作用涉及其他对象时，适用域保留训练位置。
- Python 仍运行原公开 HTTP 环境和回放，Julia 在现有公共事务内生成目标预测。联合局部结构继续使用原 Rust E-Stitch 搜索和发布流程。对象晋级候选由 Julia 根据真实正反回执拟合。

## 受控和实测口径

独立裁判通过公开 HTTP 核查四个布局的动作、对象支持、晋级反馈和证据时序。前两关各提供一正一反，第三关改了位置、颜色和形状，首个预测动作推进。第四关改变条件，反例撤回原预测，重新探测后推进。同样的 20 条公共命令预算内，旧版 19 个动作完成 1 关，新版 8 个动作完成 4 关。控制器只有公开动作和帧作为输入。

`config/acceptance/object_interventions.toml` 运行独立验收。原版重跑沿用 `config/autonomous_public.toml`。其他 24 款对照使用相同版本列表、每款 900 条公共命令、schema 2 搜索配置和 Rust 二进制。运行器分别记录对象探测、坐标探测、事前晋级预测、命中和反例。首次探索推进与学得关系指导的推进分别统计。
