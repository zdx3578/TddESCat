## 2. 先分清三种“数量”

| 数量 | 现在如何得到 | 实际意义 | 当前问题 |
|---|---|---|---|
| 离散组件数 | `LocalEffects.jl::observed_effects` 按形状原型统计连接组件；`JointMechanisms.jl::model_count` 重读组件数 | 某类可见离散组件有几个 | 已有 `count_shift` 适用于该语义；不能直接拿来解释一根条缩短 |
| 区域计量读数 | `VisualFields.jl::read_counter` 在已绑定矩形内数指定颜色像素，再除以矩形短边 | 当前公开显示所表示的数量；目前带有条状显示先验 | 视觉控制器可以读，通用效果、程序端口、预测反馈还不能统一消费 |
| 未处理候选数 | `VisualControl.jl::contact_facts` 计算 `targets - matched` | 当前控制器已绑定、尚未标为处理过的候选数 | 域并非全部真实目标；“进入就处理过”仍是控制器先验，集合完整性也未独立审计 |

三者都可以落到整数域，但必须保留各自的取值对象、计量方法、适用域和证据。把它们统一写成 `count` 会混淆对象个数、显示读数和目标状态。

### 2.1 为什么条形变化没有进入原版连续程序

`LocalEffects.jl:161–176` 的 `count` 统计组件出现/消失。168–169 行特意拒绝仍保留部分同色支撑的轮廓变化，避免把形状变化误报成整个组件消失。条缩短后仍有同色部分，通常正好落在这个保护条件中。

`SequenceCorpus.jl:185–193` 要求效果解释完整且没有像素残差，否则切断语料。这是有效的闭合约束，不能为了增加样本把残差直接清空。

05 报告的口径是：

- 764 个动作中，8 段两步共 16 个动作形成已验证程序语料。
- 748 个解释义务分为 736 个作用域未闭合、12 个缺少已验证相邻步骤。
- 736 中有 733 个像素残差义务、52 个真实中间变化义务；后两项允许重叠。
- 271 个动作的全部残差位于已绑定计数区域，并伴随读数变化；其中 251 个只剩像素残差这一项义务。

这足以确定计量语义值得优先接通。仍须逐项重算，确认区域身份、显示变化、相邻步骤和角色续接均成立，才能增加有效程序语料。

## 5. 两个可独立验收的下一里程碑

这两个里程碑接续既有 03/04 计划，不新建项目，不重新搭建 Python、Julia、Rust 框架，不改小现有开放搜索配置。下面的名称均为待实现职责说明，不表示代码已经存在。

### 里程碑 A：公开计量、静止效果和候选集合形成统一可验证语义

#### A1. 明确计量解释，先不称为“能量”或“钥匙”

从既有公开像素候选提取器开始，输出以下信息；每项都有明确用途：

- **计量方法**：如何从可见支撑得到值，例如某选择域内指定颜色的像素数、符合某关系的组件数。它决定整数的含义。
- **单位**：原始像素数可以直接使用；按宽度归一化只有在该显示编码得到核验时使用。不能用整除掩盖不规则变化。
- **实例绑定**：本次读取的是哪个区域/对象。坐标属于该实例绑定，不应自动成为跨布局概念定义的常量。
- **可见性与定义域**：哪些支撑可见、哪些读数有效；裁切、遮挡、多个同等绑定时返回未知，不把未知写成零。
- **前后值及公开读集**：前值、后值、差值分别来自哪个已确认回执；预测时只能读取当前及更早证据。
- **显示变化证书**：哪些像素变化可由该计量显示变换解释。读数变化与像素重构是两项不同保证。

原先矩形长条识别可继续作为明确登记的候选先验。实现应允许通用选择域与测量函数扩展，不增加 game_id、关卡号、固定颜色和固定面板坐标分支。

#### A2. 两种语料使用同一观察解释

修改位置：

1. `LocalEffects.jl::observed_effects`：从公开前后帧及之前已签收的绑定得到计量变化。观察到 q→q' 只构成样本，不直接发布无条件 q'=q+δ 定律。
2. `LocalEffects.jl::relation_corpus`：不再自行重做一套缺少计量上下文的观察解释；接收/恢复同一个已记录 PublicEffects。
3. `SequenceCorpus.jl::compile_sequence_corpus`：沿用 observations 入口读取相同解释版本和证据截止点。
4. `ConceptTerms.jl::evidence_signature`、`Mechanisms.jl::typed_motion_signature`：为新测量关系注册输入/输出类型及语义版本；保持组件 count_shift 原义。
5. `LocalEffects.jl::effect_program`：所有 family 显式分支，未知 family 报不可解释，不再默认成为 selection。
6. `JointMechanisms.jl::joint_model/result_model/measure_joint`：新增一致的实例绑定、预测及回执求值。
7. `ProgramSemantics.jl::verify_program_interval/program_input/current_program_step/program_feedback!`：理解同一计量类型及其端口身份。
8. `SequenceCorpus.jl::shared_sequence_ports`：计量端口按同一计量实例与相邻值续接，不能仅比较相等的数值或要求变化前后的像素支撑完全相同。

Rust 的 `rust/bridge/src/codec.rs::Registry::new` 已按声明签名注册算子并验证语义身份。优先复用现有类型签名、描述符与展开证明链。只有协议确实拒绝所需新类型时才改协议，并同步 Julia/Rust 的身份校验；不要在 Rust 中新增 ls20 识图器或另写一套计量解释器。

统一处理伪代码：

```text
处理已确认的公开动作(前回执, 动作, 后回执):
    绑定 = 从动作前公开前缀恢复有效绑定
    轨迹 = 保留后回执的全部帧
    观察 = 同一解释器(前帧, 动作, 轨迹, 绑定)

    对每个计量候选:
        读取前值、后值，并检查实例身份、单位、可见性
        若任一项未知:
            保留对应解释义务
            继续
        登记观察到的计量关系及公开来源
        仅将有可检验显示变化证书的像素标记为已解释

    残差 = 实际变化 - 已被证书解释的变化
    保存观察正文、解释版本、证据截止点、残差和歧义
    单步效果语料与连续程序语料读取这份相同记录
```

不能仅凭“残差落在矩形内”或“计量值改变”消除像素残差。显示形状、颜色变化仍须解释；无关动画可能出现在相同区域。

#### A3. 保证计量身份与迁移正确

`scope_key` 应以计量方法、单位、对象身份和角色绑定生成通道身份，当前数值只作为通道值。两个独立条同为 5，必须仍是两个通道。

`resource_interaction_scope` 不能直接删除。新位置上的“移动同时改变计量”必须依据共同的动作—对象关系及适用条件重新绑定；条件未验证时保持未知。每一步的计量输出必须与下一步同一实例输入对应，换条、换单位、同值替代均不能通过。

#### A4. 静止与完整响应轨迹共同解释

无位移也允许发生计量变化、图案变化、可通行条件变化。移除 VisualControl 专用计量/信号学习中以 moved 限制费率、补给及 VisualContact 样本的门槛，并让静止样本进入同一通用关系与程序消费者；这不表示现有 LocalEffects 的所有效果都要求 moved。

一个公开动作返回多个帧时：

- 重复快照不新增动作或机制步骤。
- 多次真实可见变化保留内部轨迹顺序；不能伪造为多个 API 动作。
- 只有已解释整条内部轨迹，才能宣称该公开动作作用域闭合。
- 若暂时仅能解释终帧，则保留中间变化义务，不把端点正确包装为整步正确。

时序学习比较可观察的动作计数、移动计数及响应轨迹相关候选；响应帧数不自动等于环境物理时钟。原地动作也推进动态对象时，旧移动时钟必须能被反驳并停用。

#### A5. 把剩余候选集合从控制器断言变为可审计关系

先保持“已绑定域”的有限范围，独立重放绑定、解绑、进入、状态变化及重新激活事件。审计器计算剩余集合后，与 solver 声明集合逐项比较；域存在歧义则数量未知。

“曾经进入”是已观察事实；“该对象已永久完成”是待验证假设。两者拆开。删除 `point in matched` 导致永远不再收反例的逻辑，允许新证据使义务重新打开。是否单调完成要由公共反馈支持，不预先写死。

晋级拟合继续保持正反证据、未见值未知、候选分歧未知。数量输入的集合语义改变时必须生成新的语义身份，不能把旧 matched 数量的模型无证据搬到新“完成目标数”上。

#### A6. 最小因果单元与验收

这里的闭合对象是“某次公开动作，对某个已绑定对象/计量/条件，在明确前置条件下造成的变化”。验收按功能区分，不能只统计总 WIN：

| 检查面 | 必须覆盖的情形 | 通过标准 |
|---|---|---|
| 数量语义 | 条缩短、增长、不变、清空；离散组件数量变化 | 各自计量定义正确，不混用；零值与未知分开 |
| 身份与组合 | 两个同值条；移动对象与远端计量同时变化；新位置 | 通道不碰撞，共同动作效果可组合，跨位置绑定有证据 |
| 静止机制 | 受阻但扣量；原地动作改变标记后下一动作通行 | 静止效果进入同一机制及程序消费者 |
| 观察边界 | 裁切、遮挡、同区无关动画、真实多次中间变化 | 未解释部分仍保留义务，重复快照不新增动作 |
| 目标状态 | 列表漏项、重复项、错关项、已处理项重新加入；目标重开 | 审计拒绝伪造清单；真实状态重开能重新学习 |
| 端到端解释 | 原版现有 764 动作回放、原报告 251 候选逐条映射 | Python 独立读取与 Julia 解释一致；重算可用动作和连续段，不预定必须增加 251 |

A 的交付：共享计量/状态语义、独立审计与真实语料重编译报告。报告逐动作列明闭合/未闭合原因，提供真实新增连续段；尚未接通的多帧或时序类型明确列出，不能用“整体通过”覆盖。

### 里程碑 B：原版同局程序进入目标控制，再验证共同子目标策略

#### B1. 先闭合程序发布、恢复与重复尝试

程序任务持久化区分：

- submitted：输入快照已固定、搜索任务已提交。
- verified：展开证明、来源、语义及输出已核验。
- published：结果已签收，对某个明确公开回执之后的动作可用。

这三个状态分别回答“做过没有”“结果可信没有”“现在能否消费”，不能以一个 program_prefix 代替。

`recover_learning!`、`learning_jobs` 与待处理汇总同时处理效果和程序任务；程序从 sequence-corpus.json 恢复。失败不能把输入当已发布；同语料失败后仍有未完成义务。恢复不重发已经确认的公开动作，不追记模型到过去决策。

`may_retry_visual_attempt!` 的身份改由当前相关机制正文及绑定生成，包含真正改变可执行判断的历史条件、运动条件和晋级关系。增加“旧端点/签名集合不变，但新条件模型改变”的检查；不能仅加事件计数使任何新帧都触发重试。

#### B2. 在动作截止点冻结可学习前缀

计量单调变化时，完整帧可能一直不回访。只要连续前缀所有动作都已确认、效果与绑定都闭合，就可以在当前截止点固定语料，而不等待关卡结束。

每个快照标记已包含的事件区间和解释版本；同一快照已有在途任务或已经完成核验时不重复提交，失败或中断任务保留未完成义务并按恢复流程重试。新增闭合事实产生新快照。未闭合动作构成边界，不跨 RESET、缺失回执或不成立的角色续接拼接。

增加一个结构测试：同一可复用子程序位于不同前缀长度及不同 Seq 二叉分组位置时，检查是否被发现、签收和消费。`candidate_intervals = n(n+1)/2` 只是当前统计字段，不是所有子区间都已枚举/发现的证据。

#### B3. 程序参与同一个目标规划入口

不能只删除 `!composing`。应将程序和原始动作都变成具有下列可检查含义的控制候选：

- **进入条件**：当前哪些已绑定关系必须成立。
- **预计后继/子目标**：完成后哪些关系改变、哪些目标条件被建立。
- **终止条件**：何时这次调用已经完成，不再机械执行剩余动作。
- **未知或反驳出口**：新反馈与预期不符时撤回后缀，保留新的区分义务。

这些条件来自经过验证的效果、关系和实例绑定，不由固定 ls20 攻略填写。先让有限程序获得这些契约；随后再扩展条件分支与可变次数重复。

统一候选选择考虑当前目标进展、建立必要条件和消除相关预测分歧。仅“能够执行”“更长”“结构更短”都不足以优先控制环境。避免程序启动后无条件跳过关键通行/计量条件以及待服务探索义务。

```text
选择下一公开动作(当前观察, 已签收知识, 当前目标):
    构造当前可验证的原始动作候选与程序候选
    对每个候选:
        绑定对象、计量、前置关系与证据
        检查当前目标相关性，或是否能区分影响目标的未知机制
        未知前置条件不得伪装成已证明可执行条件
    选择具有可说明目标/探索价值的候选
    若选中程序:
        只发送当前已重新核验的一步
        用实际回执更新绑定、子目标和程序状态
        遇到反驳/未知立即撤回不再成立的后缀
```

#### B4. 联想功能落到“缺什么条件、谁能产生它”

对尚不成立的通行或晋级条件，从已有机制/程序的后置关系中召回能产生该条件的候选，通过共同角色做变量绑定，再检查候选自己的前置条件。这就是当前最需要的目标驱动联想。

例如“目标接触要求某图案关系成立”，可召回能够改变该图案关系的已学动作；若该动作消耗可见计量，再回归其计量前置条件；若尚不确定消费关系，则形成一个能区分候选的公开实验。这里的图案、计量、接触关系均必须来自已有公开证据，不能凭概念名称认定因果。

使用已有 Catlab 的角色接口与组合来约束共享端口；Julia 负责关系求值、适用域、反例修订和目标回归；Rust E-Stitch 搜索、压缩可复用表达，并保留展开证明。不要为三种语言分别造一套相互不一致的机制语义。

#### B5. 七关统一规则需要同时提炼三个东西

1. **共同机制**：哪些动作在什么条件下改变对象、显示量、通行关系。
2. **共同成功关系**：进入、推进下一关、最终 WIN 分开；每种关系引用哪个有限绑定域和可观察条件。
3. **共同子目标策略**：未满足什么条件时选取什么子目标，怎样调用技能，何时重新观测、重开义务或终止。

当前 `remaining_sites=1 → progress` 属于第二项的有限经验关系，不等于三项已统一。当前 Step/Seq 只能表达固定动作串，任意变长策略不能靠把定义嵌套到更深自然获得。

实现顺序是：跨实例对齐角色和关系 → 保留共同条件及差异参数 → 用正反轨迹筛选候选 → 将可复用子程序附上目标契约 → 检验不同子目标个数/布局所需的组合。如果确实需要重复或分支，再把通用控制算子加入可学习语言并核验终止/撤回语义；不要先写一个必然输出“处理全部目标”的游戏专用框架，再声称它由学习发现。

对于看不到全图的情形，“当前绑定域内无剩余候选”不能直接推出 WIN。最终成功仍以公开反馈为标签；迁移到未见状态时应保留未知。

#### B6. 原版实际验收及证据包

A 通过后，在配置文件中开启 sequences，保留现有开放搜索能力，不添加环境变量或任意降低参数。重新固定当前完整代码、配置、引擎身份，运行原版同一公开会话。

必须分别验收：

- 空库启动，程序训练证据早于签收，签收早于第一次消费，且原版决策真正读取定义。
- 同一已学程序在新绑定实例被消费；每一步的对象、计量、条件和完整回执都得到核验。
- 至少出现一个有目标或探索价值的选择影响：在同一冻结公开状态和相同知识下，程序候选与普通排序/撤回该程序后的选择不同；实际执行的选择得到支持。未执行替代动作的结果不能编造。
- 晋级关系单独设置验收：事前预测 enter_only/progress 的不同情形获得回执支持，同一关系正文跨新绑定实例消费。整体 WIN 不代替此项断言。
- 遇到资源不足、条件改变、目标重开、程序中断时，机制能撤回并产生新的解释/探索义务。
- 跨关学习按时间前缀进行：前关可用知识只来自前关及更早；后关反例可在线修订，但不得倒写成先前就知道。七关结束后再统一拟合，应另标为离线分析。
- 留出新布局、颜色/身份替换、不同子目标数和条件组合，检验共同正文是否保持、具体路线是否随绑定改变。真实通关波动只分析机制、控制链及极端失败原因，不以普通动作数涨跌决定能力结论。

发布可访问、固定哈希的证据包：运行清单、代码与配置身份、公共回执/必要帧、decisions/checks、定义和签收时点、独立审计输出、语料/残差逐条映射。大文件不必直接进入源码仓库，但不能只提供作者机器上的本地路径。

B 的交付首先是“原版同局程序成为有目标价值的控制组成”，然后单列跨关共同策略的验证范围。若只有固定两步程序获得消费，就只签收该有限结论。

## 6. TDD 与概率电路当前应该放在哪里

Tree Decision Diagram（树决策图，TDD）可用于压缩已经明确编码的有限约束、绑定关系及其查询；Probabilistic Circuit（概率电路，PC）可用于将来有明确随机变量和统计语义的概率模型。二者都不能自动补出当前缺失的计量含义、目标完成状态或程序契约。

本轮未验证原版执行链实际调用了 TDD；不能把 E-Stitch 的结构压缩收益写成 TDD 收益。当前先补统一语义和目标消费，后续只有在同一语义、同一输入和可比测量下，才评估电路编译是否节省匹配/推理成本。
