## 3. 程序究竟贡献了什么：三个参照必须分开

### 3.1 普通排序、实际规划与程序执行

当前原版控制链是：

1. 计算底层普通动作排序。
2. 现有自主空间/视觉规划器选择路线。
3. 在可用程序中寻找能够完成该路线中某段目标的程序。
4. 程序负责当前步骤、对象/计量续接、预期结果和反馈撤回。

`OnlineSession.jl:685` 保存第 2 步的 baseline_action。708–709 行要求候选程序首动作与空间规划首动作一致。

`ProjectedPlanning.jl:164–178` 进一步从已有路线提取动作和落点，并逐步要求程序预测与之匹配；返回的契约名是 `observed_route_waypoint`。本局所有带程序执行记录的契约都是这一类。

所以：

- 21/32 不同于 ordinary，证明程序实际进入控制链并覆盖普通排序。
- 0/32 不同于 baseline，表明这些成功调用没有替换空间规划器原本选择的动作。
- 程序的对象绑定、计量预测、跨关调用及撤回是真实功能。
- 新路径、目标先后顺序或共同任务分解尚不能归因于程序发现。

合成显式目标路径还支持 `distance_to_marker` 和 `goal_predecessor`，但其目标由配置/已有投影输入。它证明程序可以服务目标，不等于系统已自动发明了原版七关的共同成功关系。

### 3.2 不能为了制造差异而取消路径条件

下一步不是删掉 708 行匹配检查后任由程序抢占控制。应让原始动作、空间路线和程序在同一个关系目标上比较：能建立什么必要条件、保留哪些已完成条件、消耗什么计量、哪些预测仍未知。

路径可以相同；若策略声称有新的选择能力，则应提供有区分价值的实例，证明候选或子目标选择因已学知识发生合理变化，而不是只比普通排序首位。

```text
收到程序步骤的公开回执:
    局部判断 = 核对已声明的移动、计量及对象关系
    投影差异 = 比较预测与实际，按绑定和读写范围归属

    保存局部判断，不把正确局部效果误判为错误
    若投影差异非空:
        撤回当前不再成立的程序后缀
        保存到“该投影正文 + 适用条件 + 当前绑定”的反例集
        召回能够区分正反实例的公开关系
        为新增条件或共同效果生成待检验候选
    只有新的条件化投影通过相关历史与新实例核验:
        恢复该作用域的程序可用性
```

#### 验收

- 用当前七个反例重放，确认局部机制仍保留正确支持。
- c109 后的局部正例不能单独解禁原整帧断言。
- 某个新条件得到公开证据支持后，相应投影在新实例恢复，并改变下一次可用程序或探索选择。
- 构造远端变化相关与不相关两类公开实例，核验适用域；不采用无条件屏蔽残差。
- 五个失败任务明确标注真实终止原因与尚欠证据；70 个未提交候选进入独立账本，不宣称已经搜索。
- 不要求重复已成功的整局运行来替代这些有区分力的局部验收；本交付闭合后再用原版确认生产接续。

### 交付二：以关系目标组织程序，提炼跨关共同子目标策略

#### 先把目标从既定路线中分离

当前 `observed_route_waypoint` 来自已选路径。下一步目标应能表达“某个公开关系需要成立”，例如通行条件、角色间关系、计量条件或已学习的晋级条件。

关系必须引用当前公开绑定和已学正文。不要把固定颜色、坐标、关卡号或“剩一个就一定通关”写成先验策略。进入、推进、WIN 仍分开。

#### 建立有证据的目标回归

新增的是现有机制与程序的关系索引和统一消费，不另写独立攻略求解器：

1. 从当前目标中找尚未成立或尚不确定的关系。
2. 按已学机制/程序的后置关系召回候选：哪些变化可能使它成立。
3. 对齐共同对象、计量实例和时间端口；形状相似或数值相同不能替代身份与适用域。
4. 检查候选进入条件。尚不成立的必要条件形成子目标；尚不确定的条件形成区分实验。
5. 将候选的预计共同效果交给统一规划比较，允许与旧空间路径不同，但仍要求可执行条件和反馈责任明确。
6. 每次只执行当前经过重新核验的一步，公开反馈更新目标、机制和后续计划。

```text
规划(当前公开关系, 当前目标):
    欠缺关系 = 当前目标中尚未建立的条件
    产生者 = 召回后置关系能够匹配欠缺关系的已学机制/程序
    对每个产生者:
        根据当前对象与计量重新绑定
        核对其进入条件、预计效果与投影适用域
        未满足条件 -> 生成前置子目标
        未知条件 -> 生成能区分解释的公开实验
    在原始动作、空间方案和程序方案之间作统一选择
    保存为什么选、哪些证据支持、什么反馈将使其失效
```

Catlab 复用现有共享角色与接口组合；Julia 负责当前绑定、关系求值、条件回归和反例修订；Rust E-Stitch 在这些已有计算意义的表达上发现与压缩共同结构。不要从未解释像素直接要求高层逻辑规则学习器猜所有语义，也不要让不同语言各自持有冲突的数量或目标含义。

#### 再从多关轨迹提炼共同正文

跨实例对齐的对象应是“建立某关系—执行技能—核验某后继关系”的结构，而不仅是 ACTION1、ACTION2 的字符串。

将颜色、坐标、实例身份等差异提升为参数；保留每个前置条件、效果和终止关系的证据。使同一个高层正文可以在不同绑定下产生不同具体路线及子目标组合。

固定 Step/Seq 的嵌套加深不能自动产生条件分支、可变次数重复和成功停止。确有需要时，应将这些通用控制算子纳入可学习语言，并检验展开、终止和撤回；不能先手写“逐个处理所有目标”的游戏流程，再把它记为发现的抽象。

当前的候选完成域已经可修订，但“进入就处理过”的工程状态仍要与“某个子目标已实际完成”的假设分开。目标可失效、可重开应进入高层策略条件。

#### 验收贡献，而不是强行改变动作

- 从空库或明确冻结的前缀开始，目标与程序只引用当时已经可用的证据。
- 至少有一个有区分价值的公开实例：关系目标回归产生了旧路径选择没有提供的必要子目标或可行程序方案，实际反馈支持。
- 对同一状态撤回相关抽象正文后，候选、子目标或预测发生可说明的变化；只记录实际执行方案的结果。
- 同一高层正文跨新的布局、绑定和子目标数量消费，具体路线可以不同。
- 跨关反例修订共同正文，不把后关信息倒写到前关。
- 判断通关能力时检查因果和控制链、极端失败及恢复，不以普通运行中的动作数升降代替机制贡献。
- 新概念数量按独立正文、适用域、留出预测和实际消费统计，不能把任务数、发布次数、分组数当作概念数。
