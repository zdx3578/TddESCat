“461 步引用定义”准确，但“461 步预测全部得到支持”不准确。r04 的 461 条引用分为 432 条所有局部 `assessments` 为 `supported`、11 条同时含 `refuted` 与 `supported`、17 条只有 `refuted`、1 条含 `supported` 与 `unknown`。其余 283 条没有定义引用，也没有该口径的结构预测。

432 条局部查询全支持也不能解释成整帧全部正确或动作所有效应已解释：其中 **256 条 `evidence.residual` 非空**。这里的 residual 是现有语义编译后仍保留的未解释变化；本次仅依据实际字段计数，没有把它当作自动证明遗漏某种具体机制。全运行的 `coverage.qualification` 为 461 条 `predicted_queries_only`、283 条 `unresolved`，没有全动作因果闭合的资格声明。程序的 20 步另经预期整帧 SHA-256 与真实回执逐步核对，全部支持；这与 432 的局部查询口径不同。

## 实际用到的抽象和控制

r04 中 20 个程序决策及反馈的 `program.goal.contract` 全部是 `observed_route_waypoint`。没有 `establishes_contact_precondition` 或 `establishes_goal_relation`，独立程序审计的 `relation_uses` 为空。r02 的 24 步也全部如此。因此可以证明当前原版运行消费了已学路线子程序，不能以这两包证明原版已经自动发现并执行关系子目标策略。冻结公开布局的关系回归验证应作为另一实验单列。

r04 每次程序均为两步。20 个程序步骤中 18 步的 `program.depth` 为 2、2 步为 1，实际程序控制最大依赖深度为 2。r02 为 22 步深度 2、2 步深度 1，同样最多 2 层。

不能把普通单步结构预测的 `consumed_definition_depth` 与程序深度混用。r04 所有引用定义动作的该字段分布为：1 层 297 条、2 层 163 条、3 层 1 条；唯一的 3 层在 `c000000747`，局部结果是 `supported + unknown`。局部全部支持的 432 条中，1 层 281 条、2 层 151 条，没有成功完成的 3 层条目。r02 则有 18 条 3 层结构消费，其中 15 条局部全支持；这也不等于 3 层程序或统一七关策略。

“743/744 与空间选择一致”的可复核含义为：723 条直接走 `spatial_experiment` 选定动作；另 20 条程序动作等于当时记录的完整 `baseline_action`。本次重新核对这些实际动作与字段相等关系，但没有在另一个进程重新运行 Julia 规划器来重新生成这份完整基线。两包完整动作及帧轨迹的独立逐项一致，为该记录提供另一项可观察支持。

## 时序、账本与源码身份

当前 `program_audit.py` 对实际程序步骤核对：训练事件不得晚于签收事件；签收事件必须不晚于当前动作的之前事件；输入清单摘要、签收记录、验证记录、发布定义、训练连续片段必须一致；程序每步必须连续；完整预测与回执匹配后才计为成功完成。两包均零错误。本次重算验证这些已保存的材料和关联关系，未重跑 Julia 定义展开证明。

本轮 r04 的 149 个模式只有 57 个完成，92 个尚未提交。r02 是 74 个完成、5 个未完成、70 个未提交；所谓 79 是已尝试数量。历史“70 个积压全部恢复”属于随后冻结账本的独立续学结果，不能覆盖本轮 r04 的 92 个未提交模式。

两包 `manifest.git_commit` 都是 `7d519eb7d07adbac4cfa4e84faf35ce76f85ec84`。r04 的工作树摘要为 `7274c4c8d341fe9c98baebc8e4ec9d70b9b525ff212b642676a2378e4d0104bb`，r02 为 `7afed768d43a33c02797ad98faf429befb62ef89d584b4df97a6ba2ea237bbeb`。工作树摘要函数会聚合当时已跟踪和未忽略文件的内容摘要，不能从一个摘要恢复全部运行源文件。本次能证明“用 19e9 的 Python 审计器复核两包通过”，不能证明“运行时工作树逐文件等于提交 19e9”。需要运行源码清单或可复原源快照才能完成后一项。

当前索引所列的全部项目大小和摘要均一致；归档还附有索引外的辅助结果，所以“索引全部通过”指所列文件。归档整体 SHA-256 另由解包步骤核对，不在本脚本中重新读取 7z。

## 可复现执行方式

以包含指定提交四个审计源码文件的 checkout 为 `--repo`，两份已解压证据根目录为 `--optimized`、`--official`，独立输出目录为 `--output`：

```bash
python 13-audit-native.py --repo /path/to/TddESCat --optimized /path/to/optimized-r04 --official /path/to/official-r02 --output /path/to/review-output
```

脚本校验四个源码 SHA-256，避免把其他版本审计结果标为指定提交。它只取 `autonomous_report` 的 Python 审计函数体，明确移除会启动 Julia 的前置步骤；回放退出码作为作者归档字段保存，不伪装成本次执行。输入根目录不写入，输出也禁止位于输入根内。脚本输出的 `compact-audit.json` 在此以 `13-independent-audit.json` 提交，是精简结果；较大的展开报告不包含帧原图，但无需随本次说明上传。

关键源码位置：

- `tests/bench/check_real_public.py::autonomous_report`：逐动作证据、公开回执、准入/晋级及结构消费的核对；`structural_consumption` 的计入只要求局部查询全支持。
- `tests/bench/program_audit.py::audit_live_goal_programs`：签收与训练前缀、程序连续性、整帧反馈和两种动作基线。
- `tests/bench/program_audit.py::audit_projection_record`：整帧写入、实际像素差异、条件读集时序。它不重新拟合投影条件。
- `python/src/tddesc_tools/run.py::worktree_digest` 与 `run_task`：记录运行时 Git 基点及工作树摘要；两者不能直接证明运行工作树等于后来的提交。
