# 整帧投影修订专项核查

核查提交：`19e9cf31de1e555da7f93928c8151780c77054c2`，分支 `impl/2026-11-23-toolchain-bootstrap`。源码通过 GitHub connector 获取。证据只读使用 `optimized_r04/public` 与 `official_r02/public`；没有运行新游戏、昂贵搜索或修改证据。

## 结论

**此前“整帧反例没有自己的修订状态，随后局部 supported 即可重新放行”的缺口已经实质解决。** 现在投影适用域与局部机制适用域分开维护，程序控制必须通过投影适用域；局部效果正确不会直接删掉投影反例。新版条件是在所记录历史内一致的经验条件，尚不能称为通用角色相对遮挡规则或充分因果机制。

本次另写独立 Python 前缀审计，逐条重建公开动作历史、投影候选特征、全历史一致性、重复支持、条件读集、实际差异与条件补丁。优化包 112 条、对照包 103 条投影均无状态或像素差异。此审计没有独立重构 Julia 的完整对象解释器、数量识别器或机制身份哈希；沿用记录的数量输入和局部支持标记，因此不将它称为整个推理器的独立证明。

## c107 → c109 → c110 的真实含义

三次使用同一投影契约 `projection-f1c8523f95e7b22f10d30d5cb6de873f3ba2bbedf5b8f704d455891edf69ae54`，其训练机制来源为 c27。

| 动作 | 执行前状态 | 历史支持与实际结果 |
|---|---|---|
| c107 | witnessed_base | 先前 c86、c87、c88、c89、c90、c105 的投影无差异；这次局部 supported，但基础整帧预测有 5 个像素错误。记录第一条投影反例。 |
| c109 | unproved_projection_scope | 当前 5 个绝对像素值落入反例分支；此前该分支仅 c107 一个不同 before 帧，无法准入程序。普通探索执行后再次得到同一 5 像素差异，第二反例进入历史。 |
| c110 | conditioned_projection | 当前像素进入已有 6 个不同 before 帧支持的 unchanged 分支。两步程序开始，基础预测与条件预测相同，整帧实际匹配。 |
| c111 | conditioned_projection | 同一 unchanged 分支，整帧匹配，程序完成。 |

五个条件位置以零基坐标表示：`(50,47)`、`(51,46)`、`(51,47)`、`(51,48)`、`(52,47)`。c109 输入依次为 `[9,12,9,9,9]`，c110 输入为 `[1,0,0,1,0]`。每一个位置单独形成“此颜色 → 哪个精确补丁结果”的经验表，并且所有表必须一致；并非把五个像素自动提炼成了共同对象或遮挡关系。

c110 的条件读集为 c85–c90、c104–c109，共 12 个更早事件。这些包含上述 8 次投影试验的 before 与 after 引用，均早于 c110，没有使用本步回执作为本步决策前提。

**必须保留的归因边界：**把 c110 的输入放回仅包含 c107 之后历史的旧 scope，仍会得到 conditioned_projection / unchanged。因而 c109 新增第二反例不是 c110 在该输入重新准入的必要原因。精确表述应为“反例后收缩适用域，之后在已有支持的不同上下文重新准入”，不能写成“c109 学到的补丁使 c110 预测被改正”。c110 的 projected hash 与 base hash 相同，correction 为空。

c107 和 c109 的主体绑定位置完全一致；两次 before 帧仅在其他区域有 16 个像素差异，计量从 36 变为 32。因此“不同 before 帧”是去重门槛，并不是对关键条件做了独立干预的证明。

优化包还确有 **c290、c292、c303 三次非空条件补丁**匹配公开回执，分别修正 9、9、4 个像素；它们均由普通接触关系探索执行，`program=null`。所以已经证明条件补丁可被计算并正确预测，但本包没有证明非空修正补丁被跨步程序消费。对照包非空条件补丁次数为 0。

## 两个剩余问题及具体解决方式

### 1. 条件及补丁缺少角色相对表示与多条件组合

**代码位置：**`ProjectionRevision.jl:32–77`、`152–166`。

**当前逻辑：**候选只包括反例补丁涉及的绝对像素位置、配置长度的动作后缀和已有数量索引。每个特征独立拟合“输入值 → 完整补丁结果”；单特征存在冲突就丢弃。补丁同样保存绝对位置的旧值、基础值和修正值。

**后果：**相同作用移至另一个位置不自动等价；两个条件共同决定效果但任何单条件都不充分时，所有单特征均被丢弃。某个远端条件像素自身不改变、也不在错误补丁坐标中时，不会成为像素候选。独立构造 8 条有限数据（A、B 两像素各有 0/1，只有 A∧B 产生修正，每组合有两个不同 before 帧），当前拟合逻辑产生 0 个条件，虽然联合规则确定且全覆盖。它会保守返回 unknown，这是能力边界而不是错误预测。

**解决方式：**先复用已有绑定，把候选和补丁坐标改成“绑定角色 + 相对偏移/几何关系”，数量以角色身份寻址而非仅位置索引；在候选层接入同色、相邻、覆盖、关系状态和动作历史等已有通用可观测谓词。允许从单谓词向联合谓词提升，用全部历史核验最小一致条件，并保留未见组合为 unknown；由 E-Stitch 搜索可复用条件结构，TDD 可作为有限候选关系的共享表示，不能代替语义生成。先验不应注入 ls20 的具体坐标或颜色含义。

**必须验收：**同一关系整体平移后的角色重绑定；同色干扰物；A∧B/XOR 式联合条件；未见组合；远端静态开关；非空补丁被真实程序消费且改变其可用性。保持已有反例不会被局部 supported 清除。

### 2. Python 独立审计还未重建投影条件的成立性

**代码位置：**`tests/bench/program_audit.py:38–79`。Julia 的更完整前缀检查位于 `ProjectionRevision.jl:283–339`。

**当前逻辑：**Python 重建预测像素和散列，核验实际差异、公共状态、契约/版本字段相等及声明的条件引用早于当前事件；没有从先前回执重新拟合条件、要求条件读集完整、核查当前输入的重复支持。Julia 恢复会做较强条件复验，但它与被测学习器使用相同实现，且数量、局部 supported 仍部分来自记录。

**后果：**Python 的 PASS 不能单独证明“此时有充分历史条件可以重新放行”。在只读内存中把 c110 的 `condition_reads` 从 12 项删成空表，原 `audit_projection_record` 仍通过。未改原证据；本批真实记录经新增独立前缀核查正确，因此不把此问题说成已经发现原版违规放行。

**解决方式：**将独立 Python 前缀拟合正式加入 program_audit，按事件顺序维护每契约试验、重算条件输入与重复支持、精确比较条件读集和修正补丁，并要求允许状态与重算结果一致。继续从公开帧重算数量绑定与局部效果，避免信任 claim 中的输入。以“清空读集、混入未来引用、去掉唯一反例、替换数量/绑定、换用其他角色的补丁”等内存负例验证审计会拒绝；不需要新游戏或大搜索。
