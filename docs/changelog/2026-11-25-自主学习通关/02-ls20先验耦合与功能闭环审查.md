## 1. 结论与本轮证据边界

**这次是有实际价值的公开反馈学习与控制闭环：在已经工程化的视觉谜题表示和机制候选族内，Agent 从空经验库开始，筛选条件、更新模型、连续完成同一游戏的七关。当前证据还不足以将它称为通用的对象、机制与高级概念自主发现系统。**

应同时保留以下判断：

1. 没有在本次审查到的正式求解入口中发现绕过公开接口读取游戏私有状态的依据。正式入口建立独立环境、冷启动知识状态，并禁止自主配置夹带先验轨迹或目标。不能把强归纳先验直接说成私有信息作弊。
2. 接触通行条件并非只剩唯一答案的固定条件。代码枚举四种比较关系的 81 种合取，依据公开正反回执筛选；关键反例被移除后，对应判断回到未知。这是限定假设空间内的真实学习。
3. 变量选择与模型族预设很强：哪个窗口代表上下文、哪些图案是接触目标、资源怎样消耗与补充、什么事件推动时钟、规划状态包含哪些因素，主要由代码规定。这些预设明显偏向目前已调试的这类像素谜题。
4. Rust E-Stitch 的定义确有动作前预测消费及动作后核验；当前自主路线却主要由 `VisualControl` 直接生成。不能把 464 次定义引用解释成“464 次动作由高级抽象决定”。
5. 首要改进不是增加定义数、参数上限或人为制造依赖深度，而是让模型的适用条件可被反例修订，并打通“视觉解释—关系概念—持续程序学习—规划消费”。

**本轮实际完成的是固定版本的文档与源码审查，没有重新运行约 45 分钟的求解或约 147 分钟的完整验收，也没有取得原始运行目录的全部回执。** 764 次动作、19 个定义、464 次消费等属于仓库报告中的运行结果；这里独立检查了产生和验收这些结果的实现，不能声称本轮又逐条复核了 764 条原始动作。

范围：完整阅读今日 00、01，以及昨日 16—24 文档；检查相关 Julia 学习与规划模块、Python 隔离与独立验收代码、配置和单元测试。昨日早期计划不再当成当前实现状态。

## 3. 先验分层：哪些值得保留，哪些需要改成可修订假设

### 3.1 通用表示先验值得保留

公开像素、局部四/八邻接、颜色相等、相对位移、时间顺序、动作干预标识、精确来源和有限域关系运算，都是可复用的计算基础。没有必要为“零先验”删除这些基础。

当前角色候选从共同位移、空间相邻和可重复定位中产生，动作方向也有公开回执学习及动作编号置换测试。它比写死“某种颜色就是玩家、ACTION1 永远向右”更通用。

但共同运动只能先产生“共同变化支持集”的候选；尚不能直接证明它是唯一可控对象。自动移动物、相机移动、多个同形对象和选择切换，都需要后续干预与角色绑定区分。

### 3.2 当前较强的领域模型先验

| 模型部分 | 实际实现 | 约束及影响 |
|---|---|---|
| 图案表示 | `VisualFields.jl:1–34`，单前景色、规则格子、至多 64 位占据掩码 | 多色、非规则或较大图案无法直接进入此模型 |
| 上下文窗口 | `VisualControl.jl:111–146`，离格点的候选中取最大窗口 | 装饰面板、多个面板、位于格点的有效面板可能导致错绑 |
| 接触目标 | 同一位置按格点、尺寸、完整边界筛小图案 | “目标/条件窗口”语义来自几何筛法，尚非干预后竞争得到 |
| 接触规则 | `ContactLearning.jl:22–59`，尺寸、轮廓、颜色、数量的相等/不等/不使用，合计 81 个合取 | 无法表达析取、资源阈值、动作方向、时序或局部模式切换；冲突后退到未知但不会自行扩充语言 |
| 变化机制 | `VisualControl.jl:305–360`，按落点图块与输入图案归类，匹配精确案例、矩形变换、颜色映射、方向等变 | 是指定机制族内的参数学习，条件不包含完整动作/历史上下文 |
| 资源 | `VisualControl.jl:227–266,514–654`，首个下降确定耗量，条形几何长度给满充量，位置补给一次 | 常量成本、几何容量与一次性补给还不是普遍经过证据认证的规则 |
| 时钟 | `SceneMemory.jl:80–124` 及 `VisualControl.jl:242–244`，成功位移计时、最短完整相邻周期 | 等待/受阻也计时、一次动作推进多相位等环境不在当前模型内 |
| 路线状态 | `VisualControl.jl:368–374`，位置、图案、资源、已用补给、相位 | 钥匙、选择对象、开关、可推动物、历史状态等不能自然加入；按剩余资源支配还隐含“资源更多不会更坏” |

**耦合显著存在于候选选择、状态表示和模型适用域。** 它不是仅靠搜索 `ls20` 字符串就能发现的耦合，也不宜统计成一个没有基准的“耦合百分比”。

今日 01 文档已经诚实说明这些候选是在调试 ls20 的公开反馈过程中加入。正式冷启动只消除了轨迹与学习结果的预载，不会消除开发过程中形成的表示偏向。

## 5. E-Stitch、联想、范畴和 TDD 的实际位置

### 5.1 已经实现的工作不能再列作“尚未开始”

昨日 17—22 文档及当前代码已有 schema 3 关系解释、关系宏消费与反例修订、有序程序、八步程序依赖深度 5、点击重绑定、共享资源程序、中间帧条件、后台学习和有限强策略等验证。

因此不能继续提出“先写一个 Seq”“先开放深度”作为主要下一步。这些基础已存在。需要处理的是它们在真实原版、自主视觉路径上的覆盖与接线。

### 5.2 本次正式 ls20 的实际消费边界

`config/autonomous_public.toml:21–25` 未启用 association/sequences；后台作业为 effect / joint-mechanisms。联合机制从认证展开的表达生成效果模型，动作前预测、动作后测量，引用是实际存在的，不是虚构调用。

但 `VisualControl` 使用自己的接触、图案、资源、时钟和空间路线数据；`OnlineSession` 在它决定动作后选择同动作的机制行附加预测。现有统计不能分离压缩、预测和控制三种贡献。

Catlab 对同一动作多效果的角色结构组合已有价值。下一步应复用现有有类型端口、角色粘合、关系解释及程序边界检查，将视觉解释接入；无需另造与现有语义平行的专用视觉概念库。

Tree Decision Diagram（树决策图，TDD）可以作为已明确有限变量关系的候选求值/共享后端。本次接触 81 条候选与空间路线搜索并不是 TDD 实现，本次运行也没有 TDD 或 Probabilistic Circuit（概率电路，PC）带来增益的调用证据。它们不替代变量发现、反例选取或概念控制消费。

## 6. 独立验收还需加强的边界

### 6.1 已有的强核验

`autonomous_audit.py:84–210` 从保存的公开像素重建接触结果并重新计算候选集合与判断；这是实质语义核验。正式入口外层已有网络命名空间隔离，不能因 solver 内层没有重复设置网络选项而误报失守。

`VisualControl.jl:428–456` 在真正执行接触前会重算当前条件并更新选择时点，不能把独立审计器的防篡改缺项说成生产控制已使用过时规则。

### 6.2 需要补齐的独立检查

1. **重建图案与目标位置的对应。** 生产按图案框、角色尺寸计算接触点；审计目前分别验证点与图案，却未独立重建两者的几何绑定。用“另一处同值图案替换”应当能被新审计拒绝。
2. **检查样本遗漏。** 当前审计重算的是已报告的 contact_feedback；应在声明的公共候选域中独立枚举实际接触及未知原因，发现该报未报的反例。
3. **检查非接触路线依赖。** 独立重算被采用的运动边、资源更新、时钟假设和图案转换；未认证的前提必须保留未知，不能因已有一条学习来源就升为高置信。
4. **增加结构学习闭环签收。** 当前自主 PASS 条件不强制新定义或结构消费。应独立列出 WIN、条件学习、结构预测、程序参与控制、反例修订各项结果，防止单一 PASS 掩盖未完成的能力。
5. **区分原始回执回放与策略重算。** 原回放继续保留；新增从空状态、只读取当前事件之前证据的策略重算记录。两者检查对象不同，不能互相代替。

## 7. 下一步优先顺序与验收方向

采用两个有明确功能终点的交付阶段，详细落实见同目录后续实施计划。

**第一阶段：先验可修订与最小因果单元闭合。** 修正成功边忽略失败、静止动作漏入视觉链、固定资源/时钟外推；建立统一公开效果与模型候选，保留并重解释未知。以公开接口端到端的反事实环境检验，不再只手工填入正确 role/field/targets。

**第二阶段：真实会话中的概念—联想—程序—控制持续学习。** 将已闭合动作及多帧关系接到现有关系/程序框架；在线发现、认证发布、反复召回、逐步重绑、反例局部修订。验收要求概念实际改变候选路线或动作，并在保留条件的未见实例中复用。

新增实验应覆盖两类独立变化：

- 保持机制、改变显示：颜色与动作编号置换、无关大面板、多面板、布局和尺度、多个同形角色。
- 保持显示、改变机制：同位置开关门、原地改变状态、变量资源耗量、补给重复性、受阻也推进时钟、远端条件、同外观依赖历史。

合成生成器的机制参数只给独立裁判，Agent 始终仅见正式公开帧、合法动作与回执。改造不能依赖游戏名、固定颜色或专用解题模板。既有单元测试保留，新增验收必须走“发现→消费→反例→修订→再次消费”的完整路径。

## 8. 衡量抽象与通关改进的口径

至少分别报告：

- **表达闭合率**：按公开事件及候选作用域统计，动作、对象绑定、条件、效果、时间/资源依赖哪些已解释，哪些残余/歧义仍在；不可把所有像素都预设为已知语义。
- **预测适用域**：支持、反驳、未知和机制冲突分别列出；明确所预测查询与未预测变化。
- **反例修订能力**：反例后下一次同类决策是否撤销错误、增加区分条件、重新学习并恢复使用。
- **迁移质量**：未见布局/颜色/对象绑定/条件组合中的正确复用；跨关与跨游戏分开。
- **控制贡献**：定义是否参与生成转移、排除路线或改变选择；仅附加解释与预测不能计成控制贡献。
- **抽象质量**：去除别名后的依赖、参数共享、冻结任务前置库、新定义与改写语料的总成本（全局存储成本另报）、可复用作用域、反例稳定性；不以层数或定义数量单独验收。
- **动作覆盖**：每个当前合法动作及已发现对象绑定的效果和条件是否仍有未决项，无法试验的原因是否明确；不将重复移动次数当覆盖。
- **资源实测**：按环境交互、Julia 推理、Rust 搜索、证明验证、结束签收分别记墙钟时间与峰值，后台重叠不能直接相加。

按现有报告口径，约 45 分钟对应 Julia 求解进程，约 147 分钟对应完整验收。本轮未取得两者的计时原件，尚不能独立核对起止范围和各阶段耗时，也不能把差额归因于某个组件，或据此建议简单减少搜索深度与参数。
