# 投影反例修订和程序搜索账本验收

整帧投影现在有独立契约。决策冻结时保存机制补丁、当前绑定、被读取的区域、写入区域、其余区域保持不变的假设和来源。回执按写入区内、区外、绑定与公开状态变化归属差异。局部位移和计量正例仍更新局部机制。投影反例保留在相应契约的证据集中，并用作用域版本约束后续规划。

修订会从公开动作历史、计量读数和确实发生差异的位置提出条件。候选条件要能一致解释已见对照，允许消费的输入值要有不同公开前帧的重复支持。能完整核对的联合效果可形成条件化补丁，逐格校验原值和目标值。候选分歧、对象不明、多帧义务或公开状态未能解释时保持未知。提交前的投影记录与确认后的反馈可从原始回执恢复。

## 核验结果

| 证据 | 结果 |
|---|---|
| 原版 r04 的七条反例 | 原预测摘要全部复原，局部查询全部保持支持 |
| `c109` 和紧随的 `c110` | 原写入区 5 像素不符。下一次局部正例保持原投影未知 |
| 其余六条原版反例 | 写入区外分别出现 36、36、36、36、230、296 个差异像素 |
| 程序调用审计 | 用同一入口核对 16 次完成和 7 次反驳撤回，审计错误为零 |
| 隔离公开对照 | 反驳后未证实的候选失效，加入公开对照后恢复。两个新位置分别核对保持和联合变化 |
| 原版程序账本 | 149 组可识别模式，74 组完成搜索，5 组搜索不完整，70 组可生成且未提交 |
| 五份冻结输入的监督重跑 | 原 6 GiB 限额下均退出 137，控制组分别记录 `oom_kill=1`，峰值 6,442,450,944 字节 |

监督器等到记录退出状态后读取本次控制组的内存峰值和事件。五份输入均在搜索第一轮耗尽内存，尚无可核验的完整轮次。开放搜索策略沿用原配置。待提交组、已提交但不完整的搜索、部分发布和新观察成员分别保留。部分发布可以消费已核验结果，同时保留搜索义务。

原版复核使用已有回执。条件化恢复的两次实际执行使用隔离公开合成环境。完整当前生产复核随关系目标控制验收另行记录。
