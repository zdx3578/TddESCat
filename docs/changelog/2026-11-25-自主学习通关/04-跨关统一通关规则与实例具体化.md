## 1. 将最终目标明确为游戏级的统一规则

用户提出的目标是：同一游戏七个关卡应形成共同的通关规律；每一关的对象、布局、初态、条件和机制组合，是共同规律的具体化。

这一目标比共享一个接触条件、复用一段固定动作宏或增加定义依赖层数更完整。建议把它设为 03 计划的明确终点：

> 从各关公开经验中发现共享机制与成功关系，形成可在不同实例中选择子目标的策略；进入新关后，通过公开绑定和必要的新实验，产生该关具体控制。

Generalized Planning（泛化规划）研究的是用共同策略解决同一领域的多个实例，适合为这一层提供方法参考。这里还需要补上 ARC-AGI-3 的公开像素解释、成功关系发现和不完整证据处理，不能直接假定已有完整规划模型。

“最高抽象”在这里指相对于一个游戏的高层共同规律。有效抽象仍必须保留会改变成功和动作后果的差异。“完成所有要求即可成功”没有可执行判定，不构成完成的成果。

同一游戏的后关可能只增加布局和组合难度，也可能引入新机制。系统应先尝试现有规则的具体化，再以反例判定是否需要扩展共同模型，不能为了维持“七关统一”而掩盖实际差异。

## 2. 一套统一规则应包含三个部分

| 部分 | 要回答的问题 | 具体化时改变什么 |
|---|---|---|
| 成功关系 | 当前满足哪些可观察条件，执行怎样的干预，会产生关卡推进或最终 WIN？ | 本关目标的角色绑定、数量、组合与初始满足情况 |
| 共享机制 | 动作怎样改变位置、图案、选择、计数量、开关或时序状态，适用条件是什么？ | 作用对象、坐标、数值、具体机制实例与可辨模式 |
| 参数化策略 | 当前还缺哪些条件，用哪些机制建立它们，子目标怎样组织与反馈修订？ | 具体路线、动作次数、局部顺序和必要的探索 |

可以将共同模型记为 H，将本关参数记为 θ，将抽象角色到公开对象的绑定记为 β。这里：

- H 是共享的条件、效果和子目标组织正文。
- θ 是布局、数量、初态和可辨参数，不存储预写答案或整条路线。
- β 说明抽象角色此刻对应哪些可见支持或关系实例，保留绑定歧义和证据。
- Instantiate 是实例化：使用 θ 和 β，将共同正文变成本关可求值的关系与规划问题。

于是本关模型来自：

\[
M_\ell=\operatorname{Instantiate}(H,\theta_\ell,\beta_\ell).
\]

这表示声明作用域内的模型构造，不声称未知隐藏状态已被完全还原。当前关的具体动作序列再由 M_\ell、当前公开历史和目标求解产生。

关卡编号可用于证据分组，不能充当预测特征或万能条件分支。“第一关执行脚本A，第二关执行脚本B”不满足这里的统一要求。若确有公开机制模式不同，应由公开可辨条件选择机制，而非从关卡编号取答案。

## 3. 当前代码与这个目标之间最关键的差别

### 3.1 当前接触条件没有区分准入与完成

VisualControl.jl:285–295 原本区分：

- blocked：受阻；
- entered：进入，但没有关卡推进；
- progress：进入并产生关卡推进。

但 ContactLearning.jl:43–50 拟合时使用：

~~~julia
key = (
    contact_signature(sample.context, sample.site.value),
    sample.outcome != :blocked
)
~~~

entered 和 progress 都被折成 allowed=true。因此已学到的“完整支持和颜色相同”首先是接触准入条件，不能直接提升为整个游戏的充分通关条件。

今日 01 报告记录第六关 c000000429 只确认进入，c000000498 才确认推进。这是区分准入和完成的实际线索，不是已经证明“必须完成所有接触点”或任何其他新机制。后者需要额外候选与证据。

后续应分别保存三个问题的结果：

1. 空间接触是否受阻或进入；
2. 公开关卡进度是否增长；
3. 会话是否达到 WIN 或其他终态。

这些结果可以同时成立，不要再把它们混成一个允许/不允许标签。进度与 WIN 来自公开回执，作为学习结果标签；禁止把动作后回执或下一关画面放进动作前预测条件。

### 3.2 现有跨关复用是分散的

VisualControl.begin_visual_level! 保留 contact_samples、changes、refill、boundary_rules，重置本关 field、targets、scene、resource、rate 和 continuation。OnlineSession.jl:753–760 重建空间学习，并尝试保留仍能定位的角色。

这些是已经存在的跨关复用，不能说完全没有。但 OnlineSession.jl:790–796 又会清空联合机制 trials 并重新拟合条件。不同子系统各自决定保留什么、重置什么，尚无统一的共同模型、实例参数和绑定合同。

改造需要区分：

- 本关过期的对象绑定和地图实例；
- 可跨关重绑的机制正文；
- 支持该正文及其适用域的历史证据；
- 新关仍待辨明的参数和机制差异。

不能简单全部清空，也不能把上一关的绝对坐标和条件直接带入。

### 3.3 固定步骤宏尚不是可变实例策略

ProgramSemantics.jl:52–91 将宏展开后核对与来源轨迹相同步数、动作编号、效果数和共享端口；LearnedProgram.steps 保存有限具体步骤。

这些宏具有实际复用价值，但增加依赖深度不会自动产生“对象数量不同也能处理”“路线长度不同也能规划”的策略。

第一步可以先让共享机制与目标关系驱动现有规划器，生成不同关卡的具体序列；不必等待一个巨大的循环宏被发现。进一步学习可变长度程序时，再明确加入通用条件、子目标调用和循环/进展语义。

## 4. 如何从七关经验提炼：六个相互衔接的操作

### 4.1 将成功、失败与未完成结果都变成学习材料

数据单位使用 Frame–Action–Trace–Frame，即动作前帧、公开动作、同次响应的全部有序帧、最终帧；必要的公开历史可以进入条件。

优先组织这些对照：

- 图案相似但受阻；
- 接触可以发生但不推进；
- 已满足部分条件但仍未完成；
- 同一机制在新位置或新角色上成立；
- 某些效果改变后，之后的动作从失败变成功；
- 同样外观因公开历史不同产生不同结果。

七条成功路线不能单独确定唯一规则。成功轨迹里的试探、绕路和恢复也不能自动标成必需步骤。

普通移动没有推进，并不自动成为“目标条件错误”的有效反例。反例必须与候选声明的干预、对象、前置条件及作用域相符；未观测分支保持未知，不能标成坏动作或死路。

### 4.2 对齐关系角色，再参数化具体常量

Typed Anti-unification（有类型反统一）用于找多个已解释关系/程序的共同结构，并保留每个实例如何替换回来。

以下是说明算法的例子，不是对全部 ls20 机制的最终裁决：

- 经验A：输入图案是“形状P、颜色9”，接触图案也是“形状P、颜色9”，进入。
- 经验B：输入图案是“形状Q、颜色12”，接触图案也是“形状Q、颜色12”，进入。

可以提出共同候选：

~~~text
contact(
    signal(shape = S, color = C),
    site(shape = S, color = C)
)
~~~

S 是在这一对关系中共享的形状变量，C 是共享的颜色变量；signal 和 site 是由公开解释产生的角色接口。两处重复使用同一个 S、C，保留了“必须相同”的关系。

若把两边分别改成四个互不相关的变量，就丢失了共同机制。反统一也不能单靠两个正例证明该条件必要或充分，仍需要同色异形、同形异色及其他条件对照。

跨关对齐以行为接口、条件读取和效果产生关系为依据。颜色相同、形状相似、位置接近只提供候选线索，不直接证明对象的机制角色相同。

### 4.3 对齐条件依赖，不要求动作顺序相同

同一高层要求，在不同关卡可以有不同实现：

| 假设性实例 | 当前缺少什么 | 某种可能的具体化 |
|---|---|---|
| A | 颜色不满足目标条件 | 找到并执行相关变化，再到达目标 |
| B | 形状与颜色均不满足 | 组合两个已验证机制，再到达目标 |
| C | 条件机制相同，但资源或通路不足 | 先建立执行条件，再完成相关变化和接触 |

这些是解释方法的假设例子，不是 ls20 各关内容表。

共同结构来自“哪些效果建立了哪些后续条件”。若两个变化相互影响，则顺序必须保留；若已验证互不影响，才允许具体化时交换。不能仅因最终图案相同就认为资源、时间和中间状态也等价。

从实际效果与后续条件读取可先建立候选依赖图。必要性和可交换性仍需反例或动作对照；数据流上的相关不能未经检验提升为完整物理因果结论。

### 4.4 从成功关系向后寻找可实现的子目标

Regression Planning（回归规划）在这里指：从要达到的条件向前提追问。

例如：

1. 要产生已学的推进结果，需要哪些条件？
2. 当前哪一项没有满足？
3. 哪个已经验证的机制能够建立它？
4. 该机制又要求什么对象、状态、资源或时间条件？
5. 本关是否有可执行实现；如果没有，哪个未知关系需要实验？

答案形成带条件的子目标图。这个图可以跨关共享；路线和具体动作由本关绑定与规划生成。

Policy Sketch（策略纲要）可以表达“需要达到怎样的下一个子目标”，允许具体规划使用不同数量的动作。当前固定 Step/Seq 表示不能自动获得这种能力。

采用循环、集合量化或“反复处理未完成目标”时，必须有可执行语义和进展检查。未完成数只有经过验证不会被后续动作随意恢复时才可作为进展量；有干扰时需要更完整的依赖和重规划。不能预写“数量总会减少”来保证终止。

### 4.5 联合选择共同模型与各关实例化

Minimum Description Length（最小描述长度）提供一个模型选择思想：共同规则应使整体经验更容易表达，同时保留正确预测与控制。

应同时计算或检查：

- 共同正文有多复杂；
- 每关还需要多少绑定、参数和局部解释；
- 哪些真实效果仍未解释；
- 是否存在很多只服务一个关卡的例外；
- 是否能正确解释全部已知反例；
- 能否生成可执行的子目标与控制。

“七套脚本放进一个 switch”会留下大量实例专属正文。“满足条件就成功”则没有解释具体条件与实现。两者都不满足目标。

这项联合模型选择尚不是当前 E-Stitch 已实现的完整目标函数。E-Stitch 负责已编码语料的结构发现与压缩，继续使用冻结任务前置库、新定义和改写语料的整数总成本；全局存储成本另报。环境证据一致性与有效控制另行验收，不能用压缩收益抵消已确认反例。

### 4.6 在新关具体化，并按反例修订正确层次

进入新关后，依次判断：

1. 旧角色在这里如何绑定？
2. 布局、数量、初态等参数是什么？
3. 共同成功关系和机制目前哪些可用，哪些未知？
4. 哪些子目标可由已有机制实现？
5. 新反馈冲突来自绑定错、参数不同、缺失条件、新机制，还是公开信息不可辨？

修订应保留仍正确的共同结构。若新增机制有可复用作用接口，则加入共同模型，并回查早关是否受影响；不要增加按关卡编号选择答案的分支。

## 5. 范畴、偏序、反统一与 E-Stitch 如何协作

| 方法 | 在这项任务中的职责 | 不能替代的部分 |
|---|---|---|
| 多维偏序 | 组织条件更强/更弱、适用域更宽/更窄，以及模块组合的关系 | 无法单靠排序决定哪个经验解释正确 |
| 有类型反统一 | 从不同实例提出共享正文和具体替换映射，保持重复变量约束 | 不证明未观察情况下仍成立 |
| 范畴组合 | 检查机制和子程序的输入输出角色能否组合，具体化是否保持声明的关系 | 不自动发现目标语义，不让经验规律变为全域定理 |
| E-Stitch | 发现可节省表示与计算的共享关系和程序正文 | 不能压缩尚未编码进语料的条件，也不自动发明缺失的循环语义 |
| 主动公开实验 | 区分候选、发现缺失变量、支持或反驳预测 | 有限交互不能识别所有不可观察差异 |
| 具体规划 | 用共同机制和本关事实生成可执行动作，逐步反馈检查 | 不能把模型未知当成安全可行 |

“具体化更强”必须在角色与语义对齐后讨论。不同布局、对象域和目标集合可能互不可比，后关不必在所有维度上都严格包含前关。

范畴方面，可以采用可检验的关系保持条件：将具体公开状态投影到抽象状态后，实际执行某个抽象步骤的具体动作，其结果必须落在抽象关系允许的后继中。若只有集合包含和不确定性，应表达为保守模拟，而非强行声称两边同构或完全相等。

同时还需验证被选择的抽象步骤在当前关卡有具体实现；只验证实际结果不越界，不能排除抽象模型存在不可实现的虚假边。

## 7. 生产闭环伪代码

以下是拟实现的职责，不是现有函数名：

~~~text
for each confirmed public event:
    preserve before, action, all response frames and public outcome
    update role/condition/effect hypotheses with past evidence only
    retain admission, level-progress and terminal outcomes separately

    if new goal evidence, mechanism evidence or counterexample appears:
        recall related typed relation graphs across levels
        propose shared bodies and per-instance substitution witnesses
        reject conflicts with known public evidence
        record unresolved distinctions and candidate experiments
        send worthwhile repeated bodies to existing E-Stitch workflow

    accept completed publications at action boundaries
    record publication availability and empirical applicability version

on entering a new level:
    reset expired instance bindings
    bind shared roles and determine observable parameters
    keep unresolved bindings and new conditions explicit

before each action:
    evaluate shared goal and mechanism relations on current public history
    select a reachable subgoal or a distinguishing experiment
    instantiate using current roles, objects and available actions
    refine into an executable current step
    freeze all evidence/definition/guard reads
    execute and verify the public response

after a contradiction:
    distinguish binding error, parameter change, missing condition,
                missing mechanism and unidentifiable hidden difference
    revise the affected scope
    recheck dependent plans and earlier compatible instances
~~~

## 8. 怎样验收确实得到了统一规则

### 8.1 回顾性统一

使用已见七关证据形成共同模型，检查能否解释所有已确认正反例及各关具体化。报告统一正文、每关绑定和残余，不把已见七关再解释称为未见泛化。

这能检验是否仍在维护七套互不相关的控制逻辑。

### 8.2 前向跨关迁移

只用前 k 关已经发生的证据，进入第 k+1 关时记录：

- 哪些共同机制直接可用；
- 哪些参数需要绑定；
- 哪些条件需要新实验；
- 第一次及后续决策实际消费了哪些共享定义；
- 新机制出现后扩充了什么，旧知识是否仍成立。

已经用七关调试过的表示代码不能靠遮掉后关轨迹就成为完全无开发先验测试。应明确区分算法固定后的在线时间约束与真正未参与开发的新任务。

### 8.3 未见实例与机制组合

在隔离公开接口环境中，固定机制正文，改变布局、对象数量、参数和组合。必须重新公开交互，不能借用旧轨迹中与新策略不一致的未来回执。

冻结验证中不更新知识；反例用于修订后，其数据进入训练，下一次验证换未使用过的实例。

关键通过条件：

1. 同一共同正文在不同绑定下产生不同具体动作与路线。
2. 不读取游戏编号/关卡编号选择解法。
3. “可进入但不推进”能排除过宽的成功关系。
4. 新增对象数量或路径长度不要求复制更多固定脚本。
5. 已知干扰会影响子目标顺序；无证据时不擅自交换。
6. 反例能定位到绑定、条件或机制，并恢复后续消费。
7. 每关的解释残余、未知条件、未服务动作和失败范围明确列出。

定义个数、依赖深度、七关推进记录和最终 WIN 仅作辅助记录。主要成果是可迁移正文、可检查的具体化以及实际控制收益。

## 9. 主文献与可借鉴范围

1. [Learning General Planning Policies from Small Examples Without Supervision，AAAI 2021](https://bonetblai.github.io/reports/AAAI21-learning-policies.pdf)：将跨实例特征与策略共同学习，区分目标/非目标以及策略允许的转移。它已有规划域谓词、状态图及目标等输入；不能把该方法直接说成从原始像素完成 grounding。这里借鉴其共同特征与可执行策略的联合选择，不导入未观察分支的真值。
2. [General Policies, Subgoal Structure, and Planning Width，JAIR 2024](https://publications.rwth-aachen.de/record/988540/files/988540.pdf)：策略纲要以子目标组织不同实例中的具体搜索。本文不将其有条件的正确性或复杂度结论直接套到未知 ARC-AGI-3 环境。
3. [E-Stitch: Top-Down Library Learning for E-Graphs，官方会议说明](https://pldi26.sigplan.org/details/egraphs-2026-papers/7/E-Stitch-Top-Down-Library-Learning-for-E-Graphs)：从程序语料发现共享函数；用于本文已编码机制、关系和局部程序的结构发现，不替代成功语义与经验适用域的识别。
