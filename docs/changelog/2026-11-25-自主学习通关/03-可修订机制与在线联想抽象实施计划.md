## 1. 本计划的交付目标

完成两条可单独签收的功能闭环：

1. **公开反馈能够修订变量、条件与机制，并立即影响下一次相关控制。** 已有成功记录不能压过后来的反例；原地动作、远程变化、中间帧、资源和时间都能进入共同解释。
2. **本局产生的新关系和多步程序能在本局继续学习、发布、反复调用和修订。** 抽象定义必须进入动作选择之前的推理；新的经验继续形成更长、更可复用的语料。

不重建一套平行框架。沿用 Python 环境隔离与独立验收、Julia 公开观测解释及关系/程序语义、Rust E-Stitch 搜索与压缩校验。已有 learn.v3 协议与 schema 3 语义签名、八步深度 5、点击重绑定、共享资源、反例修订、后台作业及有限强策略实验继续保留。

这里的“联想”具体指：根据当前未解释的结果，召回结构相关的旧经验，提出可执行的关系映射和条件候选，用公开动作区分候选，再把成立的关系交给同一概念与程序库使用。近似相似性只决定查找顺序，不能直接授予因果等价。

本文件是实施计划；列出的新函数名是建议实现接口，不冒充已有函数或已通过验收。

## 2. 开工约束与配置

### 2.1 公开接口与证据

所有求解输入均来自 strict public API（严格公开应用程序接口）：公开帧、合法动作、请求参数、完整响应帧及公开状态。禁止求解器读取生成器参数、游戏源码、对象元数据、私有碰撞图或独立裁判结果。

合成实验可以由隔离测试环境控制机制，裁判可以知道构造真值；这些内容不进入求解器挂载、网络返回、文件名提示或训练标签。原版 ARC-AGI-3 保持官方原版环境，合成变体不能冒充官方通关。

### 2.3 参数与性能原则

配置写 TOML/JSON 配置文件，不增设环境变量。沿用正式 `config/stitch.toml` 的开放搜索策略及 `max_arity=1000`，不新增小轮数、定义数、依赖深度、程序长度或动作数来掩盖未完成工作。涉及规模的实验参数不得低于相应默认配置；每份报告保存配置原文、摘要和引擎身份。

进程资源监管继续如实记录。资源中断的结果必须带未完成义务，不标成收敛或通过。性能优化优先处理重复解析、重复候选、重复匹配、历史全量重拟合和不必要的展开，具体修改以剖析数据为依据。

`RelationSemantics.compose_relations` 当前的 `max_work` 接口不得成为新路径“少做即完成”的依据。复用它的类型和见证语义，改为按有限关系索引完整求值或持久化增量求值；中断时明确 incomplete，不把缺边当否定。

## 3. 第一阶段：可修订机制与最小因果单元闭合

### 3.1 阶段终点

在只有公开输入的端到端环境中，从空知识开始完成：

> 发现作用对象及关系候选 → 执行动作 → 记录完整效果 → 得到受支持的条件机制 → 下一动作实际消费 → 遭遇反例 → 撤销错误适用域 → 生成新条件/绑定 → 再次消费并验证。

第一阶段以可辨的公开机制为范围，不要求从不可观察的隐藏差异凭空获得确定解释。

### 3.2 A1：所有动作共用观测与解释入口

修改 `OnlineSession.run_online!` 的确认回执处理段与 `LocalEffects.observed_effects`。建议新增职责明确的 `interpret_public_event!` 入口，由现有模块共同实现，不复制另一套事件存储。

处理顺序：

1. 验证请求已确认、前后事件连续、所有响应帧完整保存。
2. 从动作前帧提出角色、支持、窗口、计数量和关系候选。候选只读当时已经存在的帧。
3. 解释动作后全部帧中的位置、形状、颜色、计数、选择、远端变化与公开状态变化。
4. 记录“未观测到位移”和其他通道的实际变化；不能用无位移作为退出所有通道的开关。
5. 为无法唯一绑定或解释的变化保留歧义与残差。
6. 更新空间、图案、资源和时序假设，再更新概念语料。

具体删除 `VisualControl.jl:242` 的全通道早退语义。保留位移通道自己的条件判断；原地改色、无位移扣资源、远端开关、等待和选择仍进入其余通道。

**一次公开动作是一个干预单元。** 同次响应中的多帧带有顺序，不能当成独立动作或增加独立样本数。

### 3.3 A2：先解释清楚每个可消费机制必须包含什么

复用已有描述器和证书字段。需要扩充时，内容必须满足下表；表中是语义职责，不要求再造一个庞大的平行结构。

| 内容 | 含义 | 消费端用途 |
|---|---|---|
| 动作与参数 | 实际公开动作编号、点击坐标或当前绑定后的参数 | 区分不同干预，不能把相同画面下不同动作混成一个机制 |
| 角色绑定 | 哪些像素支持/关系实例充当输入和输出角色，哪些绑定仍有歧义 | 逐步重新定位对象，防止同形对象误认 |
| 条件正文 | 用现有有类型关系语言表达的可执行条件 | 在当前公开画面和历史上重新求值 |
| 效果与 trace | 输出变化、同次响应中间帧关系、未解释残差 | 预测、动作后核对和多步接口连接 |
| 适用范围 | 解释版本、变量范围、时间阶段、已知条件及尚未区分的模型 | 限定结论，不把样本一致性提升为全域定律 |
| 证据与反例 | 动作发生、像素读取、正反样本、比较见证 | 独立审计和针对性修订 |
| 依赖与版本 | 使用的定义、观测解释和条件版本，以及签收可用时点 | 新反例只使受影响的规划边和程序续段失效 |

“结构展开等价”与“环境机制受到支持”保留为两种证书。库正文展开正确，并不自动意味着世界遵守该正文描述的规律。

`domain_complete` 只用于确已完整枚举的声明有限观测域。经验样本齐全、当前批次处理完或没有发现反例，都不能自动设置环境转移关系 complete=true。创建经验 `FiniteRelation` 时必须显式传入完整性状态，避免沿用默认 true。

### 3.4 A3：立即修复运动边的反例失效逻辑

位置：`SpatialLearning.jl:109–110`，`VisualControl.projected_motion:490–500`。

将“同位置、同动作存在一致成功就可用”的逻辑改成成功、受阻、不同后果共同约束。状态键不再把位置和动作当作完备机制输入；它们只是召回入口。

伪代码：

```text
revise_transition(event):
    bucket = recall_same_intervention_interface(event)
    append evidence(event) exactly once

    results = compare_public_outcomes(bucket)
    if same current representation yields different outcomes:
        withdraw unconditional deterministic edge
        invalidate plans/program suffixes reading that edge version
        retain all positive and negative evidence
        create discrimination obligation(conflicting events)
        ask relation constructor for observable distinguishing conditions

    for conditional hypothesis affected by event:
        evaluate all relevant earlier evidence plus event
        retain supported scope, retain unknown scope
        refuted scope is unavailable for certified planning

project_transition(state, action):
    bind roles and evaluate current guards
    collect outcomes of all still-compatible hypotheses
    all retained interpretations agree, relevant counterexamples processed,
    and declared interpretation scope checked -> qualified prediction
    disagreement or missing condition -> unknown / distinguishing experiment
```

上述预测只在声明模型和观测作用域内成立；证据诱导候选族处理完毕不等于环境机制全局唯一。仍有相关解释义务时保留未知或限定结论，不能据此宣称真实环境中的全局可达保证。

不能仅在日志里写 refuted 而让 `projected_motion` 继续返回旧成功边。也不能遇到一次反例就永久禁用该动作；开门—关门—再开门必须能重新得到条件化通行。

### 3.5 A4：让变量和条件语言随反例扩展

位置：`VisualControl.bind_visual_fields!`、`ContactLearning.fit_contact_guards`、`ConceptConstruction.construct_relation`、`AssociationIndex`。

具体落实：

1. 最大窗口、规则格点、完整边框、共运动支持、细长条形仅作为候选的产生与排序依据；保留多个公开可解释候选。
2. 若同一输入表示出现不同结果，保存冲突对并召回两次动作前的局部、远端和历史关系。
3. 候选关系使用当前已有的颜色相等、支持、邻接、包含、位移、计数、时序等公开原子；相关新原子必须有精确像素解释和独立校验。
4. 将固定的 81 合取条件、32 邻居颜色查询改为通用候选构造的可覆盖子集，不保留独立专用解释器作为另一条控制通路。
5. 相同训练输出只代表当前证据不能区分；不同机制保持独立候选，安排区分实验。

有限搜索的边界由当前冻结证据决定，不能声称能穷尽未知环境中的所有机制：

```text
construct_for(obligation, confirmed_events_up_to_k):
    scope = freeze relevant witnessed atoms, roles, phases and source occurrences
    graph = typed occurrence graph(scope)
    agenda = new atoms and changed canonical queries

    while agenda has a new canonical candidate:
        generate legal shared-port joins on finite graph substructures
        generate projections and equality comparisons on existing columns
        form normalized unions of same-header candidates
        allow finite complement only on explicitly complete domains

        normalize using syntax and proved algebraic identities
        do not add unsupported occurrence nodes within this frozen round
        do not count reuse of one occurrence as new evidence

        evaluate candidate with existing exact relation interpreter
        check all relevant positive, negative and unknown examples
        save construction certificate and unresolved distinguishing pairs

    return hypotheses, explicit unclosed obligations,
           "this evidence-induced candidate language was processed"
```

本轮候选身份由有限发生子集、有限端口映射和相位、规范列投影、比较集合、规范析取集合构成。连接与投影必须归约到该规范形；不新增冻结范围外的变量或常量，不以重复层产生新身份。无法归约的表达记录为本轮声明语言未支持，不能将其遗漏说成全语言枚举完成。新角色、新 trace 或新证据出现后扩展图并增量继续。

颜色常量既可出现，也可参数化为“两个角色颜色相同”；跨颜色联想时必须重新检验，不能因改名而默认机制不变。多跳关系长度由实际相关关系图和新证据决定，不写死“最多两跳”。

如果公开状态和历史确实无法区分两个相反后果，保留不确定状态及可能后果集合。系统不能为了减少 unknown 伪造可见变量。

### 3.6 A5：资源、时钟和角色作用域进入共同机制

资源改造：

- 细长条先被解释为一个公开计数量候选，记录实际读数。
- 学习条件化的前值—动作—后值关系；首个下降不固定全部动作成本。
- 充满、部分补给、可重复补给、一次性补给分别由反馈区分。
- 资源为零是否阻断动作、是否仍可恢复，也由公开反馈决定；移除“零必然 RESET”的通用假设。
- “资源更多支配资源更少”只有在声明范围的转移与目标条件允许时才可用于剪枝；否则保留不同值状态。

时钟改造：

- 同时保留由已确认动作数、成功位移数、公开响应帧序列等产生的可检验时序解释；明确这些都不是环境私有 tick。
- 新的静止、受阻或多帧事件能反驳旧时钟解释。
- 相邻周期可以是候选模型；周期性、推进单位和相位都要有来源及适用域。
- 缓存图块保留读取时点与失效条件，遇到公开变化重新解释，不能永久把旧像素当静态世界。

角色与状态改造：

- 单像素、多个同形支持、大型自动运动干扰均可提出候选；用动作条件与重复干预证据辨认控制关系。
- 计数、选择对象、远端标记、携带物或历史模式只有在公开证据需要时加入相关状态。
- 规划状态由当前目标和机制依赖闭包投影得到，不继续固定为五个槽位，也不展开所有原始像素的全部笛卡尔积。
- 区分“当前可以站立”“某动作可以通过”“经多步可以到达”；终点合法不等于扫掠路径合法。

### 3.7 A6：共同语义必须位于动作选择之前

位置：`OnlineSession.jl:636–664` 和 `VisualControl.jl:514–654`。

建立一个共同的候选转移求值入口。已经认证的直接关系正文和已经压缩的宏正文都交由同一解释器求值。直接正文是统一表示的正常形态，不能把它做成旧专用求解器的兜底分支。

路线与实验选择顺序：

1. 当前公开观察更新角色绑定与条件真值。
2. 从共同机制生成带来源的候选后继，包括已知结果、分歧和未知。
3. 对当前目标提出可证的路线及需要实验确认的路线。
4. 若目标推进依赖未分辨条件，寻找当前可执行或可到达的区分实验。
5. 将其他可用动作—角色的未解义务纳入持续服务；不能因视觉链每次都有建议就永久饿死点击、等待或其他作用。
6. 冻结选定动作和它真正读取的机制/定义/证据，再通过现有 Recorder 提交。

实验优先级至少显式考虑：是否解除当前阻塞、能区分哪些候选、是否可达、已有重复证据是否过多，以及义务长期未被服务的情况。候选没有概率模型时使用可审计的分歧集合，不把任意分数叫作置信概率。

合法动作覆盖以公开接口为准；点击域、已绑定对象域与未覆盖坐标域分别记录。游戏 WIN 不自动清空其他因果义务。不可再交互的剩余义务留在报告中，必要时由新的公开会话继续验证。

### 3.8 A7：第一阶段端到端验收

下面六组是故障类型，不是六个里程碑。每组都有现有模型能处理的正回归，以及可辨的模型变化；求解器不预填 role、field、targets。

| 组 | 实验构造 | 必须观察到的闭环 |
|---|---|---|
| A-边条件 | 同位置同动作：门开成功、门关受阻、再开成功；远端公开开关区分 | 旧无条件边失效，新条件来自公开关系，并实际改变下一次选择 |
| A-静止与选择 | 原地改色、远端变化、点击选择同形主体、受阻也推动变化 | 无位移效果被记录；下一动作重新绑定实际受控角色；未知保持明确 |
| A-资源 | 不同动作不同耗用，失败也耗用，部分/满补给，一次/重复补给，零资源仍可恢复 | 学到并消费各自条件；不能从一次下降或几何长度推断全域机制 |
| A-表示 | 加大无关面板、移动面板到格内、多面板、多色/实心/超过64单元图案、单像素主体 | 由证据选择/修订绑定，失配可恢复；不是硬改一个最大面积常量 |
| A-条件与历史 | 四种原比较完全相同，远端关系或先前动作不同导致相反结果 | 新条件超出旧81规则空间；经统一关系解释器消费；不可辨版本保留未知 |
| A-移动几何 | 宽主体窄通道、长步扫掠受阻、同色但不同可达性、动态障碍 | 分开局部相邻、单步通过、有限路线，不以颜色或终点代替完整行动判断 |

每组顺序统一为：冷启动探索、冻结后的未见实例消费、公开反例、修订后的再次消费。反例进入修订时显式退出冻结阶段；已用于修订的验证样本转入训练，修订后的冻结验收使用另外未使用过的实例。划分按完整会话和机制组合进行，不从同一轨迹的重叠窗口拆成“训练/测试”。

门/开关等状态变化必须由普通公开动作或声明的公开环境演化触发，测试侧不得中途暗改机制再要求求解器预知。远端标记做正、负及假相关对照，区分可预测关联与受干预支持的控制关系。

第一阶段签收要求：

- 所声明可辨场景达到条件发现和正确消费；不能全部 unknown 获得 PASS。
- 不可辨场景不签发确定机制；随机猜对不能计为学会。
- 原始回执中的所有已声明效果通道均有解释或明确残余；新解释可重新打开旧义务。
- 独立裁判核对下一动作实际使用的条件及输入绑定，包含错误几何绑定、漏掉反例的变异拒绝测试。
- 保留已有有限内核、单步、关系宏和程序测试；ls20 原版完整通关作为回归，失败时分析具体模型/调用链而非普通分数波动。

## 4. 第二阶段：同局持续联想、程序发现和控制复用

### 4.1 阶段终点

一个公开会话从空程序库开始，先通过交互学出可消费机制；这些机制形成连续动作语料；后台真实搜索发现程序；程序在该会话之后的不同位置/对象绑定中被调用；新反例撤回错误后缀，修订后再次调用。随后更长经验能够复用已经发布的子程序。

每层抽象都必须能指出：解决了什么重复结构、共享了哪些参数、作用域是什么、对规划或执行有什么实际作用。

### 4.2 B1：闭合同一动作的 trace 后再接长序列

位置：`LocalEffects.jl:197–206`、`SequenceCorpus.jl:143–181`。

当前多帧统一 incomplete 的保护不能直接删除。改为：

1. 为每个同次响应的相邻帧建立有序变化及角色对应。
2. 解释第一落点、终态、选择/图案/资源变化与公开状态；中间帧与终态不同必须保留。
3. 对每个通道给出绑定、完整性、残差和证据；有歧义的角色不强制连接。
4. 动作整体闭合后才允许作为一个 Step。
5. Step 之间仅在实际连续事件和共享端口可验证时组合成 Seq；RESET、断链、关卡边界及未解释帧保留明确边界。
6. 编译器可以复用程序中的已证明接口，但程序本身不能为缺失的原始观测提供伪证据。

不按固定“2、4、8步”裁切原版学习语料。使用实际连续闭合区间及接口边界；长区间和子区间通过共享有向无环图与索引惰性产生，避免为每条子序列复制全部正文和来源。同一语料范围内一次干预只计一次，跨批复用不增加独立样本量。

### 4.3 B2：把准备、搜索和签收接进在线循环

从现有函数抽出职责：

- `RelationLearning.train_prior_relations!` 拆出 `prepare_relation_learning` 与 `collect_relation_learning!`。
- `ProgramSemantics.train_program_corpus!` 拆出 `prepare_program_learning` 与 `collect_program_learning!`。
- 原有 `prepare_effect_learning!`、`collect_effect_learning!` 继续使用。
- 三种任务共用现有冻结输入、worker 监督、`read_stitch_rounds`、`publish_stitch!` 和尾批恢复流程。

建议在线循环：

```text
while current public session can act:
    k = latest confirmed event sequence

    if worker completed:
        verify frozen corpus, origins, signature, prelude, engine and policy
        verify rewritten bodies, proof and total structural cost
        transactionally publish with existing Library procedures
        record when publication became available

        recheck empirical applicability against all confirmed evidence up to k
        update affected relation/program consumers
        retain correct structural definitions even if their empirical use is refuted
        reactivate dependent unresolved interpretations

    derive bindings and candidate successors from current common semantics
    re-evaluate program applicability when dependencies changed
    choose progress or distinguishing experiment

    freeze decision:
        source events have sequence <= k
        definition publication was accepted before this decision
        record parameter bindings, guard versions and predicted queries
        record which relations/programs affected candidate generation or choice

    submit exactly one public action and confirm all returned frames
    append event once
    check predictions and program step
    withdraw invalid suffix; preserve confirmed prefix
    reinterpret affected mechanisms and extend closed sequence corpus

    if worker idle:
        choose next affected effect / relation / program task
        freeze source scope, interpretation version and prelude dependency closure
        launch existing background worker
```

意图、来源范围和解释版本用于任务召回；真正去重使用完整冻结输入摘要，包括候选/语料正文、语义签名、槽位上下文、前置库摘要、策略与引擎身份，直接复用现有 manifest 和 input_sha。同来源的两个不同查询不能相互覆盖。原始证据没变但解释版本变化时，允许重新打开义务；同一版本不重复提交完全相同任务。

对动作实验和学习作业分别维护可服务义务轮。冻结轮内每个当前可执行义务必须得到服务，或记录公开的阻塞/失效证据；新到的 effect 作业不能永久挤占 relation/program。阻塞恢复保留原等待次序，新义务进入下一轮，终局仍未服务者明确留为未完成。这是公平调度约束，不额外设置小工作量上限。

旧任务晚到时，结构证明仍需对它实际冻结的前置库验证。通过现有事务发布后，用当前证据重新检查适用域；不能把旧条件不经检查激活。若事务的当前版本检查失败，明确重新准备或重验证，不伪改摘要绕过检查。

签收时间同样参与读集约束。仅“源事件发生在过去”不够；未来才发布的定义不能回填过去的动作预测。收尾 `finalize_learning!` 完成的程序只算发布，未来动作确实使用后才能计消费。

### 4.4 B3：程序召回可重复，绑定每步重验

位置：`OnlineSession.jl:541,582,611–634`、`ProgramSemantics.jl:188–235`。

删除会话级 `tried_program` 作为程序选择的终止条件。用相关知识版本、角色绑定、当前目标/未解义务和公开条件变化触发适用性重算。

必须处理四种情形：

1. 会话开始程序库为空，后来发布程序，能立即参与后续决策。
2. 程序已存在但开始不适用，后来进入可适用状态，能被召回。
3. 一个程序完成后，可以再次调用或选择其他程序。
4. 某程序应用被反例撤回后，修订了条件或绑定，可以重新调用正确部分。

每一步沿用 `current_program_step` 和 `program_feedback!` 的角色/资源共享检查，并扩展到共同关系语义；不能只检动作编号、计数差量或定义 ID。

目前程序列表按长度、依赖深度排序（`ProgramSemantics.jl:142`）。改成依据当前适用性、任务相关性、认证成本和预期后继选择；依赖深度只统计，不作为独立奖励。长程序并不天然优于短程序。

### 4.5 B4：让新表示真正进入消费者

位置：`OnlineSession.jl:160–169,491–495`。

效果模板相同只提供归组线索，不证明条件化机制等价；条件或作用域不兼容的假设继续分别保留。

保留“同一语义机制”的身份；把它与“该机制的某一压缩表示”分开。同一机制可有直接正文和多个认证等价宏表示，分别记录来源、适用声明和成本。

合并算法：

```text
for each incoming certified representation:
    identify semantic mechanism using existing identity rules
    verify representation denotes the same declared body/interface
    merge empirical evidence without duplicating intervention identities
    retain distinct valid representations and dependency certificates

on consumption:
    bind current roles
    choose a valid representation by actual evaluation cost and applicability
    evaluate its canonical body or macro with the same interpreter
    record the representation actually read
```

不要只把旧 rule 的 references 换成新 ID；必须实际经过新表示的解释或编译产物。也不要为了“消费深度更高”选成本更差的包装。

### 4.6 B5：联想如何产生更有价值的新概念

扩展 `AssociationIndex` 的召回接口：

- 同一动作、同一完整模板继续提供精确候选。
- 增加按类型端口、作用阶段、关系形状、条件角色和效果接口的结构召回。
- 映射可以将具体颜色、坐标、对象身份参数化；映射必须有显式绑定和公开回查。
- 来源不同的片段保留独立事件、独立状态和连接条件，禁止仅因相似就粘合成实际发生过的轨迹。
- 反例优先召回：当前解释相同却结果不同的经验，能够推动新增条件；成功相似例用于发现可复用结构。

概念晋级需要逐项回答：

1. 该关系或程序在独立实例中是否重复出现，参数是否正确共享？
2. 是否覆盖已知反例，并明确未知作用域？
3. 是否通过冻结任务前置库、新定义和该任务改写语料的整数总成本核验，或已作为有用的直接条件参与控制？全局库 storage_cost 单独报告。
4. 在未见的布局/角色绑定/条件组合中能否重新绑定和消费？
5. 新反例出现后是否能定位条件或应用错误，而不是重置整套知识？

例如，若公开经验先后支持“某动作改变一个状态标记”“另一动作的通过性依赖该标记”“通过时还伴随计数量变化”，系统可以从连续事件构造共享标记、对象和计数量端口的程序。这里的“开关”“门”“补给”等人类称谓只用于报告；不作为预写宏名或生成器标签传给发现器。

更高抽象来自真实机制与程序的组合复用。目标是有效的语义压缩和规划能力，不要求定义图每轮必须加深。

### 4.7 B6：独立验收与对照实验

新增四类检查，分开签收：

**表示等价检查。** 固定同一机制、同一输入、同一绑定，直接正文和压缩宏必须返回相同关系、预测、实际公共证据依赖和未知范围；宏额外的定义/展开证书不要求与直接正文的证明结构字节一致。比较表示大小、重复计算和求值开销；语义等价时不要求动作不同。

**学习内容的控制作用检查。** 在同一公开状态下，使用已经辨明的新条件与把该条件撤销为未知两种知识状态，重算候选边及动作。必须展示新条件在哪里改变可用路线、排除错误尝试或确定下一实验。这个检查证明学习内容参与控制。

**程序复用检查。** 固定基础机制知识，比较开启/关闭程序复用的规划展开、接口检查、重复求值和实际执行。正确程序可能产生相同动作序列；其价值可以是复用和减少重复规划，不能伪造“必须换动作”的验收。

**在线任务效果检查。** 用新的、经公开接口启动的相同任务族会话比较完整过程；保存所有动作及新证据。离线重算不能冒充反事实分支已经真实通关，改变策略后没有观察到的后续回执不能借用原轨迹。

必要回归案例：

| 用例 | 必须通过的行为 |
|---|---|
| 本局冷启动→发现→消费 | 初始空程序库，本局发布的程序在之后动作实际使用；没有未来引用 |
| 后到绑定激活 | 最初不适用的程序，当前对象/条件成立后被选择 |
| 重复调用 | 一个程序完成后，在新位置或新对象再次重绑定执行 |
| 多帧连续程序 | 同次动作多个帧只算一个 Step；中间条件变化影响后续步骤 |
| 反例局部修订 | 第 j 步失败后撤回未执行后缀；旧正确前缀与结构定义保留，修订后恢复 |
| 新条件推动新抽象 | 超出原81语法的关系进入程序，并在未见条件组合中复用 |
| 表示更新 | 更低成本的认证表示能被真实消费，旧消费者不会永远停在首次引用 |
| 作业闭合与语义未闭合 | pending jobs 为空、仍有解释义务时，报告明确未完成；新解释能再次激活 |
| 持续服务 | 持续产生 effect 作业时，已有 relation/program 和可执行的未试动作义务仍能按轮得到服务 |
| 独立审计变异 | 错图案位置、漏反例、未来定义、错误共享角色和伪宏消费均被拒绝 |

阶段二的真实原版验收必须包含可定位的控制过程证据；不要只列游戏输赢涨跌。极端失败与机制反例单独分析，普通游戏结果波动通过完整轨迹和重复实验口径解释。

## 5. 动作—对象最小因果单元如何检查闭合

最小单元不是“一个动作编号”，而是：一个公开干预、当时可辨的作用对象及绑定、条件、效果、时序与资源依赖，以及已知适用范围。

对每个单元分别维护：

- 是否采样：有无确认的动作和完整回执。
- 是否解释：对象绑定、效果及中间帧是否唯一，残差是什么。
- 是否可预测：在什么条件下预测哪些查询，是否有支持/反驳/未知。
- 是否鉴别：当前仍有哪些机制解释都能拟合，什么公开实验可区分。
- 是否消费：条件或程序是否实际参与后续决策。
- 是否可修订：反例能否使错误依赖失效，并在新解释后恢复。

这些维度不能压成一个“很高置信度”的布尔值。重复 700 次同种移动不等于对 700 种条件完成覆盖。

按声明的有限场景范围检查所有合法动作和可辨对象绑定；不能把不可到达、未测试点击坐标、隐藏不可辨状态删除后宣称全覆盖。报告可明确区分已闭合、仍歧义、不可到达、资源中断、尚未解释等状态。

未来引入概率模型时，置信度需要独立校准和跨实例验证。当前候选一致或单条预测 supported 不直接换算成 99% 等概率。

## 6. 高级表示与性能的接入顺序

Tree Decision Diagram（树决策图，TDD）只在变量、有限域和关系语义已经明确后作为可替换的求值表示来评估。比较应固定同一语料、同一语义、同一条件判定，测构建时间、峰值内存、查询/更新成本和共享收益；不把更换后端当成新概念发现。

Probabilistic Circuit（概率电路，PC）在确有概率建模需求、数据和校准流程后再评估。当前优先解决观测/变量遗漏和不能修订的模型族；不能用概率权重遮盖已知的解释缺口。

本轮无需阻塞于 TDD/PC 集成。Python、Julia、Rust 的实际接线先形成完整学习控制闭环，后端优化使用共同语义基准验收。

性能报告分开记录：

1. 环境启动和公开请求。
2. Julia 角色、关系、条件和规划求值。
3. Rust 搜索及输入/输出规模。
4. 类型、证明、语料成本与发布核验。
5. 结束尾批、回执回放、独立裁判和产物索引。

后台任务与前台推理的重叠单独表示，不直接相加。每个长任务保存可恢复的当前产物和未完成原因。先用原有复杂序列复现热点，再决定索引、共享或引擎改动，不根据一次整体耗时猜测瓶颈。
