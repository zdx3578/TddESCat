## 一、这次应优先解决什么

系统能从公开动作学出局部作用，已能把一部分作用绑定到新角色、组织成程序并改变真实动作。我判断下一轮应优先把**一个可重复的作用，提升为另一个任务确实需要的条件**。当前出现两个相反的实例。一款游戏里同类探测 848 次都预测对了局部作用，一款里 244 次只对了 12 次。前者要查重复该技能还能建立什么有用条件，后者要查在哪个角色、环境条件或动作前史下预测会反转。两者都能用同一套关系与实验接口处理。

M1 应先让绑定、反例和用途共用一份有作用域的事实，并让修订及时抵达仲裁。M2 应从经对照的任务依赖提炼抽象状态、分支和可迁移的程序。沿用同色四连通观测、现有作用学习器、E-Stitch、单一动作派发和公开回放。所有训练输入来自当时可读的公开前缀，游戏编号只用于分组评估。

## 四、抽象认知具体怎么提升

1. **从像素实例提升到有条件的角色作用。** 对一次干预保存动作、选择角色、受影响角色、前后关系、保持项、未知项、历史和结果。让两次具体实例通过带类型的变量对应进行对齐。保留步间角色同一性和相对方向，允许同外观有相反作用、不同外观承担相同角色。逐一尝试删除颜色、位置、某个支持成员或历史条件，检索全部适用正反见证。遇反例保留区别。存在可执行区分实验就进入原任务议程。只在可判定有限域内声明等价。新概念必须可回到原帧指出它绑定了谁。
2. **用未来动作的响应检验状态抽象。** 同一具体屏幕可有不同隐状态，不同屏幕也可能对同一任务等价。以候选角色关系、已知合法动作和相关历史做共享索引，保留原始场景身份。比较同一绑定下的预测响应、危险结果及下一动作能否执行。只对有观察的部分进行有限域共享，缺边仍为未知。若两个候选在一个合法动作上预测不同，安排该实验。角色、动作相同而响应分叉时按远端关系或前史拆分，并重新编码历史，检查受影响的任务是否重开。
3. **从可重复技能提升到前提。** 把具体作用写入一份有来源的关系事实。后面的任务明确登记它读了哪些事实、谁最后建立它、何时它被破坏。沿同一尝试回溯可以越过与这些事实无关的步骤。若中间转移可能改写该事实，保留未知并申请复验。对照包括省略准备、反转可交换步骤、改变远端条件、复用相同角色更换动作。首次晋级前可用“打开一个新合法动作”“区分两种响应”“建立一个能到达新状态的前提”组织实验。一次晋级即登记公开事实，准备依赖单独保留为待验证假设。
4. **让程序服务一个当前缺失的关系。** 由上述依赖图生成顺序、条件分支和重复候选。先按所需效果召回程序，再向前回归角色和 guard。对于仍有失败后继的绑定，执行区分实验或选择明确标记的可能计划。保证计划要求考虑声明域内的全部后继且非空。重复可用阶段转换、已完成的角色集合或有界资源验证进展，也允许增加对象和恢复候选。E-Stitch 在真实候选中搜索共享正文，Julia 独立回代轨迹，执行器按已确认回执推进。记录哪个准备关系建立了、哪个后续任务实际消费了它。
5. **按下一步能学到什么选择动作。** 候选携带目标缺口或待区分的两个假设、二者预测、所需角色、当前风险与回执判据。优先使用已知前提能推动目标的动作。对未知前提比较哪些实验能区分会导致不同后续选择的解释。给长期可达旧义务留实验机会。只有经过持出验证且仍适用的概率模型参与排序。相同技能反复成功后，只有出现新绑定、新用途或能区分的风险条件，才有新的实验理由。相同局部结果兼有 GAME_OVER 时，同时更新作用合同和失败条件，重开后复验修订实际改变的动作。

例：一条公开轨迹里，点击 A 改变远端 B，随后一个无坐标动作才使 C 移动，中间还夹有显示动画。先记录 B 的具体变化，提出“C 的移动依赖 B”及“依赖刚才的动作历史”两个解释。在可比较的公开状态下改变 B 或前史，预先登记 C 的预测位移并独立回读结果。若两个解释在可达状态始终一起变化，保留二者。只有能够区分它们且新绑定仍能预测时，才扩大条件适用域。若游标确实调用了建立 B 的技能，并且它让下一步可执行，才计一次控制用途。此例用于设计通用测试。

## 五、施工顺序和放行依据

| 阶段及依赖 | 在何处施工 | 可独立核验的交付与失败判据 |
|---|---|---|
| M1.1 / M1.3，先做 | 扩展 `RelationTasks`、`OnlineSession` 和 `tests/bench/public_coverage.py` 的既有生产者、任务与核验字段 | 从 13 个晋级回执及配对未晋级前缀离线定位“没有候选生产者 / 已找到但条件未知 / 缺乏对照 / 没有被下游读取”各发生在哪一步。记录事前假设、用途、具体后果、全局仲裁和后继回执。旧版本缺少的字段登记为不可判，不倒填 |
| M1.2 / M1.3，与上一项并行后汇合 | `Grounding`、`JointMechanisms`、`AssociationIndex`、`RelationQueries`、`GuardRepair`、`RelationAgenda` | 以相对角色的具体作用和潜在反例召回候选。生产预测、条件修订、仲裁读取同一版本。验同外观相反位移、异外观同机制、多区域共同作用、无关闪动。持出布局上的预言、证据和撤回与独立枚举相符。附真实查询尺寸及后端选择。小关系直接执行 |

| M2.1，复用 M1 的角色作用 | `PublicFrontier`、`CircuitLearning`、`ProjectionRevision`、现有 Python worker | 比较整帧上下文与可重绑的角色/历史变量。在训练截止后以不同实例检验具体效果、下一动作可用性与风险。报告基线损失、校准、缺失、重编码开销及入选动作。若只增加候选工件、没有新的已验证预测或实验用途，该改动继续实验 |
| M2.2 / M2.3，依赖可读取的中间事实 | `RelationPolicies`、`PolicySemantics`、`GoalRegression`、现有程序生产者索引、cvc5、E-Stitch | 构造有多余中间动作、两个有不同前提的实现、重复中增加对象、局部正确却失败的公开协议场景。裁判留出不同结构和布局，核验遗漏/换序的反例、分支两侧、循环进展及退出、作用前像、反例撤回、下一次重绑定和真正的派发变化。语料里出现单一骨架或仅多定义，继续定位候选生成责任 |

**最先提交的功能点**是把“作用已支持 → 哪个后继任务实际读它 → 该任务是否在回执中成立”贯通原账本，并将同一依赖用于安排一次省略准备的可区分实验。它可以在首关中验收，输入与输出也直接供后续抽象使用。若先发现 13 条晋级见证在某一步全缺可比状态，就让控制器产生获取该对照的实验。若事实已建立而后继选择全未消费，再修生产者召回或任务仲裁。两种情形对应不同的代码改动。

## 六、如何验收收益

- **表示与语义 H1。** 查看新绑定上作出具体预测的覆盖率、已预测子集准确度、未知及反例数，按动作家族和样本来源分层。核验来源回代、未知传播、反例后旧绑定失效及历史重编码一致。无实际可达对照时保留不可辨识。
- **计算收益 H2。** 同一公开前缀、同一查询、同一证据和输出对齐后，按既有 B00/B10/B01/B11 比较索引和压缩，区分冷启动、复用、维护/失效、跨语言往返及峰值内存。固定时间报告完成工作量，固定工作量报告耗时。局部降低分配的结果只覆盖该处理阶段。
- **认知与控制 H3。** 固定前缀上作盲测，按实例或尝试切分训练与验证，禁止同一干预的多帧分到两边。用相同起点配对比较已有控制、加入条件作用、再加入任务回归、再加入程序抽象，单独记录内部候选差异、最终派发差异、首次出现差异后的真实后果。逐款报告首关与第二关、跨实例复用、危险反例后行动变化、完整 WIN。另报重复尝试间分布。阳性和阴性场景均要保留。重复发现同一作用、减少残差或增加库规模，各自单列。
- **覆盖与发布。** 按定义域、已执行绑定、可预测效果、有反馈的控制消费四层保留分母。P01–P46、I01–I16 用规格版本、提交、冻结输入、实际消费者、独立裁判结论作索引。把已通过的局部场景、未测门和研究项分别保留。当前只能签署此轮复核，M1/M2 的全门禁及 Public25 全通仍待同版验收。


## 七、证据复核入口

两份小型 JSON 保留选择口径、版本和事件定位。实验快照的 `same_revision_one_witness_per_game_level` 含 13 条晋级见证，可用 `run/game/public/events/<event>.json` 找到 `before_ref`、`command_ref` 和 `response_blob`。读取前后两个 `blobs/<response_blob>`，分别校验 SHA-256、比较 `levels_completed`，再按同一 command 对齐 decisions、predictions 和 checks。统计模型明细在 `per_game.*.confirmed_examples` 保存 22 个事件和模型快照。对照相应的 `learning/circuits` 或 `learning/histories` 即可复核发布时适用性。留存的是审查时的文件集合和摘要，继续运行会产生新文件。
