## 1. 交付目标与两个里程碑

### 里程碑A：联想产生的新关系改变真实单步控制

必须完成以下链条：

公开事件完整登记 → 跨批召回 → 共享角色精确对齐 → 自动构造关系 → 验证与发布 → 当前条件求值 → 真实动作 → 反馈与修订。

验收必须同时包含两类新关系：

1. 稀有但能区分成败的关系，即使没有正压缩收益，也能经构造证明和公开样本验证进入消费者。
2. 多次出现、参数不同的共享关系，真实E-Stitch搜索产生新宏，Julia核验后在未参与发现的公开场景中读取。

这一步不能只交付索引、日志或一个没有消费者的库。连续动作生产端在A内完成并验证，B不再重新采集才能起步。

### 里程碑B：从连续实际动作发现程序，并持续形成更高层概念

必须完成以下链条：

连续公开动作 → 带共享对象、中间条件与资源的有序语料 → 真实E-Stitch发现程序 → 新场景召回与绑定 → 原控制器逐步执行 → 新定义回流历史 → 下一批更高层定义 → 反例局部撤回后重新消费。

两个里程碑分别提交完整验收报告。A和B内部的步骤是实现依赖顺序，不是再拆成若干只交文件的“里程碑”。

### 3.2 每项新增信息的意义

先说明信息用途，再落schema。至少必须包含以下内容：

| 信息 | 它具体回答的问题 | 检查规则 |
| --- | --- | --- |
| operator descriptor | 同名/同arity操作究竟有哪些列、哪些列共享、输出次序是什么 | 列名及类型、共享映射、distinct约束、作用域规则、前后相位、结果类型参与确定性编码 |
| semantic digest | 该定义用到的原语含义是否变化 | 只对实际使用的原语及依赖闭包摘要；新加无关原语不使所有ID变化 |
| program context | 这一条训练表达属于哪次公共轨迹、哪种解释、哪些帧 | 绝对事件/帧绑定留在来源上下文；定义正文仅保留相对角色、时间和接口关系 |
| constructed origin | 一个新Join/Project/Seq表达是怎样从已有事实构造出来的 | 保存构造操作、父引用、列/角色映射和求值域，叶子必须落到已确认公共证据 |
| activation evidence | 为什么这个表达目前可以影响哪个动作或查询 | 保存适用域、支持/反例/未决、知识截止、消费者及版本；不与结构展开证明混成一项 |
| job intent | 本次搜索解决哪个具体未完成问题 | 绑定义务ID、消费者、输入摘要、前置库闭包和有效策略，不允许无目标的自触发任务无限重开 |

稳定定义ID包含：规范参数类型、结果类型、正文、相关operator descriptor与semantic digest。结构相似索引另存，不能用相似hash充当身份。

在进入Rust之前，将规范descriptor确定性编码为专属operator符号，例如op_DIGEST；Call.operator必须引用这个符号。Registry端口使用具体列模式的单态rel_SCHEMA_DIGEST和具体输入/输出接口的prog_INTERFACE_DIGEST，不能全部擦成一个无差别的Relation/Program。这里的大写后缀是摘要占位说明，生成文件必须替换为实际合法标识符；descriptor存v3签名注册表，不能塞进只接受现有标量值的Const。两端重算并核对符号与descriptor：相同arity但不同共享映射、Project列序或Seq资源接线，不得成为同一个e-graph节点或被Expand/Reuse混配。绝对场景ID留在上下文，不能进入通用类型而阻断跨场景复用；每个匹配见证仍独立核对实际作用域和解释分支。

构造来源使用Directed Acyclic Graph（有向无环图，DAG）共享父节点。Join的来源是两个父见证同时成立；Project的一行可能来自多个合法见证，保留“或”关系，不将不同中间角色拼成同一见证。新概念不是新的独立物理干预。

### 3.3 两类证书共用一个解释与激活入口

- constructed-query：由类型正确的关系构造获得；验证构造DAG、作用域、相位、有限域求值及公开样本的区分能力。
- EStitch-learned-macro：除上述语义约束，还必须有真实worker身份、正结构费用收益、完整展开及精确来源证明。

二者都用ConceptTerm、相同语义ID规则、关系解释器和activate入口。前者不需要伪造压缩收益，后者不能绕过Rust搜索。统计时分别记“构造关系”和“搜索发现宏”。

04号§11的“有区分作用就提出条件/查询”和“多处结构使用再送E-Stitch”保留；修正任何把所有可用关系都误要求为publish_stitch!产物的调用关系。

在Library中抽取统一publish_verified_concepts!与activate_concept!入口，证书类型显式为constructed-query或EStitch-learned-macro。前者调用构造DAG/语义核验，后者由现有publish_stitch!适配真实worker证书进入同一提交器；不得让构造关系伪造job receipt。两者复用一个全局库、串行结构提交、原子激活和崩溃恢复合同。

## 4. 里程碑A的具体实施顺序

### A1. 补齐事件学习水位、实验服务和参数真实生效

#### A1.1 已确认事件立即形成持久义务

修改OnlineSession.run_online!。当前549—553的满批触发改成“事件先登记，批次只负责分组”。

对每条已确认事件分别记录：原始证据已保存、解释是否完成、是否生成合格表达、进入哪个job、最后核验结果、是否还待新语义重解释。事件没有合格表达时必须说明是静止但未解释、身份歧义、缺少历史、部分可见、没有支持的效果，不能统一当作已学会。

建议入口：

    register_evidence_obligation!(session, event_ref, semantic_version)
    prepare_learning_job!(session, obligation_ids)
    poll_learning_jobs!(session)
    finalize_learning!(session; frozen)

这里session是现有运行状态加持久义务索引；event_ref指已保存公共事件；semantic_version决定这次解释用哪版原语；obligation_ids只是已有义务的集合；frozen说明本次是否为禁止更新的评估。

    on_confirmed_feedback(event):
        persist full public event and all frames through existing Recorder
        create obligation id from run/episode + event_id + interpretation version
        use content hash to verify integrity, not to merge distinct interventions
        idempotently persist obligation before advancing learning watermark
        explain event; retain residual and alternative interpretations
        schedule eligible expressions and unresolved obligations
        poll completed jobs and revalidate activation

    on_training_end():
        freeze this end-of-run evidence frontier
        submit any remaining eligible tail events
        finish verification/activation for the finite frozen obligations
        persist unresolved meanings and interrupted jobs explicitly
        emit final summary with every confirmed event's disposition
        do not send another public action

    on_frozen_evaluation_end():
        store feedback in evaluation quarantine
        assert model/activation/library digest unchanged
        do not train on evaluation tail

恢复时从现有事件及义务账本重建未处理集合，不能靠内存pairs长度推算。已完成job重复读取幂等；公共请求不重发。所有正常出口和WIN/GAME_OVER都调用同一finalize路径。无法完成的任务保留为未完成，不写成压缩固定点或阶段PASS。

#### A1.2 让未覆盖动作获得实际实验机会

改ranked_public_actions的固定优先级逻辑。保留当前可用动作、角色绑定和反馈检查；将“为目标执行的动作”和“为区分模型的公开实验”作为同一调度器中的不同义务。

每项实验义务必须说明：哪个当前可用动作、哪个候选角色/坐标域、哪个公开前置上下文、要区分哪些效果或模型。相同义务由规范键合并，重复看同一画面不会反复插入同一任务。

训练模式按服务轮次调度：一次轮次冻结当时可执行义务的有序集合并持久保存游标。本轮每项仍合法可执行的义务必须实际服务一次，或记录有证据的失效/阻塞原因，才可完成该轮；“最多一次”不能代替服务保证。逐项执行前重验当前条件，暂不可执行项转入阻塞或可达子义务，不能卡住其他项；恢复可执行时保留等待年龄，失去执行机会只记未服务，不能计入覆盖。新义务排入后续轮，不挤掉旧义务。模型反驳的撤销立即执行，后续修复计算与其他发现义务仍公平推进。目标模式执行已经验证的目标策略；用于覆盖验收的训练不能永久停在目标动作队列。

保证只针对仍可达且当前可合法执行的义务；条件暂不可达的义务保留原因和使其可达的子目标，不能靠违规动作完成。ACTION6全部坐标在公开有限域中可以枚举；物体代表点只能作为先验排序，不能无证明合并未试坐标。

### A2. 实现统一关系解释器与明确的视图

新增RelationQueries.jl、ConceptIdentity.jl；扩展ConceptTerms、RelationSemantics、CategoryBackend。

首先实现04号定义的Atom、Rename、Join、SelectEqual、Project。Union及带完整域证明的否定按其合同实现，不能把未观察到当假。

每个关系结果必须同时提供：

- 哪些有类型列组成一行。
- 每行在哪个场景/解释/时间作用域成立。
- 行的来源见证。
- 答案枚举是否完成。
- 所声明的实体域是否完整。
- 是否仍有互不相容的解释。

前两项防止同名角色误连；来源用于撤回和独立证据计数；后三项决定缺少一行时可否判断false。在同一已固定且证据支持的解释分支内，一个合法见证可支持该分支的true；存在多个可接受解释时，只有所有分支一致true才可作为确定guard。解释域和枚举完整且各分支均false才为false；有分歧、缺失或未完成则unknown。不能任选一个分支的见证就执行。

Join实现用全部共享键建哈希索引，键包含共享列值、兼容作用域、解释分支和所需身份约束。选较小侧建表只改变执行顺序，输出列顺序不能变化。小型测试以朴素双循环作独立裁判，比对行集合和来源公式。

把当前model_binding中颜色失败后自动退到几何的逻辑替换为显式视图：

- color-support：颜色与形状共同参与匹配。
- geometry-support：忽略颜色的几何关系，具有独立语义版本。
- connected-4与connected-8：四邻域和八邻域分量，分别构造。
- frame-local与history-linked：当前帧出现和有历史见证的跨帧对应，不能混为一个对象ID。

视图不是多次干预。一个事件可产生多个视图，但它们共享原始event_ref。移除大于192像素就永久丢弃的逻辑；保存全部有限像素和分量，面积只影响遍历先后。裁剪后重新分量化与全图分量的裁剪片段是两种不同操作，不能自动视为同一个自然变换。

同时改Config、GuardRepair、OnlineSession.fit_joint_condition和JointMechanisms.joint_model：新关系入口不得再被max_guard_atoms、max_guard_candidates或max_parameter_term_nodes=7提前截断。按明确的候选语言、证据和持久前沿完成求值/构造；已验证参数项按完整类型与语义解释，不因正文稍长就静默return nothing。会话配置及tests中的配置生成器同步迁移，删除失效字段，不回填大整数或保留被忽略的旧参数。

### A3. 关系构造与联想召回共同产生候选

新增ConceptConstruction.jl、AssociationIndex.jl。本步必须有具体预测问题作为输入，例如“同一个公开动作，为何在这些场景产生位移，在另一些场景没有该位移却有计数变化”。

关系构造按类型和共享接口展开：

    solve_relation_obligation(obligation, public_examples):
        obtain primitive relations from allowed pre-action views/history
        recall earlier objects, relations, mechanisms and program fragments
        exact-align types, roles, phases and scopes
        enumerate connected Join / SelectEqual / Project constructions fairly
        evaluate each construction on support and counterexample cases
        retain distinguishing queries with complete derivation records
        submit repeated structures with different bindings to real E-Stitch
        verify returned macros independently
        propose activation only for the declared consumer and evidence scope

“公平枚举”指候选按结构费用分层、同层确定顺序处理并保存前沿，不设置top-K永久丢弃。任意无限表达语言不能声称已经穷尽；验收针对明确的有限原语/事实域和冻结义务，区分“该义务已获得足够可辨证据”与“所有可能概念都搜索完”。

第一项必需关系实验：

- 提供基本的局部邻接、颜色、已观察作用关系等原语，不提供最终关系公式。
- 正例里，角色a与中间角色k有第一种关系，同一个k与b有第二种关系。
- 负例里分别存在k1和k2满足两段，但没有共同k。
- 构造器必须保留同一k的Join约束，再将k投影掉；不能先分别存在化后做布尔与。
- 所得关系进入实际动作条件，在新布局执行正确动作；反例不能被错误合并。

所有关于“过去作用”的原语只能读取本次决策之前已经确认的历史。当前动作后的帧可以用于训练标签和事后核验，不能成为当前动作前条件的输入。

召回分两层：

1. 倒排索引和Weisfeiler–Lehman（WL）结构特征提出候选。节点保留类型、端口次序、前后相位；视图相似只用于排序。

### A4. 拆开同步学习与激活，保持一个真实worker入口

现有online_learn!兼任构造、等待、签收、发布和机制激活。按05号将其拆为准备、提交、收取、核验、发布和激活步骤；Python只负责启动和监督Rust，不决定概念语义。

- job：某次固定输入、前置库和版本下的一次计算。
- attempt：这个job的实际进程执行；失败不能抹去义务。

具体调度：

    service_agenda():
        first invalidate applications contradicted by new public feedback
        poll existing worker and read complete checkpoints
        verify types, sources, costs and semantic identities
        also consume locally verified constructed-query candidates through the same publication entry

## 5. 连续动作语料必须怎样构造

### 5.1 来源与边界

SequenceCorpus读取现有confirmed公共事件和完整响应。按同一episode/guid中的before_ref链连接，不能根据时间戳排序后猜相邻。

- RESET建立新段；未知/未确认请求形成断点，不能跳过后连成一条程序。
- 关卡改变、公开动作域变化和终止状态都作为显式边界事实；跨边界组合必须有已验证接口，不能沿用旧对象绑定。
- 一个响应有多帧时，这些帧属于同一次干预。保留顺序及每帧来源，不拆成多次“独立行动”。
- 首末帧相同仍可能有中间信号、资源、选择或公开状态变化，不自动编码为no-op。
- 不足学习批次不切断轨迹；后批可以引用前批已确认末状态。

### 5.2 Step与Seq的含义

使用现有第一阶Call表达，不发明带内部变量捕获的新语言。需要两个语义构造器：

| 构造 | 含义 | 每个部分的解释 |
| --- | --- | --- |
| Step(action, pre, effect, post) | 一个公开动作及它的条件和效果合同 | action是公开动作及参数；pre是在执行前能求值的关系；effect是有类型效果/状态转移表达；post是执行后核对的查询 |
| Seq(left, right) | 先执行left，再在其中间状态上执行right | left/right都返回Program；descriptor明确哪些输出角色连接到下一段输入角色、哪些状态/资源共享 |

每个Step/Seq的operator descriptor还包含角色端口、前后相位和共享映射。它们不是可以省略的注释：同样两个子程序，如果连接不同对象或不同资源，就是不同程序。

角色端口表示当前公开支持中的某个出现及其对应假设。位置只是属性，不是跨帧对象身份。中间帧的RoleAfter不能因为编号碰巧等于下一帧RoleBefore就粘合；必须是同一frame、同一解释分支下的同一个role/support occurrence，或有显式有效Correspondence见证。仅共享event/frame来源不足以推出两个角色相同。

时间跨度用相对端口表达：某段的输入、中间、输出。绝对event/frame ID保存在program context及来源DAG中，不能写死进可复用定义。一个持久角色与它在各帧的出现要分开；同一角色跨两帧的链接带证据，不能用同色/同形直接断言身份。

Program是“当前绑定下可以尝试验证的有序关系”，不是天然正确的环境机制。宏的展开正确与宏在新世界中的适用性分开核验。搜索中的Step/Seq是构造程序值的纯语法操作，不在e-graph求值时执行环境副作用；实际动作只由既有控制器和Recorder执行。

### 5.3 编译算法

    compile_confirmed_segments(event_chain):
        split only at public discontinuities or unresolved request gaps
        for each contiguous segment:
            preserve full response traces and public state changes
            construct one-step effects and primitive relation views
            build candidate correspondence interfaces between adjacent steps
            keep incompatible interpretations as separate branches
            create typed Step terms with pre/post read phases
            create ordered Seq terms using verified shared interfaces
            normalize role names once for the whole segment
            emit expressions, contexts, provenance and unresolved obligations

    verify_sequence(term, context):
        typecheck every call and interface
        require each adjacent response/next-input source to agree
        verify role equalities and distinctions under one interpretation
        require pre-action reads <= that step's knowledge cutoff
        replay observed post-queries against saved public frames
        return accepted expression or explicit unresolved reason

整段只做一次一致的角色重命名。若逐步分别规范化，两个不同对象可能都变成“角色0”，会产生错误共享。跨颜色视图、相机平移和遮挡的对应都必须保留具体证书；没有证书则保留歧义，不能靠概率最大的一项冒充确定绑定。

Step的post和观察到的effect是训练/核验信息。在线执行只绑定已知输入，用模型给出预测输出，等真实响应到达才确认输出端口；禁止把训练里的后态Slot当作当前已知状态。知识截止逐Step检查：第二步允许读第一步已确认的输出，不能把整个Program统一标成第一步的before，也不能在第一步预填后续帧。

### 5.4 输入规模、重叠与结构费用

一个含n个确认动作的完整段有n(n+1)/2个连续区间。用共享节点和区间索引保存候选，按长度/结构费用公平推进，不设置最大序列长度。不要将所有区间展开成互相复制的字符串。

必须避免重叠窗口虚增证据和压缩收益：

1. 保留整条轨迹为证据基准；所有窗口都能回到具体事件区间。
2. 一个用于计费的学习job中，同一实际Step不得因为多个重叠窗口被重复收费。使用确定的非重叠区间覆盖，并为未进入本覆盖的窗口保留后续义务。
3. 不同长度/起点的覆盖可形成后续job；报告每个job的语料范围和局部费用，不能把它们的事件数相加当独立样本。
4. 新定义在整条原始轨迹和独立留出轨迹上重放，消费次数按实际事件去重。
5. 同一学习输入的有效费用在Julia独立核算；全局库与当前job闭包费用分开。不同窗口覆盖的局部收益不能累计成全局净收益；新增宏须对固定原始轨迹的规范表示再核算一次增量净费用。

规范构造平衡的Seq树以避免长序列的左链造成纯语法深度膨胀，严格保留动作次序和共享接口。这只是等价编码，不能交换动作。若需要改变括号形状，必须提供顺序和接口组合一致的构造证明；当前Rust只证明定义fold/unfold，不能直接新增无证的动作交换或领域重写。

暂时无正压缩收益的序列仍可作为已验证程序表达被索引和鉴别；不得预置一个宏名让它冒充搜索发现。程序宏的验收必须由真实worker输出。

## 6. 里程碑B的具体实施顺序

### B1. 同一E-Stitch学习程序与跨层依赖

在A生成的程序语料上，复用prepare/freeze/worker/verify/publish链。按返回类型登记Relation或Program，不再让所有新定义都通过JointMechanisms的四类effect解码。

后续批次可用已发布定义改写原先程序，再参与下一轮搜索。依赖由真实稳定ID建立；原语深度为0，定义深度为1加其依赖最大深度。拒绝环、缺失依赖、错误语义版本和类型不一致。

    on_definition_activated(definition):
        find historical expressions and unresolved obligations affected by its interface
        instantiate/align against those public records
        rebuild relation/program candidates with certified dependencies
        deduplicate by obligation + evidence + semantic + relevant dependency versions
        enqueue new jobs only when input meaning or evidence actually changes

无需把整个全局库重新塞进每个job。父定义失效时区分两件事：结构定义仍可作为正确的表达式展开保留；依赖被反驳应用的经验适用性和计划后缀应失效。删除或损坏结构定义则所有引用必须拒绝加载。

### B2. 程序解释器接入原控制器

新增ProgramSemantics.jl，解释经验证的Step/Seq和库调用。它不发送HTTP。它输出当前程序游标、下一原子动作、所需关系条件、预期查询、读集和后续待核对端口，由现有OnlineSession、Plan、Recorder处理。

每个部分的用途：

- 程序游标：当前完成到哪一步；与实际confirmed事件绑定，恢复时不能跳步。
- 下一原子动作：仍是官方公开动作及坐标。
- 条件：执行前必须重新求值的公开关系。
- 预期查询：响应后要核对哪些位移、计数、选择、信号或动作域。
- 读集：哪些证据和定义使这一步成立，供反例局部撤回。
- 后续端口：只在回执验证后，才向下一步传递的角色和状态。

    advance_program(cursor, current_public_observation):
        verify semantic/library/application versions
        bind input roles in current explicit view
        evaluate current Step.pre before issuing action
        if a required precondition is false:
            return inapplicable_to_replanner without submitting an action
        if binding or any required precondition is unknown:
            return unproved_application without submitting an action
            # any later selected experiment uses its separate experiment obligation
        require known binding, every required precondition true,
                and action available in current public action domain
        produce prediction and command through existing Recorder
        wait for the complete confirmed response
        evaluate all declared post/effect queries over the full trace
        if any required query refuted:
            invalidate this application and dependent suffix immediately
            preserve unrelated definitions and observed effects
            enqueue counterexample repair
        elif any required post/effect query, binding or domain is unknown:
            preserve confirmed facts; do not advance the proved suffix
        elif every required post/effect query is true and the interface is verified:
            bind verified intermediate outputs
            continue with the next Step via the same planner

资源消耗、位移、选择和信号是独立效果通道。撤销位置不代表撤销资源；后续条件必须从真实回执求值。滚动后不能重放旧点击坐标。中间步骤失败不能把整个历史标为“从未发生”。

### B3. 让现有有限规划充分消费长程序

当前Plan.solve_policy的固定depth和max_work，以及ProjectedPlanning的depth/work/states截断，会阻挡长程序消费。复用PlanningModel、SuccessorScope、PolicyNode和observable_successors，改为已声明有限模型上的可达信念图与目标吸引子固定点。

Belief State（信念状态）表示当前公开观察仍可能对应的状态集合，不是一个任意置信度数字。从初始非空集合按公共可用动作及完整观察分支按需展开可达图，交替更新吸引子；未知后继单独记录。初始belief已进入吸引子即可返回正证书，无须先展开所有历史；否定结论才要求有关前沿穷尽。

    W = all reached nonempty beliefs whose states all satisfy the goal
    rank[B] = 0 for B in W

    repeat until W stops changing:
        for each reached belief B outside W:
            for each currently legal common action a:
                successors = observable_successors(B, a)
                if scope is proven, complete, nonempty
                   and every observation branch is already in W:
                    add B to W
                    store action a and its dependency versions
                    rank[B] = 1 + max(rank[child] for child in branches)
                    break

    if initial belief in W:
        build existing PolicyNode tree/graph with decreasing ranks
    else if the declared reachable model and all relevant edges are complete:
        report no strong policy in this model
    else:
        report incomplete model with concrete missing relations/edges

这是保证所有已建模分支有限步达到目标的强策略；未进入吸引子不代表任意随机/公平循环策略都不存在。只对声明有限模型作结论，不宣称已枚举整个未知游戏。

ProjectedPlanning改用精确状态键、去重和持久未处理前沿。只有已验证转移可加入已知边；未知、无法投影、未完整枚举或未核验的解释、未建模动作域都保留为缺口。完整的有限替代解释应进入belief及观察分支，不是一律拒绝规划。消除人为96状态或短深度截断，不把它们换成另一个固定小数。

历史状态只可按已经证明对当前查询与机制充分的摘要折叠。没有充分性证明时不得任意丢掉旧动作。程序宏作为有证明的复合边或搜索种子；选择后仍逐Step执行核验，不建立第二个planner。

### B4. 持续概念提升与反例修订

重用04—06的构造、召回、部分序和依赖失效。增加以下触发：

- 新Step/Seq实例能与旧程序共享条件或中间角色。
- 某个关系定义使旧残差可表达。
- 同一动作在相似局部画面中出现不同效果。
- 同一程序在新布局成功或失败。
- 中间帧、历史或动作目录变化区分了原有模型。
- 已发布程序被多处调用，形成更高层可共享结构。

局部修订顺序：

1. 先撤销被反驳的具体应用和依赖后缀。
2. 区分身份绑定错误、前置条件缺失、效果通道遗漏、语义版本过期。
3. 召回该读集相关的正例、反例和未决，不盲目清空全库。
4. 生成能区分这些情况的关系或实验义务。
5. 通过公开反馈获得必要证据。
6. 重新核验、激活并在下一次真实动作消费。

库结构正确不等于经验应用正确；一次反例也不必证明所有相似宏都错误。每次修订报告具体被撤回的消费者、保留的定义和随后改变的公开动作。

- 将现有三批依赖夹具扩为4、8批，验证真实搜索、稳定ID、父依赖损坏拒绝和消费记录。
- 继续保留19参数真实搜索与1000参数codec。参数数、AST正文深度、依赖深度、动作长度分别记录。
- 48/96及4/8是有限测试材料大小与观察点，不是生产停止条件；禁止给程序增加对应上限。

**公开复杂语义扩展：**

- 用实际干预形成可复用单步关系、跨动作程序、复用程序的更高层程序。
- 在设计为有重复组合的合成公共场景中，要求至少一条真正被执行的三层定义依赖链，随后扩大到4层及更长序列材料。
- 每一层必须增加可验证的条件、共享角色约束、时间组合或控制作用；空包装和别名不计。
- 检查2、4、8及更长的真实连续动作材料，并在独立布局消费。材料长度不等于宏依赖深度。
- 如果搜索选择了更低费用但更浅的等价表示，控制能力可通过；层级增长检查单独标明未达到，不能手工套宏把深度补到目标值。

第一阶无binder不限制定义调用图继续变深。但当前codec有嵌套JSON边界；长序列先使用平衡表达和库共享。新增59/60/256层窄正文、1000参数宽浅正文、8层库依赖三个独立轴的往返/证明检查，明确实际边界。当前两端60层调用会触及2×depth+8<128的检查，Rust底层JSON解析另有递归边界，不能只删前置判断。合法目标语料触及边界时，在本里程碑修复解析、序列化、遍历和释放的栈安全，再完成该输入；不能丢弃或报无新概念。保留codec1须保持原JSON树字面合同；若改成平坦节点/DAG线格式，另升codec版本并同步全部生产端，不能悄悄换格式。

## 7. 复杂实验如何设计，才能回答“还差多少”

### 7.1 统一的最小因果单元

每项覆盖义务都要回答六个问题：

1. 选择哪个公开动作和参数？
2. 作用的公开角色如何绑定，是否有其他可能解释？
3. 执行前哪些关系/历史条件成立？
4. 对位移、颜色、数量、选择、信号、动作域和完整帧轨迹分别预测什么？
5. 哪些可区分对照支持或推翻这个预测？
6. 结果如何改变下一步动作、修订条件或程序后缀？

这些信息共同定义本实验的动作—对象最小因果单元。只测动作编号、只测最终位置、只看一个supported总数，都不足以证明单元闭合。

### 7.2 新增公共实验矩阵

私有环境生成器和独立裁判可以知道真值；solver仍只看公共接口。测试世界中的最终概念公式和隐藏对象类别不得出现在solver输入配置。

| 实验 | 公开材料与必须区分的情况 | 新功能必须做到 | 主要归属 |
| --- | --- | --- | --- |
| L01 动作服务 | 一个已知可循环动作+未知可用动作；随后新增/移除动作 | 按公平义务实际尝试新动作；只执行当前合法动作 | A |
| L02 共享中间角色 | 相同k与分离k1/k2；位置颜色干扰 | 自动Join后Project，防止假共同见证，实际条件消费 | A |
| L03 辅助条件与通行 | 局部墙/边界/目的支持、远端可见信号分别改变；多像素完整footprint及落点合法但途中碰撞 | 区分可站立域、单步合法转移和多步可达；视觉4/8连通不等于行动可达；能建立辅助条件后再通行 | A/B |
| L04 资源与顺序 | AB/BA、A重复、两动作争用同一计数、无关计数同步变化 | 学到共享资源和顺序条件；冻结新布局选择有效序列 | B |
| L05 推动链 | 一个/多个角色协同位移、出口窄/宽、有条件障碍 | 共享角色链保持一致；阻断反例进入条件，不只增加pair项 | B |
| L06 历史与撤销 | 同末帧不同公开历史；位置恢复但资源不恢复 | 历史进入关系；各效果通道单独核对；不把undo当全状态逆 | A/B |
| L07 镜头与身份 | 镜头动、主体动、多人共动、同色歧义、遮挡重现 | 显式解释分支与新坐标绑定；可辨必预测，不可辨保留unknown | B |
| L08 中间帧 | 首末相同，中间信号不同并影响下一动作 | guard读取已发生中间帧；一条多帧响应只计一次干预 | B |
| L09 反例后继续提升 | 已消费深层程序中一个条件被公开反例推翻 | 撤回受影响后缀、保留无关定义、修复后真实再消费 | B |
| L10 官方离线发现 | 25款当前可用动作及公开可区分角色/条件 | 同一通用solver采集、学习、冻结评估、反例修订；逐义务报告缺口 | A/B外部验证 |

每个可辨核心设训练、开发、冻结留出；区分“冻结原库迁移”和“新布局重新训练”。原有多种子环境自测继续保留，不能替代solver冻结迁移。

官方离线25款现有10动作测试继续作为采集回放回归。先取得可回读artifact index，核验事件/响应摘要和before_ref链，再把已保存的250动作轨迹送入新解释/序列编译；缺原件则该复用任务标BLOCKED，不能根据汇总数字重造数据。随后按未完成义务组织新的公开干预。所有参与召回、构造、选参的旧轨迹只算训练；冻结留出使用未参与这些步骤的新轨迹。事后重解释不能记成当时已作出的正确预测。不能简单把每款10改成100后就宣布复杂验证扩大十倍。

真实在线与本地官方HTTP分开报告。不能接通在线时明确说明未完成，不能由本地结果替代。

### 7.3 什么算高级概念质量提高

报告以下相互区分的指标：

| 指标 | 计算口径 | 防止的误判 |
| --- | --- | --- |
| 新构造关系数 | 语义ID去重，附区分证据与消费者 | 将每个候选都计成已学概念 |
| 新搜索宏数 | 真实Rust接受、Julia签收的稳定定义 | 手写宏、别名或构造关系冒充E-Stitch发现 |
| 激活/消费/复用数 | 分别统计激活、实际读到、留出/新布局读到 | 库大但没有人使用 |
| 定义依赖深度 | 稳定ID DAG最长路径及分布 | 24定义当24层；只报告最深孤例 |
| 实际消费深度 | 决策/查询实际读到的定义及依赖 | 库里有深定义但控制永远只用浅层 |
| 程序长度 | 实际confirmed原子动作数 | 8步程序当8层抽象 |
| 独立支持与反例 | episode/干预来源去重，重叠窗口只计原事件 | 678帧或多视图变成678次独立因果证据 |
| 闭合覆盖 | 声明有限义务中正/负/未知/未服务及消费者证据 | 少量supported掩盖遗漏通道 |
| 实际费用与性能 | 同冻结语料、语义、机器条件下的阶段耗时、峰值和匹配规模 | 硬件/输入改变导致的波动被当算法收益 |

不把零反驳直接报告为高因果置信度。必须显示试过哪些反条件、哪些作用通道尚未预测。来自同一自适应轨迹的支持不能当独立同分布样本直接计算一个“99%可信”数字。

### 7.4 里程碑B的退出条件

必须同时满足：

- 连续公共事件真正产生带角色/资源/条件接口的语料，非手写目标程序。
- 至少一个跨动作Program宏由真实E-Stitch发现，完整展开、来源、费用和类型核验通过。
- 宏在未参与发现的公开实例中被原控制器逐步执行；不是仅有离线查询或日志引用。
- 新概念能触发旧经历重解释，并在后批形成真实更高层依赖。
- 至少一条设计为可辨的三层依赖链被实际消费；更高目标单列结果，不伪造达到。
- 反例导致受影响应用/后缀立即撤回，修订后有下一次公开消费。
- 资源、顺序、身份与多帧核心正反例有实质判断；真正不可辨例保持unknown。
- 所有未完成、不可达、缺少证据和执行中断明确列出。

## 9. 性能改进与理论后端的安排

在相同答案和证据的前提下落实07号三项：

1. 后继匹配真正物化之前，用完整规范状态键做精确去重；probe不得提前污染seen。
2. 在固定e-graph epoch内建立规范e-class/算子形状索引，Expand保留全部合法子节点。
3. Reuse用相同完整共享键进行哈希连接，计数和生成共享实现；跨深度的合法位移规则不丢。

这些优化要与未优化路径比较：匹配多重性、类型、角色约束、来源集合、定义、调用、展开和成本全部相同。当前Factor.rows已Arc共享，typed apply已分块，不再重复实现或宣称这两项仍缺失。

关系解释器也应复用AST、来源DAG及作用域缓存，不能通过删除难匹配对象获得速度。缓存键必须覆盖语义、角色映射、解释、相位和相关依赖版本。

只有实际profile表明匹配/关系布尔约束成为主要成本后，才做TDD替代后端的对照；其输入变量必须来自明确的候选绑定和关系合同。TDD不决定哪个未知机制为真，PC也不把未覆盖情形自动变成高置信概率。二者的接入都必须保留同一关系求值与公开反馈验收。

## 10. Codex交付时必须回答的问题

1. 新关系/程序从哪条实际公共证据产生，是否有手写目标模板混入？
2. 搜索发现与构造鉴别各产生了什么，哪些已被激活并实际消费？
3. 新定义如何召回旧证据，是否真的形成了下一层依赖？
4. 复杂移动的墙、边界、推动、辅助条件、共享资源、顺序、身份和多帧分别还有哪些未完成义务？
5. 反例改变了哪个后续动作，哪些后缀撤回，哪些无关定义保持有效？
6. 所有已确认事件是否都有去向；尾批、异常和恢复是否闭合？
7. 实际参数和策略是否与冻结配置一致；有没有下游隐含截断挡住高级概念？
8. 构造、学习、验证和控制是否仍各自只有一个权威语义入口？

只有以上链条可逐项追到实际代码与产物，才能把“联想已实现”“深层概念持续提升”“复杂移动验证完成”写进报告。
