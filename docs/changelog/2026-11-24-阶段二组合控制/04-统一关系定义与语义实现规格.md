# 统一关系定义、自动构造与语义接口

日期：2026-11-24。代码基线、分支、任务顺序见同目录 03 文档。本文件规定待实现接口；所有新增函数名均为计划，不能当作现有 API。

## 1. 一种定义，多种用途，但不混淆能力

当前 `ConceptTerm` 已有 `Literal / Slot / Parameter / Call`，真实 Rust E-Stitch 能学习其中的参数化定义。本轮继续使用这个结构；新增的关系计划是它的 elaboration（结构细化编译）结果，不建立第二种独立学习语言。

同一个发布库保存不同返回类型的定义：

- **Effect（效果表达）**：现有 link、pigment、count_shift、selection 等含义，能由现有机制解释器消费。
- **Relation（表值关系）**：在有限解释域中返回若干有序角色／值的元组，可用于查询、条件、目标和模式构造。
- **Program（有序程序）**：保存已有机制的组合及接口；只有经过控制入口检查的程序能执行公共动作。

首版必须完成 Effect 和表值 Relation 的同库、同版本、同来源管理。程序先复用当前规划器的有序结构与依赖索引；不在此轮把任意程序 AST 宣称为已学到可执行新动作。

关系定义“能判断某些对象是否满足一种模式”，不自动意味着“能生成后状态”。可作为 guard（适用条件）、目标、效果观察或状态生成器的能力必须单独声明并检查。`read_joint_mechanisms` 只能消费效果能力；新增 `read_query_definitions` 将表值定义登记到条件／查询入口。

## 2. 三种变量必须分开

| 名称 | 实际含义 | 示例 | 禁止混用 |
| --- | --- | --- | --- |
| `Slot`，外部自由槽 | 一次程序调用传入的已绑定输入 | `$0::SceneBefore` 是某条公共动作前的解释场景 | 不能把动作后场景改个类型名伪装成动作前输入 |
| `Parameter`，宏参数 | E-Stitch 从共同结构中提取的可替换子表达 | `?#0` 可以替代一个场景输入或一个同类型关系子表达 | 不承担查询的存在量词或对象身份 |
| 查询列／角色端口 | 关系表中的有序位置，用列映射说明共享关系 | `(主体, 工具, 障碍)` 的第 1 列被后续 Project 隐藏 | 不直接编码成 Rust 的 `$0` 或 `?#0` |

这样无需往当前没有内部 binder（绑定器）的语言强加 `Exists`。存在量词由关系表的投影实现，宏替换仍然是一阶、无捕获的替换。

Const（常量）仅允许 schema 声明的语义标量，禁止把场景、对象或响应 payload 塞进 Atom 字符串绕过 scope。运行时测量即使被常量折叠，也必须保留实际读取来源。此前训练学到的固定标量另存 `parameter_training_refs` 和激活知识水位，证明它在当前决策前已经可用；它不因训练来源曾是某次动作后数据就永远禁止使用。用新知识重评历史是 post-hoc（事后）评估，不能计成当时的先验预测。

## 3. 关系类型与求值作用域

### 3.1 静态类型

一个关系的列接口是一个**有序列表**。每列说明值类型与时间角色，例如 `[ObjectBefore, ObjectBefore]`、`[ObjectBefore, Integer]`、`[ObjectBefore, ObjectAfter, Delta]`。可读列名方便解释，实际计算使用确定的列位置。

生成字符串 sort：`Rel_<header_digest>`。摘要覆盖有序列类型、时间角色及关系接口语义版本，不包含具体 frame、对象 ID 或事件 ID。同类型但含义不同的关系可以使用同一个返回 sort；具体含义由定义体和算子描述决定。

`SceneBefore / SceneAfter / TransitionScene` 是求值上下文输入类型。具体场景仍引用公共证据和一种对象解释，不复制整个世界状态到每个定义中。

### 3.2 运行时作用域

每次求值额外带下列信息。它们不藏在相似度特征中：

| 内容 | 为什么必须保存 |
| --- | --- |
| 公共事件、响应帧编号、历史区间 | 区分动作前、动作后以及响应中的中间帧；最后一帧不代表完整响应 |
| 解释 ID 与解释版本 | 两种对象分割是假设，不允许把它们的局部见证混起来完成一个 Join |
| 视图和窗口 ID | 明确完整画面或局部窗口的边界；坐标归一化可恢复 |
| 时间相位与读取来源 | 条件必须在动作前可计算；读取检查沿宏展开与对象绑定传播 |
| 原语语义版本与定义版本 | 使缓存、证明、任务和活动判断不能跨版本偷偷复用 |
| 域是否完整、求值是否穷尽 | 没有找到答案是否足以判 false，取决于这两件事同时成立 |

默认 Join 要求同一个解释作用域。跨帧关系只能由明确的 `TransitionScene` 或带两端 scope 的连接操作构造，不能通过忽略 frame ID 来拼接。

## 4. 首版关系算子以及精确语义

令一个关系表的行是有序元组。所有原语在有限、已声明的域上求值，附来源见证。

| 算子 | 计算 | 类型／接口检查 | 首版用途 |
| --- | --- | --- | --- |
| Atom（原子读取） | 从公共像素、候选支持、动作或已发布定义取得关系表 | 读取域、相位、原语版本明确 | 坐标、颜色、支持成员、像素相邻、相对位移、已有观察效果 |
| Rename（列重命名／重排） | 明确排列列位置 | 必须给一一列映射；不得暗中合并两列 | 对齐两个合法接口 |
| Join（按共享列连接） | 对公共列值相等且 scope 相容的行合并 | 共享列类型一致；输出布局明确；保留共享见证 | 组合“主体—工具”“工具—目标” |
| SelectEqual（等值约束） | 要求两列相等或列等于同类型常量 | 不相容类型直接拒绝；未知值不当相等 | 参数复用、颜色／位移相等 |
| Project（存在投影） | 留下指定列，隐藏其余列 | 输出顺序显式，去重答案但保留所有可用见证路径 | 从三角色机制得到二角色能力 |
| Union（并） | 相同接口的答案合并 | 列类型、列含义与 scope 对齐；无默许补列 | 有多种合法实现的同一关系 |
| SafeNegate（受限否定） | 对显式有限域取补 | 只有原域完整、输入关系穷尽时才能断言缺失元组为真 | 有条件使用的排除关系；不从观察缺失推“没有对象” |

自动构造第一批只使用 Atom、Rename、Join、SelectEqual、Project。Union 和 SafeNegate 先交付求值器与测试；只有任务明确需要且域完整时才能进入枚举，避免把否定空间无限扩大。

例子中的 Holds、Matches、Near、Closed 只是便于理解的名称，不是本轮直接预置的高级认知原语。真正的输入必须已经具有像素／历史上的可求值定义。例如“两个支持中的像素四邻接”是可计算原语；“这是正确钥匙”必须作为候选关系经过证据筛选。

## 5. 一条贯穿类型、共享见证、投影和 E-Stitch 的例子

假设已有四个可求值子定义：H 的列为 `(a,k)`，M 为 `(k,d)`，N 为 `(a,d)`，C 为 `(d)`。它们都读同一个动作前场景。我们希望构造：

$$
R(a,d) = \exists k.\; H(a,k) \land M(k,d) \land N(a,d) \land C(d).
$$

执行步骤：

1. `J1 = Join(H,M)`，共享 `H[1] == M[0]`，输出布局 `[H[0],H[1],M[1]]`，即 `(a,k,d)`。
2. `J2 = Join(J1,N)`，共享 `(J1[0],N[0])` 和 `(J1[2],N[1])`，保留 `(a,k,d)`。
3. `J3 = Join(J2,C)`，共享 `J2[2] == C[0]`，保留 `(a,k,d)`。
4. `R = Project(J3,[0,2])`，输出 `(a,d)`，隐藏 `k`，但在来源中保留具体工具见证。

类型化的一阶表达如下，符号后缀是算子描述的摘要：

```text
q_project_P(
  q_join_J3(
    q_join_J2(
      q_join_J1(q_atom_H($0), q_atom_M($0)),
      q_atom_N($0)),
    q_atom_C($0)))
```

`$0` 的唯一角色是输入 `SceneBefore`。`a/k/d` 是表列，不是宏参数；E-Stitch 对子表达进行参数化时不能改变这些列映射。

如果 H 有 `(a,k1)`，M 只有 `(k2,d)`，且 `k1 != k2`，R 不能成立。先分别投影 H 与 M、丢掉工具后再连接，会制造一个假答案；这必须成为独立反例测试。

发布后，guard 不是把 R 的名字拼入字符串，而是 `RelationPredicate(definition_id, head_binding)`：将当前绑定 `(a,d)` 对 R 做 membership（成员判断），检查相位、作用域和见证，得到 true／false／unknown。

## 6. 编译到现有 E-Stitch 协议

### 6.1 每个算子都带规范描述

对于 Join，描述包括算子种类、输入 header、共享列对、输出列布局、不同角色约束、scope 规则、原语语义版本。Project 包括输入 header 和输出列选择。把这些完整内容规范序列化后生成符号名，不能只 hash 输入输出的列数。

`schema_context` 冻结该任务实际用到的有限算子描述。Julia 先检查描述与符号一致，再生成 `Primitive.inputs/output/reads`；Rust 将它视为有类型的纯一阶算子，不猜测其数学等式。返回后 Julia 重新核对 metadata 并求值。

不要为每个具体事件创建一组算子：事件值是外部槽绑定，算子描述只包括结构与语义。避免 registry 随帧数线性重复膨胀。

### 6.2 协议变更必须两端一起完成

采用单次显式升级的协议 `tddescat.learn.v2`，新增语义上下文摘要和关系描述目录。AST 的无内部 binder 编码继续使用 typed-free-slots 的原则；不要在兼容判断里静默接收旧语义。

实现时一起修改 `Schemas.jl`、`StitchCodec.jl`、`StitchBridge.jl`、`Library.jl`、`rust/bridge/src/codec.rs` 的 `Registry / Definition::check / stable_id`、`protocol.rs`、`engine.rs`、`main.rs`，以及 Python `stitch.py::run_worker` 的学习 schema 路径。完整清单见 06。新的 worker 身份和冻结 manifest 必须对应同一协议版本。旧原始公共证据可重放；旧派生库或缓存不能假装通过新语义验证，应由明确的离线重建生成新版本。

具体义务：

- 新算子的 `read_rule` 必须覆盖真正被读取的输入，不可以声明空读集逃避相位检查。
- 关系、效果语料每条标明 semantic kind（语义类别）和返回 sort；不同槽语义按任务分组。同一任务内 `$0` 不能一会儿指 before、一会儿指 after。
- 在发送 Rust 前完成真实角色规范化；把恢复到各原事件角色和坐标的映射放入 origins，不只保存程序文本。
- 多个发生具有同一表达正文时，可共享正文，但保留 occurrence ID、频次和独立来源；一次事件的多视图不能虚增独立实验数。
- 返回宏必须具有同一返回类型，且展开后与冻结 source program 在声明等式理论下等义；本轮没有额外重写时要求规范 AST 相同。来源路径全部可回放；随后才求表值含义或效果含义。
- 本轮 `rules.json` 仍不接收未经证明的经验等式。定义展开／折叠使用现有证明通道；控制动作不因共现而交换顺序。

新关系 AST 的 Join／Project 节点并非直接在像素中“观察到”。其 origin 要区分 `observed` 和 `constructed`：前者引用公共记录和原子提取；后者引用构造步骤、父定义、输入 occurrence 与作用域。`input_occurrences` 仍要求原始搜索语料每个 AST 节点有唯一 occurrence；新增构造节点的来源应沿构造 DAG 回到公共记录，而不是伪造一个“观察到此高层规律”的标签。Julia 和 Rust 的 origins schema 一起升级；结构来源有效与关系命题获得经验支持是两项不同检查。

构造 DAG 的节点保存 operator descriptor、父 term ID、列／角色映射、参数来源、冻结求值域；叶子引用原子求值器版本与公共记录。校验器重放这些构造节点，重建冻结的 source program，再独立求值；不能只检查 origin 字符串存在。正例／反例／unknown 评估与结构构造来源分别保存。

## 7. 唯一的语义身份与缓存规则

在 `ConceptIdentity.jl` 提供 `canonical_bytes`，对映射按键排序、对有序数组保持顺序，对整数、字符串和布尔值作确定编码。禁止用 Julia 进程随机化的 `hash` 作持久 ID，禁止用显示文本中的空格或对象地址作内容身份。

一个定义的精确身份覆盖：参数类型、返回类型、规范定义体、引用定义 ID、接口描述、原语／求值器语义摘要。语义摘要只包括正文实际使用的原语、列映射、相位、定义依赖闭包及关系演算的版本，**不 hash 整张可增长 registry**。新增一个未使用的算子不改变旧定义身份；所用 Join 语义或列接口变化则改变身份。局部变量只在真正允许重命名的位置按首次出现规范化；输出列顺序、动作顺序、共享角色不能被排序抹掉。

跨语言采用固定字段顺序的规范向量编码；Julia 和 Rust 必须有相同 golden bytes 和 ID 测试。临时 `fn_N` 依赖重命名为 stable ID 时，按依赖拓扑重新计算正文身份和语义摘要，不把临时编号当永久含义。

实现 `semantic_dependencies(term)`：遍历实际调用算子；对库调用递归取定义闭包；收集实际使用 header、descriptor、read rule 和关系演算版本；按规范 ID 排序去重。`definition_identity` 对规范正文、参数／输出接口和这些 `(依赖 ID, 语义摘要)` 计算摘要。完整 registry 与 worker 二进制身份属于 Job 监管身份，不无条件进入每个定义 ID。

出现记录与定义分开：两次观察到同一种形状，是两个 occurrence，共享一个规范形状描述。碰撞检测必须比较规范字节；相同摘要但不同正文为错误，不能合并。

缓存键至少覆盖定义身份、输入绑定、解释 scope、查询域、读集版本和求值预算状态。完整结果可供较小需求读取；不完整缓存必须保留游标或 incomplete，不得伪装为完整空表。

定义是不可变表达；其“在哪些证据上暂可使用”另有版本化的适用记录。新反例可能只撤销适用范围，而不是证明正文的参数化展开错了。

## 8. 三值结果与来源见证

查询求值先返回已找到的元组及来源，再回答特定元组是否成立：

$$
\operatorname{member}(q,t)=
\begin{cases}
\text{true}, & t\text{ 有有效正见证};\\
\text{false}, & \text{声明域完整、枚举穷尽，且 }t\text{ 不在结果中};\\
\text{unknown}, & \text{其余情况}.
\end{cases}
$$

这里的 true 表示在声明的解释和域中成立，不代表未知环境全局规律被证明。

来源采用可共享的证明 DAG（Directed Acyclic Graph，有向无环图）：叶子引用公共证据和原子判断；Join 形成 AND 见证；多个相同输出元组的不同实现形成 OR 见证。不能仅把所有来源 ID 求并集，因为那会丢失“哪些证据必须同时成立，哪些只是替代见证”。

SafeNegate 的 true 见证必须引用有限域完整证书、相关枚举穷尽证书及其读集，不能生成没有来源的真值节点。

分别记录：答案枚举是否完整、解释域是否完整、见证枚举是否完整。已找到一个有效见证足以使某个元组为 true；但不能由一个 true 推断整个关系表已穷尽。来源 DAG 的内存预算单独计量。

若有多个未排除的对象解释，分别求值，不混合行。控制 guard 只有在其声明的所有可行解释中都为 true 才能作为确定动作依据；存在 true 与 false 冲突时进入区分实验／状态细化；空解释集合是需要修订，不使用全称命题的空真。

## 9. 精确哈希连接与范畴保证

### 9.1 替换双重枚举

当前 `bounded_glue_matches` 对所有左右行组合进行检查。新实现先按 `(scope, 所有共享角色值)` 为较小输入建索引，再扫描另一输入，保留原有不同角色约束。`interface` 必须存在于两侧；除显式接口外的同名共享角色仍须一致，不得只核对接口而忽略其他同名列。

```julia
function exact_join(left, right, descriptor, budget)
    validate_descriptor(descriptor)
    # 真正声明的空共享接口是笛卡尔积，不伪装成低成本连接。
    buckets = index_by_scope_and_shared_columns(smaller(left, right), descriptor)
    answers = new_answer_table(descriptor.output_header)
    for row in deterministic_rows(larger(left, right))
        charge!(budget, :row_visit)
        for other in get(buckets, key(row, descriptor), empty_rows)
            charge!(budget, :candidate_check)
            compatible_all_shared_roles(row, other, descriptor) || continue
            satisfies_distinctness(row, other, descriptor) || continue
            emit_with_and_witness!(answers, combine(row, other), budget)
        end
    end
    return finish_with_completeness(answers, left, right, budget)
end
```

索引构造、输入访问、候选检查、实际输出和来源节点分别计量。输出确实稠密时不能承诺规避输出规模下界。若 budget 用尽，返回已得结果和未完成状态；调用方需要完整真值时得到 unknown。

选择较小输入建索引不改变逻辑左右侧：每行携带原 side tag，键、输出布局和 distinct 始终按 descriptor 的原 Left／Right 解释。不得因 build/probe 交换而把结果列含义翻转。

### 9.2 与范畴的准确连接

在选定模式范畴中，若模式 P 是 P1 与 P2 沿公共接口 I 的 Pushout（推出），则有自然的匹配对应：

$$
\operatorname{Hom}(P,X) \cong
\operatorname{Hom}(P_1,X)
\times_{\operatorname{Hom}(I,X)}
\operatorname{Hom}(P_2,X).
$$

右边正是两个匹配集在共享接口上的 Pullback（拉回），可以实现为精确连接。这一律给出“先拼模式再匹配”与“先匹配再连接”的测试预言机。

但必须固定：模式范畴、态射类型、接口和作用域。若额外要求单射或颜色／平移约束，要检查这种受限匹配在拼接后是否仍满足额外条件；不能直接套用所有 Hom 的普遍性质。两侧均需保存对齐见证，有限预算下不能将少算的一侧宣称为双射已证。

同样，不能先丢弃共享列，再应用 Join 重排。投影只在保留连接键或其他已证明的独立条件下向下移动。首版不做通用查询优化器，仅实现已经验证的有限重排规则。

## 10. Grounding 的自然性边界

在固定像素域上，动作前后逐点差异 Diff 与相同窗口的限制可以交换。保存完整公共响应和相位后，可以检查：

$$
\operatorname{restrict}(\operatorname{Diff}(B,A),W)
=\operatorname{Diff}(\operatorname{restrict}(B,W),\operatorname{restrict}(A,W)).
$$

但“裁剪后重新计算连通块”一般不等于“完整图中连通块的局部限制”。窗口外可能有一条桥把窗内两块连接起来。

因此：

1. 全帧四／八连通各是一种明确解释视图。
2. 限制视图保存全局候选 ID 和窗口内支持片段；不能把片段当完整对象。
3. 局部重新分割是另一种解释，不沿用全局对象 ID。
4. 边界未闭合时，依赖对象完整性、计数或否定的关系返回 unknown。
5. 对象组只允许从接触、共变、共享动作接口等已有连接生成有界候选；不能穷举 64×64 网格上的任意子集。

这些视图仍共享同一原始证据，后续实验可以排除不合适的解释，而不是覆盖原图或抹掉分歧。

## 11. 有界自动关系构造器

### 11.1 输入和输出

输入是一项明确缺口：例如“当前动作的两类结果不能由现有 guard 区分”，或“目标关系需要两个角色，但库中只有中间角色连接”。输入还包括相关证据、可用原语、已有定义、目标列、相位与预算。

输出是可求值的 `ConceptTerm` 候选、每个候选的类型／来源／已评估结果，以及未穷尽的 frontier（搜索前沿）。不是 Python／Julia 自由代码，也不是自然语言猜想。

### 11.2 固定算法

```text
construct_relations(gap, snapshot, limits):
    pool = 相关作用域内、相位合法的原子和已发布子定义
    queue = 与种子角色或目标列相连的 pool 项
    seen = 空的规范定义集合

    按 (AST 节点成本, 生成深度, 规范键) 确定地取出 q:
        类型检查 q；若已见则跳过
        在冻结证据域求值，保存正例/反例/unknown/见证
        若提供目标接口且有区分作用，提出条件或查询候选
        若有多处结构使用，登记到 E-Stitch 语料候选

        在节点数、角色数、深度及总工作预算内：
            与至少共享一个合法角色的已登记项 Join
            加入同类型 SelectEqual 候选
            Project 到当前目标或后续组件需要的接口
            做明确 Rename 使接口可以相接
            将新项入队，保存来自哪个构造操作

    返回候选与未完成前沿，不把预算停止视为无解
```

避免只按频次筛选：当前反例涉及的谓词候选不能因稀有而被常见运动压掉。候选本身可以只得到少量支持；上线适用性必须继续遵守作用域、未知和实验反馈。

E-Stitch 接收这个构造器产生的合法结构材料，负责寻找重复结构、参数共享和库压缩。构造器负责语言可表达的候选扩展，二者互补，不能把枚举一个 AST 写成已经实现 E-Stitch 的能力。

共享列不是外部预写答案。`enumerate_join_descriptors(L,R)` 枚举同类型列对组成的非空、无矛盾部分一一对应，检查相位、scope、输出列宽和不同角色约束；输出布局固定为左列加未共享右列。需要同侧两列相等时先由 SelectEqual 明确约束，不能暗合并。实际有共同见证的布局优先，未查布局保留前沿。每产生一个布局即计 work，不能只在求值阶段计预算。

`enumerate_projects(header,target_header)` 枚举类型与目标有序接口相符的列选择；改变顺序必须显式 Rename。角色数、列数和节点数均有界，生成范围写入结果，不能声称遍历了语言中所有关系。

### 11.3 从关系到真正条件

新增 `RelationPredicate` 包装已验证的动作前关系定义。`predicate_pool` 从活动定义索引召回输出端口相容的关系，绑定到当前机制角色，调用统一 membership 求值。

`fit_joint_condition` 保存正例、反例和 unknown；新增关系只能在声明训练范围形成暂用条件，未参与构造的验证事件另计。动作后才知道的关系只能描述效果；不得因为“非常能预测成功”就允许泄漏到动作前。

### 11.4 接回多维偏序、查询抽象和目标

同一有序接口、语义版本和解释域内，关系外延包含可形成**带范围的**偏序边。只有在完整有限域上检查 `answers(A) ⊆ answers(B)` 才登记该域的包含证书；少量样本上的包含只作经验候选，不能登记成全局逻辑蕴含。不同接口先用显式 Rename／Project 转换再比较。关系表的 Join 是自然连接；概念格的 Join 是偏序中的上确界，代码与文档不能把两个同名单词当同一运算。

本轮保存可验证的偏序／投影边，不枚举完整概念格。Pattern Structures（模式结构）中的共同描述可作为候选生成来源；若未给出该描述域的合法半格运算，不用一个任意“共同图”函数伪装 meet。E-Stitch 返回参数化共同正文，也不自动给出全局最小上界。

当前 `QueryAbstraction.factor_query / refine_partition / causal_square_witness` 接收有限模型。新关系只能先在每个模型状态的公共解释中求值得到查询；unknown、未覆盖状态和动作单列。查询保持证书记录定义、分区、状态域、动作／查询生成元、版本和首个反例，继续调用现有逐状态方块；不得调用 `check_schema_map` 替代。

新目标入口采用 `QueryGoal`：保存已发布关系定义和当前目标角色绑定，通过同一 `relation_membership` 求目标真值。现有颜色／距离目标先编译成同一关系表达，`bind_observed_goal / goal_truth` 转为统一入口的构造与调用，不增加失败后切换旧目标语义的分支。表值目标不会产生后状态；`ProjectedPlanning` 仍用已验证的机制投影生成状态，再求值新目标。对这些有限转移，继续使用 `RelationSemantics` 的 `post_image / liberal_precondition / safe_precondition`；只有启用、后继非空且范围完整时，反向条件才能成为确定控制依据。

## 12. 发布与激活是两个原子边界

沿用 `Library.jl::publish_stitch!` 发布可回放的结构定义。新增 `activation` 快照引用：结构库版本、语义版本、可求值关系目录、当前机制／条件版本、验证证据水位和依赖摘要。

只有完整验证的激活快照才能替换在线读者的 current 指针。读取方一次决策只读一个激活快照，不能把新关系与旧 guard 列表混用。

结构发布成功但激活失败时：保留结构产物供审计，记录激活失败／incomplete，继续使用仍有效的已发布激活快照；这不是旧算法回退，而是尚未批准的新版本从未进入消费者。若旧适用性已经被反例撤销，它也不能因新版本未就绪而继续执行。
