# 后台学习与共享资源程序验收

在线会话可通过 `[learning].background_search = true` 启用后台搜索。Julia 先冻结已确认批次，Python 仍只监督一个 Rust E-Stitch 进程。环境动作继续走 `Recorder`。动作之间签收完整结果，签收时用当前证据检查机制。收尾先签收未结束的任务，再按批处理剩余确认事件。冻结留出继续禁止新学习。

## 实跑结果

| 运行目录 | 公开反馈与结果 |
| --- | --- |
| `runs/association-background-r01` | 前两条确认动作进入第一个冻结任务。监督器等到第三条实际动作到达后才交付结果，收尾得到三个两动作任务，六条动作全部登记并处理。决策 `c000000005` 保存了当时未签收的任务身份。 |
| `runs/association-joint-sequence-r01` | 从已确认的训练轨迹搜索到依赖深度 2 的两步程序。在未参与训练的布局中，第一步同时核对两个角色的位移与资源扣减，剩余资源为 2。第二步重新校验同一个计数端口，确认资源降为 1，并完成程序。原四步程序留出和反例撤回回归同时通过。 |
| `runs/association-eight-steps-r01` | 新采集 20 条独立八步公开轨迹，共 160 次动作。八步任务在独立的 12 GiB 进程内存诊断限额下终止，未发布八步定义。留出的八次动作中，前四步实际消费此前学得的深度 4 程序，后四步由普通控制器完成。正式 `stitch_open.toml` 保持开放策略。 |

验收产物记录每条动作的完整回执、程序索引、来源、预测与核对。`association_background.toml` 和 `sequence_learning.toml` 可通过标准运行器独立重跑。两步和四步的组合消费成立，八步结果保留为资源诊断。
