## 1. 本轮要交付的行为

当新的公共动作响应进入系统时，系统能自动判断：它与哪些历史对象、对象组合、关系定义、机制及动作程序有关；这些联系分别值得执行哪一种计算；结果怎样改变下一次预测、实验选择或动作。这个过程必须能恢复、能受预算约束、能追溯到原始证据，并且在出现反例后只撤销受影响的适用判断和消费者。

完整行为为：

**公共事件确认 → 增量登记多视图 → 廉价召回 → 有类型的结构对齐 → 选择构造算子 → 真实 E-Stitch 搜索或关系求值 → 证明与证据检查 → 版本发布 → 条件／预测／规划实际消费 → 新反馈触发下一轮。**

“联想成功”必须至少落到一个明确的后续任务；“概念提升完成”必须至少有一个实际消费者读取新版本。仅增加相似边、仅输出宏、仅生成日志均不算闭环完成。

## 2. 已确定的实现选择

1. **Julia 拥有唯一语义。** 原始公共证据、角色解释、概念定义、关系求值、条件、机制、依赖和发布均由现有 Julia 主干管理。保留 `ConceptTerm` 和现有库发布通道，新增可求值关系是其有类型扩展。
2. **Rust E-Stitch 继续作为实际结构发现引擎。** 使用当前 `best-first` 搜索、证明回放和来源校验；不以 Julia 反统一器替换真实发现链。本轮不打开任意经验等式，不引入新的 Sequential Monte Carlo（序贯蒙特卡洛）搜索路径。
3. **首版检索固定采用倒排索引和有类型的结构特征。** 不引入向量数据库、大模型嵌入或 Locality-Sensitive Hashing（局部敏感哈希）依赖。Weisfeiler–Lehman（魏斯费勒–莱曼）局部结构特征只用于候选召回，随后必须精确对齐。
4. **Hash（哈希）分工明确。** 精确摘要回答“是否同一规范内容”；相似特征回答“值得检查谁”；角色对齐和语义求值回答“能否复用”。相似得分不能写入真值、同一性或因果置信度。
5. **所有检索与构造有明确作用域。** 对象、关系、机制和程序使用不同类型的入口；跨层联系通过 `defines / uses / supports / predicts / implements / refines` 等有含义的引用实现，不把所有节点塞进一个无类型相似桶。
6. **快路径和深搜索分离。** 每次确认事件只做有界索引、反例失效和少量精确检查。深层关系构造和 E-Stitch 在阶段节点、重复结构、缺口或反例驱动的冻结任务中执行。每个任务仍来自同一批可追溯的公共记录。
7. **未知是一等结果。** 没找到候选、读取域不完整、预算耗尽、对象绑定含糊，均不得自动写成“关系为假”或“已经完全覆盖”。反例和未覆盖动作有独立的调度义务，不能被相似度前若干名过滤掉。
8. **只走 Strict Public Application Programming Interface（严格公共应用程序接口）。** 全部响应帧保留；不读取游戏内部对象、胜利条件、调试状态或源代码作为求解器知识。Python 保持传输／进程监管职责。

## 5. 概念与联想知识保存在哪里

不创建一个吞下所有信息的“大范畴对象”。保留现有事件存储和概念库，新增可恢复的索引、任务和评估记录。各部分的含义必须分清：

| 保存内容 | 所属位置与责任 | 生命周期 |
| --- | --- | --- |
| 动作前观测、公共请求、完整动作后响应 | 现有 `RunStore`／`Evidence`，保持内容摘要和事件顺序 | 不变的原始证据 |
| 对象／对象组及局部解释 | 视图登记与来源引用；包括分割算法、参数、支持像素、解释作用域 | 可重算、有版本；多解释可并存 |
| 可求值概念定义 | 现有 `LibrarySnapshot` 扩展；保存定义体、类型、列接口、语义版本 | 内容寻址、不可原地改语义 |
| 当前适用判断、机制条件、查询结果 | 同一解释器求值及现有活动机制；带证据域和依赖 | 新证据可使它失效；不等于定义体本身错误 |
| 精确索引与相似特征 | 可重建的 `AssociationIndex`，引用上述内容 | 只加速查找，不拥有事实真值 |
| “为什么想起它、准备做什么” | 持久联想任务账本 | 保存触发、对齐、预算、状态和后续消费 |
| 压缩、查询保持、因果支持、控制结果 | 分开的检查记录，汇总到同一概念版本 | 不合成一个模糊的“可信度”数字 |

自然变换不保存成一句标签。需要保存两个解释、共同底范畴／查询生成元、分量的实际计算、检查域、版本和失败见证。只有具体检查成功的方块才能被消费者引用。

重要修改点：

- `Config.jl`：严格解析新增配置文件，拒绝拼写错误和不支持值；配置相对于文件所在路径解析。
- `Schemas.jl`、`StitchCodec.jl`、`StitchBridge.jl`、`rust/bridge/src/codec.rs`、`protocol.rs` 和 Python `stitch.py`：共同承担关系列接口和语义版本的编码校验；不能只改 Julia 发送端。
- `CategoryBackend.jl`：精确索引连接；保留匹配语义和完整性标记。
- `Grounding.jl`、`LocalEffects.jl`：提供有来源的视图和发生记录；同一个事件的两个解释不能当成两个独立实验。
- `Library.jl`：唯一发布入口，区分结构定义发布与经验适用性激活；写完整 activation 快照后原子切换；拒绝过期依赖。
- `GuardRepair.jl`、`JointMechanisms.jl`：通过统一定义解释器消费新关系，替代继续增添游戏专用条件分支。
- `OnlineSession.jl`：拆分 `online_learn!`，将同步批处理改为提交和收取；先撤销反例再选下一动作。
- `Plan.jl`、`ProjectedPlanning.jl`：注册并重验新定义、条件和视图依赖；仍由现有控制器唯一发动作。
- `public_run.py`：执行不可变任务和恢复监管；不得在 Python 计算关系含义或决定搜索语料。恢复范围是计算，不自动等于原游戏在线恢复。
- `scripts/run.jl`：先验训练通过同一调度器完成后，建立显式冻结边界，再开始只读评估；旧任务不能越过边界激活。
- `TddESCat.jl`：按类型定义依赖重排 include，新增文件没有循环引用；测试仅导入公开入口或明确的内部测试入口。

## 7. 两个里程碑及准确实施顺序

### 里程碑一：同一关系定义能被构造、求值、检索和精确对齐

**A1：先固定语义与协议边界。** 修改概念身份与有限关系 schema；把 `Slot`、宏参数和查询列区分开；加 scope、phase、三值和完整性契约。Julia、Rust、Python 的 v2 学习协议同时贯通，使里程碑一可通过现有真实 worker 做编码／展开回环；异步调度在 B2 完成。先实现 04 文档中的示例和错误输入测试。

**A2：实现关系求值和精确连接。** 原子读取 → Rename → Join → Project → Union；安全否定只能作用于完整有限域。`bounded_glue_matches` 使用同一共享角色键语义。只在声明条件满足时应用范畴连接律。

**A3：登记原始证据的不同视图。** 四／八连通、局部片段、变化支持和有界对象组保留源事件；平移归一只是检索视图，不改公共坐标。视图失效可从证据重建。

**A4：实现两阶段联想。** 精确摘要去重；倒排结构特征召回；有类型端口／角色对齐生成见证。允许同一源事件参与多个视图，但统计实验数按事件去重。

**A5：实现有界关系构造器。** 从对齐后的结构、正反例差异和目标端口生成相连的 Join／Project 候选；评估后进入同一待压缩语料入口。不在此处宣布机制因果成立。

**A6：通过里程碑一退出门。** 06 文档的身份、关系、作用域、连接、检索和碰撞测试全部通过；在一个最小合成公共记录集中，自动形成新关系定义，并能在未用于构造的场景求值。不能仅手写目标关系并调用求值器冒充自动发现。

到此提交代码和中文 changelog。此时有可复用计算内核，但深搜索、发布和在线消费尚未闭环；报告必须明确这一点。

### 里程碑二：联想驱动真实搜索，发布后改变预测或控制，并接受反例修订

**B1：建立持久任务账本。** 把新事件、反例、目标变化和定义发布变成不同任务；完成去重、合并、版本检查、mandatory（必须处理）义务和预算状态。冻结评估时禁止生成或发布新的训练定义。

**B2：改造真实 Rust 通道。** 将 `online_learn!` 拆为提交／收取；使用召回语料和明确 origin 映射调用 `freeze_stitch_job`。Julia 校验完整轮次、证明、类型、来源和语义，继续调用 `publish_stitch!`。缺少 worker 时返回明确 BLOCKED，不使用替代发现器。

**B3：完成新关系与程序视图的消费闭环。** 新定义成为 `GuardRepair` 候选、关系查询和 `QueryGoal` 目标表达；仍可由 `JointMechanisms` 与 `ProjectedPlanning` 组合。当前规划器产出程序视图，目标变化后召回、逐边重验并交回同一个规划器。新定义发布后产生精确的下游重算任务，不重拟整个库。至少一个实际后续公共动作或明确的 abstain／实验选择必须读取新定义；不能用仅被索引的程序冒充程序复用完成。

**B4：完成反例、重启和版本闭环。** 新反例先撤销受影响消费者，再排队局部修复；旧任务与新语义版本不一致时禁止发布。进程重启能恢复任务，不能重发未确认的公共动作。当前数据不足时保留 unknown 与待实验义务。

**B5：完成真实匹配成本改进。** Julia 精确连接先完成；Rust 跨因子、同绑定深度的 Reuse 使用规范 e-class 键的精确连接，按 05 文档限定范围做差分测试。非等深情形继续走它自身定义的精确 shift 检查，不以 hash 近似代替。只优化已证明的同语义计算，不同时开放任意重写。

**B6：通过里程碑二退出门。** 同一固定证据与预算下，真实 Rust 产生新库定义、Julia 发布、后续消费者读取、公共反馈支持或反驳、依赖撤销和再发布全部有链接；新增验收与受影响原验收通过。记录资源、覆盖、未知和具体消费，不以平均得分代替闭环证据。

两个里程碑内部按 A1→A2→A3→A4→A5→A6→B1→B2→B3→B4→B5→B6 执行。A3 与关系测试可在接口确定后并行；发布、消费者变更与版本迁移必须顺序落地。

## 8. 最小认知提升例子

假设多次公共事件显示：一个支持区域在某动作后平移，旁边另一区域也随之平移；另一些事件同样动作只改变一个区域。系统首先从原始帧得到多种候选支持和完整变化，而不是直接命名“拿着钥匙”。

1. 检索通过形状、相对位移和共变结构召回历史事件；颜色和绝对位置可以不同，但这种忽略只作用于召回。
2. 精确对齐保留事件、前后角色、共享位移和不同对象约束，生成“两个角色在此事件共变”的可求值关系。
3. 构造器提出共享位移、接触、包含、相对距离等有限组合，与成功／失败事件对照；E-Stitch 从这些合法表达压缩出参数化定义。
4. 一个动作前关系若能区分机制适用与失败，进入条件搜索；动作后共变关系只能用于效果检查，不能偷偷进入动作前条件。
5. 之后只要在同一可检查条件范围内未见反例，可以暂时复用并登记证据；新反例触发条件特化、对象解释调整或新实验，而非删除原始证据。

这个闭环学到的是“带作用域的关系／机制假设”。是否应该把它命名为 Holds（持有），需要更强的任务语义；首版可以使用稳定的定义 ID，名字不是算法成立的前提。

## 9. 本轮明确不承诺的能力

本计划不宣称有限检索和有限关系语言能发现所有新概念；不宣称没有反例等于因果已被证明；不宣称一个相似图或一个自然方块已证明整个 ARC-AGI-3 求解能力。目标发现、任意高阶关系发明、无限历史、完整反事实识别、任意语义等式自动证明不属于本轮完成门。

首版必须交付的是一个可自动触发、生成新关系、调用真实压缩、实际消费、受反例修订的有限闭环。以后扩展视图、关系语法和规划范围，都沿同一类型／证据／版本接口扩展，不增设旁路。
