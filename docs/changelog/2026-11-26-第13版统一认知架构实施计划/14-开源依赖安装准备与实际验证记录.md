## 4. 独立能力验证结果

### 4.1 Satisfiability Modulo Theories（SMT，模理论可满足性）

断言整数 `0 < x < 2`，实际返回SAT且模型 `x=1`；增量push后再断言 `x<=0`，实际返回UNSAT；pop后恢复SAT。验证实际求解、模型提取与增量上下文，不只是 `import cvc5`。

### 4.2 Syntax-Guided Synthesis（SyGuS，语法指导合成）

要求整数函数对所有输入满足 `increment(x)=x+1`，实际得到 `(lambda ((argument Int)) (+ argument 1))`。再用一个独立solver查询合成函数与规格不等的输入，结果UNSAT。该例证明已安装库具备目标API能力，尚未完成项目typed AST下译、假设一致性检查或真实轨迹guard合成。

### 4.3 CirKit编译、概率查询和训练

构造两个二值变量、两个独立乘积分量和一个显式Softmax权重和节点。先用手算混合分布给出四个赋值的独立期望 `[0.24, 0.26, 0.36, 0.14]`，再调用真实CirKit编译到PyTorch并使用 `lse-sum`。

| 检查 | 实际数值/状态 |
|---|---|
| 输出结构 | `(4,1,1)`，先验证形状，不任意squeeze |
| 四项联合概率 | 约0.239999998、0.260000004、0.359999999、0.139999999，与手算误差在2e-7容差内 |
| 对全部变量积分 | 1.0 |
| `observed_mask`取反作为积分mask | 两个部分观察样本的边缘约0.5和0.6，与显式求和一致 |
| 条件概率 | 约0.7200000004，对应0.36/0.5 |
| 一次默认Adam更新 | 默认学习率0.001；训练参数确实变化 |
| 更新前/后的固定样本负对数似然 | 1.59524833499 → 1.59452776963 |
| 更新后的总概率质量 | 1.0，规范化保持 |

缺失变量采用合法类别占位值和mask边缘化，不把缺失当false、NaN或额外类别。该例不证明动态变量重编码、跨证据去重、模型发布、长期结构学习、概率校准或真实因果识别已完成。

### 4.4 Regular Positive and Negative Inference（RPNI，正负样本正则推断）

显式history extra启用后，将四个前缀闭合的toggle输入及on/off末次输出交给 `run_RPNI(..., automaton_type="mealy", input_completeness=None)`。实际学习到两个状态，四个已观测前缀全部回放一致；未观测输入未补成self-loop或sink。测试未创建live System Under Learning（SUL，被学习系统）连接，不能自行向游戏发动作。

## 5. 安装入口仍需纳入整体工程改造

实施分支支持独立执行 `python scripts/bootstrap.py --config config/toolchains.toml --compute-only`。此入口使用固定的 Python 3.12.9，校验锁并运行 CirKit、cvc5、AALpy 的项目适配器测试。Linux x86_64 计算环境使用 PyTorch `2.15.0+cpu`，发行文件及摘要由 `scripts/check_sources.py` 核验。Public25 会在启动对局前核对实际计算后端的能力，并将计算锁和内核摘要写入运行清单。

这些准备资产不取代现有 `scripts/bootstrap.py`。下一步应就地扩展现有脚本与来源校验，而非再加第二套安装系统。

| 具体问题 | 源码位置与当前逻辑 | 后果 | 应落实的修改 |
|---|---|---|---|
| 所有工具链先同时到齐 | `bootstrap.py:main`先解析Julia/Cargo/Rust，再同步Python | 某个后端未准备会阻塞独立计算能力的准备 | 同一bootstrap增加明确component选择和逐组件状态；完整运行仍严格检查其全部实际依赖 |
| 仅识别原Python锁 | `check_sources.py:main`只读 `python/uv.lock` | 新compute锁不能纳入统一来源验证 | sources条目明确所属lock_path；同一校验程序逐项目核对，禁止把未知包静默略过 |
| 假设每个Python发行物都有sdist | `check_sources.py`无条件读取package.sdist及archive_sha256 | 官方CPU Torch这种wheel来源不能直接按当前合同验证 | 来源合同区分sdist/wheel，并核对明确选定发行物的摘要、平台和索引；不伪造sdist |
| bootstrap依赖环境变量定位 | 现有代码使用 `UV_PROJECT_ENVIRONMENT` 与 `JULIA_LOAD_PATH/JULIA_DEPOT_PATH` | 不符合本轮配置文件与可迁移启动要求 | 在同一入口改为明确项目目录、配置与Julia进程内初始化；保留严格路径校验，不添加旧变量兼容分支 |
| 原工具链检查未覆盖新能力 | `check_toolchain.py`检查原Cargo工作空间和E-Stitch烟测 | Factor Rank与compute接入状态不可见 | 扩展同一检查入口、能力清单和结果状态；完成薄适配后再增加真实消费验收 |
