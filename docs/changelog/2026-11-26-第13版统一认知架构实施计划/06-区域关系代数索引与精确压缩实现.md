## 1. 同色四连通：确定性区域先验如何成为后续计算入口

### 1.1 精确存储和区域生成

直接复用 `Grounding.color_components`（4–30行）。输入为真实 `Matrix{UInt8}`，检查实际 H,W 及颜色域；索引按 y,x 扫描，像素坐标使用外部0起始。基础分区覆盖全部颜色，包括大背景、UI、边缘和单像素。分割仅代表空间事实，不推断玩家、道具或背景的无作用性。对一个响应的每个帧调用同一接口，缓存键为 FrameRef 和颜色事实内容身份，若帧内容相同可以共享存储但不能合并时间证据。

具体物理表示：原帧维持已有紧凑颜色记录；一次计算 `owner[y,x]`（区域局部编号）及每区域有序成员。编号使用 `UInt16` 可覆盖至4096，0留给未赋值；如果已有 `Int` 类型先保持语义，切换窄类型需测分配与边界。一个区域使用 `(row, UInt64 bits)` 的非空行稀疏列表或全帧颜色位平面中的共享切片，不为4096个单像素每个分配64行稠密块。形状与颜色由成员及原帧回读生成，几何平移归一化结果只能作为候选签名。对边界、包含、相邻、对角接触和面积等按实际查询生成，不重复复制坐标事实。

目标函数 `region_view(frame_ref, snapshot) -> RegionView`：返回区域身份、颜色、精确成员访问、owner 映射与来源，提供 `members(r)`、`pixel_region(p)`、`color(r)`、`render(view)`。独立 Python 洪泛裁判逐像素重建。区域相邻关系只扫描右/下的网格边，按无序区域对累加共享边数；四连通分量之间同色不可能边接触；八连通粗化在同色对角接触图求闭包。边界采用有效域内边及外缘分开计数，不能把越界当普通颜色0。

```text
label_frame(frame):
    owner = zero(H,W); groups = []
    for y,x in deterministic grid order:
        if owner[y,x] != 0: continue
        r = create_group(frame[y,x]); mark_and_push(x,y,r)
        while stack nonempty:
            p = pop(); groups[r].members.add(p)
            for q in four_neighbors(p) inside frame:
                if owner[q]==0 and frame[q]==frame[p]: mark_and_push(q,r)
    adjacency = count shared region edges by right/down scan
    diagonal = same-color diagonal contacts between distinct regions
    publish exact region view and its proof of reconstruction
```

复杂度 O(HW) 网格访问、O(HW) 成员与 owner；稀疏相邻数不超过实际网格边数，不构造4096²矩阵。区域数最坏为4096；不得凭理论宣称所有游戏显著压缩。实际 profile 应显示分割只算一次并被所有生产消费者复用（`public_components`、`support_features`、LocalEffects 等当前重复取区域的入口统一转为同一视图）。

### 1.2 精确差分与增量维护

对同尺寸前后帧：

`delta = {(p,c0,c1) | F0[p]=c0, F1[p]=c1, c0!=c1}`；完整不变部分由有效位置域与变化掩码之差定义。`apply_delta(F0,delta)` 检查旧值一致后逐项写入新值，重建 F1；`reverse_delta` 是数据回读，不是游戏 ACTION7。对于不同尺寸返回不同空间域和公共可观察变化；不能裁切后假装原始帧一致。

帧序列 `[F_before, F_response1, ... F_responsek]` 建立相邻差分及首尾差分，统一同一个事件 ID。`EventDelta` 返回所有变化位置、各受影响基础区域、公开状态变化和中间帧顺序。将 delta 用于候选定位，不据此认定变化区域即动作直接目标。所有未变化区域/位置仍可读取，用于验证不变关系和负例。

区域分区是每帧完整事实，优先验证现有 O(N) 重算及缓存；不为了“增量”强行实现动态连通。若实测瓶颈在分割：改变像素的旧区域可能断裂，新色相邻区域可能合并。将旧区域全体、改变点和相邻新色区域加入待重标范围，迭代扩展直至边界无同色连通穿出；再重标局部，更新接触边，复核未受影响范围。不能只重算改变点的局部邻域（桥像素删除可能分裂远处）。若不能证明边界闭合，使用同一算法对完整精确域求解，而非退回旧版认知策略。与全域分割比较每个输入的成员集合，忽略局部 ID 重编号。

### 1.3 区域→属性、结构关系的代数定义

成员 U(p,r)、颜色 V(r,c) 为确定关系；B(p,c)=∃r[U(p,r)∧V(r,c)]。区域间邻接 A(r,s)=(r≠s)∧∃p,q[U(p,r)∧J(p,q)∧U(q,s)]；若另需区域内部边计数，应使用单独定义，不把自环混入区域邻接。不要把 U 的有理数秩（等于非空区域数）称为必然低秩。所有关系有列变量及类型，J 是数学定义而不是游戏物理碰撞规则。

| 关系 | 目标执行与返回 |
|---|---|
| same_color/neighbor | 位平面或成员查找，布尔值；同色、相邻与功能联系严格分离 |
| region_members | 稀疏行位集迭代；支持集合并、交、差、包含；准确位置回读 |
| area, edge_count | 自然数聚合；相邻共享边计数不等于不同区域数 |
| shape_signature | 相对坐标集合及类型/颜色映射；原定义不丢失，签名只在指定变换等价下有效 |
| correspondence | 07 的关系候选/见证；不将最高相似度当成已证实同一对象 |
| region_union/refine | 产生对象候选支持的集合表达，基础分区保持原始；允许重叠、非连续、区域内任意精化（按证据产生与可续搜索） |

下面按“调用者→项目适配→上游调用→结果→消费者”逐项固定。所有项目适配函数是拟新增接口，不能误写成 Galley 原生函数。

`Galley.Optimizer` 是该固定版本实际公开的子模块，查询构造器不依赖 README 中已移动的源文件路径。以 [Optimizer.jl](https://github.com/finch-tensor/Galley.jl/blob/8eefbb52c64c9dd1f7cad39e30c9541a9ab9dc56/src/Optimizer/Optimizer.jl)、[plan.jl](https://github.com/finch-tensor/Galley.jl/blob/8eefbb52c64c9dd1f7cad39e30c9541a9ab9dc56/src/Optimizer/PlanAST/plan.jl)、[executor.jl](https://github.com/finch-tensor/Galley.jl/blob/8eefbb52c64c9dd1f7cad39e30c9541a9ab9dc56/src/Optimizer/FinchCompat/executor.jl) 的签名为准。`galley` 的结果还含 `opt_time/execute_time/overall_time`，适配器另外测量域映射、证据和结果解码成本，不只记录内核时间。

Boolean Semiring（布尔半环）的 OR 是幂等操作；Natural-number Semiring（自然数半环）的加法会保留重数。Provenance（来源与推导证明）是第三项责任，不能把权重整数或输出数值直接解释成证据。输入缺少元组，只代表该真支持张量中未存 true；是否已假、未知或冲突，由 05 定义的显式正／负证据与覆盖域共同确定。

### 2.3 可编码的降低规则与伪代码

对每个类型化关系，先保存“逻辑列到张量维度”的一一映射和反向值字典；字典稳定性以定义版本和域版本为准。自然数、对象 ID、帧 ID 不直接混成整数坐标。`Element(false)` 表示该**确定支持集合**的稀疏填充值；未知集合与已知假集合另有视图。

下例是源码签名核对后的接入伪代码，尚未在本环境执行：

```julia
import Galley
import Galley.Optimizer
const GO = Galley.Optimizer

# R(x, y) 与 S(y, z) 均为本作用域已知真支持的 Galley.Tensor。
# x/y/z 是已通过类型检查的逻辑变量；false 是 OR 的初值。
joined = GO.MapJoin(&, GO.Input(R, :x, :y), GO.Input(S, :y, :z))
projected = GO.Aggregate(|, false, :y, joined)
query = GO.Query(:support, GO.Materialize(:x, :z, projected))
run = GO.galley(query)
support_xz = run.value[1]  # 只说明支持集合，不能自动说明知识完整
```

编译规则：

- `Join`：相同逻辑变量共享索引；不相等约束引入同域布尔约束因子，不能只在结果排序后过滤。
- `Project/Exists`：`Aggregate(|, false, eliminated_indices..., expr)`；如果输出是不同元组数量，先完成此步，再以加法计数。
- `Union`：对同列、同域关系用 `MapJoin(|, ...)`；重复事实不会增加独立样本数。
- `SelectEqual`：绑定合法常量，或引入已验证的等值约束因子；保留原始角色身份，不凭列类型相同就合并变量。
- `SafeNegate`：只有语义层提供完整域证书时，编译 `D ∧ ¬R`。D 是明确合法元组集合，不能对稀疏存储的整个整数空间取补。
- `Rename`：只改变经检查的变量对应与维度排列，不改变关系事实。
- `Zero-column projection`：布尔空元组表示“存在一个满足绑定”；自然数零维结果是计数。二者的类型标签不同，即使数值都是 1。

```text
compile_query(expr, snapshot):
    verify types, legal domains, scope mappings, evidence cutoff
    distinguish Boolean support, natural-number aggregate, proof request
    obtain versioned input views from the existing knowledge owner
    lower only proven algebraic identities and supported exact operations
    give factor structure and actual cardinalities to Galley
    return executable query + variable mapping + dependency certificate

execute_query(plan, snapshot):
    reject mismatched definition/domain/snapshot dependencies
    run the selected indexed access or Galley plan
    decode output coordinates to original typed values
    attach a factorized proof query over original input witness IDs
    publish result completeness separately from witness enumeration completeness
    return relation view / scalar + evidence dependencies + execution measurements
```

Functional Aggregate Query（FAQ，函数聚合查询）的变量消去和物理优化复用 Galley，不由本项目重写 InsideOut。具体查询先绑定状态／动作，再联合匹配 P(r1)、Q(r2)、C(r1,r2) 和动作许可。输出必须保留同一绑定；“分别存在 P 与 Q”不能代替“存在满足联合约束的 r1、r2”。

### 2.4 证明、不完整关系与缓存如何闭合

上游张量优化返回数值，不返回本项目的证据 DAG。这里的 Directed Acyclic Graph（DAG，有向无环图）按事实引用与推导引用组成，继续由 `relation_witness!` 和 05 的证据所有者管理。

对输出 q 的见证保留因子化表达 `∨binding ∧input proof(input, binding)`。精确布尔支持由 Galley 求得；证明层保留原始输入根、绑定条件、变量消去范围和查询定义，不先展开所有证明。`explain(q)` 或撤回操作在该表达上限制输出绑定，再求所需见证；若只返回一个见证，`witnesses_complete` 必须为 false。这部分是拟新增的证明查询适配，不能宣称 Galley 已完成 provenance。

正证据与负证据分别保留，但传播规则不能机械相同。存在查询有一个真绑定即可证真；要证假，必须覆盖所有合法绑定并证明它们都不能满足。不能对负支持也做一次 OR 消元，就把“存在一个失败绑定”误写成“没有成功绑定”。冲突时保留两方证明。一个支持为空的稀疏张量不能据此给出完整反证。完整性证书需要覆盖本查询涉及的合法域、输入关系和消去变量；数据表的所有已存行都处理过，不等于环境中的事实已全部知道。

缓存分为执行代码缓存与语义结果缓存。前者可以复用相同类型／形状／代数操作的代码；后者必须检查定义、域、输入内容及证据版本。上游 `galley_scheduler` 默认 `cache=false`，重复执行子式的正式入口显式启用 `cache=true`；`threshold` 保留上游默认含义，仅决定重新优化时机，不决定删除候选或合并知识。

### 2.5 增量连接及证明撤回

对固定定义、已物化的查询，保存输入因子根、反向依赖和执行视图。插入 delta 在环／多重集语义可使用 `ΔR⋅S + R⋅ΔS + ΔR⋅ΔS`；布尔语义以 OR 去重。把各 delta 子查询再次编译给 Galley，不另建一套稀疏连接器。重复同一事件的证明仍指向同一事件 ID。

删除不能在布尔半环直接减法。删除对应根证明后，沿反向依赖找受影响结果；只要还有有效 OR 分支，结果保留。仅在整个结果支持空且域覆盖完整时，才能形成相应反证。证明计数与独立样本计数不得相互替代。

Galley 本版没有本项目需要的模型修订事务、证据撤回或任意递归增量接口。定义改变时失效相关计划并对受影响作用域重新计算；递归查询删除后按 Strongly Connected Component（SCC，强连通分量）重算受影响固定点，不能让循环支持自我保留。第一版可采用受影响查询的完整精确重算，独立小域从头计算作为裁判；这种同语义更新是本实现明确算法，不接入另一个旧求解器或新增隐含备用框架。

## 3. 六维偏序索引：具体数据结构、查询、插入与撤回

### 3.1 共享索引管理

扩展 `AssociationIndex` 的访问结构和共同查询（已存在 `entries/ports/inverse_features`），不再为每种玩法写只认颜色、形状或接触目标的检索。由同一个 `IndexRegistry(snapshot)` 管理派生索引。它的键包含四项：`relation_definition` 指关系定义及其版本；`domain_epoch` 指当前合法对象／值域版本；`columns` 指本索引绑定的有序逻辑列；`comparison_kind` 指集合包含、属性匹配、条件蕴含等明确比较语义。这样相同列的访问可以共享，不同定义或域不能误用旧索引。用户要求六个维度均可查：每维必须实现查询语义，但物理索引按实际需求共享，绝不是六份完整知识表。`select_index(query, registry)` 依据实际绑定列和访问统计决定计划；对无物化索引的精确查询仍走同一关系执行，不是旧 solver fallback。弱特征、统计相似和秩只排序，不能硬排除合法候选。所有索引项指向同一 Knowledge/DefinitionRef 与版本。必要筛选若无法保证覆盖，就使用完整域候选，并将提示排序；不能只召回最相似前几个。

### 3.2 具体查询定义和实现

| 维度及操作 | 首选具体访问结构 | 检索/最终验证算法 |
|---|---|---|
| 集合 `contains(A,B)` / supersets / subsets / intersections | 成员→集合 ID 的有序 posting；集合大小；稀疏/压缩位集 | 超集=对查询集合所有成员 posting 求交；空集返回同域全部集合。子集=对查询成员累计候选集合的不同匹配成员数，等于该候选真实基数才入选，另返回空集。最后验证同域精确成员；交集/差集用位运算 |
| 属性 `match_attributes`、共同属性、闭包 | (属性定义,值,scope) 倒排；整数范围有序键 | 正合取通过 posting 交集；区间按合法值域检索重叠再精确判断蕴含；否定仅用明确负例/封闭域；缺失值保持 unknown。共性由实例→属性及属性→实例交替求闭包；该闭包只描述明确给定的证据上下文，不把未知填为假后声称全环境规律 |
| 条件 `implies/stronger/weaker` | 规范 AST 指纹、正文字项索引、已验证蕴含边及逆边 | 正合取可用集合反包含提出充分候选；一般条件以 D∧C1∧¬C2 不可满足为证，另检 C1 非空；使用现有有限关系检查或 ATDD（完整布尔域）。缺乏证明边不是不蕴含。按需缓存经证明边，域变化失效 |
| 对象 `match/decompose/compose` | 成员倒排、形状归一化签名、空间范围（行列 interval）和对应关系索引 | 对象候选以精确可回读支持与类型化映射验证；多角色 Join 绑定；签名不等只能在查询显式要求精确形状时排除，否则作为排序。跨帧索引不能靠局部 region ID；保留部分、重叠及多对多匹配 |
| 机制 `find_producers/bind/reuse` | `(动作或动作类型,读取角色,条件谓词,输出关系及极性)` 多列 posting；输入/输出及作用域索引 | 由目标效果向后找原子作用及程序定义，再核对参数、所有条件、完整联合绑定。没有效果索引条目代表未知识别，不是不可达。实际因果等价需保持相关后继/控制区分，而非仅相同作用类别 |
| 时间 `prefix/range/history_test/sequence_match` | 事件顺序索引、序列 Trie、程序子式规范键、历史-测试二部关系 | 精确前缀、窗口与后缀按事件 ID/时间角色查询；历史匹配须带状态条件与动作参数；未来测试响应一致只是候选等价。跨期组合映射需检查输入输出接口和证据截止 |

Set Trie（集合字典树）是集合子/超集查询备选对照，复用 Julia 位集与现有倒排基础，测实际数据后决定是否需要追加；参考 [Set-Trie](https://pmc.ncbi.nlm.nih.gov/articles/PMC7875400/)。多列索引避免所有列排列的复制：根据生产查询绑定模式选取共享前缀访问，参考 [Automatic Index Selection for Large-Scale Datalog Computation](https://souffle-lang.github.io/vldb19.html)。选择性统计只能影响执行计划，不改变合法答案集。对不同维度的查询结果做 AND 时必须共享变量绑定/定义版本，而不是独立交集错误合并对象角色。

每个索引插入或撤回时维护：(1) 元组对应的独立证明引用；(2) 实际有效逻辑条目；(3) 对应 posting、基数和版本。当一个 OR 证明仍有效，条目不应撤回。蕴含 DAG 按需存边/常用可达关系；删除边后清除依赖该边的路径证书，重新查询真实关系；不能直接保留旧闭包。相等取商只对完整、明确语义证明成立的条件执行；经验等价保留多个解释。`compare_order` 对对象结构映射及机制映射不强制所有关系形成偏序；定义反身、传递、等价取商成立时才称偏序，任意对应/因果边单独建关系。跨维依赖通过类型化 Join，不构造全域笛卡尔积偏序表。

### 3.3 必须实现的查询合同与复杂度记录

```text
retrieve(spec, snapshot):
    q = normalize_and_typecheck(spec)
    scope = resolve_scope(q, snapshot)
    necessary = compile_proven_necessary_filters(q)
    seeds = all_applicable_domain(scope)  # lazy
    for f in selectivity_order(necessary):
        seeds = exact_intersection(seeds, access(f, snapshot))
    for binding in multiway_bind(seeds,q.variables,q.relations):
        verdict = evaluate_required_semantics(binding,q,scope)
        if verdict == proven: emit binding, witness
        elif verdict == unknown: retain as unresolved binding or symbolic unknown range
        else: retain refutation proof if useful for learning
    return query_result_and_completion_certificate
```

任何不可证明必要的筛选不得参与 seeds 硬交集。对所有合法结果的查询可以惰性输出；实际输出本身巨大时只声明尚未枚举的剩余域，返回游标，不截断宣布完成。与独立穷举小域比较完整答案、未知范围、证明，记录 posting访问量、交集次数、候选量、精确验证次数、构建/更新耗时和峰值内存；O(1) 哈希命中不等于 O(1) 包含/机制推理。对预期稀疏结果，禁止每次物化所有 pairwise 关系。

#### 反例提取是项目适配算法，不能假装上游已经返回绑定

作者 `ops::entails` 只返回bool，`is_zero_function`只回答是否恒零。需要真实反例的查询，由适配器组合已有作者运算：

```text
implication_with_witness(D, C1, C2):
    require same domain/encoding/tree and Boolean promise
    premise = D AND C1
    if premise is identically zero:
        return logical_true, applicability=empty_premise  # 不给控制复用证书
    h = premise AND NOT(C2)
    if h is identically zero: return logical_true, applicable
    assignment = empty bit binding
    while h has at least two active variables:
        bit = first active bit in declared stable order
        h0 = author_condition(h, bit, false)
        if not is_zero_function(h0): choose false; h = h0
        else: choose true; h = author_condition(h, bit, true)
        remember chosen bit under its original bit-id
    if one variable remains:
        use author point_eval on its 0 and 1 values, choose one with value 1
        remember its original bit-id
    binding = decode_and_check_legal_domain(assignment)
    independently re-evaluate original D=true, C1=true, C2=false at binding
    return logical_false, verified_typed_counterexample=binding
```

每次条件化处理新树和当前活跃bit-id，零函数/末变量沿4.5规则；已消元变量不重新编号为另一个逻辑变量。初始所有列单值而无bit时直接在唯一合法绑定核对标量。该算法是数学模型内的反例提取，不是一次真实环境实验；若用于提出实验，仍须经当前合法动作和角色绑定检查。独立测试对照小域穷举，验证返回绑定确实违反蕴含，且不存在域外二进制码；存在反例时不能只返回模糊的“失败”。

### 4.4 有限域编码：先说明变量代表什么

ATDD 编译对象是**定义完整的有限布尔函数**。帧颜色关系 B(x,y,c) 的变量是查询坐标与颜色，不是 4096 个像素颜色随机变量。完整 64×64、16 色查询域只需 x 六位、y 六位、c 四位，共 16 个布尔变量；这不意味着整帧只含 16 bits 信息。

编码规则按下列顺序实施：

1. 给每个逻辑列固定类型、合法值集合及值→整数码的双向字典；已有有序整数域可直接平移映射。0 基坐标与 1 基数组访问的换算仅发生在边界。
2. 大小 m 的非空有限列使用 `ceil(log2(m))` 位；m=1 的列可以编码为零位，但仍保留该列及唯一合法值。m=0 产生空域结果，不伪造值 0。非 2 的幂次大小必须加入合法码掩码 D。
3. 全局 bit-id 从 0 开始，每列位序和变量树叶序写入编码版本。作者约定是 Most Significant Bit first（MSB-first，高位在前），全局赋值索引按叶序解释；数值位权、全局 bit-id、树节点 ID 是三个不同概念。
4. 消元后保留未消去 bit 的原始 ID；作者 `Vtree::var_space()` 可能大于 `n_vars()`。例如剩余 ID 为 0、4、7 时，不能把赋值数组按“只剩 3 位”错误重编号。
5. 稀疏关系以合法元组的 conjunction cube（文字合取块）构造，等值和范围约束以表达式构造；共享表达子式和平衡 OR 归并。先去重同变量同极性文字，发现相反极性直接得零。不要为了编码先枚举巨大补集或全赋值。
6. 零位的常量列仍须在投影时更新逻辑列元数据，在解码时恢复其唯一值；不能把“没有编码 bit”误认成“不存在此列”。不完整关系分别编译已知真与已知假支持，或经过 05 明确定义的上下界；编译成功不代表真实转换已经完全已知。已知真／假重叠就是冲突，必须传回，不能偷偷消解。
7. 如果采用 CNF 辅助变量变换，辅助变量必须在关系投影前按布尔存在量化消除；不允许把辅助变量的多个赋值计为多个对象或动作结果。

所有输出都解释为合法域上的函数。域内补集是 `D∧(1−f)`，不是所有 bit 串上的 `1−f`；计数是对 `D∧f` 求和；投影同时更新剩余列的合法域。这些是本项目通用有限域接口，作者库不会自动知道 ARC-AGI-3 的坐标和颜色含义。

### 4.5 零函数、常量、零变量、规范化和布尔承诺

适配层返回三类精确内容，并解释它们的含义：

- **零支持**：当前合法域内没有 true 赋值；仍带列域与证据完成状态。它不等于“环境中没有这种事实”，后者还需要完整性证明。
- **无活跃 bit 的标量**：编码中已没有布尔变量，唯一空 bit 赋值上为 0 或 1；如果逻辑层仍保留 m=1 的常量列，按其唯一值恢复元组，只有逻辑列也为空时才是零列存在判断。合法域为空时值为 0；count 是 0 或 1，不凭消元前变量数乘 `2^n`。
- **非零图**：有至少一个活跃 bit 的 TTN／ATDD，保存树、规范 pivots、编码与合法域。常真图用上游 `constant_one`，如果合法码域不是全 bit 空间，还必须与 D 相交。

零变量输入不调用 `Vtree::balanced(0)`；最后一位条件化或存在消去不调用 `without_var`。按完整赋值构造 `contract::Partial`，调用 `point_eval(a, vt, vt.root(), partial)`，读取根唯一值。条件化直接返回该值；存在消去取两值的布尔 OR。这是对作者不支持边界的精确适配，不是第二套决策图算法。

```text
normalize_boolean(raw, encoding, domain, construction_proof):
    if no active bits:
        check scalar is exactly 0 or 1
        return scalar with domain/dependency identity
    raw.check(vtree) or reject structural corruption
    if raw.is_zero_function(vtree):
        return ZeroSupport(encoding, domain)
    require Boolean-preserving construction proof
        or verify pipeline.is_boolean(raw, vtree) for imported/untrusted diagrams
    minimize(raw, vtree)
    pivots = canonicalize(raw, vtree)
    raw.check(vtree)
    retain CanonicalForm.snapshot only when identity/export actually needs it
    return CanonicalBoolean(raw, pivots, encoding, domain)
```

```text
project_bool(handle, retained_columns):
    require Boolean handle, matching snapshot, complete declared encoding
    value = restrict_to_legal_domain(handle)
    for bit in bits_of_eliminated_columns_in_fixed_order:
        if value is zero support:
            remove bit from metadata without calling canonicalize
        elif active_bit_count(value) == 1:
            z0 = point_eval(value, bit=false)
            z1 = point_eval(value, bit=true)
            value = BooleanScalar(z0 OR z1)
        else:
            new_tree, raw = ops.forget(value.diagram, value.vtree, bit)
            value = normalize_boolean(raw, updated_encoding, projected_domain, proof)
    return value with exact remaining-column mapping
```

`project_bool` 明确不提供“有理数求和就是存在”的隐式行为。需要自然数见证聚合的查询走 `aggregate_natural` 与 Galley，而 `count_models` 只读取布尔支持的模型数，并检查有理数分母为 1、结果非负；传输使用十进制大整数字符串，不截成 u64 或浮点。

导入图必须先结构检查、精确布尔承诺检查，再规范化；本项目构造的每个布尔步骤保留操作与输入证明以传递承诺，独立验收继续重跑 `is_boolean`。内部有负有理数系数是算法实现，不代表负概率。未经布尔承诺的任意加权图不能调用 Boolean NOT、OR、entails 或本版 canonical API。

规范身份由**编码版本、合法域身份、树形及叶标签、规范数据与 pivots、规范化协议版本**共同确定。先用摘要检索，再比较规范内容以处理哈希碰撞。同一函数跨树可能有不同规范内容；不能以 hash 不同断言函数不同。证明／事件引用与数学内容身份分开，共享图不合并独立事件。

### 4.6 常驻 worker 的句柄与恢复边界

统一链路是 `RelationQueries → FactorRankAdapter → ComputeBridge → rust/factor-kernel → atddc`，结果返回原语义所有者。worker 只处理有限数学对象，不读取游戏 debug 或元数据。使用 05 的共同请求／结果 schema；下列内容必须在 Factor Rank 载荷中明确，而不是各调用者自行约定：

| 内容 | 为什么必须有 |
|---|---|
| 协议版本、请求 ID、操作及精确结果类型 | 区分查询、错误、布尔标量、自然数和图句柄；配对批量响应 |
| SnapshotRef、定义／域依赖、编码／树身份 | 防止旧定义、非法码或不同树的对象被错误组合 |
| worker 会话身份、槽位与 generation | 槽位复用或进程重启后，旧句柄必须失效，不能误指另一个函数 |
| 返回状态与适用域 | 成功、输入不合法、语义不支持、计算失败、未完成分别处理；失败不返回 false |
| 精确有理数与规范摘要 | 分子／分母以字符串编码，分母正且已约分；摘要不能替代完整规范身份验证 |
| 依赖、字节量、时间与系数位长 | 测量实际编译、传输、规范化、查询、持久化及维护总成本 |

新增 worker 操作固定为 `capabilities`、`compile_bool`、`apply_bool`、`condition_bool`、`project_bool`、`count_models`、`equal_bool`、`entails_bool`、`describe`、`export_canonical`、`import_canonical`、`acquire`、`release`。这些名称属于项目适配协议；上游仅提供 4.2 的函数。没有声明支持的操作在编译时拒绝，不悄悄改用另一种数值语义。

句柄只在该会话有效；可跨请求引用但不会被序列化为持久知识 ID。按05为每次借用分配lease_id；同一lease的acquire/release幂等、不同lease独立计数，已释放lease的计算请求拒绝，对象在无使用者后才回收；重启使旧会话全部句柄失效。恢复时用原始表达和已锁定编码重编译，或验证后加载规范对象；不因恢复失败把未知结论当真。上游 interchange 只有单向诊断序列化，没有通用反序列化，因此规范导入／导出、常量和标量格式由本项目实现并独立做往返测试。作者 `Vtree` 也未提供任意树形反序列化构造器；本版导出同时保存初始 `balanced_order/right_linear_order` 和经验证的旋转／删变量构造记录，导入通过这些公开方法重建树，再核对显式树形和叶标签。旋转位置以当前节点的变量集合定位，不保存进程内节点编号。图数据通过公开 `Atdd/NodeData` 和矩阵构造函数重建，必须重新进行结构／布尔／规范检查。不能把诊断 JSON 当成已有通用 loader，也不为加载而调用真值表。

每个 worker 常驻，批量操作一次传输；不得逐像素启动进程。JSON 消息只传所需表达、引用与结果；大图仅在持久化或检查时导出，不能每次查询复制整图。通用 codec 可以与既有 Rust 桥共享基础机制，但 Factor Rank 与程序学习的业务语义和句柄池必须分开。

## 5. 精确的三类持续压缩（M1）及索引协同

### 5.1 原始数据和关系共享

- 相同帧内容通过规范字节 hash-consing 共享，事件、时序与独立样本身份仍不同；差分保存旧新颜色可逆。所有公开证据按实际原始格式/映射可回读，压缩率含索引和引用。
- 相同成员集合、属性集合和关系根共享内容；基于可验证的类型/变量域/映射组织因子化连接。例如 B(p,c) = U(p,r)×V(r,c) 布尔投影；存成员及颜色因子，不要求 materialize 像素两两同色矩阵。
- 精确矩形因子分解：对已知关系矩阵 R，选择行集合 X、列集合 Y，检验 X×Y⊆R；用闭包提取 maximal rectangle（按包含关系不能继续扩大的极大矩形），逐个加入因子并记录未覆盖正例作为精确 residual；验证 OR(矩形、残差)=R。对于已知真、未知、假混合的域，压缩仅覆盖已知真，不补未知；候选外推另存假设。布尔矩阵分解最优化困难，不声称最优。

### 5.2 因子化关系如何直接服务索引

成员 posting 使用共享集合 ID，合取复用交集；因子 R(X,Y)=∨_k U(X,k)∧V(k,Y) 的索引访问先查 k、再访问 V、输出时按逻辑语义去重。不同矩形重叠时 OR 证据不能变成见证计数。对查询输出完整但见证未全部枚举的情况，区分结果域完整与证明完整。不得为了索引重新全量展开因子表。

### 5.3 持续精确压缩调度

每次新事实/关系/新定义或重复查询统计出现后，依赖索引产生受影响候选：同内容块、相同子表达式、共享关系因子或可优化变量树。对候选先精确语义证明，再计入构造+持久化+索引+维护+查询的实际净成本。比较同工作负载的真实字节/访问/耗时；模型越小不保证运行越快。对当前已定计划下一版的优化先独立验证，失败则说明该数学表示对此查询不适用，不把失败结果强制装进生产。压缩后保留能够恢复语义/证明的定义引用；反例若改变模型，重建受影响部分，而非在旧电路上沿用已经失效的等价。

本版真正需要自行实现的是有限域编码、关系到上游查询的降低、因子化证明查询、六维索引的语义访问、版本依赖事务、跨进程句柄与恢复；这些接口直接连接作者库与现有生产消费者。不会自行重写 Galley 的通用优化／稀疏代码生成、作者 ATDD 的精确线性代数／最小化／规范化，也不额外开发平行数据库。矩形压缩先沿用 07 的概念闭包结果形成经过精确包含验证的因子，避免 06 与 07 各实现一套候选发现。

| 邻接与边界 | 区域不能与自身形成“区域间邻接”；共享边数、外缘和不同邻区数各有样例 | 网格逐边扫描，不复用生产接触图；方向及0基坐标单独核对 |
| 关系连接与投影 | 两个不同中间 y 支持同一 (x,z)：布尔投影只产生一条；见证两条，独立事件数按事件 ID 去重 | Python `itertools` 穷举原始类型化小域；输出关系、证明绑定、完成状态分别比较 |
| Bool 与自然数 | 取 `f(x,y)=x∨y`，消去 x 的布尔结果恒真，而自然数求和在 y=true 时为2；后续 NOT 不能对2计算 | 独立真值表明确区分 `project_bool` 与 `aggregate_natural`；匹配及计数消费者读取正确结果类型 |
| 未知、冲突与否定 | 缺行、显式负例、正负冲突、不完整域、合法码域外各一种 | 四状态及域证书逐项断言；不能仅比较最后 true/false |
| 六维完整召回 | 空集合子／超集、范围边界、非合取条件、多角色绑定、多对多对象对应、相同效果不同程序、不同时间顺序 | 每一维及跨维联合查询与独立完整扫描一致；不以相似度最高的前几个代替合法域 |
| 插入、删除与修订 | 两条 OR 证明删一条仍保留；删最后一条失效；定义换版本、蕴含边删除、SCC 循环支持 | 从头重算的逻辑结果与增量结果一致；受影响消费者不能读取旧结论 |
| 缓存和并发边界 | 相同形状不同内容、相同内容不同证据、域版本改变、并发提交编译请求 | 执行代码可复用而语义结果不可错复用；没有上游全局命名竞争或跨作用域污染 |

### 6.3 Factor Rank 适配必须通过的边界

- **编码**：非 2 的幂次列域、m=0/m=1、不同帧 H/W、非法坐标、颜色边界、不同叶序、消元后不连续 bit-id；完整 64×64×16 帧查询的 65,536 组输入逐点一致。
- **构造和运算**：重复文字、相反文字、零函数、恒真、单变量、零变量；AND／OR／域内 NOT／条件化／布尔 EXISTS／蕴含。零函数必须在最小化前分派，最后一位必须产生标量而非 panic。
- **规范化**：重复构造与代数等价表达在同树上规范内容一致；规范化幂等；非布尔权重0.5或2在 Boolean API 被拒绝；内部负有理系数可以存在但函数仍须0/1。
- **计数**：布尔计数的分母必须为1；超过固定整数位宽时仍准确；重叠OR不重复计数。空输出列、空合法域和零函数分别覆盖。
- **树和函数身份**：局部旋转后原始逻辑列赋值求值相同；固定树 canonical key 可重复；不同树 hash 不能作为不等证明。生产调用链没有 `func/bond_vectors/vtree_change` 的全真值表展开。
- **进程边界**：跨 worker 句柄、释放后复用、generation 不匹配、进程重启、批量响应乱序、请求重复、错误数值格式、损坏规范内容均有明确错误；错误不会被变成 false。
- **恢复与证据**：导出→验证导入→求值及规范身份一致；原表达重新编译结果一致；同一个数学函数的两个事件证据可以独立撤回。
- **独立性**：小域裁判直接解释关系和原始公开数据，不通过生产适配器再问生产后端。作者 Rust↔Python 差分测试与项目业务裁判分开记录，前者不替代后者。
