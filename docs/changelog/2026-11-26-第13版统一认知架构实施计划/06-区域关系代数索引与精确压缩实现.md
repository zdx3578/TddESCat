# 06｜底层计算的具体实现：区域、类型化关系、六维索引、Factor Rank 与持续精确压缩

实施锚点见 04；接口及证据规则见 05。主责文件是 `Grounding.jl`、`RelationQueries.jl`、`RelationSemantics.jl`、`AssociationIndex.jl`，扩展 `OnlineKnowledge` 接入真实生产；新的纯数学适配可以独立成文件，但不能形成第二个区域库或知识库。以下是目标实现，不是现状声明。

## 1. 同色四连通：确定性区域先验如何成为后续计算入口

### 1.1 精确存储和区域生成

直接复用 `Grounding.color_components`（4–30行）。输入为真实 `Matrix{UInt8}`，检查实际 H,W 及颜色域；索引按 y,x 扫描，像素坐标使用外部0起始。基础分区覆盖全部颜色，包括大背景、UI、边缘和单像素。分割仅代表空间事实，不推断玩家、道具或背景的无作用性。对一个响应的每个帧调用同一接口，缓存键为 FrameRef 和颜色事实内容身份，若帧内容相同可以共享存储但不能合并时间证据。

具体物理表示：原帧维持已有紧凑颜色记录；一次计算 `owner[y,x]`（区域局部编号）及每区域有序成员。编号使用 `UInt16` 可覆盖至4096，0留给未赋值；如果已有 `Int` 类型先保持语义，切换窄类型需测分配与边界。一个区域使用 `(row, UInt64 bits)` 的非空行稀疏列表或全帧颜色位平面中的共享切片，不为4096个单像素每个分配64行稠密块。形状与颜色由成员及原帧回读生成，几何平移归一化结果只能作为候选签名。对边界、包含、相邻、对角接触和面积等按实际查询生成，不重复复制坐标事实。

目标函数 `region_view(frame_ref, snapshot) -> RegionView`：返回区域身份、颜色、精确成员访问、owner 映射与来源，提供 `members(r)`、`pixel_region(p)`、`color(r)`、`render(view)`。独立 Python 洪泛裁判逐像素重建。区域相邻关系只扫描右/下的网格边，按无序区域对累加共享边数；四连通分量之间同色不可能边接触；八连通粗化在同色对角接触图求闭包。边界采用有效域内边及外缘分开计数，不能把越界当普通颜色0。

```text
label_frame(frame):
    owner = zero(H,W); groups = []
    for y,x in deterministic grid order:
        if owner[y,x] != 0: continue
        r = create_group(frame[y,x]); mark_and_push(x,y,r)
        while stack nonempty:
            p = pop(); groups[r].members.add(p)
            for q in four_neighbors(p) inside frame:
                if owner[q]==0 and frame[q]==frame[p]: mark_and_push(q,r)
    adjacency = count shared region edges by right/down scan
    diagonal = same-color diagonal contacts between distinct regions
    publish exact region view and its proof of reconstruction
```

复杂度 O(HW) 网格访问、O(HW) 成员与 owner；稀疏相邻数不超过实际网格边数，不构造4096²矩阵。区域数最坏为4096；不得凭理论宣称所有游戏显著压缩。实际 profile 应显示分割只算一次并被所有生产消费者复用（`public_components`、`support_features`、LocalEffects 等当前重复取区域的入口统一转为同一视图）。

### 1.2 精确差分与增量维护

对同尺寸前后帧：

`delta = {(p,c0,c1) | F0[p]=c0, F1[p]=c1, c0!=c1}`；完整不变部分由有效位置域与变化掩码之差定义。`apply_delta(F0,delta)` 检查旧值一致后逐项写入新值，重建 F1；`reverse_delta` 是数据回读，不是游戏 ACTION7。对于不同尺寸返回不同空间域和公共可观察变化；不能裁切后假装原始帧一致。

帧序列 `[F_before, F_response1, ... F_responsek]` 建立相邻差分及首尾差分，统一同一个事件 ID。`EventDelta` 返回所有变化位置、各受影响基础区域、公开状态变化和中间帧顺序。将 delta 用于候选定位，不据此认定变化区域即动作直接目标。所有未变化区域/位置仍可读取，用于验证不变关系和负例。

区域分区是每帧完整事实，优先验证现有 O(N) 重算及缓存；不为了“增量”强行实现动态连通。若实测瓶颈在分割：改变像素的旧区域可能断裂，新色相邻区域可能合并。将旧区域全体、改变点和相邻新色区域加入待重标范围，迭代扩展直至边界无同色连通穿出；再重标局部，更新接触边，复核未受影响范围。不能只重算改变点的局部邻域（桥像素删除可能分裂远处）。若不能证明边界闭合，使用同一算法对完整精确域求解，而非退回旧版认知策略。与全域分割比较每个输入的成员集合，忽略局部 ID 重编号。

### 1.3 区域→属性、结构关系的代数定义

成员 U(p,r)、颜色 V(r,c) 为确定关系；B(p,c)=∃r[U(p,r)∧V(r,c)]。邻接 A(r,s)=∃p,q[U(p,r)∧J(p,q)∧U(q,s)]。不要把 U 的有理数秩（等于非空区域数）称为必然低秩。所有关系有列变量及类型，J 是数学定义而不是游戏物理碰撞规则。

| 关系 | 目标执行与返回 |
|---|---|
| same_color/neighbor | 位平面或成员查找，布尔值；同色、相邻与功能联系严格分离 |
| region_members | 稀疏行位集迭代；支持集合并、交、差、包含；准确位置回读 |
| area, edge_count | 自然数聚合；相邻共享边计数不等于不同区域数 |
| shape_signature | 相对坐标集合及类型/颜色映射；原定义不丢失，签名只在指定变换等价下有效 |
| correspondence | 07 的关系候选/见证；不将最高相似度当成已证实同一对象 |
| region_union/refine | 产生对象候选支持的集合表达，基础分区保持原始；允许重叠、非连续、区域内任意精化（按证据产生与可续搜索） |

## 2. 关系计算核心的精确算法

### 2.1 实际接入

沿用 `RelationQueries.exact_relation_join`、`apply_relation_operator`、`evaluate_relation`，扩展通用表达算子；`RelationSemantics.compose_relations` 改为同一连接/投影执行与 AND/OR 见证；不重复实现第二个 Join。`RelationTable` 作为逻辑接口，可用行访问或因子化句柄，不能要求所有消费者调用 `.rows` 展开巨大关系。保留 `Scope`、`completion_ref`、`event_reads` 检查；所有连接必须明确变量匹配、列相等/不等及输出变量。时间跨帧连接先通过真实事件 `before_ref/after_ref` 及合法变换显式建立，不直接取消现有 scope 校验。跨解释域仅经验证的映射合并。

基本算法：

```text
compile_query(expr, snapshot):
    type_check(expr, variable_domain, semiring, scope)
    normalize only proven identities, preserve zero/unknown/provenance semantics
    extract factors and requested output variables
    choose order using domain sizes, posting cardinality, factor scope,
        actual reuse / statistics and intermediate size; preserve aggregation order
    return typed plan with dependencies and access handles

execute_join(factors, shared_vars, bound_values):
    obtain legal ranges/postings from each factor for current partial binding
    intersect necessary postings; no speculative negative filters
    enumerate compatible next bindings, lazily restricting remaining factors
    at leaves, verify constraints and combine AND witnesses/weights
    project output and merge alternative witnesses with OR or requested algebra
    return iterator + completeness certificate (not just returned row count)
```

二元等值 Join 用已有较小端 build 的哈希索引；将重复 build 对象提升为版本化 `lookup_by_columns(relation, keycolumns)`，按真实查询多列索引。三元以上共享变量的查询可按 `Functional Aggregate Query`（函数聚合查询）变量消去/多路交集执行：先消除不需要的局部变量，利用 shared key 与 factor scope，不盲目先做巨大笛卡尔积。`InsideOut` 的最坏情况最优连接及复杂度需要满足特定条件；初版实际实现先为安全连接、复用桶、连接重排、聚合下推提供正确接口，不把普通启发式宣称已经实现全部理论算法。可用 Galley 的稀疏查询优化作为对照；官方 [Galley.jl](https://github.com/finch-tensor/Galley.jl) 明示开发并入 Finch，正式后端版本锁定后才接入。初版在现有 Julia 关系核心实现，无须把概率统计或每个小关系桥接到额外系统。

**实际查询计划实例**：某作用需对象 r1 的属性 P、对象 r2 的属性 Q、它们的关系 C(r1,r2)、当前动作许可及目标效果。先绑定当前状态/动作域，然后以最有选择性的已绑定列检索 P,Q/C，连接 r1,r2（检查角色不同/共享的真实约束），调用完整适用条件判定；保留每个输出绑定的证明。若仅查是否存在，使用布尔 OR 消去中间变量；若查不同对象数，先投影布尔关系再计数；若需控制，返回见证绑定。不能使用各自独立的 P/Q 满足当作联合存在证明。

### 2.2 增量连接及证明维护

对版本中已物化的常用查询，保存因子根、反向引用及访问路径。对插入 delta，令 R'=R+ΔR、S'=S+ΔS，则环/多重集上的 join 变动为 ΔR⋅S+R⋅ΔS+ΔR⋅ΔS；布尔语义要去重且保留全部 OR 支持。删除不能在布尔半环中直接减法；应删除相应根证明，若输出仍有其他支持则保留。避免统计投影丢失中间见证。支持按同一事件身份去重、不以同一条证据在多个路径出现当多个样本。

对非单调或域/定义改变，不照搬固定查询 delta 公式；根据反向依赖重编译受影响计划、重新检查该作用域全部历史。固定点递归在删除时精确重算受影响强连通分量，不能循环支持残留。独立从头重算是测试裁判，也可作为正确完整的同语义更新策略；禁止降级到旧规则或减少验证。性能验收须单列更新成本。

## 3. 六维偏序索引：具体数据结构、查询、插入与撤回

### 3.1 共享索引管理

扩展 `AssociationIndex` 的访问结构和共同查询（已存在 `entries/ports/inverse_features`），不再为每种玩法写只认颜色、形状或接触目标的检索。建议一个 `IndexRegistry(snapshot)` 管理所有派生索引，键是 `(relation_definition, domain_epoch, columns, comparison_kind)`。用户要求六个维度均可查：每维必须实现查询语义，但物理索引按实际需求共享，绝不是六份完整知识表。`select_index(query, registry)` 依据实际绑定列和访问统计决定计划；对无物化索引的精确查询仍走同一关系执行，不是旧 solver fallback。弱特征、统计相似和秩只排序，不能硬排除合法候选。所有索引项指向同一 Knowledge/DefinitionRef 与版本。必要筛选若无法保证覆盖，就使用完整域候选，并将提示排序；不能只召回最相似前几个。

### 3.2 具体查询定义和实现

| 维度及操作 | 首选具体访问结构 | 检索/最终验证算法 |
|---|---|---|
| 集合 `contains(A,B)` / supersets / subsets / intersections | 成员→集合 ID 的有序 posting；集合大小；稀疏/压缩位集 | 超集=对查询集合所有成员 posting 求交；空集返回同域全部集合。子集=对查询成员累计候选集合的不同匹配成员数，等于该候选真实基数才入选，另返回空集。最后验证同域精确成员；交集/差集用位运算 |
| 属性 `match_attributes`、共同属性、闭包 | (属性定义,值,scope) 倒排；整数范围有序键 | 正合取通过 posting 交集；区间按合法值域检索重叠再精确判断蕴含；否定仅用明确负例/封闭域；缺失值保持 unknown。共性由实例→属性及属性→实例交替求闭包 |
| 条件 `implies/stronger/weaker` | 规范 AST 指纹、正文字项索引、已验证蕴含边及逆边 | 正合取可用集合反包含提出充分候选；一般条件以 D∧C1∧¬C2 不可满足为证，另检 C1 非空；使用现有有限关系检查或 ATDD（完整布尔域）。缺乏证明边不是不蕴含。按需缓存经证明边，域变化失效 |
| 对象 `match/decompose/compose` | 成员倒排、形状归一化签名、空间范围（行列 interval）和对应关系索引 | 对象候选以精确可回读支持与类型化映射验证；多角色 Join 绑定；签名不等只能在查询显式要求精确形状时排除，否则作为排序。跨帧索引不能靠局部 region ID；保留部分、重叠及多对多匹配 |
| 机制 `find_producers/bind/reuse` | `(动作或动作类型,读取角色,条件谓词,输出关系及极性)` 多列 posting；输入/输出及作用域索引 | 由目标效果向后找原子作用及程序定义，再核对参数、所有条件、完整联合绑定。没有效果索引条目代表未知识别，不是不可达。实际因果等价需保持相关后继/控制区分，而非仅相同作用类别 |
| 时间 `prefix/range/history_test/sequence_match` | 事件顺序索引、序列 Trie、程序子式规范键、历史-测试二部关系 | 精确前缀、窗口与后缀按事件 ID/时间角色查询；历史匹配须带状态条件与动作参数；未来测试响应一致只是候选等价。跨期组合映射需检查输入输出接口和证据截止 |

Set Trie（集合字典树）是集合子/超集查询备选对照，先实现倒排和位集，测实际数据后决定是否需要追加；参考 [Set-Trie](https://pmc.ncbi.nlm.nih.gov/articles/PMC7875400/)。多列索引避免所有列排列的复制：根据生产查询绑定模式选取共享前缀访问，参考 [Automatic Index Selection for Large-Scale Datalog Computation](https://souffle-lang.github.io/vldb19.html)。选择性统计只能影响执行计划，不改变合法答案集。对不同维度的查询结果做 AND 时必须共享变量绑定/定义版本，而不是独立交集错误合并对象角色。

每个索引插入或撤回时维护：(1) 元组对应的独立证明引用；(2) 实际有效逻辑条目；(3) 对应 posting、基数和版本。当一个 OR 证明仍有效，条目不应撤回。蕴含 DAG 按需存边/常用可达关系；删除边后清除依赖该边的路径证书，重新查询真实关系；不能直接保留旧闭包。相等取商只对完整、明确语义证明成立的条件执行；经验等价保留多个解释。`compare_order` 对对象结构映射及机制映射不强制所有关系形成偏序；定义反身、传递、等价取商成立时才称偏序，任意对应/因果边单独建关系。跨维依赖通过类型化 Join，不构造全域笛卡尔积偏序表。

### 3.3 必须实现的查询合同与复杂度记录

```text
retrieve(spec, snapshot):
    q = normalize_and_typecheck(spec)
    scope = resolve_scope(q, snapshot)
    necessary = compile_proven_necessary_filters(q)
    seeds = all_applicable_domain(scope)  # lazy
    for f in selectivity_order(necessary):
        seeds = exact_intersection(seeds, access(f, snapshot))
    for binding in multiway_bind(seeds,q.variables,q.relations):
        verdict = evaluate_required_semantics(binding,q,scope)
        if verdict == proven: emit binding, witness
        elif verdict == unknown: retain as unresolved binding or symbolic unknown range
        else: retain refutation proof if useful for learning
    return query_result_and_completion_certificate
```

任何不可证明必要的筛选不得参与 seeds 硬交集。对所有合法结果的查询可以惰性输出；实际输出本身巨大时只声明尚未枚举的剩余域，返回游标，不截断宣布完成。与独立穷举小域比较完整答案、未知范围、证明，记录 posting访问量、交集次数、候选量、精确验证次数、构建/更新耗时和峰值内存；O(1) 哈希命中不等于 O(1) 包含/机制推理。对预期稀疏结果，禁止每次物化所有 pairwise 关系。

## 4. Factor Rank 精确代数后端：真实原型如何落地

### 4.1 上游已经核查的能力

用户上传 `factor-rank-supplement.zip` 内 `LICENSE`：code/、lean/、toy/、scripts/ 为 MIT，其他材料 CC BY 4.0；可依法复用代码并保留许可证和作者署名。`code/Cargo.toml` 为 `atddc 0.1.0`、Rust edition 2024、`num-bigint`、`num-rational` 等依赖。此次读取实际函数声明和 `vtree_change` 实现，未运行编译器。正式引入将补充包及其校验摘要、许可和上游版本固定到 `config/sources.lock.toml` 或现行依赖锁，复用项目 `third_party/` 风格而非新 `_vendor`；不把完整作者实验包放入运行结果或本次交付。理论来源 [Factor Rank, arXiv 2611.10842](https://arxiv.org/abs/2611.10842)。

`atddc` 的完整 CNF 编译入口 `backend.rs::compile<AtddBackend>` 是 CNF 编译器，不自动理解项目任意关系表达。必须实现下述小而明确的类型化布尔编译适配，不靠把所有关系变成巨大真值表。

### 4.2 精确函数编码和构造（M1 必有真实工作负载）

编译仅用于定义完整的有限函数：已知帧颜色查询、已验证关系条件、有限模型逻辑谓词。未知的真实转换不能编码成已知真值表。对于不完整关系，只能分别编译已知真/已知假或下/上界函数（包含合法域证书），缺失域继续未知。整数取值编码要有合法码约束（非2幂域多余码不得被计数/存在量化）。同一变量的编码与位顺序固定，遵循原型 MSB-first、vtree叶序规则，Julia 明确列域到 Rust bit-id 映射，所有输入输出映射可回读。

首批实际任务：
1. 对已知帧 B(x,y,c)，x/y 六位、c四位，定义有效范围掩码 D；在 64×64、16色域完整穷举 65,536 组输入。不同 H/W 的非法坐标返回域外而非游戏颜色。构造对每个区域颜色及成员的符号关系 OR，再使用共享表达；不把整帧的4096个像素随机变量误认为只有16位。精确原始帧仍是权威。
2. 对区域成员、属性包含、目标条件及动作合法坐标类，以表达式 DAG 的布尔 AND/OR/NOT/EXISTS 编译；先用有限值域/位平面约束共享结构，叶为 `term` 或常量。稀疏关系转成每个合法元组的 conjunction cube，可通过成员/颜色/坐标公共前缀和 TDD 共享减少重复；多项析取使用平衡归并，合并后必要时 `minimize + canonicalize`。禁止先枚举巨大补集或全赋值。零函数显式表示并测试。
3. 条件蕴含 `D∧C1∧¬C2` 模型计数为0；反例查询在同一有效域。若存在量化多个变量，逐一消去/重新对齐变量树，检查不再包含消去变量；自然数路径计数与布尔存在量化不能混用。对于作用条件未知，返回候选和未知，不宣称完整蕴含。

变量树初始比较：按 x/y/c 的平衡分区、坐标位交错、依赖/列共用频率。所有比较保持相同输入函数与域；同一固定树的 canonical key 才能直接比较。跨树的语义等价通过同一树重新按紧凑原表达编译、或证明转换后等价，不以不同 hash 判不等。局部旋转使用已核查原型；若需要论文定理26的输出多项式任意树变换，按其 Gram 内积独立性测试逐目标树节点构建，不能调用 `vtree_change` 真值表版本。M1 先以固定树与局部旋转完成实测，任意树变换不是通过门的前置，但若工程选择使用它则必须实现紧凑算法并验证。论文保证不代表原型已实现。系数位长可能增长，实测实际算术和内存。

### 4.3 Rust-Julia 调用协议与执行成本

在现有 Rust workspace 增加纯计算 `factor_kernel` crate/接口（名字拟定；不要把它塞入 E-Stitch 的学习语义）。先在同一常驻计算进程按批次实现：`compile(request)`、`apply(op, handles)`、`condition(handle, binding)`、`project(handle, variables)`、`count(handle, domain)`、`equal/entails(handle1,handle2,domain)`、`describe(handle)`、`release(handle)`。请求包括协议、输入表达 DAG、共享函数 ID、编码/变量树、合法域、SnapshotRef；输出有精确结果/句柄、认证语义、系数和结构摘要、耗时/内存、完整状态及依赖。批量请求跨语言一次，不每像素开启进程。序列化精确有理数、固定变量树及 canonical pivots，不以浮点近似替代。对已确认语义的计算结果，Julia 回读并校验接口、域和版本；小域用独立 Python 裁判，大域对同树等价与证明、代数恒等式及真实查询抽验分开标注。未获得完整编译结果不允许作为硬约束。

生产不做“ATDD 失败就恢复旧 agent”。**同一查询语义允许事前选择执行计划**：简单空间查询直接用位集合；关系连接采用稀疏/因子计划；稳定、重复且可编译的逻辑查询采用 ATDD。计划必须在计算前按输入语义和实测成本选定；失败/中断记录未完成、可续任务或明确不可处理，不降低责任或改为未经验证的近似。选择哪些查询使用代数后端基于实际 workload，不是强制每一步编译。

## 5. 精确的三类持续压缩（M1）及索引协同

### 5.1 原始数据和关系共享

- 相同帧内容通过规范字节 hash-consing 共享，事件、时序与独立样本身份仍不同；差分保存旧新颜色可逆。所有公开证据按实际原始格式/映射可回读，压缩率含索引和引用。
- 相同成员集合、属性集合和关系根共享内容；基于可验证的类型/变量域/映射组织因子化连接。例如 B(p,c) = U(p,r)×V(r,c) 布尔投影；存成员及颜色因子，不要求 materialize 像素两两同色矩阵。
- 精确矩形因子分解：对已知关系矩阵 R，选择行集合 X、列集合 Y，检验 X×Y⊆R；用闭包提取 maximal rectangle（最大矩形），逐个加入因子并记录未覆盖正例作为精确 residual；验证 OR(矩形、残差)=R。对于已知真、未知、假混合的域，压缩仅覆盖已知真，不补未知；候选外推另存假设。布尔矩阵分解最优化困难，不声称最优。

### 5.2 因子化关系如何直接服务索引

成员 posting 使用共享集合 ID，合取复用交集；因子 R(X,Y)=∨_k U(X,k)∧V(k,Y) 的索引访问先查 k、再访问 V、输出时按逻辑语义去重。不同矩形重叠时 OR 证据不能变成见证计数。对查询输出完整但见证未全部枚举的情况，区分结果域完整与证明完整。不得为了索引重新全量展开因子表。

### 5.3 持续精确压缩调度

每次新事实/关系/新定义或重复查询统计出现后，依赖索引产生受影响候选：同内容块、相同子表达式、共享关系因子或可优化变量树。对候选先精确语义证明，再计入构造+持久化+索引+维护+查询的实际净成本。比较同工作负载的真实字节/访问/耗时；模型越小不保证运行越快。对当前已定计划下一版的优化先独立验证，失败则说明该数学表示对此查询不适用，不把失败结果强制装进生产。压缩后保留能够恢复语义/证明的定义引用；反例若改变模型，重建受影响部分，而非在旧电路上沿用已经失效的等价。

## 6. M1 可直接编码的测试组（接入09）

- 区域：全同色、棋盘格、洞、对角、边缘、大区域、多个颜色、桥像素分裂、不同帧尺寸、全部动画帧；重建和区域图独立裁判零差异；大区域不因96像素等阈值消失。
- 代数：共享变量、多见证、零/空域、重叠矩形、整数/布尔计数差异、否定、未知及交叉 scope。所有新算子类型、合法域和截止检查；小域与直接枚举相同。
- 六维索引：各维上下位、插入/删除、哈希冲突、条件非合取、跨对象映射、相同效果不同程序、时间顺序不同；联合检索完整结果与独立扫描相同。反例触发依赖删除后恢复其他支持和已排除候选。
- Factor Rank：全部65,536个查询输入、固定树规范重复构造、零/常量、合取/析取/否定/条件化/存在消去/蕴含、非法编码、局部旋转、精确有理数；核对上游 golden 与 toy tests（不假定通过）。记录系数位长、编译及运行开销；验证大域没有 `func` 全展开路径。
- 生产：从 `scripts/run.jl` 的真实公开路径跟踪到区域/索引/统一 query，确认 JointMechanisms/GoalRegression/Controller 等调用同一核心，不只是单元测试运行了新库。每次更新读一致快照；真实日志有索引命中与所用执行计划、编译/查询/维护总耗时。M1 不能把上述精确性合格直接宣布 H2 性能合格。
