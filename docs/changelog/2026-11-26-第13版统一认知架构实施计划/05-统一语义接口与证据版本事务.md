# 05｜统一语义接口、证据事务与三语言契约

本文是 04 总入口的实施规格。除明确标为当前实现的函数外，以下名称为拟定的目标接口；可以在原有类型/函数上实现，不要求另建同名类型。以 `TddESCat` 固定基线 `0d53a1c683fbe0ba3c9d8e41ac66cb6fe23dce81` 的现有代码为接入对象。M1.1 必须先完成本合同，M1/M2 后续调用都遵守同一语义。

## 1. 不同身份及唯一所有者

不能让 frame、区域、对象和概念使用同一种 ID。不同对象共享计算定义也不等于对象相同。Julia 是权威知识语义所有者；Rust 纯计算或发现函数，Python 分为既有公开试验/独立裁判环境与新增的纯计算 worker；后者承接 CirKit/cvc5，不能取得游戏内部状态或发布知识。当前 `PublicAPI.jl`、`Evidence.jl`、`RelationQueries.jl`、`ConceptIdentity.jl`、`Library.jl` 已有对应基础，必须复用。

| 引用 | 含义与生成 | 能否修改、跨关复用 |
|---|---|---|
| EventRef | `Recorder` 已确认事件 ID + 公开请求/回执摘要；一次动作关联全部返回帧 | 不可修改；跨关可读作历史证据，不能假设同一对象 |
| FrameRef | EventRef + 该动作响应内从0开始的帧序号；初始 RESET 也有事件 | 不可修改；相同内容可共享像素存储，但仍保留两个时间身份 |
| RegionRef | FrameRef + 极大同色四连通成员定义规范键；局部数组编号只用于本次计算 | 每个帧唯一，绝非跨帧对象 ID |
| ObjectHypothesisRef | 定义、解释域、版本与成员/角色见证；跨帧角色存在单独绑定关系 | 可撤回或精化，不篡改 RegionRef 或历史像素 |
| DefinitionRef | 类型化规范表达式/接口/数学语义 + 内容摘要；命中后严格结构比较 | 相同定义可共享；语义变化创建新定义版本 |
| ScopeRef | 事件域、解释/绑定版本、变量域、已知范围、截止点 | 所有语义判断、证明、否定、缓存均限定 scope |
| SnapshotRef | 单调发布序号、内容摘要、前一版本、已接纳证据截止 | 只发布一次；历史快照可回放，禁止静默替换 |

不同句法下的规范表示仅可证明在指定定义域内的函数等价。相同 SHA-256（安全散列算法256位）不是最终的语义证书；重复节点用 hash-consing（结构哈希共享）+规范字节比较。确定性排序：变量按 stable sort ID 和位置；关系元组按类型编码字节；禁止依赖字典迭代次序或 Julia 进程内 `hash`。保留旧哈希规范所声明的协议版本，不在同一版本悄悄改变序列化。

## 2. 公共 API、事件与数据入口

### 2.1 已有实现与使用方式

`PublicAPI.jl:1–40` 只允许 `/api/games`、`/api/scorecard/open`、`/api/scorecard/close`、`/api/cmd/RESET`、`/api/cmd/ACTION[1-7]`；`validate_response` 在101行之后验证会话、状态、进度、动作、坐标、可用动作、帧列表。`Evidence.jl:148–195` 的 `transact!` 先持久化 sent、后接回执；`submit_action!` 验证当前动作可用性。沿用已有一次一请求、禁止隐式 POST 重试、隔离未知回执及离线恢复责任。不得绕过 Recorder 直接调用 HTTP 或游戏 SDK 内部对象。

公共 ARC 接口文档：[Game Schema](https://github.com/arcprize/docs/blob/main/game-schema.mdx)；官方 agent release [0.9.3 字段变更](https://github.com/arcprize/ARC-AGI-3-Agents/releases)。只读当前正式公共返回。ACTION6 使用现有 `screen_click` 或经公开数据验证的显示映射；记录原坐标域、目标显示坐标、依据，不猜测逻辑格坐标和比例。公开合法的参数域按实际协议，不以区域代表点代替全域。所有 ACTION1–7 以 `available_actions` 为准；编号不注入方向或游戏功能。ACTION7 与 RESET 分别作为实际动作及生命周期关系，不宣称为前向算子的代数逆。

### 2.2 统一公开事件视图（扩展现有 Recorder/证据索引，不新增原始证据权威）

`public_event_view(recorder, confirmed_ref) -> PublicEventView`。目标字段及具体含义：

| 字段 | 具体用途 |
|---|---|
| `ref, before_ref, session_ref` | 指向已确认事件、其已确认前驱及实际会话；RESET/新关卡边界由公开回执确定 |
| `request_action, acknowledged_action` | 请求与回执一致的动作及参数；失败/结果未知不得伪装为成功动作 |
| `frames` | 有序 FrameRef 与完整网格读取句柄；所有帧可精确取回，非只保留 last |
| `available_before, available_after` | 动作前后公开可用性；只用当前可用动作派发 |
| `public_before, public_after` | 允许公开的状态、levels_completed、win_levels 等实际返回项；原始字段来源明确；不擅自补默认进度 |
| `boundary` | 普通动作、RESET、关卡推进、终止、公开状态变化、无法确认等由公开证据分类；不能根据像素猜边界 |
| `evidence_cutoff` | 本次已确认事件的序号；预测仅能用截止点以内证据；动作前预测的截止点不得包含本动作结果 |

`load_frame(ref)` 返回 `Matrix{UInt8}`，行 y 列 x；对外坐标0起始、Julia 下标1起始。域为实际 H×W，最大64×64；颜色0..15，不假设每个游戏固定64×64。若响应尺寸变化：原样存证，产生不同域/解释，不裁掉新区域，不直接将不同尺寸做像素 diff；可产生公共坐标子域对应候选。公开回执中的新增字段先由允许列表/真实协议核对，不把任意 metadata 透传给 learner。

事件收集与学习事务分开：收到回执首先确认和持久化；学习失败或进程退出也不能删除事件。动作日志记录请求、已使用快照、冻结预测、候选域证明、选择依据；确认后追加实际结果与审查，不覆盖事前预测。禁止将同一次动作多个动画帧当作多条独立干预。未知回执不推进知识中的已确认状态，也不得偷偷重发。

## 3. 共同关系语义：既有 RelationTable 的升级而非新库

### 3.1 类型、域及查询结果合同

每个 `RelationScope` 继续限定 episode/frame/interpretation/view/phase；补入实际变量域与 SnapshotRef（以及 cutoff）。列必须有独立 VariableRef；不同列同类型不意味着同一变量，Join 必须显式列映射。对象角色与坐标类型分开。`RelationTable` 已有 columns/rows/枚举完整性/见证；升级为可返回因子化访问句柄的同一逻辑关系。不能把稀疏 `rows` 的缺项自动当假。

`RelationDomain(columns, domains, constraints, epoch)`：
- columns：有序变量、类型、时间角色；例如区域索引不是颜色，也不是跨帧对象标识。
- domains：每个变量的合法有限取值或惰性可枚举定义，如本帧全部坐标、已确认对象候选或给定动作合法参数域；有限定义不意味着所有事实已知。
- constraints：域内已证明的联合约束，允许表达变量相关性；不能把独立笛卡尔积当作全部合法绑定。
- epoch：域及约束版本；新增对象、变量或条件改变即创建新域版本。

`RelationResult` 逻辑上至少回答：
1. 合法域是什么、查询何时开始、读取哪个快照；
2. 哪些绑定有正、负见证（相同上下文的真实冲突单独保留）；
3. 哪些范围已经完整枚举、证据搜索是否完整，哪些仍未知；
4. 结果是完整、未完成且可恢复、无效/失败，还是域/作用范围不足；
5. 每条结果如何回读事实及证明、缓存键和依赖。

建议采用 `support/refute` 两个独立标志来记录经验命题的四态（00未知、10支持、01反驳、11冲突）；不是将任何真实二值像素变成四值布尔。支持只表示存在经审查的适用域内见证；统计事件预测的支持/反驳不是数学真值。精确封闭关系的真/假可由其完整域证书严格决定。原 `proven/disproven/unknown_truth` 在公式查询中的使用继续保留，避免把不同认识状态混成一个 enum；外部消费必须区别经验候选与精确证明。对随机机制同一条件的不同结果可同时支持一个分布，不能将其自动视为逻辑矛盾；只有声明确定性、同语义状态、同适用域下冲突才触发确定模型修订。

### 3.2 表达和计算的最小 API（建议 Julia 泛型函数，可将现有函数签名统一到此）

| 接口 | 入参 | 输出、错误与调用者 |
|---|---|---|
| `observe_relation!(evaluation, name, columns, rows; domain, witnesses)` | 快照内已知关系、类型和真实证据 | 创建/更新同一评价上下文的关系；域不一致/未来证据报错；Grounding、机制事件适配 |
| `query(snapshot, expression, requested_vars; bindings, algebra, mode)` | 类型化关系表达式、共享变量、明确语义 | 返回 RelationResult（可迭代），不会隐式 materialize；无绑定或作用域不充分返回未知；所有消费者 |
| `bind(snapshot, role_spec, context; constraints)` | 角色约束、当前帧与历史 | 全部符合条件的联合绑定或未完成游标；证据不充分不选唯一；机制和控制 |
| `compare_order(snapshot, dim, lhs, rhs; scope, mapping)` | 维度、定义/实例和同域或明确映射 | 真/假/未知及见证；不是数值相似度；索引、反统一、搜索剪枝 |
| `find_knowledge(snapshot, QuerySpec)` | 变量域及要求，必要约束与可选排序明确分离 | 精确结果+未知范围+证明+游标；06 的多维检索实现 |
| `compile_exact(snapshot, expr; representation, domain, tree)` | 完整定义的有限函数、显式编码及代数 | 只读派生可计算句柄，语义与证书；输入非完整不编译为确定函数；06 的 ATDD |
| `propose(snapshot, trigger)` | 可追溯发现触发及未解释范围 | 新对象/关系/条件/机制候选与待区分义务；不是写入事实；07、08 |
| `revalidate(snapshot, proposal, affected_events)` | 候选及完整历史影响范围 | 各证明域/经验反例/未知、变化集；未完成标识；发布前检查 |
| `predict(snapshot, contract, binding, action)` | 有效机制契约/角色/当前公开动作 | 允许后继关系或有效概率、声明范围和公共效果；未知不是失败；08 |
| `preimage(snapshot, contract, goal, mode)` | 作用或程序、目标、存在/保证/概率方式 | 条件关系、绑定及证明/未知；08 |
| `publish!(knowledge, proposed_delta, parent_snapshot)` | 同一知识所有者、已验证的定义与变更 | 原子发布新快照或拒绝陈旧父版本；下一决策必读新快照；见第5节 |

注意接口不预先限制存在多少种概念、对象或动作机制。计算语义以表达式 AST（抽象语法树）及类型确定，不为不同游戏预设宏。原有 `ConceptTerm` 的 `Literal/Slot/Parameter/Call`、原语类型与 `infer_term` 等保持；新关系/函数操作注册可计算语义，不允许未实现原语成为正式预测程序。

### 3.3 后端能力合同：查询可表达，不等于每个后端都可执行

能力由 `BackendCapability` 描述，随已安装库的不可变版本注册，由 `ComputeBridge.jl` 管理；名字是拟增接口。必须先检查语义，再选择物理计划，不能捕获异常后换成含义不同的旧算法。

| 必需字段 | 解释及约束 |
|---|---|
| `backend_id, source_pin, build_id` | 实际引擎、源码/发行版、构建身份；例如作者 `atddc` 的归档摘要，不使用“最新版”代替固定来源 |
| `operators` | 当前适配器已实现并验收的操作；上游有函数而尚未接入的操作不能登记为可用 |
| `input_algebras, output_kinds` | 输入是 Boolean、NaturalCount、RationalField、NonnegativeProbability 中哪类，输出是标量、关系、证明、模型或候选；不能通过名字猜测 |
| `domain_requirements` | 有限域、显式变量映射、完整函数、完整后继、共同变量树等前提；未知事实不能被预填成零 |
| `structural_requirements` | 电路分解性、平滑性、确定性、兼容分区、作者 ATDD 的 raw/minimal/canonical 状态等具体前提 |
| `guarantee` | 精确数学运算、浮点模型内推理、统计估计、启发式候选四者分开；不把 tractable（可处理）解释成所有查询都快 |
| `update_support, resume_support` | 能否增量追加、删除、重新编译、保存完整搜索前沿；没有原生删除就明确重建，不能伪造增量能力 |
| `proof_support` | 返回可回检见证、结构证书、模型反例或无证书结果；无证书不冒充外部形式证明 |

能力矩阵的正式初始范围：

| 选择 | 首批可接入能力 | 不自动承诺 |
|---|---|---|
| Galley（含其内部 Finch） | 已声明代数上的正关系连接、投影/归约、物理稀疏执行 | 经验未知、因果、开放世界否定、带来源回撤由本项目语义层负责；不能让优化器擦掉证据 |
| Factor Rank 作者 `atddc` | 首批接入完整有限布尔函数；内部精确有理数TTN算术；非零且满足布尔承诺后最小化/规范化 | 一般RationalField函数及其规范化、任意半环、所有变量树转换多项式、概率归一化、在线因果发现 |
| CirKit 0.3.1 | 已验证结构的非负概率电路、证据查询/边缘化、参数训练 | 任意 MAP（Maximum A Posteriori，最大后验）/熵/KL 查询、自动因果识别、跨变量版本自动改写 |
| cvc5 1.4.2 | 支持理论片段内的 SMT（Satisfiability Modulo Theories，模理论可满足性）与 SyGuS（Syntax-Guided Synthesis，语法引导合成） | `unknown` 不能变 `unsat`；找到一个程序不证明其真实环境效果 |
| E-Stitch + 当前固定 egg 补丁 | 实际 typed corpus 的结构共享与程序抽象 | 循环终止证明、条件语义发现、原生任意时刻完整续搜；08 明确必要补丁 |
| PDDL / SymbolicPlanners | 已验证确定、有限、闭世界动作模型的规划 | 未知后继、概率效果、信念状态的保证规划或全局控制完备 |

`select_plan(expr, requirements, available_capabilities)` 的算法顺序：类型/域检查 → 列出满足全部语义前提的可用物理计划 → 使用实际数据规模/复用次数/运行 profile 排序 → 记录选定计划与理由 → 执行。没有满足项返回 `unsupported` 和缺失能力；未知前提返回待证义务。Julia 原生小集合/位图访问和 Galley 是同一新关系执行器的不同合法算子，并非两个互相兜底的求解器。

### 3.4 执行状态、语义答案和覆盖分别返回

一个统一状态字符串无法表达“程序执行成功，但命题未知”。`ComputeResult` 在逻辑上分三部分；每一项都必须由适配器填充、由消费者检查。

| 部分 | 字段/取值 | 含义 |
|---|---|---|
| 执行 | `execution_status`：`completed / incomplete / unsupported / invalid_input / failed / invalidated` | 依次是本次操作已结束、未完成可描述剩余工作、后端无该能力、输入不合法、运行故障、依赖已失效 |
| 答案 | `result_kind, value, semantic_status` | `result_kind` 指 Boolean/Integer/Rational/Relation/Probability/Candidate/Checkpoint/Handle/Artifact/Capabilities/Acknowledgement；逻辑可为 true/false/unknown/conflict，统计结果则携带模型语义，不能当逻辑真值 |
| 覆盖 | `requested_scope, covered_scope, completeness, remaining_work` | 指本次实际请求和完成的范围、完整性证书与未做部分；返回空列表不说明域已穷尽 |
| 原因 | `reason_code, native_status` | 保留上游真实状态及原因；例如 cvc5 正常返回 unknown：执行 completed，答案 unknown；崩溃则 failed，不能伪装 unknown |
| 追溯 | `request_id, input_digest, snapshot, read_dependencies, evidence_cutoff, backend_pin, artifact_digest` | 将结果绑定到实际输入、语义版本和构建；不是仅日志注释 |
| 数值 | `arithmetic, value_encoding, error_description, normalization_status` | exact rational 或 floating point；`value_encoding`明确probability/log_probability，概率归一化依据、浮点误差与统计不确定性分开 |

结果值不得用 `null` 同时表示空集合、未知、无解与程序崩溃。概率内部可用log-space，但JSON不写IEEE的NaN/Inf：零概率可编码为probability=0，或类型化log-zero标记；条件分母零返回语义unknown及zero_evidence原因，有限分母下分子log=-Inf是合法0，NaN/+Inf是明确数值失败；有限log值取指数下溢不能宣称模型本来零质量，应保留log值或单独标记underflow。对精确求解，`unsat` 只证明已编码片段无解；对真实世界经验命题仍需保持作用域。经验冲突的支持/反驳不能同时作为无条件布尔公理送入solver；先明确一致的模型假设，假设不一致返回unknown与inconsistent_assumptions，不用空真产生剪枝证书。对 cvc5 返回 `sat` 的反例，先按项目类型和当前 scope 解释模型；再验证其是否对应合法绑定，不能直接派发未经公共合法性验证的动作。

Boolean/Integer/Rational分别是布尔、任意精度整数、精确有理数标量；Relation是带域的关系；Probability有模型和数值编码；Candidate是待验证提案；Checkpoint是可校验续算状态；Handle是本worker对象引用；Artifact是持久工件；Capabilities列已验收能力；Acknowledgement只确认控制操作，不产生世界命题的真值。协议支持一种类型不等于所有后端支持该类型的运算。

### 3.5 句柄生命周期：逻辑定义可持久，进程内编号不可持久

`DefinitionRef` 指不可变逻辑定义；`ArtifactRef` 指可校验的模型/电路文件；`HandleRef` 仅指当前 worker 内已加载对象。三者不能互换。

| 句柄项 | 解释 |
|---|---|
| `worker_session, generation, local_id` | worker 启动实例、该实例对象代次、局部编号；重启后旧句柄全部失效，避免编号复用误命中 |
| `definition, domain_version, algebra, structure_version, parameter_version, parameter_digest` | 被计算对象的函数身份、变量域/顺序、代数、结构及参数版本/摘要；结构相同也不能复用旧权重的结果 |
| `owner_snapshot, read_dependencies` | 可消费范围；定义无关更新不强制重建，实际依赖变化必须失效 |
| `state, active_requests` | alive/releasing/released/invalidated 及使用者计数；进行中操作使用不可变版本，不能原地换权重/变量 |
| `artifact_ref` | 可重载的持久工件；只有上游允许保存的内容才声明为可恢复；重载要重新核对构建与内容 |

拟增接口 `compile/load → acquire → batch_query → release`。每次借用分配稳定 `lease_id`，同一lease的重复acquire/release幂等，不同lease分别计数；重试不多减引用。已释放lease的查询拒绝；其他有效lease不受影响。对象进入releasing后不再允许新借用，在执行请求和全部已有lease结束后才回收为released。另一worker不接受该句柄。任务结束释放借用；结构/参数发布生成新句柄，旧快照使用者完成后才回收。进程崩溃从逻辑定义/持久工件重建，不能把缓存路径称为恢复完整搜索前沿。批量结果保留每个子请求身份，部分成功与整体失败不得混淆。

### 3.6 协议字段与目录合同（待实现schema）

新增 `protocol/compute/v1/request.schema.json` 与 `result.schema.json`，严格禁止未知字段、限定类型并覆盖真实库状态。公共封装固定 `protocol_version / request_id / operation / backend_pin / input_digest / config_digest`；语义操作另外携带 `snapshot / read_dependencies / evidence_cutoff`。请求按operation使用严格载荷分支：compile接类型化表达式及域；load接ArtifactRef及摘要；query接HandleRef和有效lease_id及运算参数；acquire/release接对象/租约身份；capabilities查询不要求虚构样本。训练/观测载荷才包含变量编码、`observed_mask`和去重证据清单，不能要求count_models或release填无意义mask。响应按3.4返回并回显实际`read_dependencies`；没有`dependencies`等别名。Handle/Artifact/Capabilities/Acknowledgement是明确结果分支，不能临时塞进未登记字段。`observed_mask=true`只表示该样本值实际观测可用；它不同于经验support/refute四态。CirKit积分mask由适配器按未观测变量取反；冲突样本先分解释/标无效，不能随便填一个值。协议路径限定为冻结的 `job/inputs/` 只读区及 `job/outputs/` 候选写区，分别白名单校验大小/摘要；不允许读取任意环境文件，也不允许改写冻结输入。

精确有理数用规范十进制 `numerator` 与正 `denominator` 字符串，最大公因子约分；零编码为0/1，不经 Float64。本版Factor Rank布尔图消尽所有变量返回Boolean标量，模型计数返回Integer；不能向要求非空变量树的作者函数传零维图。协议定义Rational用于精确系数或其他声明支持的操作，不代表首期Factor Rank支持任意有理数函数规范化。布尔图必须声明并检验全域值在{0,1}，随后才允许 Boolean OR/NOT 与模型计数语义；普通有理数求和不等于存在量化。

## 4. 统一代数、溯源和未知传播

### 4.1 基本操作

| 运算 | 规则及具体语义 |
|---|---|
| `product` | 同身份共享变量对齐再乘积；布尔 AND、计数乘法、精确有理数乘法或概率因子乘法 |
| `aggregate` | 消去变量，按输出变量分组；布尔 OR、自然数计数、有理数求和、概率边缘化 |
| `map` / `reindex` | 逐元素映射及类型化重命名/列重排；每次明确是否保持零/结构；不得隐式换代数 |
| `condition` | 对绑定切片，或与合法域/条件关系连接；概率条件化还需归一化且分母>0 |
| `least_fixpoint` | 有限域单调规则的增量最小不动点：种子、delta、直到无新行；回撤必须精确维护 |
| `safe_not` | 在明确完整合法域对已知关系求补；不完整时只产生可证明负例/未知，不以缺项判假 |
| `count_distinct` | 布尔投影去重，再映射计数；与路径/证明次数不同 |
| `argmin/max` | 目标、可行域及输出见证明确；不把最大化与求和任意交换 |

共同表达式 Q(X)=⊕_Y ⊗_i R_i(V_i)。每次组合检查列域、时间角色、语义、类型、完整性及结构性质。PC（概率电路）/ATDD（代数树决策图）/稀疏关系表示是计算计划，不持有独立真值。若查询中含否定、递归或有未知域，逐项说明所需条件；不能将所有运算自动解释为一次 sum-product。

对于不完整关系可保持下界 L（确定成立）和上界 U（尚可能成立），L⊆真实关系⊆U。在相同完整域内，正查询的单调运算传播保守上下界；`not` 交换并取补，不能把各变量的未知独立化后当作精确结果。若 L/U 太宽，返回未知和相关条件。查询结果有 `known_scope` 和 `possible_scope`，并能回读未枚举的部分（不能假设全笛卡尔积已处理）。对于证据冲突先保留不同解释/范围；原始确定帧的颜色不会产生学习上的冲突。

### 4.2 见证 DAG：保留替代推导，不只保存证据并集

沿用 `relation_witness!` 的规范哈希及事件截止验证。Provenance Semirings（溯源半环）启发：对一个结果，AND 表示同一个证明需要所有父节点，OR 表示任一证明成立。使用紧凑共享有向无环计算结构，不展成巨大多项式。叶为确认 EventRef/FrameRef/定义版本/精确域证书；逻辑模型假设另外标注。元组关系只引用根证明。

例如 `Reach(A,C)` 由 `Edge(A,B)∧Edge(B,C)` 或 `Edge(A,D)∧Edge(D,C)` 推出。撤回 A-B 对应假设时，第一条 AND 失效，第二条仍有效，不能删掉 Reach。实现边反向依赖：证据/定义→证明节点→关系条目→索引/缓存/程序证书。递归关系采用单独不动点维护；删除时对受影响强连通分量重新求最小不动点，防止循环自证。证据 DAG 对已展开有限查询可保持无环，递归定义不通过人为循环引用制造证明。

证据不是独立概率。共享同一事件的两个证明，不能简单相加当作两次独立实验。真实干预样本以EventRef为去重主键；条件、历史和对象绑定只是该事件对特定模型的投影/分组，不能增加独立事件数。同事件多对象样本若用于训练须声明簇相关及权重，置信估计不能当独立重复。重复帧、重放和重复推导不会增加支持计数。

## 5. 持续更新的实际事务与快照

### 5.1 版本和所有者

当前 `OnlineKnowledge` 有 rules/active/trials/programs/policies/observations/projections。继续作为统一知识所有者，扩展受控快照/索引/待处理义务；不再引入另一套永久 `WorldModel`。`LibrarySnapshot` 已存在，作为其中程序定义引用；原始 `RunStore` 继续负责证据持久化。索引和因子化缓存均可由快照重建，不能成为知识权威。

每个派生条目记录：语义定义及版本、绑定解释域、实际证据读取集合/范围、父证明、域完整证书、物理计划版本（仅用于执行），以及逆向依赖。编译缓存键 = 表达式规范身份 + 显式变量域/作用域 + 依赖版本 + 代数语义 + 后端/变量树版本。不能使用只按 frame hash 或 action id 的全局缓存。每条已发布机制/策略的完整预测保留读取的具体定义和绑定快照。

### 5.2 事件即时发布与慢学习异步发布

原计划把完整历史重编码、所有结构候选验证放在每次回执事务内，会阻塞下一次公开决策。现改为一个权威所有者、两类明确事务；精确事实和必要失效同步完成，慢任务始终读取冻结快照。这里的“异步”不允许陈旧模型继续被当作当前有效模型。

```text
on_confirmed_receipt(event):
    require Recorder has durably confirmed receipt and all frames
    old = active_snapshot()
    txn = begin(parent=old, cutoff=event.sequence)
    txn.add(exact_public_fact_delta(event))
    conflicts = compare_pre_action_frozen_prediction(event)
    affected = reverse_dependencies(exact_delta, conflicts)
    invalidate_unsupported_proofs_and_all_dependent_models(txn, affected)
    update_required_exact_indices_or_mark_affected_queries_unavailable(txn)
    txn.add(residuals, unknown_scopes, validation_and_discovery_obligations)
    publish_after_reference_and_parent_validation(txn)
    enqueue_unique_frozen_jobs(affected_history, variables, programs, statistics)
    return active_snapshot()  # 当前有效精确知识与明确未知即可继续统一仲裁

on_background_result(job, result):
    check_protocol_input_digest_build_and_artifacts(job, result)
    record_job_overall_status_and_unfinished_frontier(result)
    units = independently_completed_units(result)
    # 可以是已完成且完整验证的一轮；不能是半个电路工件/半个库事务
    if units is empty: retain_pending_or_failure_reason; return
    for each unit: validate_and_publish_unit(unit, job)

validate_and_publish_unit(unit, job):
    require unit has its own complete schema, digest and validation boundary
    current = active_snapshot()
    changed = compare_actual_read_set(job.read_dependencies, current)
    if changed invalidates proposal definition/domain/encoding:
        invalidate_artifact_and_enqueue_rebuild_with_new_snapshot()
        return
    validate proposal on newly relevant evidence since job.cutoff
    if validation unfinished: retain candidate and pending obligation; return
    if counterexample: publish hypothesis revision, not failed model
    else:
        construct dependent indices/certificates for current parent
        compare_and_publish(proposal, expected_parent=current)
        if parent changed: repeat dependency validation, never force overwrite
```

作业整体incomplete可以含独立完整的学习轮次或查询子结果；只逐项消费已完成且独立校验的单元，整体仍记未完成。一个模型工件、库及其依赖索引的原子发布组必须整体通过，不能从半成品抽取局部状态发布。

分别记录job输入cutoff、模型training_cutoff、validation_through和publication_snapshot：重新验证新增事件不会改写模型原训练截止，更不能回写已经发生动作的事前预测。

完整历史验证责任没有取消：新变量、结构或条件发布前，必须覆盖它声明的全部相关历史；差分验证要求原验证证书仍成立并补查新增/变更事件。不具备可证明差分条件就完整重算，但它作为后台任务，不把旧失效候选留在 active。后台输出不会直接更改 action selection；只经新快照发布后由统一仲裁读取。

正常新样本追加、概率模型预测误差、确定性命题反例是不同事件：前两者记录误差并排学习任务，不自动撤销所有概率模型；定义/域/编码改变或明确失效条件成立才撤销依赖。事件去重也不证明相邻样本统计独立。

依赖精确声明到定义、域、事件范围和样本编码。无关快照变化不会使所有后台工作作废；遗漏实际依赖则是错误。相同事件+任务定义+依赖版本做幂等排队。工作不能被无限更晚的新任务挤掉，调度保留可续游标和未完成义务；不通过减少候选域或降低算法参数维持流畅。

正式行动冻结时要求快照已处理所有在该时刻已确认的公共回执，包含必要失效；不要求所有慢候选研究完成。若某目标依赖尚不可用，只能明确未知并由当前有效知识生成合法探索/其他任务，不能绕过该条件盲执行旧计划。

否定、计数和完整性证明登记实际扫描的谓词、作用域及查询范围，即使该范围当时没有匹配行。新增、删除或修改满足该范围的事实时更新相应读取依赖。例：对某一区域的 `count=0` 在同域新增匹配事实后必须撤回；另一作用域的写入不得使其失效。无法证明新增事实与查询范围无关时，重新验证依赖范围或将查询标为暂不可用。

### 5.3 崩溃与恢复（复用现有 RunStore/Evidence/学习目录）

1. 先持久化原始公开请求/响应和确认事件，后构建派生事务；manifest 保存前一版本、事件截止、定义/索引/库/证明根及各文件摘要。
2. 复用 `RunStore.atomic_write` 已有的文件 fsync、rename 与目录 fsync；在此基础上写临时文件、校验摘要和所有引用后，原子替换快照指针。若指针未更新，恢复时只认上一有效快照，重新处理已确认但未消费的事件；已发布的事件不能重复计数。
3. 学习 worker 仍以现有 job manifest、round、completion 和引擎身份恢复。记录未搜索子问题、绑定域、搜索游标、模型版本、已发现证明及失败原因；恢复的游标依赖改变时只重启相应受影响部分，已证实的其他知识保留。不得把中断当成 exhausted。
4. 写入前/后、索引一半、后台 job 一半、回执确认后学习前、下一动作冻结前注入崩溃；离线完整重放与无崩溃快照逻辑一致。任何未确认动作保持协议规定的未知/隔离，不通过重发猜测结果。

## 7. 本文件功能闭环验收

- 生产代码没有第二个证据/世界模型所有者；每次合法行动都由 Recorder 发出，所有返回帧和公开状态可读，错序/错会话/未知回执不污染学习。
- 关系语义测试：真、假、未知、冲突、空域、多重见证、变量类型错配、交叉解释域、跨版本；模型前像不利用缺失事实。
