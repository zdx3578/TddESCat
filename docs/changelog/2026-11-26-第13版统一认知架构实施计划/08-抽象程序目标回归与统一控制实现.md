## 2. 多维偏序、反统一与语义闭包的实际学习算法

06 负责索引；本节规定查询命中如何产生抽象，避免把索引/哈希相同当成概念发现本身。每个知识定义同时保留可计算内涵和在声明域内的外延，不预设对象类型、运动、计数或通关条件等游戏正确概念。

### 2.1 六维关系验证与组合

| 维度 | 方向与检验 | 形成抽象的操作 |
|---|---|---|
| 集合 | A⊆B 以精确成员差为空为证据 | 交并、共同子集、可复用集合定义 |
| 属性 | 更强属性约束的实例集合包含于更弱约束的实例集合；未知值不当假 | 共同属性、属性闭包、变量化属性 |
| 条件 | C1⇒C2 表示满足 C1 的合法绑定都满足 C2；用反例不存在证明 | 消除重复条件，反例指导精化；一般逻辑条件不能只用 token 集合比较 |
| 对象 | 分解/组合和跨实例结构映射有明确成员/角色保持约束 | 共同角色、部件与联合对象；重叠对象不自动合并 |
| 机制 | 在显式状态/动作/输出映射下保持转移、必要区分及相应目标 | 公共作用核、条件泛化/具体化、语义保持的参数化程序 |
| 时间 | 同一时间语义中的前缀、子序列、组合、历史测试响应等分别定义；不同操作并非同一种顺序 | 共同过程、重复步骤、历史状态及必要的时序约束 |

关系记录必须标明所用维度、方向、域、映射、证据、版本。只有反身/传递/反对称（或经证明等价的商结构）满足时才称偏序；对象映射、机制作用关系、不同时间映射可能只是有类型关系或预序，不能硬转成全局格。跨维度联结用共享变量及有依据的映射，禁止由“集合更小”直接推出“机制更具体”。

### 2.2 反统一（Anti-unification）与谓词发明

对索引召回的多个有类型表达式，先做显式作用域/角色对齐。对齐失败或多种对齐时保存不同候选，不直接取最像的一个。第一阶有类型最小一般泛化采用下述可审计算法；更高阶/程序抽象由真实 E-Stitch 发现及验证，不把该算法声称为全部高阶最优解。

```text
antiunify(t1,t2,alignment,memo):
    assert compatible output sorts and semantic scope
    if exact_same_term(t1,t2): return shared_term
    if both calls with same typed operator and arity:
        return Call(op, antiunify(each aligned child pair))
    if output types have valid common sort:
        v = memo.get_or_create((canonical t1, canonical t2, aligned role scope))
        return v with substitutions {v:t1}, {v:t2}
    return no_typed_generalization
```

`memo` 保留重复变量约束：若左/右子项重复，不应错误地变为多个互不相关变量。对交换运算、集合和关系的等价结构，只有已证明的等价规范化可用；不能将任意调用按字母排序。多输入反统一可逐步折叠产生候选，并保留原代换见证，不能保证不同折叠顺序的高级搜索最优。每个候选必须经过 `instantiate` 回代，重建所有来源表达式；再在全部相关历史及新绑定上检验作用条件/效果。定义内部能精确等价并不意味着环境机制因果成立。

谓词发明：查找多个经类型检查的关系表达式共享的连接子图或约束子项，将可复用子表达式提升为有明确自由变量的参数化定义；如 `P(o,q,t)=∃r[Member(o,r,t) ∧ Adjacent(r,q,t) ∧ ...]`，保留需要外部绑定的参数而不是捕获局部变量。生成内涵后用精确关系查询求外延；对完整有限域验证等价，对未知域保留适用条件和竞争解释。新定义必须有真实消费者查询，不能只生成名字或展示文本。

```text
learn_abstraction(trigger, snapshot):
    sources = find_knowledge(snapshot, multi_dimensional_query(trigger))
    for typed common subexpression / LGG / closure candidate:
        verify typing, variable identity, substitution and source relation
        revalidate against original positive, negative and unknown events
        propose new definition plus binding expression and scope witness
        if it preserves declared semantic obligations:
            publish with shared computation plan and inverse dependencies
        else retain scoped counterexample or unresolved obligations
```

注意不要由一个数值 factor 直接创造语义变量；07 先提供来源、绑定和控制区分。压缩候选是否值得采用，以实际执行节省、复用及对反例的保持判定；即使暂时不值得物化共享，也不能丢失尚有作用的正确知识。

### 2.3 条件等价与撤销：复用现有 egg 的冻结视图

在给定模型约束 A、声明域 D 和条件 C 下，对 `A ∧ D ∧ C ∧ (f≠g)` 查询。不可满足只证明编码模型中的条件函数等价；另查 `A ∧ D ∧ C` 有满足见证，防止空真被当成复用资格。关系外延的等价须声明有限域闭合；带符号公式的证明须明确所用理论和假设。不能把“有限历史上相同”提升为真实环境中的无条件等价，也不能把经验因果假设作为无条件数学公理。

继续使用 E-Stitch 已依赖的 `egg 0.10.0` 补丁版本。Julia 维护无条件精确规则的基础视图；条件视图由“基础版本、条件表达式、域、证据假设和规则版本”共同标识，在冻结任务时重建。只有已验证适用于该视图的条件规则可以加入该局部视图的等价合并；其结果不得泄漏进基础等价类。多条件同时有效时对完整条件合取重新建立视图，不能按上下文名称相同直接拼接已合并 e-class。

父定义、条件或来源撤回时，05 的反向依赖索引使相关视图、缓存、计划与重写失效。保留尚有效的独立证明；重建受影响视图及必要区别。现有 egg 不提供一般性的 union 逆操作，所以不得通过删除一条规则假装已经拆开旧 e-class。Predicate E-Graphs、Versioned E-Graphs、egglog、Metatheory.jl 属于研究比较，不安装为第二个生产核心。该选择保留条件等价能力，将必须自写的部分限定为上下文管理、证明依赖及视图重建。

### 2.4 cvc5 适配：类型表达式到判定、模型和反例

`ConstraintAdapter.jl` 从同一快照构造闭合的约束问题；`ComputeBridge.jl` 发送请求；`solver_adapter.py` 按节点类型调用 cvc5 Python API。接口中的五组内容各有用途：

| 内容 | 含义与约束 |
|---|---|
| `request_id / snapshot / read_dependencies / evidence_cutoff` | 使用 05 的唯一字段名，区分计算任务并检查证据、定义及域版本；不能用时间戳代替依赖 |
| `operation` | 只允许已注册的 `check_sat`、`check_implication`、`check_equivalence`、`synthesize_guard`、`synthesize_invariant`；说明结果究竟回答什么问题 |
| `signature / domain / assumptions / query` | 类型签名、有限对象映射、已明确承诺的假设及待检验公式；对象 ID 使用有域约束的整数或枚举类型，不能把不同角色混成无约束整数 |
| `grammar / examples / obligations` | 仅合成任务使用；分别规定允许的表达式、真实样本约束及必须满足的逻辑义务；样本候选不写回事实表 |
| `backend_pin / config_digest / input_digest` | 使用 05 的唯一字段名，固定 cvc5 版本、配置及输入内容，供缓存、回放、依赖校验；配置来自文件，不靠环境变量 |

正式支持的第一批理论片段是布尔逻辑、有界对象变量、线性整数及精确有理数算术。`signature` 的节点白名单映射到 `Kind.AND/OR/NOT/IMPLIES/EQUAL/LT/LEQ/ADD/SUB/ITE` 等实际枚举；量词只在已声明有限对象域上展开，或明确切换到已注册理论片段。未知关系格子保持为未约束变量或显式未知标记，不填 `false`；数值缺失不填零；不把域外对象截断到已有对象。可解的布尔真值与“这条事实是否已经知道”是不同信息。

05 的经验 `support/refute=11` 表示有待解释的冲突，不是同时断言布尔公理 `p` 和 `¬p` 的许可。`ConstraintAdapter` 先选择具有明确来源与版本的候选模型，将冲突保留为模型分裂、历史区分或概率机制义务；模型选择不能把其他真实证据删除。每个面向复用、剪枝或保证规划的证明请求，先单独检查模型假设 `A ∧ D` 一致，再检查适用域 `A ∧ D ∧ C` 非空；其中蕴含请求的 C 为 C1，条件等价请求的 C 为其声明条件。前置检查 unknown 时保留未知，矛盾模型/空适用域不能获得可复用证明。作为独立 `check_sat` 请求，前置公式的 sat/unsat 仍应如实返回；禁止将这个 unsat 偷换成后续命题成立。纯数学的空真可记录，但不授予环境复用或剪枝资格。

请求和响应都使用05唯一字段 `read_dependencies`，内容为实际读集及其版本；不能换一组未核验引用。所有响应使用 05 的执行、语义答案、覆盖三层合同，不另设单层 `status` 字段。官方调用形态如下，`lower_typed_query`、`decode_model`、`attach_checked_artifact` 和 `make_compute_result` 是本项目待实现的适配函数，不是 cvc5 已有 API：

```python
import cvc5
from cvc5 import Kind

def solve_boolean_query(request):
    op = request["operation"]
    assert op in ("check_sat", "check_implication", "check_equivalence")
    # 蕴含/等价的模型一致性和非空适用域证书已由前置请求核验。
    # lower_typed_query 对 check_sat 编码原公式；对后两者编码反例公式。
    tm = cvc5.TermManager()
    slv = cvc5.Solver(tm)
    slv.setLogic("QF_LIRA")   # 仅对应本请求实际使用的线性混合算术片段
    slv.setOption("produce-models", "true")
    slv.setOption("produce-unsat-cores", "true")
    terms, name_map = lower_typed_query(tm, request)
    for assertion in terms:
        slv.assertFormula(assertion)
    r = slv.checkSat()
    if r.isUnknown():
        return make_compute_result(request, execution_status="completed",
            result_kind="Boolean", semantic_status="unknown", native_status="unknown",
            reason_code=str(r.getUnknownExplanation()))
    # sat 对 check_sat 表示公式可满足，对蕴含/等价表示存在反例。
    answer = r.isSat() if op == "check_sat" else r.isUnsat()
    artifact = (decode_model(slv, name_map) if r.isSat()
                else encode_terms(slv.getUnsatCore()))
    digest = attach_checked_artifact(request, artifact)
    return make_compute_result(request, execution_status="completed",
        result_kind="Boolean", value=answer,
        semantic_status="true" if answer else "false",
        native_status="sat" if r.isSat() else "unsat", artifact_digest=digest)
```

`make_compute_result` 必须填齐 05 的 `requested_scope / covered_scope / completeness / remaining_work`、请求摘要和版本追溯；上例省略的是该构造函数内部重复填充，不是协议字段可选。正常 unknown 表示执行已返回而语义仍未决定，覆盖不能标为命题已判定；精确 Boolean 答案的完整性只针对当前声明的查询，不代表整个环境已经覆盖。见证/核心工件只写入本冻结作业允许目录，并经摘要引用；不在结果顶层增加未注册的 `witness/core` 别名。

`decode_model` 通过 `slv.getValue(term)` 取值，并按 `getBooleanValue()`、`getIntegerValue()`、`getRealValue()` 编码；有理数保存分子分母的精确整数，不能转 Float64 后当等价证明。合成返回项则通过 `getKind()`、`getSort()` 和子项遍历解码；不对 solver 输出字符串 `eval`。TermManager 内部 ID 只在该 worker 请求中有效，不充当跨语言定义身份。

Julia 接收后按顺序校验输入摘要、依赖版本、类型和域，再用自身解释器回代所有 `sat` 赋值检查原查询。反例分为“编码模型反例”和“真实公共事件反例”：前者否定给定假设下的逻辑主张，并可生成待执行实验；不得伪记为已经发生的环境事实。`unsat` 核心是相对于所列假设的判定来源，不等于独立检查过的形式证明。有限可枚举验证域另用直接解释器交叉验证；若声称可独立检查的证明，必须新增对应证明格式和检查器后才能标注该等级。

`check_implication(C1,C2)` 实际检查 `A ∧ D ∧ C1 ∧ ¬C2`；`check_equivalence` 检查 `A ∧ D ∧ C ∧ (f≠g)`。因此后两种请求的 `native_status=sat` 对应 `semantic_status=false` 和反例，`native_status=unsat` 在前置证书有效时对应 `semantic_status=true`；不得与 `check_sat` 的答案方向混淆。进程中断或未完成为 `execution_status=incomplete`，后端没有声明的理论能力为 `unsupported`，错误类型/域/请求格式为 `invalid_input`，实现异常为 `failed`，依赖失效为 `invalidated`；所有这些执行状态都不能伪装成一个已判定的 false 或无解。求解任务可用冻结输入重放，但不把重放称为恢复了 cvc5 内部搜索状态。

### 2.5 cvc5 SyGuS 的候选生成与反例循环

通用条件合成的输入是 06–07 已有语义的 Ground Atoms（基原子事实）及其查询结果，不是原始像素矩阵。程序枚举、作用角色及真实回执仍归 Julia；cvc5 合成可解释的 guard、停止条件和候选不变量，E-Stitch 抽取共享函数。三者的职责互不代替。

允许的 guard 语法为 `B ::= known_relation(role...) | true | false | not B | and(B,B) | or(B,B) | I <= I | I = I`；整数项 `I ::= 已注册数值特征 | 样本中有来源的常数 | I+I | I-I`。`not` 只对具有明确定义和当前可判定值的谓词执行；输入特征未知时，整个 guard 计算保留三值结果，不能由语法中的否定制造闭世界假设。常数来源、变量类型和操作符均随 grammar 固定；事件 ID、游戏 ID、训练轨迹序号不作为行为判别特征。

```python
tm = cvc5.TermManager()
slv = cvc5.Solver(tm)
slv.setOption("sygus", "true")
slv.setOption("incremental", "false")
slv.setLogic("LIA")
integer, boolean = tm.getIntegerSort(), tm.getBooleanSort()
flag = tm.mkVar(boolean, "relation_present")
count = tm.mkVar(integer, "count")
b, n = tm.mkVar(boolean, "B"), tm.mkVar(integer, "I")
grammar = slv.mkGrammar([flag, count], [b, n])  # 首个非终结符是返回类型
grammar.addRules(b, [flag, tm.mkBoolean(True), tm.mkBoolean(False),
    tm.mkTerm(Kind.NOT, b), tm.mkTerm(Kind.AND, b, b),
    tm.mkTerm(Kind.OR, b, b), tm.mkTerm(Kind.LEQ, n, n)])
grammar.addRules(n, [count, tm.mkInteger(0), tm.mkInteger(1),
    tm.mkTerm(Kind.ADD, n, n), tm.mkTerm(Kind.SUB, n, n)])
guard = slv.synthFun("guard", [flag, count], boolean, grammar)
for row in verified_fully_bound_examples:
    call = tm.mkTerm(Kind.APPLY_UF, guard,
        tm.mkBoolean(row.flag), tm.mkInteger(row.count))
    slv.addSygusConstraint(call if row.positive else tm.mkTerm(Kind.NOT, call))
result = slv.checkSynth()
if result.hasSolution():
    proposal = decode_typed_lambda(slv.getSynthSolutions([guard])[0])
elif result.hasNoSolution():
    proposal = no_solution_in_this_grammar_and_constraints
else:
    proposal = unresolved_synthesis
```

示例仅展示官方 API 的连接，`proposal` 是 worker 内部待封装值，不能直接当协议响应。正式返回仍使用 05 合同：`hasSolution()` 是执行 completed、Candidate 值及当前合成约束内的成立状态；`hasNoSolution()` 是执行 completed、在本语法约束下不存在候选的明确答案；`isUnknown()` 是执行 completed、语义 unknown；worker 中断为执行 incomplete。不存在候选与未知分别由状态表示，不共用 null。正式 grammar 按真实类型签名生成；全称义务使用 `declareSygusVar` 与 `addSygusConstraint`，不从 Python 字符串拼接任意可执行代码。`hasNoSolution()` 不表示不存在其他程序、其他谓词或更合适的语义层次，找到候选也不证明真实环境效果。

采用 Counterexample-Guided Inductive Synthesis（反例引导归纳合成，CEGIS）：先合成候选，由 Julia 在完整相关历史和指定模型义务上验证；逻辑反例加入合成约束；观测反例先经 Recorder 确认并更新快照，再生成下一轮任务。候选的类型、来源重建、逻辑成立、统计作用支持分别记账。若只有样本拟合，发布等级仍为有适用域的经验候选，不向无条件等价图或确定性规划域写入普遍定律。

## 3. 程序语料及 E-Stitch 真正发现什么（M2）

### 3.1 程序语言是通用的组合语义，不是固定玩法模板

在原有类型项、`SequenceCorpus` 和实际学得的 `JointMechanism` 基础上，定义一套类型化 Abstract Syntax Tree（抽象语法树，AST）。每个节点有输入输出状态域、自由角色槽、读取/写入关系、必要条件、公共动作来源、版本及未知传播；复合不会丢失中间条件。

| 节点 | 接口与执行定义 |
|---|---|
| `Step(effect_ref, bindings, action_expression)` | 当前状态与角色绑定；重新核验动作合法/guard；产生有限后继关系或公共动作候选；实际执行后核验效果 |
| `Seq(P,Q)` | `P` 输出与 `Q` 输入通过显式关系映射连接；组合全部中间状态约束；不可证明的入口不标确定 |
| `Choice(C,P,Q)` | 由可计算条件 C 对互斥分支进行选择；若条件未知，保留多个候选或安排辨别性实验，不盲选 |
| `Repeat(P, guard, progress_or_stop)` | 从真实重复轨迹提出，循环 guard 及退出条件必须可计算；要做确定性可达性保证须有证明的下降量/有限状态闭包；否则逐步滚动验证并重新规划，不一次性盲执行 |
| `Stop(goal_or_public_boundary)` | 当前目标满足或公共终止边界；不把暂时观测不到目标当完成 |
| `Call(def_ref, args)` | 调用已发布共享程序定义，验证类型、scope、版本；保持内涵及作用见证，必要时向下展开 |

AST 名称为规格，可扩展既有 `ConceptTerm`/解释器。不能在语料生成前统一套入 `Repeat(Branch(...))` 或 `remaining_sites` 结构；这些若确由证据发现可以作为某个已学程序，而不是先验骨架。

先复用 `RelationTask / RelationSequence / RelationBranch / RelationRepeat / RelationTest` 的现有语义描述符，使其分别实现上表职责，不因表中名称不同复制一套解释器。当前桥的 `typed-op-children-db-v1` 与 `protocol/v3/signature.schema.json` 约束纯描述性表达式，`binder_children=[]`；Step 表示待解释的动作/转移描述，本身不能在 Rust 中执行副作用。循环通过显式状态输入和游标组合，不偷偷加入 Lambda 绑定或可捕获的自由变量；确需高阶绑定时必须同时升级编码、捕获规避、来源映射与验证器。顺序动作也不能仅凭交换律重排。

### 3.2 从真实任务轨迹生成候选

`trace_to_corpus(snapshot, episode_refs, task_refs)`：事件序列来自 Recorder；使用已经学习的具体作用契约和当时实际选择的任务、绑定、作用反馈。每个 Step 先检查其解释与事件相符；只有证据支持的部分进入正式可执行语料，未解释部分保留在待学习账本，不直接丢掉整段事件。所有已学作用类别均可进入，不能限制某个视觉家族。

1. 记录真实前缀状态、已建立/破坏/保持关系、动作、任务选择及其见证。
2. 按实际顺序生成原子 Step 及观察到的 Seq；通过 06 的序列/结构索引召回重复子序列和可共享的作用定义，提出更高阶共同结构。
3. 两段轨迹在可比上下文中出现不同后续任务时，寻找能区分分支的已知条件或候选谓词；证据支持后生成 Choice。未知分支不能用虚构轨迹填充。
4. 有反复出现的同一关系变换/子程序时，提出 Repeat；退出条件由真实停止/进度变化与独立的可达性/下降义务产生，不能因重复两次就认定任意次数正确。
5. 将每个候选程序转换成现有 `typed-op-children-db-v1` 格式下的表达式（需要新语义原语时同步注册及类型测试），保存从 AST 到原事件/作用定义/绑定的无损来源映射。不同语义定义不可仅因字符串相同而合并。

#### 3.2.2 分支与循环的可执行生成过程

```text
derive_control_candidates(agenda, confirmed_events, snapshot):
    traces = witnessed_relation_steps(agenda, confirmed_events)
    episodes = source_policy_episodes(agenda, traces)
    for episode in episodes:
        keep real Step/Seq terms, intermediate bindings and unresolved residuals
    for comparable entry roles with multiple real continuations:
        labels = validate each continuation against its declared task/effect claim
        split labels into supported / refuted / unresolved / both-valid
        result = submit_compute(operation="synthesize_guard", typed features, labels)
        if result is proved no-solution in current grammar: request a new predicate/history test
        elif result has a candidate: validate Choice on all relevant histories
        else retain unresolved synthesis and branch obligations
    for repeated body with consistent role/state update:
        propose guard, exit, invariant I and optional well-founded measure V
        use cvc5 to search expressions; use original contracts to check obligations
        if all logical obligations proved under declared model:
            emit Repeat with model-scoped proof and actual evidence dependencies
        else emit a stepwise revisable hypothesis, never a guaranteed loop
    validate candidates; submit pure descriptions to existing E-Stitch
```

Loop 义务不能省为“重复轨迹里都成功”。对于循环体关系 `R_P(s,s')`，入口 `Pre`、继续条件 `g`、不变量 `I`、目标 `G` 和自然数下降量 `V`，至少检查：

1. `Pre(s) ⇒ I(s)`，入口足以建立不变量；入口本身有非空支持。
2. `I(s) ∧ g(s) ⇒ Enabled_P(s) ∧ CompleteSuccessors_P(s) ∧ HasSuccessor_P(s)`，继续时不能缺后继或依赖未知输出。
3. `I(s) ∧ g(s) ∧ R_P(s,s') ⇒ I(s')`，所有允许后继保持不变量；失败后继也在量化范围内。
4. `I(s) ∧ g(s) ∧ R_P(s,s') ⇒ V(s)≥0 ∧ V(s')<V(s)`，或提供完整有限转移图的终止证明；经验下降不能代替普遍下降。
5. `I(s) ∧ ¬g(s) ⇒ G(s)`，退出确实满足声明任务；公共终止/晋级边界单独处理，不能把无可用观测当目标完成。

这些证明只在使用的作用合同、状态充分性、域和版本内有效。模型级证明与现实可靠性仍分开；新公共反例可以撤回模型假设及其全部派生程序。未完成证明时，控制器继续当前合法局部任务和辨别实验，不把尚未证明的程序当必达规划。

### 3.3 Julia→Rust worker→Julia 发布协议

保留 `freeze_stitch_job`、`read_stitch_rounds`、现有 rust bridge。冻结 job 的 `job_id/evidence_snapshot_id/library_base_version/protocol_version/codec_version/program_count/slot_context/engine_pin/input_scope_complete`，及实际源码中的 `signature/programs/origins/semantic_context/initial_library/rules/config` 文件和校验。新增任务/作用域、消费目标、候选关系签名和证据版本通过正式版本化协议描述，现有旧字段语义不偷偷修改。若新表达需要桥接更新，Julia 与 Rust 同时改，严格拒绝旧含义的输入；历史文件只允许明确离线迁移及回读，不保留两套生产协议。

```text
submit_learning(snapshot, new_obligations):
    derive real typed programs and evidence origins from confirmed task traces
    freeze input scope, library version, configuration and engine binary identity
    enqueue existing native E-Stitch worker (not hand-written extraction substitute)
    collect verified rounds incrementally using existing read_stitch_rounds
    for each learned definition / rewrite:
        validate AST types, substitution, scope, proof and source semantics

```

学到的程序不是可直接执行的游戏代码，须经过 Julia 的类型、作用域、绑定、公共合法性和效果核验。Rust 不能访问游戏，也不能直接发布控制动作。现有 learning config 的搜索参数默认不减、轮次不增加人为截断；E-Stitch 的真实成功压缩/不动点终止与外部资源暂停分别记录。`LibrarySnapshot` 的旧库续学必须用实际 library 内容，而非统计“库有多少条”就当续学成功。

### 3.4 生产复用的证明

每个发布程序由 `effect_contract` 发布同一 producer 索引（下面第4节）；目标回归可召回它，当前状态可直接计算其前置条件和实际绑定，仲裁器可产生第一步合法公开动作。验收记录链 `confirmed event -> corpus origin -> Rust result -> semantic verification -> LibrarySnapshot version -> producer retrieval -> instantiated prediction -> acknowledged action -> feedback`。必须有真实消费见证；只有导出、库新增、离线重写或日志不算闭环。若反例使程序失效，已排队动作不能继续使用旧定义，重新计算下一步。

| 必须保存的内容 | 为什么需要 |
|---|---|
| 冻结 e-graph、root、typed 签名/分析、规则与库，以及输入/配置/源码/补丁摘要 | 匹配、代价和类型判断均依赖该快照；只保存候选文本无法复原同一次搜索 |
| `nodes` 的稳定整数 ID、每个 SearchState 的 pattern、matches、变量类型/冻结掩码，以及 depth/lower_bound/forced | 当前补丁使用 `HashMap<usize, Node>`，不再是假设原上游的连续 Vec；已删除节点不能凭空恢复，仍被去重代表引用的节点必须保留 |
| heap 的全部优先级和插入序号、下一个 `created` ID | 恢复 frontier 和确定性同分排序；保存长度或已处理计数不够 |
| SeenTracker 的规范 pattern/type/frozen 信息、FootprintTracker 的代表与引用 | 否则恢复后可能重复搜索或错误剪枝；序列化须保留实际 typed 扩展 |
| 当前最好解、CostSelection、best_history、lower-bound 状态、各种已处理计数 | 保持已发现候选及安全剪枝条件，恢复后不把已完成工作当未完成 |
| search/cost/variable-order 配置、实际耗时累计、随机状态（若所选算法使用） | 正式 best-first 路径不凭空加入随机性；序列化累计时长，不保存进程指针或 Instant |

只在一次节点展开及其子节点入堆完整完成后的安全点写 checkpoint；不能在“已 pop、子节点未入堆”时保存而漏掉候选。临时文件完整写入、校验并 fsync 后原子改名，再更新 manifest；manifest 记录 schema、所有文件摘要、父 checkpoint 和冻结输入身份。建议文件布局置于已有 job 下的 `search/round-000001/checkpoint-000001/{manifest.json,state.bin}`，不是根目录新建另一套知识存储。

```text
start_or_resume_search(job):
    verify frozen input, engine, patch and protocol identities
    if job has an accepted checkpoint:
        session = restore exact session state; validate IDs, references and heap
    else:
        session = initialize existing best-first search from this job's inputs
    while session has live frontier:
        expand_one_complete_node(session)
        at requested durable checkpoint: save_atomic(session)
        if public scheduling requires suspension: return incomplete + checkpoint_ref
    return completed round + existing result proof + exhaustion witness
```

不匹配源码/配置的 checkpoint 明确拒绝，保留旧文件供审计；需重跑时以新任务身份登记，不伪称续搜。证据快照变动不篡改正在搜索的冻结图；旧任务可以完成，但结果发布前重新核验依赖。完整轮次学习/发布闭环与轮内持久恢复分别验收：前者完成时应允许已验证程序进入生产消费；不能以尚未实现轮内恢复为由关闭全部程序学习。后者未完成时必须明确报告当前未完成轮次会重新计算。

## 4. 正向预测、反向目标、机制与程序的同一作用契约

### 4.1 关系复合：中间状态不能省略

以 `FiniteRelation`、`RelationQueries` 为唯一关系语义，沿用 05 的 AND/OR 见证及逐输入完整性。对两个机制/程序 R1(s0,s1)、R2(s1,s2) 与中间入口条件 C2(s1)，组合为：

`R12(s0,s2)=∃s1 [R1(s0,s1) ∧ C2(s1) ∧ R2(s1,s2)]`。

若存在未满足 C2 的 R1 后继，在“保证执行”语义中必须记录失败或未覆盖结果，不能通过过滤丢掉失败分支再声称必达。概率分布组合需要中间状态充分以及明确的条件概率语义；共享历史或潜变量必须保留，不能把边缘结果独立相乘。程序 contract 包含首尾状态、所有中间约束、输出效果、作用范围、可用动作、失败/未知后继、全步来源以及依赖版本；现有 `program_relation_contract` 需从首末汇总升级为这一合同。

定义三个不同的前像：

- `Pre_exists(R,G) = {s | Enabled(s) ∧ ∃s' [R(s,s')∧G(s')]}`：至少一个已支持的可能后继达到目标。
- `Pre_all(R,G) = {s | Enabled(s) ∧ CompleteSuccessors(s) ∧ HasSuccessor(s) ∧ ∀s'[R(s,s')⇒G(s')]}`：在声明模型内保证。实际未知后继、失败分支未记全、输入域不完整均不能进入保证集合；避免空关系的 vacuous truth（空真）。
- `Pre_prob`：在有效归一化的后继分布和声明条件下计算目标概率，报告模型不确定性/未知，不当保证。

这三种查询使用同一后继关系/有效概率表达而非三个模型。前像也可返回未确定条件/反例及有待实验的角色绑定；`GoalRegression` 不应只返回已全部证明的原子作用列表。组合的条件、因果映射和真实验证责任分别记录。

### 4.2 目标与子目标发现：首关也能启动

目标关系来源于公开任务反馈：已观察到的 levels_completed 变化、WIN/GAME_OVER、实际阶段可辨别结果及中间可控制关系。不得读取游戏隐藏目标或通关规则，不根据颜色/对象名称猜语义。只有公开事实支持的是“此次发生了晋级”；什么条件导致晋级仍为机制假设。

```text
update_goals(event, contracts, snapshot):
    observe actual public progress/state change and relationship delta
    create local tasks from supported controllable relations or distinguishing experiments
    if public progress observed:
        propose goal predicates by aligning before/after successful traces
        compare negative/failed/non-progress traces in compatible contexts
        refine competing goal hypotheses and scope; no automatic causal claim
    derive subgoals by preimage of verified or hypothetical producers
    persist unknown goal conditions and competing interpretations
```

没有晋级样本时仍可执行局部关系任务及因果探索；不能假装知道终局目标。失败发生时保留已获得结构和失败上下文，按照公开规则处理重置/生命周期；重新绑定并检验知识适用域，不强制清空全部世界模型，也不盲用失败前的对象身份。

### 4.3 统一生产者索引与目标回归算法

在 06 的机制维度索引中注册原子作用和程序的相同契约：按被建立/删除/维持的关系谓词与参数类型检索；必要条件、适用域、版本、效果来源可联接查询。未知的效果不能由于索引未命中而判不存在；未验证候选仍可进入实验义务。`regress_goal(snapshot, goal, state, semantics)` 按目标关系及当前状态检索，使用显式共享变量；先以可证明的精确范围缩小候选，随后验证。

```text
regress_goal(initial_goal, state, snapshot):
    agenda.push(GoalObligation(goal=initial_goal, required_bindings, semantics))
    while agenda contains live obligations:
        node = pop_by_evidence_and_task_order()
        if node.goal provably satisfied in current state:
            mark this subgoal solved with a witnessed empty continuation
            propagate its bindings and proof to parent AND/OR obligations
            if initial_goal has a complete joint proof: emit its witnessed plan
            continue
        retrieve producers (primitive AND published program) by effect relation index
        for producer with valid scope:
            predecessors = preimage(producer, node.goal, node.semantics)
            if proven current binding:
                register this subgoal's typed plan; propagate to dependent obligations
                emit a root candidate only when all required bindings/conditions compose
            elif missing but explicit conditions:
                enqueue unmet conditions as subgoals, with producer dependency
            if unresolved alternatives: emit discriminating experiment obligations
        merge exact duplicate obligations by canonical scope/goal/constraints/version
        prune only proved contradiction, unreachable, equivalent or dominated nodes
        maintain history and cycle proof; preserve unfinished frontier
```

同一个前像节点可共享子搜索结果，但禁止把两个不同历史/角色作用域的节点仅因目标文本相同而合并。循环处理使用精确有限状态的访问集合或证明不动点；存在不同进度资源和未来响应时不能直接合并。资源/时间导致实际暂停，保存 frontier 和下次续算依据，不能标为不可达。计划一旦有可执行首步即交仲裁，不等待所有候选穷尽；每次公共动作前按最新快照重新绑定/验证条件，并对实际返回帧重新规划。

### 4.4 确定性规划片段：PDDL.jl 与 SymbolicPlanners.jl 的实际接法

固定 `PDDL.jl = 0.2.18`；SymbolicPlanners 的版本标识为 `0.1.27`，源码固定官方维护提交 `c127297a5e90cb662dec9bbdc1d13e906aeed792`，不使用浮动 master。选择该维护提交是因为它已经修复 DataStructures 0.19 的优先队列接口，兼容范围允许 0.18/0.19；发布标签 v0.1.27 仅允许 0.18。最终 Julia `Manifest.toml` 与已有 Catlab/ACSets/Galley 联合解析并提交，不能只写一份依赖名称表就声称可安装。

`PlanningAdapter.jl` 只导出满足以下条件的片段：对象域有限且冻结；相关谓词取值已确定；动作/程序的前置条件、增加/删除效果及保持不变的关系有明确合同；每个可执行绑定有唯一完整后继；行动成本和目标语义明确。PDDL 中未列出的事实通常按假处理，所以未知关系必须在导出前排除出这个片段或作为待证义务，不能把未知填假取得一个看似可规划的状态。相应关系和作用契约继续由 05 的知识层所有，PDDL 只是同一快照的执行视图。

导出步骤为：建立域内对象和角色符号映射；将准确的前置条件/效果映射为 PDDL action；将完整当前关系估值映射为 initial state；将声明的局部目标映射为 goal；保存 PDDL action 到 `effect_ref/program_ref + role_binding` 的反向映射。变量名、谓词名和动作名由类型签名生成并转义，不把游戏字符串当可执行语法。对每种 action，在独立有限测试域中逐状态比较 PDDL 的 `available/execute` 与原作用合同，再允许该动作导入规划域。

官方公开 API 的调用方式如下；`export_verified_fragment` 和 `revalidate_plan` 为本项目待实现的语义适配，库本身不提供这些环境语义验证：

```julia
using PDDL, SymbolicPlanners

files, bindings = export_verified_fragment(snapshot, goal, current_state)
domain = load_domain(files.domain)
problem = load_problem(files.problem)
state = initstate(domain, problem)
spec = MinStepsGoal(problem)  # 只在每个导出动作代价相同且为一步时使用
planner = AStarPlanner(NullHeuristic(); save_search=true,
    save_search_order=true, refine_method=:continue)
sol = planner(domain, state, spec)

if sol.status == :success
    candidate = revalidate_plan(sol.plan, bindings, snapshot, current_state)
    # 仅提交 ActionCandidate；本段不调用 Recorder 或环境 API
else
    record_exact_planning_status(sol.status, snapshot, sol)
end
```

程序宏包含多次公共动作时，使用 `MinActionCosts(problem.goal, cost_map)`，其中 `cost_map` 是导出 ground action `Term` 到已核验实际动作代价的映射；未知循环次数不能伪设代价为一。上游路径成本内部使用 Float32，因此精确代价最优性必须限制在能精确表示且求和不失真的范围，超出时把代价类型修订并锁定补丁后再声称精确最优；否则只报告有效候选。零启发式用于首个可审计实现；以后引入更强启发式，需单独验证所声称的可采纳性，不能把 `HAdd()` 当普遍可采纳证明。

验证每一步用 `available(domain, predicted_state, action)`、`execute(domain, predicted_state, action)` 及 `satisfy(domain, predicted_state, problem.goal)` 对照原合同。`execute` 仅在预测状态上运算，不是实际发游戏动作。只有单一仲裁器和 Recorder 可以发出选中的第一步。真实回执与预测不一致时撤销计划后缀，保留失败/未知后继并回到同一任务议程。

`sol.status == :failure` 只说明这个冻结、完整编码片段中的搜索失败，不能推出真实游戏无解。`:max_nodes/:max_time` 或外部中断是未完成。已有 `refine!(sol, planner, domain, state, spec)` 可继续未完成前沿，但 `:continue` 要求相同搜索根、域和目标；环境已推进、知识版本变动时不能把新 state 传入后宣称自动重定位。使用经验证的 `:reroot` 或按新快照重建，并记录废弃了哪些旧依赖；本计划不承诺跨域版本自动恢复。默认 `max_nodes=typemax(Int)`、`max_time=Inf` 不额外降低；实际外部暂停只影响运行调度，不产生无解结论。

**上线前必要的状态身份补丁。** 已核对固定提交的 `src/planners/forward.jl:228,254,328,338,410,433,552` 直接把 `hash(state)`（ActionGoal 分支含 action）用作 `UInt` 节点身份；`src/solutions/path_search.jl:198,206` 查询也依赖该哈希。这不能满足本架构“哈希碰撞不能合并不同状态”的要求。必须为所使用的 forward/search-solution 路径加入 session 内的 `StateInterner`：先用完整 canonical state bytes、角色/历史上下文及必要 action key 做可比较键，在 Dict 碰撞时仍比较完整内容，再分配稳定唯一整数 ID；所有建立、重定位、访问集合、轨迹回取和日志查询共用同一 interner。保存搜索时连同 interner 及下一个 ID 保存。不得只替换初始状态一处，也不得全局覆盖第三方 `Base.hash`。

该改动是固定上游的小补丁，保留搜索与优先队列实现；补丁纳入源码锁及 bootstrap 校验，未通过人工制造碰撞的独立测试前不能启用该规划后端。其他未适配 planner 不挂入正式入口。无需另引 POMDP 库；概率后继、部分可观测和未知作用继续通过本项目显式的 `Pre_prob`、历史状态和辨别任务处理，不能因 SymbolicPlanners 有 RTDP/MCTS 或 `ProbAStarPlanner` 名称就宣称已支持当前因果模型的随机转移。

## 5. 单一动作仲裁：从第一帧开始运行（M1 先接通，M2 扩充规划）

### 5.1 合法域、统一候选接口

`ActionCandidate` 拟包含：实际公开动作及坐标、`task_ref`（局部关系、目标推进、区分实验或恢复）、当前 snapshot、角色绑定及其验证、事前预测和未知效果、该候选能消除的义务、计划路径或来源、合法性证据、选择理由。每一字段是实际决策输入或审计信息，不另建事实源。

动作候选来自同一公开合法域：非坐标动作按当前 `available_actions`；ACTION6 用公开合法坐标域惰性枚举，区域成员与作用索引优先排序，不能仅代表点、不能 `take(max_action_coordinates)` 后称完整。若某些点有已证明的作用等价，可共享候选及其覆盖见证；经验同形不能证明整块点击等价。ACTION7 保留独立时序/作用；RESET 仅由公共生命周期规则允许时执行。无可执行动作/未知回执时停止派发并记录原因，不随机发送非法动作。

### 5.2 从多入口切换为同一次决策

复用当前 `OnlineSession.jl:899–941` 已存在的 `task_arbitration` 和关系策略入口，将局部作用任务、目标计划、已学策略、关系实验及动作覆盖义务整理为同一种 ActionCandidate。代码现在会依据选中的来源清理不再执行的旧计划状态，这种一致性维护应保留；不能沿用旧结论误称当前版本完全没有仲裁。需要消除的是候选构造时提前修改公共游标、来源互斥导致合法候选没有进入比较、以及未来新增的仲裁后动作替换。M1 要求这个现有仲裁扩展接口实际控制全部公开请求；M2 扩充语义与候选，不重做仲裁器。

初始可实现的排序是确定性分层规则，而非含糊“使用综合评分”：

1. 拒绝非法、已失效版本、无法绑定必需角色的确定性执行候选。对于未知作用但合法的探索候选，保留实验身份及未知预测；不是确定计划。
2. 若有目标相关且在模型内验证可行的首步，依据任务当前证据、后继保证/概率/可能性与真实成本排序；保证和可能性必须分别展示。若有多个，优先能够推进已声明目标、保留可行后续的动作。
3. 未决假设对可达性/条件有决定作用时，将其辨别实验与上述计划共同比较；采用预测分区的区分能力、实际可达性和影响的任务义务排序，统计信息增益只能是辅助，不能覆盖硬证据。不能因存在点击就固定优先点击。
4. 当没有已支持目标推进计划或无法再区分关键模型时，选择可合法执行的待学习作用/参数/上下文义务。维持公平的持久待办：新证据改变相关性时重新调度；长期未处理义务按等待/证据新颖性进入选择，而非永久饥饿。已完成可证明等价的义务可复用结果；不可达或仍未知的范围明确记录。该步骤属于同一认知闭环，不是兼容旧求解器的 fallback。
5. 同优先级以稳定定义 ID、作用域和动作参数确定顺序；随机探索若采用需记录种子和选择概率，不声称游戏本身随机。

实施者应记录排序的实际比较键及所有候选来源；真实任务缺少足够信息时允许探索，不伪造目标收益或概率。可研究更优的控制/实验联合决策，但不得将自定权重作为正确性保证。公平策略应可审计，不能只测一段对自己有利的轨迹就认定公平。

```text
run_online!(recorder, knowledge, config):
    initial event = confirmed public RESET result
    while public session permits action:
        update region and effect facts from confirmed events
        publish validated changes and invalidate dependent results atomically
        collect completed actual learning jobs; validate before publication
        s = current snapshot; state = bind_current_observation(s)
        tasks = local_tasks + goal_tasks + contrast_obligations + legal_coverage_obligations
        candidates = generate_action_candidates(s, state, tasks, active_programs)
        action = choose_action(s, candidates)  # only selection owner
        freeze prediction, selected binding, obligation and snapshot reference
        receipt = submit_action!(recorder, action)  # only dispatch owner
        if receipt not confirmed: handle according to strict public lifecycle; no replay of uncertain command
        else: on_confirmed_event(s, receipt); validate_prediction; update obligations
        schedule ongoing learning/compression from evidence and affected definitions
        terminate only for actual public boundary or explicit run condition; save unresolved search
```

实际接入仍用现有 `capture→run_online!`、`Recorder`、`publish_library` 及恢复入口；不另起 `run_new_agent`。正式控制路径中不保留能绕过新仲裁的旧 `explore!` 作为可运行求解选择；若已有函数仅为纯候选生成，改为被统一仲裁调用。试验基线通过固定历史提交独立运行，不是生产备用路径。

### 5.3 判定“反例确实改变下一动作”

同一当前公开观测下冻结旧快照的合法选择 A_old 及其预测，不执行两次环境动作；新事件/反例形成新快照，重新绑定当前观测得 A_new；记录导致改变的版本、条件、候选及依赖证明。在实际可区分的合成环境中，确认 A_new 对应的请求确实由 Recorder 发出且回执确认，并检验后续响应。对真实游戏仅依据已发生动作，不把未发送的 old action 当已测反事实。若前后选择一样但知识修订有效，不伪造改变；用预设具有唯一可区分正确动作的独立裁判测试必须改变的条件。

## 6. 七类压缩从底层到控制持续发生，必须支持撤销

统一压缩议程，不强制每次事件同时进行昂贵的所有分解。触发来自新事件、重复查询、定义发布、真实复用及反例；受影响结构通过 05 依赖索引进入队列。每个操作区分无损精确共享与待验证的语义/统计泛化。

| 类型 | 具体执行算法 | 消费处、正确性与逆向操作 |
|---|---|---|
| 原始数据 | 帧内容寻址、可逆差分与稀疏区域成员；共享相同内容 | 06；保持全部事件和帧身份；每个帧可独立重建 |
| 关系 | 相同作用域下共享成员/连接因子，联合索引只保存必要引用；查询执行按因子延迟展开 | bind/query；独立枚举对照，撤回某条证据时保留其他证明 |
| 代数计算 | 06 的规范化表达式 DAG、完整有限函数 ATDD、局部重组与增量缓存 | 精确查询/前像/验证；保持函数、域及代数语义；变更依赖后失效重编译 |
| 语义 | 本文 2 的概念闭包/反统一/共同谓词；已验证实例、参数及上下文共享 | Grounding、机制与目标；反例恢复必要条件及角色区别，不丢来源 |

持续维护算法：对每个压缩提案计算明确的原表达/新表达、合法域及保持的量；独立验证或标记需要新实验；保存来源和展开器；比较真实表示、检索、执行和维护成本；仅在证据/语义允许时发布共享定义，更新索引和 consumers。不能用节点少/秩低或压缩率高代替实际速度及控制能力。必要的新变量与精化会增加规模，属合理学习，不设置强制单调缩小限制。不同层次的压缩收益不简单相加。

## 7. 搜索压缩的安全条件与实现

参考 [Learning Programs by Learning from Failures](https://arxiv.org/abs/2005.02259)。其约束推广依赖问题定义和蕴含条件，不能将“试过没通关”当全局失败。

`FailureConstraint(scope, candidate_pattern, rejected_claim, proof_or_event, dependencies, validity)`：适用域含动作、对象/角色、条件、效果、状态语义及版本。类型化索引可查询某个新候选是否被约束覆盖。每条剪枝返回具体证据与谓词蕴含检验结果；经验失败无法证明推广时只作为排序/待检验条件。

例：同一确定性作用声明 `C1=A∧B ⇒ E` 在真实且满足 C1 的上下文观察到非 E，则同作用、同语义域的 `A⇒E` 也被这一反例否定；但不能自动否定条件更强且排除该反例的候选，或一个允许非 E 的概率机制。抽象对象身份、效果定义或适用域改变，原剪枝证明必须重新检验。

```text
check_candidate(candidate, snapshot):
    canonicalize type/role/scope and retrieve matching failure constraints
    for constraint in index hits:
        if dependencies live AND exact proof candidate entails rejected claim
           under a witnessed counterexample and same semantics:
            return rejected_with_certificate
    reuse exact equivalent completed search if scope and dependencies match
    if safe dominance proof: return dominated_with_certificate
    return pending verification (ranking hints allowed, no silent exclusion)
```

持久记录候选生成的正交范围、已处理范围、证明排除范围、待处理 frontier 及其 scope。版本变动后从反向依赖索引找失效剪枝和缓存，将相应候选范围重新开启；不要永久 blacklist。独立裁判在可完整枚举的有限语义测试域逐个比较无剪枝/有剪枝的有效候选和最优解集合；非完全枚举的真实域明确报告未知，不宣称“零漏解”。

## 8. 模块耦合及失败处理门禁

- 统一知识版本由 Julia 所有；程序、PC、ATDD、索引是共享知识的计算视图或候选，不各自修改原始事实。禁止 `GoalRegression` 从新版本查关系却使用旧版本 program cache。
- 所有关系条件、预测、任务、候选和动作均可回读同一证据；Rust worker 返回的库定义须经 Julia 检验才能消费。公共 API 层不能调用求解策略，学习器不能直接发请求。
- 明确未完成与被反驳：索引尚未覆盖、查询未完成、worker 尚未返回、域变化、证据不足不是假；无解需要明确证明。运行恢复仅续真实状态，无法确认公共请求不得重发。
- 验收不仅看能否实现单步移动或单个游戏的旧策略，还必须出现由不同类型作用自动生成的关系任务与新结构，并在正式控制链中有消费见证。完整指标、消融、测试方法见 09。
- 当前 `attempted_relation_policies`、失败约束和计划缓存要包含有效版本/语义域；新证据、guard 修订或状态细化后重开相关义务。一次尝试标记不能成为跨版本的永久黑名单。
- 本模块真正新增的通用依赖只有 cvc5 计算能力和 PDDL/SymbolicPlanners 规划能力。Z3、Popper、Metagol、Babble、egglog、Metatheory.jl、Predicate/Versioned E-Graphs 不是本轮并行安装清单；它们可保留文献比较，但不能增加另一套事实、规则或程序库所有者。
