# 11｜必须自研的部分：具体算法、文件落点与闭环

复用开源内核以后，项目仍必须定义“输入事实表示什么、不同证据何时可比较、一个程序何时能在当前环境执行”。这些责任与ARC-AGI-3的公开证据、版本和控制有关，通用数学库不会自动替我们完成。本文件明确增量实施边界；不要求推倒当前已有的区域、RelationAgenda、真实策略或Recorder。

所有拟增函数是项目内部目标接口，不是论文或开源库已经提供的函数。实现落点优先修改现存文件；只有共同桥接/第三方适配才新增专门文件。M1/M2归属见04/09。

## 2. 语义入口：确定区域先验与可修订对象分开

输入学习层的是Ground Atoms（基原子事实），例如“帧F的区域R包含坐标(x,y)”“该区域颜色c”“事件e请求动作a并得到帧序列”。像素只经过确定、可验证的区域/差分抽取；Inductive Logic Programming（ILP，归纳逻辑程序设计）不从原始像素枚举规则。

拟扩展 `Grounding.jl` 的算法：

```text
derive_event_atoms(confirmed_event):
    for frame in the actual ordered response:
        regions = maximal_same_color_4connected_components(frame)
        assert disjoint membership, complete coverage, reversible reconstruction
        emit frame/region/membership/color/adjacency atoms with original evidence refs
    for adjacent frames with compatible coordinate domains:
        emit exact change atoms and unchanged observed positions
    for size/domain change:
        emit domain_change and only explicitly verified partial correspondences
    retain all unexplained changes as residual relations
    return versioned exact facts, never cross-frame object identities by default
```

跨帧对象身份是候选：支持来自动作响应、持续对应和可区分的预测，不由颜色连通或像素相似直接决定。一个连通区可能需要分裂，多区域可能构成同一作用角色；这些通过07的证据触发候选产生。初始区域不被事后改写，新的对象解释引用它们及新定义版本。

实现复用已有 `color_components`，不另装大型视觉框架或重写通用图算法。96像素、相邻二元组合等旧候选限额不再定义语义可达范围；采用惰性候选生成及明确未处理范围，全部原始证据保留。

## 3. 多维偏序、条件检索与来源回撤

多维偏序不是一个向量相似度。集合包含、属性/条件蕴含、对象映射、作用契约精化、历史范围等，各有方向及证明责任；06给出各维的精确定义。索引只缩小必要候选范围，最终判定必须回到同一类型语义。

```text
find_and_verify(query, snapshot):
    validate requested types, role equalities, temporal scope and legal domains
    postings = intersect only indices that represent necessary conditions
    preserve unknown/unindexed regions as explicit remaining work
    for candidate in postings:
        compare definitions under declared mapping and same domain
        use Galley for positive joins; Factor Rank or cvc5 for supported exact predicates
        collect verified matches, verified counterexamples and unresolved claims separately
    return results with covered scope, proof roots and continuation
```

不得用形状hash相同证明对象相等，也不得用某一维排序筛掉另一维合法候选。哈希仅定位桶，桶内比较规范内容；缺少特征posting返回空已知支持，不等于世界中不可能存在该关系。

来源维护复用 `relation_witness!`：AND表示同一推导需要各前提，OR表示多个替代推导。删除一个假设时按反向依赖撤回受影响AND，仍成立的其他OR保留；递归定义的受影响强连通分量重新求最小不动点，防止循环自证。Galley可以返回关系支持，却不能仅凭计数还原证据；证明请求和支持查询共享逻辑表达式但保留各自结果类型。

## 4. 动作—对象最小因果单元的完整责任

“最小”必须相对于明确对象/状态语言与证据域，不声称已经发现自然界绝对最小因果粒度。每个待验证作用需解释：执行动作及参数、被选择角色、实际受影响角色、前置上下文/历史、全部已观察效果、不变部分、后继范围、竞争解释与未知。

拟扩展现有 `observe_relations! / prepare_relation_tests / verified_instance`：

```text
update_action_object_units(event, prior_predictions, snapshot):
    exact_delta = read all public response frames and permitted status changes
    bindings = enumerate legal joint role assignments using the relation layer
    for observed or predicted effect obligation:
        attach alternative explanations, supporting events and contradicting events
        separate clicked/selected role from remotely affected role
        retain delayed/no-visible-change possibilities when evidence cannot exclude them
    unexplained = exact_delta minus changes explained under each candidate interpretation
    generate refinements from unexplained regions, differing histories and conflicting effects
    for proposed refinement:
        check type, bindability, explanatory difference and full relevant history
        if not distinguishable: keep hypothesis plus a concrete separating-experiment need
    publish immediate exact facts and necessary invalidations
    enqueue slow structure/model work; never erase original event
```

同一关系任务可以覆盖平移、改色、数量、远端作用或其组合；不按游戏ID/玩法标签选择手写求解器。公开ACTION编号也不预设方向语义。ACTION6整个合法参数域由符号分区/惰性枚举表示；代表点只用于实验排序，除非已有等价证明，否则其余位置仍是独立未完成义务。ACTION7及RESET的效果按实际公共协议和回执学习/记录，不默认互为逆动作。

因果与置信报告分别回答：这次观察是什么；候选在哪些上下文被真实干预复现；哪些替代解释已经被区分；样本是否足以支持稳定性；是否覆盖未见对象/历史。一次实际动作提供干预证据，但不自动保证所有状态已观测、环境平稳或所有混杂已排除。概率模型可帮助选实验，不能凭压缩率或似然把范围外结论升级为高置信因果定律。

## 5. 动态变量、样本重编码与CirKit接入责任

动态变量必须是能从公开关系或可声明历史计算的函数，包含返回类型、合法域、绑定角色、依赖和未知情况。不能只生成“latent_17”名字就称为新可用知识。07的六类触发沿同一候选验证路径运行；低秩/BMF/FCA只提出可计算结构或压缩候选。

```text
propose_variable(trigger, snapshot):
    definitions = typed_candidates_from_relations_and_counterexamples(trigger)
    for definition:
        require executable binding and evidence provenance
        replay applicable confirmed history to build values + observed_mask
        preserve missing/conflicting cases, never fill them as false
        compare explanatory/predictive differences on held-out evidence
        if validated: produce new immutable variable/domain version
        otherwise: retain a concrete missing-evidence or distinguishing-task record

train_candidate_model(variable_version, current_snapshot):
    freeze unique EventRef list, sample projection, masks and training cutoff
    send normalized circuit construction + data to CirKit worker
    receive complete candidate artifact, query properties and parameter version
    validate normalization and held-out predictions independent of training
    recheck actual dependencies and any newly relevant evidence
    atomically activate candidate and its dependent indices, or keep pending/refuted
```

项目负责样本编码和数据语义，CirKit负责电路层、编译、数值推理及Adam训练。SumLayer必须显式规范化权重，CategoricalLayer域/维数满足上游限制；未知位置填合法占位并用积分mask消除，不能把缺失样本当作一个真实新类别。事件去重以EventRef为主键，多个帧/证明/模型投影不能增加“独立干预次数”。

变量分裂/合并、角色定义或类别域变化，冻结旧模型并从原历史按新编码重建样本；不能只在旧列尾部补零后接着训练。编译结构可复用与参数对象可修改是两回事，参数版本不可原地改写正在使用的预测。对于缺少Markov性或历史区别的任务，07选择AALpy离线有限自动机候选；状态划分仍需未来区分实验支持。谱PSR条件不足则标研究未完成，不以另一个模型通过代替它。

## 6. 从轨迹到分支/循环：程序语义不能外包给压缩器

现有 `RelationPolicies.jl` 已有真实轨迹到Sequence/Branch/Repeat的入口，因此自研工作是扩大条件/作用语言并完成验证，保留已有消费链。具体步骤：

1. 从确认任务轨迹建立类型化Step，角色共享由真实对应见证决定；顺序只按实际事件顺序和数据依赖组合，不凭相似拼接两段不相容历史。
2. 在同一入口语义状态出现不同合法延续时产生分叉候选。从Ground Atoms与数值关系生成guard语法；cvc5 SyGuS搜索满足带来源训练约束的表达式。两个分支都可成功的样本不能被强造为相反标签。
3. 返回guard先由Julia原语独立解释并回放全部相关历史，再检查未见绑定/留出和当前范围；精确条件等价需要一致且非空的模型前提。经验冲突先细化上下文或模型，不能用矛盾公理推出任意结论。
4. 重复片段产生Repeat候选；入口guard、不变式、完整后继、下降量/终止范围与退出目标分别验证。当前 `observed_bound` 是真实已见适用范围；未证明一般循环时逐步重验，不能宣称无界保证终止。
5. E-Stitch在这些实际语料上抽共享程序；Julia验证语义后原子激活库、程序契约和producer索引。若允许重写，检查证明链/语义，不强制改写前后字面AST相同。

关系组合和目标回归需要项目自己定义：存在前像要求某个合法成功后继；保证前像要求非空且完整的所有后继满足目标；概率前像要求有效分布及明确阈值/目标，三者不能互换。目标回归在AND/OR义务图传播绑定与证明，一个子目标满足不代表整个根目标完成。

对于完整确定片段，项目将契约下译PDDL并调用现有规划器；其他情况保持统一任务的未知义务。任一开源规划器都不会替项目判断一个经验模型的后继是不是已经完整。

## 7. 知识发布、共享句柄与可续搜索

### 7.1 两类发布事务和一个所有者

05给出实际发布算法：确认事件先持久化，发布精确事实/反例失效；历史重编码、模型训练和程序结构搜索在冻结快照上异步进行。返回后按实际读依赖检查；无关新证据不丢弃全部工作，相关定义/域变更必须重建或重验证。

训练截止、验证覆盖截止和最终发布快照分别记录。概率预测误差触发学习，不等同确定性规则反例。作业整体未完成时可以消费独立完成且完整验证的轮次/查询；半个电路、半个库与半个索引不能发布。已确认事件永远不因后台失败丢失。

`ComputeBridge`负责请求身份、按operation的严格载荷、进程会话代次、Handle与Artifact区分、每次借用的lease_id及输出复核。不同租约分别计数，同一租约重试释放幂等；所有引用消失前不回收对象。实际控制只读取有效新快照，不混用失效参数、陈旧索引与新事实。

### 7.2 E-Stitch轮内恢复是必要的小范围内核改造

08已经定位 `best_first.rs/search.rs/footprint.rs` 与 `rust/bridge/src/engine.rs`。现有进度回调和round结果文件不包含整个搜索状态，需要增量补 `BestFirstSession` 和 `search_checkpoint.rs`，保存e-graph/类型分析、节点ID及匹配、heap、插入序号、seen、footprints、incumbent、CostSelection、当前库/语法/配置与源身份。

在无半执行修改的安全点原子写入checkpoint。恢复后比较同一冻结输入的frontier及后续候选/代价，不能从种子重跑却称为续算。证据变化时先验证旧结果；不修改checkpoint身份假装它属于新输入。完成轮次学习照常可消费，与完整轮内恢复的验收单独报告。

条件e-graph视图按固定模型假设、类型和版本创建；条件失效时抛弃受影响派生视图并重建，基础无条件知识不被经验合并污染。此处复用当前egg，而不额外加第二个永久等价库。

## 8. 最后的真实闭环：候选不等于已执行

当前 `task_arbitration` 继续是唯一选择点。拟落实的关键执行约束：

```text
decide_and_act(snapshot, available_public_actions):
    candidates = collect valid task/program/experiment proposals
    for candidate:
        bind current roles; evaluate guard; compute scoped prediction
        peek next program instruction without mutating shared cursor
    selected = single_arbitration(candidates)
    freeze selected action, prediction, evidence cutoff and proposed cursor change
    receipt = Recorder.submit_once(selected.public_action)
    if receipt unconfirmed: quarantine request; do not retry or commit progress
    else:
        persist receipt and all frames
        confirm semantic effect; commit or invalidate selected cursor transition
        update action-object units, producer/guard validity and pending obligations
        publish immediate snapshot; enqueue slow work
```

仅查询或排序一个程序不得提前推进它的游标；未被选中的候选保持原位置。失败的后继不能被过滤后再声明计划保证成功。失败知识要限定适用域/版本，新的对象解释或guard修订应重新开放相关候选，而不是永久blacklist。

闭合检查覆盖实际可用动作及参数、选择/受影响角色、前提、完整公开效果、不变项、反例、未解释变化与后续控制消费者。合成小域可以完整枚举，真实环境无法证明未观察的无限范围；结论必须写清覆盖域和剩余义务。最终检查关注机制缺失、无学习、计算阻塞、错误失效/永久剪枝等实质问题，不把普通单游戏分数升降当成架构成败。

## 9. 实施验收和依赖顺序

M1先完成证据/域/失效合同、真实依赖解析和三项通用计算接入，再让当前作用任务消费它们，验证反例确实改变下一动作。M2接入动态电路/历史样本、通用分支循环/完整续搜、确定片段规划及持续压缩，逐条完成09的独立验收。

本轮只交付这些算法的详细实施计划；未把它们作为已完成代码。对尚未实现、未运行或证据条件不足的部分，后续逐项报告，不能用“整体框架已接通”掩盖缺口。
