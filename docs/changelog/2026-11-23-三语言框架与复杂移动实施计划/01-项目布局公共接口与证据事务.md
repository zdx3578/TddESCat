# 项目布局、公共接口与证据事务

本文件规定新项目必须实现的边界和接口，所有新增路径均相对 TddESCat 根目录。日期：2026-11-23，台北时间。状态：实施规格，尚未运行。

## 1. 三语言的所有权必须固定

| 进程 | 唯一拥有的状态 | 输入 | 输出 | 禁止承担的责任 |
| --- | --- | --- | --- | --- |
| Python 环境服务 | 官方游戏实例，或合成测试世界的私有规则与状态 | 官方动作请求 | 官方格式公开响应 | 不给 solver 提供对象 ID、墙掩码、可通行表或目标真值 |
| Julia solver | 已确认公共证据、派生解释、概念库、机制候选、覆盖账本、当前控制决策 | 官方 HTTP 响应；冻结的 Rust 学习结果 | 官方 HTTP 动作；不可变学习批次；公开过程报告 | 不导入环境 Python 模块、不读取游戏文件、不接受 judge 的答案 |
| Rust 学习任务 | 当前批次 e-graph、搜索前沿、匹配因子及中间候选 | 类型签名、表达语料、旧库、审核过的等式、预算 | 新定义、重写语料、来源见证、完整轮次与停止报告 | 无环境地址/凭证；不执行游戏动作；不成为第二个长期概念库 |
| Python 验收 runner / judge | 进程生命周期、测试任务安排、私有裁判记录 | 配置、solver 公开产物及必要私有 oracle | 验收结果 | 不作为 Python→Julia 的认知中间层；裁判反馈不得回传正在解题的 solver |

一次交互只由 Julia 发出一个具体动作；同一 guid 同时最多一个在途命令。学习可以异步，但只读冻结批次，返回后经过版本与新证据复核才能发布。

### 2.1 工具链和开源来源锁

首版可复现候选为 Python 3.12.9、Julia 1.10.10、Rust 1.90.0。它们是已发布版本；本轮没有实际编译联合框架。第一任务必须运行依赖预检，失败即修订这一份锁及受影响测试，不能自动换成滚动 latest。[S1][S2]

E-Stitch 使用 Rust edition 2024 及 let chains，Rust 1.85.1 不足。1.90.0 是明确候选；兼容性最终由 --locked 编译和测试决定。Julia 的具体范畴包版本及源提交见 02；HTTP.jl 固定 2.13.2、提交 7e257e1140c2d00b43ef36742e31e12ef973c7a7，其 Project.toml 声明 Julia 1.10 兼容。[S3][S4]

config/sources.lock.toml 每项说明 name（依赖名）、version（发布版本）、revision（源码提交）、archive_sha256（实际下载归档摘要）、license_path（许可证位置）、local_path（如导入源码的位置）。revision 和归档摘要来源不同，不能互相替代。归档和联合锁未生成时标记 pending，预检不得通过。

配置文件统一 TOML。必需的 API key 放 config/secrets.local.toml，由版本控制忽略并限制读取权限；其它配置仅引用其路径。不使用环境变量或 .env 装载路径。官方 Python 包内部支持环境变量不等于本项目要依赖它：通过明确构造参数供给所需配置，并测试在清洁进程环境中仍能启动。

## 3. 运行配置示例及逐项含义

以下为要实现的内部配置，非官方服务已有参数。数值是首轮可调实验预算，不表示已经测出最佳值。

~~~toml
schema_version = 1
run_name = "phase1-public"
run_root = "../runs"

[environment]
base_url = "https://three.arcprize.org"
credentials_file = "secrets.local.toml"
competition_mode = false
game_selection = "public_list"
connect_timeout_seconds = 10
request_timeout_seconds = 60

[learning]
engine = "../target/release/tddesc-stitch"
language = "typed-op-children-db-v1"
seed = 1729
batch_confirmed_events = 16
max_programs = 256
max_ast_nodes = 96
max_input_slots = 12
max_learning_seconds = 60
max_new_definitions = 8

[search]
context_radii = [1, 2, 4]
allow_full_frame_context = true
history_lengths = [0, 1, 2, 4, 8]
max_guard_atoms = 4
max_parameter_term_nodes = 7
max_guard_candidates = 4096
max_match_witnesses = 10000

[execution]
max_public_commands = 256
one_inflight_per_guid = true
post_retry = false
redirect = false
memory_enforcement = "cgroup_v2"
solver_memory_bytes = 4294967296
learning_memory_bytes = 2147483648
~~~

| 配置项 | 确切含义 |
| --- | --- |
| schema_version | 只支持本版本，未知版本拒绝；不能靠猜字段继续 |
| run_name / run_root | 人类可读运行名和输出根；相对路径相对所在配置文件，不相对调用时随机 cwd |
| base_url / credentials_file | 唯一环境服务入口及认证文件；不传给 Rust |
| competition_mode | 选择模式；false 在线上请求中必须省略 competition_mode 字段，见 §4 |
| game_selection | 从公开列表选择；可改为明确公开 game_id 的模式，不能解析 ID 暗示游戏机制 |
| 两个 timeout | 网络连接和完整 HTTP 交换期限；超时不推出动作未执行 |
| engine / language | 固定学习程序及严格受限语法；不可执行或不支持则失败 |
| seed | 学习随机性种子，必须记录实际值；不传递私有环境种子 |
| batch_confirmed_events | 默认每 16 个已确认事件尝试冻结一次学习快照；反例可触发提前重建，但同事件不重复计数 |
| max_programs / max_ast_nodes / max_input_slots | 语料条数、单项语法大小、外部角色槽上限；截断范围必须记录，不将截断称为全量学习 |
| max_learning_seconds / max_new_definitions | 从读入到最终写盘的任务时间与新定义数上限；不是仅内层搜索循环计时 |
| context_radii / full_frame | 按需扩大窗口的有限搜索域；局部解释冲突时可提议更大上下文，不能默认全部影响只在邻域 |
| history_lengths | 可区分的有限历史长度；达到上限仍冲突则保留 unknown，不强认马尔可夫性 |
| guard / parameter / witness 上限 | 条件项、参数表达和匹配见证预算；不等价于完整枚举已结束 |
| max_public_commands | 包含 RESET 与实际动作的公开命令预算；scorecard 管理另计；超时在途动作计入已发送次数 |
| one_inflight / post_retry / redirect | 本版本固定 true / false / false；配置成其它值应拒绝，防止重放有副作用动作 |
| memory_enforcement | 必需执行模式；指定 cgroup_v2 但不可用时明确 unsupported，不能悄悄降为软限制 |
| 两个 memory_bytes | solver 进程组和学习子组的内存上限；环境/judge 各有单独配置与测量，不能将其遗漏后称全系统内存 |

设置独立的 cooperative 实验配置可以只测应用预算，但报告必须注明没有操作系统硬内存保证；它不是 cgroup 不可用时的自动替代。编译预热与真实运行分别计时，冷启动成本也单列。

## 4. 官方公共 API 实现，不再造中间协议

官方参考固定为 arcprize/ARC-AGI@f2e6fee26aba92243cf768a01c8e9f08b8579a31 和 arcprize/docs@6956cde0c84b9b077d31ae98e5a9a243622a2553。官方包源码标注 0.9.10；锁 arcengine 0.9.3 后必须跑完整服务冒烟，不能仅凭版本范围宣称兼容。[S5][S6]

### 4.1 PublicAPI.jl 必需函数

| 函数 | 输入→输出 | 必需逻辑 |
| --- | --- | --- |
| open_client(config) | 配置→显式 HTTP.Client 会话 | 独立 CookieJar；禁 POST retry、redirect；认证只在请求时附加，不写原始 header |
| list_games(client) | 无→公开 game_id 列表 | GET /api/games；保留完整版本化 ID；不抓游戏源码 |
| open_scorecard!(client, mode) | 模式→card_id 或未确认状态 | POST /api/scorecard/open；竞赛发送 true，非竞赛省略字段 |
| reset!(client, session) | game_id/card_id/可选 guid→公共响应 | 首次不带 guid；后续显式 reset 带 guid；不能当作失败动作重试 |
| submit_action!(client, command) | 具体合法动作→完整响应或结果分类 | ACTION1—5/7 为 game_id、guid；ACTION6 再加 x、y；不存在 ACTION0 |
| validate_response(raw, expected) | 原始 bytes、预期会话→规范化只读视图 | 先保存原 bytes，再解析；核对身份/回显/状态/尺寸/色值/帧序列 |
| close_scorecard!(client, card) | card_id→管理结果 | 与动作分开计数；不得在未知 open 后盲目再 open |

认证使用 X-API-Key；请求正文先用锁定 JSON 库序列化为字符串/bytes，不把 Dict 直接当 HTTP.jl body，因为该库可能按表单编码。HTTP 2.13.2 调用形态为 HTTP.request(method, url; headers, body, client, retry=false, redirect=false, status_exception=false, connect_timeout=..., request_timeout=...)；用锁定版本的真实接口写测试，不用旧 readtimeout 别名。保留 bytes 时不能先调用会取得底层数组所有权的 String(resp.body) 再试图保存空数组，应先持久化或对 copy 转换。[S4]

### 4.2 官方响应字段与内部区别

| 官方字段 | 使用方法 |
| --- | --- |
| game_id / guid | 核对环境版本与会话；不一致则协议失败，不拼接到别的轨迹 |
| frame | 有序完整二维网格序列；每一帧保留，不当增量 patch；末帧可作为下一次决策视图 |
| state | NOT_PLAYED、NOT_FINISHED、WIN、GAME_OVER；未知枚举版本失败，不映射成已知状态 |
| levels_completed / win_levels | 公开进度与阈值；不能读取隐藏关卡目标来补充 |
| action_input | 核对动作编号和坐标回显 |
| available_actions | 本次公开动作域；缺失或非法不能解释为全部动作可用 |
| full_reset | 可选公开值；缺失保存 unknown，另记实际请求的 RESET 边界 |

矩阵转换只在一个函数中完成：公开坐标 (x,y) 是 0-based；Julia 访问 frame[y+1,x+1]。先验证矩形、实际尺寸及 0…15 色值，不默默缩放或补零。ACTION6 协议坐标范围是 0…63；“落在当前可见帧”是额外候选信息，不改写协议域。窗口坐标必须经保存的嵌入映射恢复全帧坐标。

### 4.3 命令事务与不确定结果

命令状态是 prepared→sent→confirmed / outcome_unknown；prepared 可因本地校验转 explicit_rejection，少数已明确证明的公开前执行拒绝可从 sent 转 explicit_rejection。

- prepared：实际动作、使用的前观测、模型版本、冻结预测全部写盘；尚未尝试网络提交。
- sent：在发出网络调用之前持久化“可能已发送”的状态。此后崩溃都不能自动重发。
- confirmed：完整响应已保存且通过协议核对；只有此状态可形成新的动作—反馈训练事件。
- explicit_rejection：本地发送前校验失败时网络调用数必须为零，不经过 sent；服务响应只有命中针对实际部署已核查的精确公开前执行特征时才用此类。首版服务白名单为空，默认服务错误均 outcome_unknown。保留拒绝诊断，不生成 no-op 因果样本。
- outcome_unknown：服务器可能已执行，但结果未确认；隔离会话，不以旧帧继续普通动作。

不能把所有 HTTP 400 当 explicit_rejection：固定官方 api.py 存在 g.step 之后才返回 400 的路径。分类只能使用客户端可见内容，不能读取故障代理或 oracle 的执行阶段。VALIDATION_ERROR 也不能单独证明未执行；若将来启用白名单，必须锁定部署版本并匹配状态与完整公开特征，未知在线部署不继承本地白名单。没有经核实的通用幂等键或只读同步路由，所以本地 command_id 不提供 exactly-once 保证。[S5]

恢复时只回放自己已落盘的完整响应。未确认的 open/RESET/动作不自动再次发送。允许采取的后续操作是明确的新会话处置决定；必须符合已选竞赛模式，另记公开命令和可能的资源/关卡损失，不把它包装成无副作用恢复。

## 5. Evidence 与 RunStore：数据项要有确切含义

### 5.0 全部文档共用的唯一落盘布局

下面相对 runs/<run_id>/。公共目录可由 solver 读写；private 和 grade 不挂载给 solver。grade 在冻结测评结束之后才生成。其它文档若使用“事件日志”“批次产物”等名称，均指本表对应位置，不新建另一套权威存储。

| 相对路径 | 唯一含义 |
| --- | --- |
| public/manifest.json | 本次运行的提交、配置、锁和公开环境身份；不含私有种子/规则 |
| public/blobs/<sha256> | 原始公开响应及其它不可变内容；摘要相同可共享 |
| public/commands/<command_id>.json | prepared/sent/最终状态的事务清单；最终状态另以原子版本更新 |
| public/events/<event_id>.json | 已确认事件与原始响应引用，权威证据 |
| public/events.jsonl | 从已提交事件重建的索引；每行引用事件文件，不重复拥有另一套原始响应 |
| public/predictions/<command_id>.json | 动作发出前已经提交的冻结预测 |
| public/decisions/<command_id>.json | 决策原因、实际消费者、计划/实验和选择依据 |
| public/learning/<job_id>/ | 03 定义的冻结输入、轮次、证明和停止状态 |
| public/library/<version>/ | 已发布定义、依赖及来源清单；current 仅指向完整版本 |
| public/claims/<version>/ | 经验机制声明与支持/反例/未知；与结构定义分开 |
| public/coverage/<version>.json | 当前有限作用域的覆盖快照及未解决义务 |
| public/revisions/<revision_id>.json | 修订的反例、失效集合、重验和下一消费者 |
| public/consumption.jsonl | 可重建的消费索引，指向 decisions、library 与实际调用见证 |
| public/plans/<plan_id>.json | 程序/策略的分支、前提、完整性及失效状态 |
| public/relations/<fixture_id>/ | 纯匹配表达的冻结压力输入及后端对照结果 |
| public/metrics.jsonl | 资源与阶段时序事件；不写密钥 |
| private/oracle-trace.jsonl | 环境与独立裁判的私有真值，不进入 solver |
| grade/assertions.jsonl | 测评完成后逐断言评分和私有证据定位 |
| grade/report.md | 裁判完整报告；不回传冻结中的 solver |
| public/acceptance.json、public/report.md | 测评结束后可披露的验收状态与过程摘要，不复制隐藏规则 |

append-only 索引发生半行写入时，以最后完整行和权威清单重建；不能因为索引重建而重复提交游戏动作。每个消费者的检查点记录处理过的 event_id/revision_id；重放更新派生状态，不再发出原命令。

每个 confirmed 事件建立一条 public/events/<event_id>.json；原响应放 content-addressed blobs，事件不能按画面内容去重。

| 内部字段 | 含义及约束 |
| --- | --- |
| event_id | run 内稳定事件身份，由会话和单调命令序号产生；同画面两次干预是两个事件 |
| before_ref | 决策时已经确认的前观测引用；禁止后写替换 |
| command_ref | 实际动作完整参数和请求摘要；ACTION6 必须包含 x/y |
| response_blob | 保存原始公开响应 bytes 的摘要引用；不保存凭证或 cookie |
| completion | 上述事务结果；未确认事件不得伪造 response_blob |
| frame_count / frame_shapes | 实际有序帧数量及各自形状；校验与 bytes 解析一致 |
| prediction_ref | 动作前冻结的预测记录；探索动作也记录“待区分假设/未知” |
| version_refs | 游戏公开版本、解析器、解释器、类型签名、库、机制和上下文版本 |
| intervention_group | 同一 episode/自适应探索簇的统计分组；不声称不同 event_id 自动独立同分布 |

具体像素来源用 (event_id, response_frame_index, x, y, interpretation_version)。frame_index 为响应中 0-based 帧序号；ACSet 行号或 Rust e-class ID 永远不能替代该定位。

RunStore 要实现 write_blob、commit_event、freeze_batch、commit_library、recover_run 五个操作。提交算法：

~~~text
校验输入和引用的已提交对象
在同一文件系统创建临时文件；写完整内容并计算摘要
flush/fsync 文件；原子 rename 到最终内容地址；同步目录
写引用这些最终对象的 manifest；同样原子提交
最后更新可恢复索引或 current 指针；读者只认完整 manifest
~~~

这是每次事件/库发布的文件事务，不宣称多个文件系统的分布式事务。索引丢失可从清单重建；半文件不进入索引。若磁盘满在响应落盘前发生，该动作仍可能已执行，结果归 outcome_unknown，不能因为没有证据文件而补发动作。

### 5.1 预测记录不能省略什么

Prediction 保存 model_version（使用的冻结机制）、binding（此次候选角色）、action（真实参数）、guard_truth（true/false/unknown）、query_scope（要核对的可观测通道）、predicted_values（在该通道预测的值或有限集合）、enumeration_complete（后继是否已找全）、assumptions（使用的暂定机制和历史范围）、created_before_command（先于发出动作的证据）。

一个只预测“所选区域平移”的记录不能自动推出分数、资源、其他区域不变。其它通道若未预测，明写 unmodelled。允许集合预测，但空集合不能执行；全集/任意值预测只算未提供信息，不能获得 100% 命中的奖励。

核对结果：所有被预测通道已可观察且满足为 support；至少一个可观察预测被反驳为 counterexample；结果未知、绑定无法区分、观测不充分或搜索未完成为相应 unknown/incomplete。多个绑定分支逐分支核对，不将“存在一个支持分支”记为唯一因果对象已确认。

### 5.2 发布竞争与缓存

freeze_batch 记录证据 watermark、library_version、interpretation_version、rules_hash。Rust 返回后先检查类型、展开、来源和成本，再对 watermark 之后新证据重验所有受影响声明，最后通过 compare-and-swap 更新 current library 指针。版本不匹配则重基或拒绝发布，不覆盖较新的修订。

缓存键包含实际依赖的库/解释/关系索引版本。一次“没有匹配”也依赖当时索引容器，新增证据或关系后必须失效。不能因为零结果没有见证就不保存依赖。

## 6. 最小因果单元的覆盖怎样落到算法

Coverage.jl 中的一个 obligation（待完成义务）是当前解释版本下的一组：具体动作域、候选作用角色、可观测条件类、效果查询、需要区分的替代解释。它不是环境已经承认的真实对象。

例如 ACTION6 的义务需要坐标域；移动类候选的义务需要身体支持区域和周边关系；暂时找不到作用对象时仍保留 unresolved_role，不能删除动作条目。状态分别记录 untried、observed_support、observed_conflict、unidentifiable、unreachable_under_current_model、incomplete。更改 guard 只改变候选适用域，被排除的条件仍是覆盖缺口。

每次新响应执行：

~~~text
从 available_actions 更新合法动作域；保留旧的历史覆盖
展开当前有限上下文/角色目录，创建尚不存在的义务
按 event_id 为相应义务登记一次干预，不按像素或宏调用重复计数
核对预测，把支持/反例/未知附到各解释分支
对每个未解决义务：
    有竞争模型且存在不同公开预测 → 提出区分实验
    没有模型但有合法动作 → 提出显式探索请求
    当前前提不可到 → 记依赖的规划/条件缺口
    搜索预算未完成 → 保留游标与 incomplete
~~~

没有任何机制时，使用有记录的覆盖探索策略：动作编号稳定排序，轮流选择当前最少已确认干预的动作；ACTION6 使用确定性坐标枚举和公平游标，已观察变化区域可以提高优先级，但未访问域不能被删除。该策略是初始化实验选择，不叫备用求解器，也不向学得库塞入移动方向或可通行规则。每个选择记录选择原因、待检验域和预算。

Coverage 唯一保存义务、计数与公平游标，提供 propose_due 和 commit_attempt。ExperimentDesign 从阶段一即提供 discriminate、rank_requests，只返回实验请求与拟推进位置；Controller 在请求事务形成后调用 Coverage 提交，不能让两个模块分别持有可变游标。已发送但结果未知的尝试次数与已确认干预次数分开。

统计报告分三层：接口覆盖（是否调过该动作及参数子域）、效应覆盖（作用角色和通道是否辨识）、控制覆盖（在已达条件下是否有成功/失败验证）。没有穷尽有限域或干预设计时，不输出一个无条件“因果置信度 99%”。去重事件数、episode 数、条件类数分别报告。

## 7. 测试隔离与协议故障用例

deploy 构建三个文件系统边界：

1. environment 镜像含官方环境包和合成规则；只暴露官方 HTTP 路由。
2. solver 镜像只含 Julia、Rust 二进制、公共协议、非敏感运行配置和自己的运行目录；不复制 python/bench、tests/private、oracle、环境种子或源地图。
3. judge 镜像可读取环境私有断言和 solver 公开产物，但没有写回 solver 观测/奖励的通道。

solver 无 Docker socket、无宿主目录全挂载、无宿主进程命名空间；网络仅允许本次环境 HTTP。环境管理/健康端点不作为 solver 的 API。测试公开 game_id 用不含场景语义的标识，场景名→ID、种子→规则映射留在 runner/judge。测试元信息在评测结束后才进入报告。

普通开发进程模式可用于单位测试，但端到端“无隐藏信息”验收必须使用此隔离配置。信息隔离验证测试故意请求一个不存在的 debug/metadata 路由、尝试读取私有路径，均应失败；不是只检查代码中有没有 debug 字符串。

| 测试名 | 故障或输入 | 必须断言 |
| --- | --- | --- |
| protocol_coordinates | 四角、非正方形网格、裁剪嵌入 | x/y 不交换；不变形；非法类型或超出 0…63 本地拒绝；协议域内但在当前帧外仅记支持不足/未测，不伪称协议非法 |
| protocol_animation_roundtrip | 三帧，首末相同，中帧不同 | 保留三帧；不能归为完整无变化 |
| protocol_cookie_affinity | 服务要求先前设置的 cookie | 后续请求保持会话；日志中没有 cookie 值 |
| protocol_before_execute_400 | 本地发送前非法命令；另模拟服务前执行错误 | 本地调用次数为零且 explicit_rejection；服务默认 outcome_unknown；都无 no-op 样本 |
| protocol_after_execute_400 | 服务先变状态再返回与前执行故障完全相同的公开 400 | 两种公共不可区分错误都 outcome_unknown；后续动作停止；不重发 |
| protocol_timeout_after_step | 动作已执行，响应延迟超时 | 仅一次命令到达环境；不得以旧帧续行 |
| protocol_crash_after_send | sent 后终止 solver | 重启不重放；该会话隔离 |
| protocol_crash_after_blob | 响应 bytes 已写，event manifest 未写 | 根据持久化事务恢复/标记，不产生两个同事件 |
| protocol_false_competition | 非竞赛配置 | 发出的 JSON 不含 competition_mode:false |
| protocol_unknown_fields | 可选 full_reset 缺失、必需字段缺失 | 前者 unknown；后者失败，不能补默认可行动作 |
| protocol_disk_full | 事务写盘失败 | 动作结果不冒充 confirmed；已提交库和事件可读 |
| protocol_rust_no_secrets | 检查学习任务目录/启动参数 | 无 API key、cookie、环境 URL 和隐藏游戏信息 |
