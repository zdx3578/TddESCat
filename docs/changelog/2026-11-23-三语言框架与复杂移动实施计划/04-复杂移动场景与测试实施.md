# 复杂移动的测试环境、学习隔离与闭环验收规格

日期：2026-11-23，台北时间，星期一。目标仓库：`zdx3578/TddESCat`。状态：待实施规格；本文没有运行环境、训练或测试成绩。

本文落实两阶段裁决中的移动测试部分。第一阶段就检验一个动作受到多个条件限制的情形；第二阶段再组合这些动作、资源与历史。这里的“主体、墙、门、开关”等名称只供测试设计者描述人工环境，不能作为正确标签、专用算子或规则输入 solver。

Python 负责环境、测试编排与隔离裁判；Julia 负责认知、假设、机制与下一动作；Rust E-Stitch 负责结构定义发现。测试运行不调用 Large Language Model（大语言模型，LLM）。Strict Public Application Programming Interface（严格公共应用程序接口）是 Julia 获得环境信息的唯一入口。

## 1. 三种测试证明不同的事情

| 测试层 | 实际运行的东西 | 能签收什么 | 不能据此签收什么 |
| --- | --- | --- | --- |
| 协议桩 | 可控 HTTP 服务或位于官方服务前的故障代理 | 请求序列、坐标、身份核对、多帧保留、超时隔离、恢复规则 | 对象发现、动作机制或真实 ARC 能力 |
| 合成机制基准 | 官方 ARCEngine 的 `ARCBaseGame` 子类，经官方 toolkit HTTP 服务提供公开响应 | 在明确有限机制族中，从帧和动作学到有用结构、条件、预测与控制，并正确保留未知 | 未测试机制、官方未知游戏或总体 ARC 解题能力 |
| 真实 ARC 公共验证 | 官方环境，Julia 只调用允许的公共 REST 路由 | 真实公共记录是否进入学习链；新定义是否被实际消费；反馈是否核对；资源是否可控 | 没有出现的机制、未尝试动作、隐藏真值或全域因果保证 |

这三层报告单独给出。不能把合成服务称为“真实 ARC 游戏验证”，也不能因为真实轨迹恰好没有反例，就捏造一个在线反例。固定公开轨迹夹具可以单独检验修订功能。

## 2. 先把 oracle 的信息渠道隔离

Oracle 在本文中指测试侧知道人工机制真值的独立裁判。它用于生成用例和事后评分，不是 agent 可调用的解释器。

### 2.1 三个隔离运行单元

1. **环境单元。** 只挂载 `python/src/tddesc_env/bench/`、已生成的私有场景、官方 Python 依赖及环境输出目录。可访问人工状态、碰撞、选择、资源和摄像机；只对外提供公共 HTTP 服务。
2. **agent 单元。** 只挂载 Julia 包、Rust 二进制、公开语言签名、agent 配置、已批准的初始库和本次输出目录。不得挂载 Python 环境包、场景配置、oracle 输出或宿主完整仓库；不得共享环境进程内存、文件描述符或可读 `/proc`。网络只允许当前公共服务及必要的回执连接，不访问外部模型服务。
3. **评分单元。** agent 退出或冻结当前测评后，读取 agent 只追加的公开证据、冻结预测和私有裁判记录，生成报告。评分结果在本轮冻结测评完成前不送回 agent。

用容器或等效的文件权限与进程隔离实现上述读权限。仅“分两个 Python/Julia 进程但挂载同一目录”不够。启动器必须实际检查挂载和可读路径；隔离不成立则该 run 拒绝计入 strict-public 验收，不切换成直接调用环境对象的运行方式。

环境可以在本地私有文件中写完整状态用于裁判，但不得添加 `/oracle`、`/debug`、`/state`、`/collision` 或自定义路由向 agent 提供。官方服务已有的额外路由也不自动进入客户端许可集。Julia 的许可集固定为游戏列表、scorecard 开闭、RESET、ACTION1–7；发现接口只取会话需要的身份，标题、标签和类名不进入条件或模型选择。

### 2.2 生成内容的两个出口

`build` 生成私有场景目录和启动清单。`serve` 将场景变成官方环境文件和最少 metadata：公开 ID 使用与机制类别无语义对应的 4 字符名称加版本；标题、tags 不携带“可推动”“历史锁”等答案。完整 seed、机制模式、精确目标、oracle 状态和理论最短路径只进入私有目录。

agent 得到的配置只含 `base_url`、凭证文件引用、运行预算、语言/引擎版本等。不得含 `scenario_family`、`collision_mode`、`selected_actor`、`world_to_screen`、训练答案或参考动作。

评分需要关联 HTTP 请求与私有轨迹时，由代理/编排器在测试侧以“会话＋已接受请求顺序”对齐。不要给公开响应增添一个暗藏答案的关联字段；关联失败本身就是实验无效。

### 2.3 隔离必须有负测试

在 agent 单元用测试替身尝试读取私有场景、导入 Python 环境包、访问私有端点和环境进程内存，均应失败。检查 Julia/Rust 对外连接记录与每个公开响应字段；禁止对象 ID、可通行掩码、碰撞体、摄像机坐标进入语料或配置。

把私有对象名称、私有目录名称和无关 oracle 注释全部改掉，保持公开响应与 agent seed 相同；agent 的认知结果与动作序列应一致。公开 game_id/guid 改名时，允许会话引用变化，但不能改变机制条件。此检查直接发现按名称、文件或元数据分派 solver 的耦合。

## 4. 有限场景生成算法

### 4.1 基准几何与像素呈现

文中尺寸一律为宽×高；Julia 矩阵为高行×宽列。首个逻辑画布取 24×20，坐标 `(x,y)` 从 0 开始。活动地图通常位于 `x=1…16, y=1…16`，候选面板位于 `x=19…22, y=2…15`，其余为留白或装饰。默认 camera 为 24×20，当前官方渲染对应 2 倍缩放及左右 8、上下 12 像素留白；该变换仅供测试生成和裁判使用，不写进 agent 配置。

默认主体支持为 `S={(0,0),(1,0),(0,1),(1,1)}`。再生成 3×2 矩形、L 形、多色连接形及分离的两个小片作为变体。所有位置约束基于完整支持，不把主体当点。首个简单实例的主体锚点为 `(3,6)`，向右一格后的目标锚点为 `(4,6)`；这只是人工测试初值，不是 agent 的先验。

每个实例先构造逻辑世界，再分配颜色。颜色分配由 0…15 的置换生成；颜色仅是标签。某些用例特意让不同角色同色或一个角色多色，此时记录“颜色相等模式”不变，而不是强求所有角色颜色互异。墙、可推动物、主体和面板的颜色在不同实例间不能有固定职责。

环境内部为每个图形保留私有身份；agent 得到的只有像素。图形可通过多个 Sprite 渲染，但这不能成为 solver 的对象数量答案。默认环境仅按公开请求推进，没有依赖墙钟的自主变化；涉及自动运动时，也明确为每次被接受动作触发的固定相位更新，避免机器快慢成为隐藏混杂。

### 4.2 三种可达性由裁判分开计算

**Configuration Space，配置空间**，至少包含主体锚点、形状/朝向、其他物体位置、门/选择/资源状态和必要历史。

- 可站立域：在固定其余状态下，完整支持 `p+S` 是否处于允许区域、是否满足当前占用约束。它只回答能否容纳。
- 一步可达：一个实际动作是否能把完整配置从 s 变成 s′；它还涉及动作映射、扫过区域、推动、资源和历史。
- 多步可达：在完整配置空间中沿合法转移到达目标，允许中间改变门、障碍和资源。

裁判可在小型配置空间中用 Breadth-First Search（广度优先搜索）穷尽，判断测试实例是否真的可达、最短证据前缀是否存在。这套搜索不被 agent 导入。像素连通组件只负责描述观察，不能作为三种可达性的答案。

### 4.3 生成顺序与拒绝条件

~~~text
读取测试配置与固定 generator_version
建立地图支持、孔洞、面板和图形的有限逻辑集合
按所选测试构造一个明确的作用条件与至少一个反事实对照
枚举少量合法初始配置，检查主体支持完整、没有无意遮挡
用独立 reference 转移列出目标动作的正例、反例和不可辨认例
检查所有“正反配对”只改变声明的条件；其他可见差异须记录
检查需要学习的差异确实存在一个有界公共动作前缀可辨认
应用颜色/旋转/平移/面板布局等变换，并重算公开帧
验证变换后的动作、坐标、终态和查询对应关系
给实例分配无语义公开 ID；将完整机制写入私有目录
先用官方 HTTP 服务执行最短校验轨迹，核对公开帧与 reference
只有环境自身通过核验的实例才进入 agent 测试
~~~

需要不可辨认性的用例则反向检查：在规定公共前缀上两个机制的帧、状态、动作可用性及其他可见字段相同；第一个有差异的实验在前缀外。不能只比较末帧就声称历史不可区分。

正反条件无法独立变化的生成结果、公开帧意外泄漏私有标签的结果、动画阶段重复扣资源的结果都直接拒绝，不交给学习器“将就测试”。

### 4.4 配置示例与每项含义

以下为测试侧配置草案，不能传入 agent；参数数值是首轮工程预算，不代表统计置信保证。

~~~toml
suite = "movement_single_step_v1"
generator_version = 1
logical_size = [24, 20]
camera_size = [24, 20]
training_seeds = [0, 1, 2, 3]
development_seeds = [100, 101]
evaluation_seeds = [1000, 1001, 1002, 1003]
cases = ["M01", "M02", "M03", "M04", "M05", "M06", "M07", "M08", "M09", "M10", "M11", "M12", "M13", "M14"]
episode_action_limit = 48
forced_prefix_action_limit = 12
per_action_solver_seconds = 10.0
learning_batch_seconds = 60.0
agent_memory_bytes = 2147483648
rust_task_memory_bytes = 1073741824
animation_frame_limit = 8
record_all_response_frames = true
allow_custom_routes = false

[variants]
palette_permutation = true
quarter_turns = [0, 1, 2, 3]
reflect = true
translate_within_canvas = true
action_1_to_4_permutation = true
panel_layouts = ["right", "top", "detached"]
~~~

`logical_size` 是测试世界大小，`camera_size` 是测试侧视口；二者不是公开元数据。三组 seed 对应开发前就固定的训练、调试和冻结测评划分；重新调试测评失败时必须生成新测评版本，不能继续称原测评未见。`episode_action_limit` 是一个运行最多允许多少真实动作；强制前缀的动作也计入。两项秒数分别限制每次决策和一次 Rust 学习批次，不将超时算无解。两项字节数分别是 agent 单元与 Rust 任务限制，实际强制机制和测量口径须写入报告；配置数字本身不等于已经实现限额。`animation_frame_limit` 约束人工环境，超过即判环境故障。

变体不是把所有组合一次物化。先执行每项最小配对，再用固定覆盖表覆盖两因素组合；第二阶段只对有具体交互的条件增加三因素用例。生成器记录未生成和未测试的组合。

变体还须分清三种用法。**位置/无关装饰变体**在已声明机制保持时可作同一冻结模型的未见测评；**颜色或几何共轭变体**优先变换整个“训练＋测评”运行，再比较相应结果，不默认只替换测评颜色仍能零样本解释新颜色角色；**动作编号置换、开关规则、资源规则和 camera 跟随阈值变化**建立新的机制学习运行。特别是 `action_1_to_4_permutation` 在一个训练—冻结测评组内保持固定，不能在冻结后悄悄改变真实动作映射，再要求旧模型预测正确。每种变化在私有分组清单中注明属于哪一类，该标签不发送 agent。

第一阶段核心固定形状域和已出现的动作效果范围：例如 M01 训练 2×2 与 3×2，冻结测试这些形状的未见位置；L 形及未见新形状另外列能力扩展。跨颜色、跨动作编码的整轮变体检验通用算法是否依赖固定语义标签；它们不冒充无条件跨机制迁移。

## 5. 学习前、冻结测评与修订后的数据边界

每个 M 用例遵守以下共同流程，其具体差异见下一节。

**A. 初始库检查。** 保存原语与初始库展开清单。不得有 `Move`、`Wall`、`Pushable`、`DoorOpen`、`SelectedAgent` 等正确游戏机制。允许坐标差、相等、邻接、有限集合和关系合取等通用算子，且每项有类型、读取范围及解释器。仅把上述禁用名称换成 `f17` 而保留手写机制体仍不合格。

**B. 可控证据定位。** 在新环境会话上，测试驱动可指定短公共动作前缀，让 agent 确实看到需要区分的观察。前缀逐条只传动作编号及公开坐标，经 Julia 唯一执行器的 collection 模式提交；驱动不得在同一 guid 背后另发动作。切换自主模式必须交接同一 confirmed 观测和命令序号。前缀产生的公开证据可以用于学习。驱动选择的动作标为 `externally_scheduled`，不得计为 agent 自主发现或主动实验。原始输入仍只能是公开响应，不能把私有解释、动作的自然语言含义或 oracle 绑定附上。

**C. 两批结构学习。** 第一批必须由这些实际公开事件的低层派生语料产生新定义，第二批导入第一批已冻结库，继续使用真实 Rust E-Stitch。保存原始语料、类型、来源、旧库、pattern/lambda、独立展开检查和完成状态。定义名称和确切语法不是验收目标；展开后的关系与来源才是。

**D. 冻结测评。** 冻结结构库、机制参数、条件、解释算法版本与证据截止点；在保留机制而改变位置、形状或外观的新实例中先预测、后行动、再看结果。当前角色绑定和正常感知可以随新帧变化，不能用测评后帧重新拟合参数后回填原预测。测评事件写入隔离日志，本轮评分完成前不回流到被冻结模型。

**E. 真正的闭环消费。** 至少一次动作必须由 Julia 自己选择；日志证明哪个已学定义参与了当前绑定、预测或选择分值，并与该次实际 HTTP 动作关联。不得仅删函数让解析失败，再把失败当作认知贡献；对照必须保留合法可执行输入和明确停用的消费者范围。固定输入重放消费者时，审计实际调用参数、定义展开和返回值怎样进入预测/排序。移除消费资格可用来检查调用依赖、所需见证、表达成本或选择是否变化；不强制要求最终数值预测变化，因为正确宏与其合法内联展开应语义相同。若存在同义表达，报告它如何承接以及压缩/计算成本，而不是伪造唯一贡献。该审计只在测试重放中进行，不是运行时备用学习路线。

**F. 修订测评。** 从冻结检查点复制出新的修订运行，投递真实发生于人工环境的反例；检查撤回旧经验声明、保留原预测、更新依赖和下一消费者。若相反结果被新条件排除，原未解释义务仍留在覆盖记录中。修订成绩与 D 的冻结成绩分别报告。

所有事件发生位置、同一事件的重叠窗口、同一响应的动画帧以及重放次数，都不能增加独立干预计数。变体副本可以检查不变性，但不能合并成某个真实 ARC 机制的大量独立因果证据。

### 5.1 预测判据避免两种无效通过

模型可以预测部分公开查询，但必须声明覆盖范围 Ω、条件、采用的解释分支、候选后继及求解是否完整。只预测未变化背景或返回“什么都可能”不算通过移动能力。

评分器在测试侧检查本用例的目标通道是否被覆盖：主体相关完整公开支持、必要另一物体、相关面板/资源以及公共状态。这个私有评分集合不回传给 agent 作为感知提示。agent 可以对由公开帧统一产生的通用查询池预测；查询池的生成不能读取 oracle。

正反例已给足、且变体在声明可学习范围内的冻结测评，应产生可检验预测，不能全部 unknown 后宣布成功。对本质不可辨认或尚未提供区分证据的对照，保留 unknown、多假设或显式的暂定模型是正确结果；不能要求正确猜中隐藏真值，也不能把猜中当保证。

## 6. 第一阶段的单动作复杂条件用例

### 6.0 两阶段签收矩阵：哪些必须学会，哪些先守住边界

“完整控制”指能够依据当前公开证据绑定条件和参数、提出预测、选择实际动作并核对；它不表示已证明未知世界的全域机制。第一阶段分为下列三种义务，结果不得混写。

| 用例片段 | 第一阶段必须签收的内容 | 第一阶段不必提前宣称的能力 | 第二阶段增加 |
| --- | --- | --- | --- |
| M01 开阔地、固定会话动作映射、完整支持重叠 | **核心学习**：真实 E-Stitch 定义、前态可定参数、未见位置的可检验预测、下一实际动作消费 | 无地标遮挡中的唯一身份 | 含自动运动/滚动时的竞争对应 |
| M02 长度 1、完整支持、矩形主体与一格碰撞 | **核心学习**：能区分可容纳与受阻，并保留边缘支持 | 任意形状或扫过机制已识别 | L 形空洞、长度 3 的终点/扫过差异与组合路径 |
| M04 一个推物、后方空/堵、可辨前态条件 | **核心学习**：联合效果、两个角色和后方空间接到同一动作 | 新物体可推性已知、任意链式推箱 | 新角色歧义与多物体程序 |
| M05 面板状态当前可见、一个远端条件 | **核心学习**：局部相同的反例促使读取远端相关条件，修订进入下一消费者 | 未见历史锁或所有面板都已解释 | 保持/切换开关、门与其他条件的组合 |
| M06 公开计数 0/1、一次动作消耗 | **核心学习**：动作前资源条件与动作后消耗都进入预测 | 任意资源类型或长期补充策略 | 两门共享一份资源、资源流与多步回推 |
| M08 两个分离图形、持久选择反馈 | **核心学习**：点击完整坐标、选择状态与下一动作实际影响对象相接 | 重叠且无反馈时的唯一选择 | 滚动后的重新定位、选择与程序顺序 |
| M03 可站立/一步/多步区别 | **边界检查**：不把像素连通当行动可达，不丢相关面板；已测局部结果保留 | 整图不可达证明与未见传送机制排除 | 配置空间路径与 C01 |
| M07 同末帧不同历史 | **边界检查**：保留完整公共历史；历史不足返回 unknown/多假设；不复用不成立的旧模型 | 所有延迟/历史机制自动识别 | 有限历史条件学习和真实后续控制 |
| M09 ACTION7 | **边界检查**：实际调用、各通道核对、历史边界；不预置全状态逆 | 全部局部撤销模式已学会 | 在已观察恢复范围内使用并验证程序 |
| M10 零位移/零 Diff | **必需管道行为**：事件、面板/公共字段和动作合法域不丢；已学核心资源模型继续消费 | 每个新公共计数器的因果规律 | 更广通道的联合机制与任务查询 |
| M11 多帧首尾相同 | **必需管道行为**：全部帧、顺序、一次干预、可回溯历史 | 所有动画线索的机制已识别 | 将中间提示用于历史条件和控制 |
| M12 镜头/自主运动 | **边界检查**：保留竞争解释和未辨认控制关系；无地标不强行唯一 | 鲁棒滚动跟踪与自动运动因果分离 | 分别验证后组合进入 C03 |
| M13 连通/裁剪/多色同色 | **精确计算＋边界检查**：四八连通准确、裁剪来源准确；组件不冒充对象身份 | 多色/粘连时全部真实对象已确认 | 后续区分动作支持的身份修订与复用 |
| M14 公共前缀不可辨认 | **必需认识边界**：同输入一致，无新增证据不增独立支持，不假报唯一保证 | 正确猜中隐藏真值 | 新信息到达后实际分叉修订 |
| C01–C03 | 保留接口与所需证据，无须提前通过完整组合控制 | 任意多步控制 | **完整组合验收** |

`config/acceptance/movement_single.toml` 必须显式选择上述六个核心的基础片段，以及全部必需管道/边界检查。核心冻结测评在预先列明的有限测试集内要求目标通道有实际预测、正反例核对正确、定义被实际消费；只返回 unknown 或只预测静止背景不通过。核心实例难度先固定，不得在结果出来后删掉失败实例缩小分母。

边界检查不要求强猜未识别机制，但也不能靠什么都不运行通过：必须取得规定的公共事件，保留对应未知原因、未搜索域和至少一个合法后续实验候选；候选尚无可区分效果时明确记录。阶段二再将相关片段升级为可辨识条件下的完整学习/控制验收。这样阶段一既有必须交付的能力，也不会把尚未解决的复杂情形伪装成已解决。

### M01：完整支持平移与重叠内部

在开阔地放置 3×2 同色主体，支持 S={0,1,2}×{0,1}，锚点 `(3,6)`。测试侧把 ACTION1–4 映射到四个方向，映射可在实例间置换；agent 不知道该表。一次向右一格后，原左列变为背景，新右列成为主体，中间两列保持原像素。增加一个远处静止同色片与一个异色自动片作为独立变体，不在第一个定位例同时打开。

训练先覆盖 2×2 和 3×2 的至少两个位置及本轮待测动作方向；同一模型冻结测评只换已训练形状的未见位置和无关装饰。动作映射置换必须新建学习运行；L 形与新形状是另列的能力扩展，不混进基础冻结分母。检验新定义是否表达多个前后对应共享关系，而不是仅描述 Diff 两条边。角色对应、重叠内部的保持、源区域腾空和目标占用都必须可追到公开像素。

正例为开阔移动；反例在目标完整支持的一格放阻挡；未知对照为两个外观相同候选在观测间交换或遮挡，使身份暂时不唯一。未知时保留多种对应，不强制生成唯一主体。产物包括前/后支持见证、位移参数的动作前来源、完整 Ω 及独立展开结果。若学到的只有变化边缘，定位 `Grounding` 的来源支持；若 d 从后态偷读，定位 `ConceptTerms/Mechanisms` 时间检查；若只导入未消费，定位 `Library/Controller`。

### M02：形状、扫过空间与边界，不能只检查中心

用 2×2 主体，先生成宽 2 的横向走廊，再把目标边缘的一格收窄成宽 1。两者主体锚点目标格都空，只有完整支持检查不同。另设 L 形主体与匹配凹口：其包围盒碰到一个空洞中的障碍，但实际支持不碰；此变体用来反驳把包围盒碰撞写死。

正例包括完整支持能进入的走廊和凹口；反例包括边缘一格碰撞、地图内孔及越出真实活动域。未知对照把目标部分放到当前视野外，不能据屏幕内空白宣布可通行或永久不可达。

增加位移长度 3 的成对环境：默认 2×2 主体从锚点 (3,6) 到 (6,6)，障碍放在 (5,6)，所以起点与终点均不重叠障碍而中间扫过区域重叠。一者只检验终点，另一者检验完整扫过区域。长度 2 对此 2×2 矩形无法构成同样反例，不使用无效场景。规则差异在测试侧显式定义；agent 须通过动作反馈区分，不能把扫过检查当通用先验。先只验长度 1 的闭环，再启用此变体。

基础冻结测评保留碰撞机制和已训练形状，改变位置；走廊旋转与颜色共轭按 §4.4 变换整组训练和测评，L 形作为阶段二扩展单列。验收保存实际被读的目标支持或扫过查询；负例不能只降低一个“移动成功率”。中心误判定位绑定/效果支持，所有 L 形均被拒绝定位隐含包围盒假设，视野外当 false 定位三值与模型域。

### M03：不可达背景、面板、岛与三种可达性

地图由两个可容纳 2×2 主体的平台和一个窄桥组成。桥宽 1 时，地面像素仍四连通，主体不能通过；桥宽 2 时可通过。另在地图旁放同样颜色的面板和一个面积足够但不相连的平台。主体不能“走到面板”不是面板无信息的证据；面板后续在 M05 改变通行条件。

训练只测主体附近的单步：接近真边界、在地图内合法移动、尝试进入一格窄桥。冻结测评提供宽桥和同色岛。评分分别检查“当前位置能容纳”“给定动作能进入”“目前是否有证据支持多步到达”；不要求第一阶段完成整幅最短路径，但必须拒绝用像素连通直接证明主体可达。

正例为宽桥一步；反例为窄桥一步和已实际试证的边界；未知为尚未探索的另一岛是否有传送/远程入口。即使私有 oracle 知道岛不可达，agent 在未完整覆盖动作机制前仍可保留未知。产物含三类不同查询及其证据；若面板被永久删除，定位 `Grounding/Contexts` 的裁剪策略；若图搜索越过窄桥，定位 `Mechanisms` 的配置支持。

### M04：可推动与不可推动的同形障碍

主体支持为 2×2，前方紧接一个 1×2 障碍。设置三种单步配置：障碍可推且后面空；障碍可推但其后有墙；障碍不可推但后面空。前两者使用同一机制参数，不通过颜色区分可推性。首批可令障碍有可观察纹理，再增加纹理相同但需要动作证据才能分辨的变体。

一次右动作可能同时移动主体和障碍，也可能二者均不位移；另设“主体受阻但计数器变化”的变体，禁止把受阻等同全状态恒等。训练从可推空位、被堵和不可推各获得独立公共事件，再在新位置冻结预测。

验收要求联合效果与两个角色的当前绑定，推出/拉回连接必须保留“这是同一次动作、同一障碍、同一后方空间”。不能把两个同色物当一个角色；也不能为了目标把不可推物的机制参数改成可推。未知对照是一个从未作用过且没有可辨特征的新障碍，正确状态为未辨认或暂定实验。产物包括共享接口、冲突见证、两个物体的 Ω 与未解释残差。遗漏另一物体定位效果关系，角色错接定位匹配连接，未知物直接赋可推定位条件/参数生成。

### M05：远端开关、门与仍有控制信息的面板

在 `x=9` 的竖向隔断中留宽 2 的门口；主体站在门左侧一格。远处面板某一 2×2 色块表示开关状态。门口的局部像素在开/关时可以相同，只有面板变化；训练前缀以 ACTION6 点击公开面板位置或 ACTION5 交互，使开关翻转，再执行同一个方向动作。

成对场景保持主体周围 7×7 公开局部窗口相同，只改变面板与门状态。正例开门后通过；反例关门受阻；未知对照为面板被视口裁出、当前历史也未记录其状态。另加一个无关面板色块随机改变，排除“任何远端变化都开门”的关联。

面板位置与颜色共轭变体按 §4.4 分组；把开关从切换型改为保持型必须建立新机制版本并重新学习，不能沿用旧资格。核心通过项是：局部相同却不同结果的反例导致读取范围扩大或历史条件增加；新预测真实读取相关面板/历史，下一次动作消费修订。若删面板后仍高置信预测，定位依赖；若所有远端像素都变成永久条件，记录条件冗余与泛化失败，不能称最小因果单元已找到。

### M06：消耗资源与共享钥匙

只在测试侧定义一个计数资源 k。面板以 k 个小块显示；一个方向动作进入门口时，若 `k>0` 则通过并令 k 减一，否则受阻。首个用例只涉及一道门和一个动作，不要求先实现整段“找钥匙”。私有初值给 k=0、1、2，各自通过公共帧可见。

正例 k=1 通过且变 0；反例 k=0 受阻；未知对照计数器样式未识别或被遮挡，不能假定仍有资源。训练中需要一个“资源改变但位置不改变”的独立公开动作，检验位置与资源通道没有合并。

冻结测评换面板布局和门位置。保存动作前资源读取、动作后资源残差及作用条件；不能把“门已开”长期缓存到下一次。阶段二再加入两个门共享一个资源，检查两条单步成功规则不能被并行复用两次。资源没有进入接口定位 `Mechanisms/RelationSemantics`；旧资源读数复用定位 `Revision` 负依赖/版本；多次渲染扣多次资源先判环境动画实现故障。

### M07：同一末帧、不同历史

设计一个可观察但不永久显示的短暂触发：ACTION5 使远端色块闪一下，并把隐藏锁存状态从 0 改成 1；完整响应最后一帧恢复原画面。随后的右动作只有在锁存为 1 时可通过门，并消费该状态。未按 ACTION5 的会话末帧相同，但其完整公共历史不同。

训练分为“触发→右动作”和“未触发→右动作”的两个独立会话；触发完整响应必须交给 agent。正例为已触发且未消费，反例为未触发或已消费。冻结测评在无关动作间隔、位置与面板外观上变化；不要求固定记忆最近一帧，必须保留与前件有关的历史状态或竞争解释。

未知对照删除触发动作之前的公开历史，且没有重建所需证据；这是专用公共轨迹夹具，不冒充正常在线凭空失忆。agent 应返回历史不足或显式假设。另做 M14 的“整个前缀也不可辨认”，不能把两类问题混为一类。验收产物含历史读界、触发和消费事件、旧预测及修订后的引用；仅按 frame hash 复用机制定位缓存键，后验补写旧历史定位 `Evidence/Revision`。

### M08：点击选择不同对象及屏幕坐标

放两个外观相同的 2×2 图形，相距 6 格；只有当前选中的一个受 ACTION1–4 控制。ACTION6 命中图形后改变选择，选中状态初版以一个短暂或持久边框显示。先测试点击本身的效果，再测试下一次方向动作；不能把“选择谁”当 solver 可以任意改写的真实身份。

坐标对照包括图形内部、边缘外一像素、留白、面板和两个图形之间。所有请求使用实际 64×64 响应坐标。环境内部可调用 `camera.display_to_grid`，Julia 不得调用该私有变换；Julia 对裁剪内候选只用自己的嵌入映回完整帧。变体包含 camera 21×17 与 24×20、面板从右侧移到顶部以及画面非对称旋转。

正例选中后移动正确图形；反例点击旁边后选择不变；未知对照两个图形重叠且选择反馈不可区分。验收记录每个实际 x/y、当前选择假设、结果；单有“试过 ACTION6”不算坐标覆盖。错位一像素定位 `PublicAPI/Contexts`；点击不确定却任意选对象定位当前绑定；多种坐标被合并证据定位覆盖键。

### M09：ACTION7 的局部恢复与非逆效果

人工游戏明确提供 ACTION7，但其规则由用例参数决定：U1 恢复上次主体位置并增加操作计数；U2 恢复主体和被推动物的位置，但不恢复已消耗资源；U3 在没有可撤销记录时只改变面板提示。不要把这些参数提供给 agent。

训练公共前缀先产生一次可见移动或推动，再 ACTION7；另从空历史调用 ACTION7。正例核对规定的恢复通道；反例核对不能恢复的资源及计数；未知对照跨 RESET 或历史缺失后尚不清楚可撤销目标。冻结测评更换前序动作与可见图形，不要求 solver 事先知道 U1/U2/U3 的名称。

必须保留原动作和 ACTION7 两次独立干预以及新的历史边界。位置回原处不能删除原始事件、合并成“从没发生”，也不能证明全部环境恢复。产物为各通道恢复/未恢复/未知的声明及下一动作的历史绑定。若 ACT7 直接套逆位移但错误恢复资源，定位程序/历史机制；若 RESET 后继续旧引用，定位会话 epoch 与缓存失效。

### M10：零位移、无像素变化与其他公开效果

主体紧贴边界。一次方向动作保持其位置，但面板计数减少；另一个变体只改变公开 `levels_completed` 或 `available_actions`，画面完全相同。状态通道的变化只能由合成环境使用官方可序列化字段实现，不能新增私有字段。

正例为位置保持且其他通道按规则改变；反例为真正整个已声明公开范围保持；未知为结果传输丢失，属于协议测试，不得生成保持样本。训练和冻结测评都需保留零像素 diff 事件，不以 Diff 为空跳过 evidence、覆盖或机制学习。

在改变可用动作的变体中，下一决策必须使用新集合；缺失该字段的协议桩必须拒绝形成“全部可用”。产物为原始响应哈希、逐通道核对、当前动作域。漏掉状态定位 `Evidence` 规范化，继续旧动作定位 `Controller` 当前合法性，超时标 no-op 定位协议状态机。

### M11：动画首尾相同，内部有运动和信息

一次 ACTION5 产生三个响应阶段：图形右移一格、远端提示闪烁、图形回到原处且提示恢复。完整响应最后一帧与动作前相同。再做末帧相同但中间提示颜色不同的配对，提示颜色决定随后一个动作是否能通过。

环境用多个 `step()` 阶段渲染，最后才 `complete_action()`；资源和动作计数只在开始阶段更新一次。先用环境自测确认完整响应帧数与顺序，再交 agent。正例为保留中间运动及提示；反例为真正一帧完全保持；未知为某一帧损坏/响应未确认，不能补造中间过程。

训练一组有提示与无提示事件，冻结测评改变动画长度、加入重复中间帧，但保持可见信息和机制。重复帧不增加独立支持。产物包括 response 内全部帧定位、相邻差分、同一个 event_id 和历史机制读取；只存末帧定位客户端/证据层，帧数被当支持次数定位统计去重，复用动作扣多次资源定位人工环境。

### M12：镜头移动与自主运动的可区分边界

世界扩为 40×20，camera 仍为 24×20。放至少三个不共线静止地标和一个主体。主体在屏幕接近边缘时，世界位置改变而 camera 跟随；公开画面中地标产生共同位移。另一个单独用例固定 camera，放一个每次接受动作都自主右移的图形；主体是否移动取决于实际方向动作。

先分别学习镜头跟随和自主运动，再在第二阶段组合。正例为有足够地标的相对运动区分；反例为背景整体滚动不代表每一地标都受动作单独控制；未知对照去掉地标、仅有一个图形与均匀背景，此时不同世界/镜头解释可产生同一画面。

方向动作与一个位置保持但仍推进节拍的动作形成对照，使自主图形在二者下都移动。controller 若仍可暂用“某动作伴随该图形变化”的模型，必须注明未区分时钟/共同原因，不登记为稳定可控主体。冻结测评换跟随阈值前仍是新机制须再学；仅换地图原点/颜色应保持关系。产物为竞争解释、相对位移和下一实验的区分预测。绝对位置误绑定位 grounding；共同变化直接算控制权定位机制归属；无地标强制唯一 camera 定位不确定性处理。

### M13：断桥裁剪、多色主体、同色粘连

构造同色“两个大块＋一格细桥”的图形。全图为一个四连通分量；裁剪窗口切掉桥后为两个分量。另设两个仅对角接触的同色点，分别核对四连通与八连通。算法只比较选定邻接边的颜色并沿边传递，不做全图非邻接像素两两比较。

运动部分生成两个对照：一个多色刚性图形在同一动作下整体位移；两个独立同色图形相接后又分离，动作只影响其中一个。正例要求保持候选支持及跨帧对应；反例拒绝“同色连通=唯一物体”与“不同颜色=永远分离”；未知对照相接期间没有任何区分动作，身份允许多解。

训练包含相接前、相接时、分离后三个公共时点，冻结测评换接触位置和颜色分配。公开局部裁剪只用于 Julia 内部视图测试，不修改环境真值。产物为全图/局部连通成员、窗口嵌入和对应候选；组件编号不同不是自然性失败的替代解释。裁剪直接复制身份定位 `Contexts/Grounding`，两种连通混用定位邻接原语，多色硬拆定位候选聚合。

### M14：不可辨认机制必须保留未知

测试侧建立两个有限环境 A/B，在给定公共前缀上的完整帧序列、状态、available_actions 和动作回显均一致。差别只在此前未尝试的 ACTION5：A 打开远端通路，B 改变另一个条件。先自动核对整个前缀的公共相同性，再冻结两个 agent 副本。

该同输入一致性检查采用固定操作计数预算、稳定排序与冻结任务顺序，不以墙钟/异步调度决定截断点；比较时规范化会话 ID、时间戳与路径。在 ACTION5 尚未尝试前，两个副本在相同 seed 和可见输入下应提出相同候选分布或决策；不能因私有实例 ID 得到不同机制。对其未观察结果可以声明候选集合或暂定单模型，不得标全域唯一、已穷尽或高置信因果保证。

发生第一个可区分动作后，新响应才允许分叉修订。正例是能区分时实际利用新信息；反例是只重复同一公开前缀却置信/资格不断升高；未知对照保持不提供区分动作。产物是前缀相同性证书、信息新增前后库/机制/资格差异和对比输入。失败优先定位私有信息泄漏、重复计票、候选域虚假穷尽，其次才是搜索能力。

## 7. 第二阶段只组合已通过的局部义务

### C01：开关—门—推动—形状约束

从 M05 的远端开关开始；通过门后遇 M04 的可推障碍；障碍后通道使用 M02 的完整支持检查。先给三个机制的独立训练实例，再在一个新地图中组合，不把参考动作序列交给 agent。

正实例有一条能先开门再推物并进入目标的公共动作序列。反实例只改变通道宽度，或让开关消耗唯一资源导致后续门条件不满足。未知实例把必要状态藏在尚未观察的区域；agent 可以选区分实验，不应直接保证整串成功。

oracle 用完整配置空间验证正负实例，目标在公共画面以可学习的标记和公共 WIN/进度呈现；不通过配置告诉 agent 哪块是终点。另可用“已由公共证据建立的目标查询”做机制组合专项测试，但这只能报告给定查询的控制，不计为自动发现游戏目标。

验收每次仅提交下一动作，检查中间状态重新绑定。第二步的 guard 应作用在第一步后的模型关系上，不能全部在初始图像相与。中间出现反例后，未执行后缀撤回；保存导致撤回的具体共享角色、资源、历史或模型域。编排程序提前整串发出定位执行器；错误共享物体定位模式拼接；资源不更新定位关系复合。

### C02：一份资源、两条分支与动作不可交换

让两扇门共用 k=1；打开任意一扇消耗资源。目标位于其中一扇之后，另一路为无效绕行。单步模型都可在 k=1 下成功，但 `open_A;open_B` 不可作为两次独立成功。

再加顺序对照：先选择图形再移动，与先移动再选择，终态不同。其表达可以共享纯定义，但动作序列不能加入交换律。正例是消耗和选择顺序均合法；反例是复制一把钥匙或交换控制步骤；未知例是尚未确认资源是否可再生。

在冻结模型内核对关系复合的全部声明后继，搜索未完不报保证。真实执行后逐步比较资源与选择状态；若选了暂定模型只记录暂定实验。产物含中间变量、资源流、完整性、候选计划被排除的具体原因及实际公共事件。没有任何 `tensor()` 调用也可通过；只有形式接口相接而真实共享资源遗漏必须失败。

### C03：滚动后的点击、历史撤销与依赖传播

把 M08 的选择对象移到需要滚动视口才能看到的位置；先选择并移动，再执行具有 M09 非完全恢复规则的 ACTION7。最后一帧位置可能恢复，但摄像机、资源或选择仍有差别。

正实例要求重新从当前公开帧定位点击坐标，不能复用滚动前的屏幕点；反实例在 ACTION7 后资源不足；未知实例没有足够地标判断对象对应。用一个底层身份反例触发修订，检查上层绑定、效果关系、程序前提和缓存全部失效或重验。

验收不只看最终到达：必须能够列出受影响和未受影响的定义/声明、后缀停止点、重新选择的实际动作、相关时间与来源。一个身份修订不应无条件删掉所有仍正确的纯结构定义；反过来保留纯定义也不能复活已被反驳的经验资格。

## 8. 协议桩的具体故障注入

协议测试使用与机制基准相同的 Julia 客户端，不能另写一个宽松客户端专门通过测试。

| 编号 | 注入方式 | 必须看见的行为 | 定位与产物 |
| --- | --- | --- | --- |
| P01 | 在 ACTION6 请求中交替使用内部、边界、留白坐标；抓取实际 JSON | x/y 不交换，不做二次缩放；窗口坐标先映射到公开全帧 | 请求字节、公开帧坐标、嵌入链；PublicAPI/Contexts |
| P02 | 官方服务动作执行并记录后，代理丢弃整个响应 | `outcome_unknown`；不自动重发、不用旧帧发普通动作；该请求不进入 no-op 集 | 服务接受次数、客户端状态、下一请求；PublicAPI/Evidence |
| P03 | 本地非法命令；另注入公开错误包完全相同、私有执行阶段不同的前/后执行 400 | 本地拒绝无网络且 explicit_rejection；服务错误白名单默认空，两种服务错误都 outcome_unknown；分类不能读私有阶段 | 私有阶段仅裁判读取，客户端状态只由公开内容决定 |
| P04 | 返回合法多帧，其中首尾相同；下一次返回错误维度/缺失必需字段 | 前者完整保存且只算一次干预；后者拒绝确认为正常事件 | 帧数、哈希、事件计数与解析错误 |
| P05 | 互换两个会话的 guid/响应，或回显不同动作/坐标 | 拒绝配对；不能把别的动作效果写入本次训练 | 原请求与响应核对证据 |
| P06 | scorecard/open 或首次 RESET 已执行，但回执丢失 | 不重复创建；未确认会话和首观察不能进入普通循环 | 创建次数、prepared/sent/unknown 记录 |
| P07 | 完整响应持久化后、认知更新前崩溃 | 从本地已确认记录恢复，只处理一次；不重放动作 POST | 恢复前后事件身份、处理游标、来源与下一动作 |
| P08 | 把当前动作移出 available_actions；另删除该字段 | 前者不再选择该动作；后者不解释为全部允许 | 当前合法域、未测试域、异常状态 |

RESET 是新控制边界，不是未知动作的自动重试。配置允许的显式 RESET 也必须保存一次命令义务，收到确认后才建立新观察边界。协议桩可以故意制造非法载荷，但不能让合成机制服务在正常成功路径使用非官方字段。

## 9. 必须先验证测试环境，再评价学习器

每个机制最少保留一个手算的小转移，例如 M01 的 3×2 平移明确列出退出、重叠、进入三组像素；M02 的窄桥明确给出碰撞的那一格；M06 的资源给出 1→0 和 0→0。独立 `reference.py` 不直接调用 `game.py` 的判断函数，否则两边同一个错误会自证通过。

环境一致性验证包含三层：手算断言；独立 reference 的有限状态枚举；通过真实官方 HTTP 请求取得的像素与公开字段。后两者只验证测试工具正确，不能代替 Julia/Rust 的学习、预测和动作消费测试。

对小状态空间枚举所有允许动作及 ACTION6 的等效像素类，核对环境和 reference；等效类由测试侧证明，不传给 agent。无限历史不全枚举，明确把历史自动机限制在本用例的有限状态并报告范围。发现未覆盖状态或 reference 不一致时该用例标 `invalid_fixture`，不作为 agent 错误。

## 10. 每个运行必须留下的验收产物

唯一磁盘布局以 01 §5.0 为准，以下为同一产物的场景检查用途；JSONL 索引不成为另一套权威事件存储。实施时在 `protocol/v1/` 固定 schema 版本并逐项解释。

| 产物 | 内容和用途 |
| --- | --- |
| `public/manifest.json` | 固定源码、锁文件、配置摘要、预算、进程身份、隔离挂载说明和运行开始/结束；不含密钥 |
| `public/events/<event_id>.json` 与 `public/events.jsonl` | 前者是已确认事件与原始响应引用，后者是可重建索引；参数/前观察/顺序完整，凭证/cookie 脱敏 |
| `public/predictions/<command_id>.json` | 动作前冻结的定义/机制版本、绑定、条件、Ω、后继约束、完整性与时间依赖 |
| `public/learning/<job_id>/` | 两批实际 E-Stitch 输入、旧库、完成状态、pattern/lambda、展开与来源核对；不只保留最终压缩率 |
| `public/consumption.jsonl` | 新定义如何进入当前识别、预测、排序和实际命令；记录发生位置，避免只统计名字 |
| `public/revisions/<revision_id>.json` | 反例、旧声明、新声明、依赖失效、未执行后缀与下一次消费；旧预测保持不变 |
| `public/coverage/<version>.json` | 动作及坐标域的已试、未试、未建模、冲突、结果未知；对应最小因果单元 |
| `public/metrics.jsonl` | 各阶段墙钟、CPU、分配、峰值 RSS、候选/匹配规模、预算停止原因；计时重叠明确 |
| `private/oracle-trace.jsonl` | 测试状态、规则、配置空间和可观测等价类，仅评分进程可读 |
| `grade/assertions.jsonl` | 每条用例断言的结果、预期范围、实际证据引用、失败最小前缀、定位模块 |
| `grade/report.md` | 中文过程结论，分别列协议、合成机制、真实 ARC，以及未完成/不适用/未知项 |

Action–Object Causal Unit（动作—对象因果单元）在此至少包括实际动作参数、角色绑定、动作前条件/历史、效果范围和解释版本。联合推动或共享资源不能强行拆成互不相关的单对象票数。报告不设一个合成“全部掌握百分比”隐藏未测域。

测试必须输出不成功的原因：`invalid_fixture`、`invalid_protocol`、`learning_not_completed`、`no_definition_in_scope`、`definition_not_consumed`、`prediction_conflict`、`unknown_evidence`、`search_incomplete`、`resource_stopped` 等应有不同解释。状态名可按总协议统一，但不能把它们都映成零分或无机制。

## 11. 可直接执行的实施次序

以下都是待新增入口。统一编排命令为 `python -m tddesc_tools.run --config config/<name>.toml`；runner 只装配进程、隔离与评分，不替 Julia 做认知。

### 11.1 第一阶段内部顺序

1. 建 `protocol` 断言和 P01–P08，先确认日志中的副作用次数与恢复行为。最小命令：`python -m tddesc_tools.run --config config/acceptance/protocol.toml`。
2. 实现 `build/serve/reference/grade`，先运行 M01、M02、M13 的环境自检，再扩到其余 M 用例。命令：`python -m tddesc_tools.run --config config/acceptance/fixtures.toml`。这是测试工具验收，不叫学习通过。
3. 用 M01 的短公开前缀接入两批实际 E-Stitch，冻结新库，再在未见位置做一次 Julia 自选动作并核对。命令：`python -m tddesc_tools.run --config config/acceptance/learn_smoke.toml`。
4. 执行 M02–M14 的单步条件测试；M07/M11 的短前缀只用于建立状态，待验的是下一次单动作预测，不提前要求通用多步规划。命令：`python -m tddesc_tools.run --config config/acceptance/movement_single.toml`。
5. 跑反例修订、旧库再用、构造期资源中止以及隔离负测试；确保不是靠测试侧规则辅助 agent 通过。对每个失败保留最小公共前缀，先定位唯一断点再修改。
6. 同一构建产物连接官方真实公共服务，至少取得一条从公共事件到新定义再到后续实际动作的证据链。命令：`python -m tddesc_tools.run --config config/acceptance/arc_public_stage1.toml`。真实环境没有出现的 M 条件记未观察，不回填合成成绩。

Julia 入口对应 `julia --project=julia/TddESCat scripts/run.jl --config <agent配置>`。`scripts/run.jl` 需实际存在，根目录不新增散落的临时程序。Python 环境服务可单独定位：`python -m tddesc_env.serve --config config/bench_server.toml`；其配置路径为测试侧可读，agent 单元不挂载。

### 11.2 第二阶段内部顺序

先跑 C01，随后 C02、C03。使用已经通过阶段一的同一语言、记录和消费者；不得为每个组合手写动作模板。命令：`python -m tddesc_tools.run --config config/acceptance/movement_composition.toml`。

冻结一个实际出现匹配膨胀的语料及消费者调用，再比较原因子实现与新增关系表示。TDD 是否引入由该任务决定；时间、计数、来源、最优成本及采样重数核对都在相同冻结输入上进行。压力变体增加同色重复图形、共享角色候选、窗口重叠和历史长度；不得先完整枚举所有绑定再编译，并声称解决构造峰值。

最后用相同产物运行 `config/acceptance/arc_public_stage2.toml`。真实过程重点核对多步前提、剩余义务、动作响应、修订后的下一选择及资源，不以个别游戏正常通关波动验收接口正确性。

## 12. 失败怎样定位，避免只加特殊规则

| 观察到的失败 | 首先核查的证据 | 应修改的位置 | 不接受的补丁 |
| --- | --- | --- | --- |
| 全部 M01 都识别为 Diff 边缘而非完整支持 | 两帧读取范围、保持像素、对应候选 | `Grounding` 候选与来源 | 给平移游戏专门恢复主体的分支 |
| 同色物接触后角色被合并 | 参数槽、身份/颜色约束、匹配见证 | `ConceptTerms/CategoryBackend` | 看到某颜色就认作玩家 |
| 只有后态可知的 d 被用于预测 | 定义读取范围、参数来源、预测冻结时刻 | 类型/时序检查与机制参数求解 | 把真实结果补进预测再算成功 |
| 远端开关反例出现后仍用旧规则 | 反例定位、条件候选、缓存负依赖 | `Mechanisms/Revision` | 把该 game ID 排除出测试 |
| 资源够一次却计划使用两次 | 中间状态、共享资源端口、复合关系 | `RelationSemantics/Controller` | 独立降低两扇门成功率 |
| API 超时后连发第二次动作 | 原命令状态、代理接受次数 | `PublicAPI/Evidence` | 自动重试或改成 direct env.step |
| 只有导出定义，没有影响实际决策 | consumption、分值依赖、命令引用 | `Library/Controller` | 新增“已消费=true”日志字段 |
| 资源停止被报未找到机制 | 构造计费点、completion、剩余范围 | Rust bridge/因子构造与 Julia 调度 | 缩小语料并继续报告全覆盖 |
| 不可辨认前缀中预测取决于私有场景 | 文件/网络访问、ID重命名、元数据 | 隔离与输入管道 | 仅在文档写“请勿读取” |

通用修复后重跑相关最小反例及它直接影响的相邻合同，不无目的扩大整套实验。已经证明协议一致，不以反复运行协议桩替代学习断点定位。

## 13. 阶段验收的准确表述

第一阶段至少交付：协议桩独立通过；人工环境自身与裁判一致；M01 的真实结构学习、两批复用与后续实际消费；各单动作复杂条件的已实现范围、成功、反例、未知和未完成状态；一次修订实际进入下一消费者；构造预算和完成轮次保存；一条真实 ARC 公共学习反馈证据链。

M01 通过不代表其他 M 自动通过。若时间或语言能力不足，逐项列出未完成，不以“通用设计支持”代替测试结果。不可辨认用例的 unknown 是正确边界；可学习正反例始终没有可用预测则是能力未通过，两者分开。

第二阶段增加：C01–C03 的组合闭环、资源/历史与不可交换顺序、底层修订到上层程序的失效传播、已测关系优化的同语义比较以及真实公共过程证据。任何阶段都不声称覆盖全部 ARC-AGI-3 动作—对象机制，不把一个人工环境的高拟合率当全局高置信控制。
