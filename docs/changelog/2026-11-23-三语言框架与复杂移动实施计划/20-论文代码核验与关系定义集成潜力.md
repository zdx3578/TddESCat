## 1. 本轮修正与结论

Conjunctive Concept Algebras（合取概念代数，CCA）应明确定位为关系概念与操作的语义规范，不能把 2024 公理化论文当成已经完成的自动概念发现算法。

这条研究线有作者公开实现：2016 cgnav、2019 Granada/dbnav。cgnav 实际包含共同图模式与概念格生成；dbnav 实际把图查询编译为 SQL 并执行。它们不是 2024、2025、2026 新理论的完整配套实现，而且存在明确的范围与代码正确性边界。

本轮已经在未修改的 cgnav 原码上运行官方家庭样例，得到预期的 9 个概念；独立有限同态语义对照同时发现 3 个不一致，其中关系标签检查缺失在同词表、单窗口、连通图中即可复现。

较有实质整合价值的新发现：

1. FCA4J 已实现“上一轮概念→关系属性→下一轮概念计算”的真实消费链。
2. Libra 已实现关系连接、投影和数值／类别条件的联合综合，直接补候选定义构造。
3. Paspailleur 提供原子模式、闭包、生成元和稳定模式筛选的源码与具体测试。
4. Catlab 0.17.6 实际源码已有 query 与 HomomorphismQuery 方法，和仍声称尚未重实现的迁移说明不一致；不能继续据旧说明声称该功能不存在。
5. Catlab query 保留多个见证产生的重复输出；接到集合语义的概念外延时，需要明确去重与见证保留。
6. Rust E-Stitch 继续承担真实结构发现与程序库压缩；上述关系构造方法为它提供语料，并消费它输出的定义。

不建议把所有外部软件拼成多个世界模型。需要复用的是经过核验的算法职责，在 Julia 的统一语义和实际 Rust E-Stitch 之间建立闭合交换。

## 2. “有实现”与“可靠”具体意味着什么

应分别记录以下证据，而不能以仓库存在代替其余结论：

| 证据 | 能支持的判断 | 不能支持的判断 |
| --- | --- | --- |
| 数学证明 | 在明示假设下，运算或表示关系成立 | 某份代码没有错误、学习器一定能发现目标 |
| 可读源码 | 某项算法和输入输出链确实存在 | 当前环境可运行、论文性能已复现 |
| 作者测试与实验 | 指定案例／数据上的行为受到检查 | 任意新接口、ARC3 隐藏状态下都成立 |
| 本地复现 | 固定版本在明确环境和样例上确实出现该结果 | 单个样例代表总体性能或因果可信度 |
| 项目集成消费 | 新定义被后续求值、构造、预测或动作实际使用 | 所有环境／动作／对象条件已覆盖 |
| 公共交互反例 | 指定经验断言可被修订 | 无反例即获得无条件普遍正确性 |

本项目可以继续采用“无反例时暂定留用”的经验策略，但不能容许已知关系标签错配、参数错绑、未知当负例等确定的表示／求值错误进入正式解释器。

### 3.1 cgnav 的实际算法

来源：[A Python Library for FCA with Conjunctive Queries，2016](https://ceur-ws.org/Vol-1637/paper_7.pdf)，及 [Intension Graphs as Patterns over Power Context Families，2016](https://ceur-ws.org/Vol-1624/paper16.pdf)。

固定版本：[koetters/cgnav @ 816e514d](https://github.com/koetters/cgnav/tree/816e514d24467cfd2ec29494c44a901d885d8f75)。Python，MIT。未找到独立测试套件或 CI；作者明确说明只适合小样例，建格只支持一个公开对象角色。

主要算法均在 [cgnav.py](https://github.com/koetters/cgnav/blob/816e514d24467cfd2ec29494c44a901d885d8f75/cgnav.py)：

| 函数及源码位置 | 实际工作 | 对我们有价值的部分 |
| --- | --- | --- |
| windowed，435 起 | 设置公开角色别名，未公开节点成为内部角色 | 关系接口与存在隐藏 |
| quotient，446 起；sum，482 起 | 重命名两图，再按共享别名识别节点、合并关系 | 共享角色合取与模式拼接 |
| product，513 起 | 构造图乘积、保留共同属性与关系结构 | 从关系事实产生共同图模式 |
| morphisms，606 起 | 邻接遍历和回溯匹配 | 模式求值与同态预序 |
| minimize，747 起 | 枚举自同态，选择最小像 | 小规模定义缩减；可能很昂贵 |
| PatternStructure.build，782 起 | 从带根对象描述反复生成共同模式、外延与上下邻接 | 真实自动概念格构造 |

其意义不是“只有一个查询界面”：从关系数据自动产生共同模式确实已经实现。官方家庭例子可生成关系链概念。但它依赖既有关系词表，不自动获得像素、时间、动作和因果解释。

| 模式要求 r 边，目标只有 q 边；同签名、单窗口、连通图 | False | True | 关系标签检查缺失 |

第三个反例可以独立写为：

~~~python
P = star({"r"}, "x", "y").windowed(x="x")
H = star({"q"}, "a", "b").windowed(x="a")
common = P.schema.union(H.schema)
P.schema = common
H.schema = common
assert P.leq(H) is True  # 实际结果；完整同态语义应为 False
~~~

源码原因：matches(r1, r2) 检查端点绑定和节点属性，但没有检查 r1.atts <= r2.atts。它会让不同关系被接受为同态，进而影响蕴含、缩减与建格判断。

非连通和多窗口案例不能用于断言“单根连通建格的全部功能已被反驳”；关系标签案例则已经限制在单窗口连通范围内。以上均是代码语义问题，不是 CCA 数学定理被反驳。

本轮完整实测结果和核查脚本在本目录 evidence-cca/ 下。执行时间仅是该次本地运行记录，不作为软件间性能比较。

## 4. CCA 的 2024—2026 后续：哪些是定理，哪些不是算法

2024 [Conjunctive Concept Algebras — Named Perspective](https://ceur-ws.org/Vol-3911/paper2.pdf) 给出相应合取子代数的公理刻画。Proposition 10、11 是已给出的结果；Conjecture 12 仍是猜想。正文明确尚未得到所讨论完整形式的 Basic Theorem。

2025 [A Data Model for Relational Concept Algebras](https://doi.org/10.1007/978-3-032-03364-2_24) 进一步精确化数据模型。本轮只取得官方摘要，没有获得完整正文或配套新实现。

2026 [TACL 作者讲义](https://iphils.uj.edu.pl/tacl/slides/133.pdf) 共 59 页，进一步讨论 unnamed perspective 的列删除、列插入、对角相等和元数结构；相应完整刻画仍列为猜想。未在讲义中找到代码链接、学习算法实验或性能结果。

因此：

- 可以采用已经明确的有限正关系语义、角色操作和相应已证明规律。
- 实现这些具体运算不必等待整个表示分类问题解决。
- 不能从公理刻画推导自动发现率、搜索效率或 ARC3 控制效果。
- 本轮没有核到 2024/2025/2026 新理论的一套完整配套生产软件；这不等于断言世界上不存在任何实现。

### 6.2 query 的输出不能直接冒充集合外延

固定测试 [test/wiring_diagrams/Algebras.jl](https://github.com/AlgebraicJulia/Catlab.jl/blob/ca2b685bdc5fb7507460a42e8dc4aa3b5d202a32/test/wiring_diagrams/Algebras.jl) 中，两个不同内部路径产生相同公开起点和终点，预期输出仍有两行：

~~~text
start = [1, 1]
stop  = [4, 4]
~~~

这是见证保留／多重结果行为。概念的集合外延应只有一次 (1,4)，但可以保留两个来源见证。

项目需要明确：

$$
\operatorname{Extent}(P,G)
=
\operatorname{set}\bigl(
\operatorname{project}_{X}(\operatorname{Matches}(P,G))
\bigr).
$$

X 是公开角色；Matches 包含内部绑定；set 去掉重复公开元组。来源见证单独关联到该元组，而不是被丢弃。若直接把重复见证当独立事件支持，会虚增概念支持和经验置信度。

### 6.3 有限查询基础已经有算法，不等于归纳已完成

[HomSearch.jl](https://github.com/AlgebraicJulia/Catlab.jl/blob/ca2b685bdc5fb7507460a42e8dc4aa3b5d202a32/src/categorical_algebra/pointwise/homsearch/HomSearch.jl) 实际使用 Constraint Satisfaction Problem（约束满足问题，CSP）回溯与 Minimum Remaining Values（最少剩余值，MRV）顺序。

## 7. FCA4J：概念递归回灌的实际算法

固定版本：[guti34/fca4j-project @ 75b53685](https://github.com/guti34/fca4j-project/tree/75b536850cffd0138e8796859533f2a989e47bec)，2026-11-19 的主线提交。官方文档为 0.5.1，Java + 部分 C/JNI，BSD 3-Clause。

[ExploRCA.java](https://github.com/guti34/fca4j-project/blob/75b536850cffd0138e8796859533f2a989e47bec/fca4j-core/src/main/java/fr/lirmm/fca4j/algo/ExploRCA.java) 的真实链条：

~~~text
computeStep
    第一轮生成概念
    后续轮次 extendContexts
        遍历已知关系
        读取目标上下文上一轮的新概念
        对源对象进行关系 scaling
        addAttribute 登记新属性与外延
    generateConceptOrders 让新属性参与下一轮
~~~

默认 existential scaling 实际计算关系像和目标概念外延是否相交，亦即：

$$
(\exists r.C)(x)
\iff
r(x)\cap \operatorname{Extent}(C)\ne\varnothing.
$$

RelationalAttribute 保留关系上下文、scaling operator 和目标 concept ID。对于默认 exist 算子，这些结构能编译成我们的 Exists(r,C) 定义，具有追溯和重新求值的基础；其他 scaling operator 必须分别保持其量化与比较语义。

### 7.1 Datalog 导出不等于一般关系定义的可执行交换

[官方 -cd/-cdu](https://www.lirmm.fr/fca4j/Rca.html) 确实导出 Datalog 描述。但源码 RCACommand 调用 ConceptUtilities.buildDatalogDescriptor 后写文件，没有在该路径调用推理器消费。

[DlgpUtils.java::buildConjunction](https://github.com/guti34/fca4j-project/blob/75b536850cffd0138e8796859533f2a989e47bec/fca4j-core/src/main/java/fr/lirmm/fca4j/util/DlgpUtils.java) 将属性名直接写成 predicateName + "(X)"。该导出不是把所有关系属性展开成一般 r(X,Y) 或 CoMove(E,U,V)。

因此，集成应读取结构化的关系属性定义，不能仅解析概念名字，也不能把一元 Datalog 字符串当作完成的多参数程序接口。

### 7.2 共享见证是实质表达边界

$$
\exists y\,[r(x,y)\land s(x,y)]
$$

与

$$
(\exists y\,r(x,y))\land(\exists z\,s(x,z))
$$

不同。分别做两次 existential scaling，可能丢掉“必须是同一个对象”的约束。我们的公共角色模式需要显式共享变量，并由统一求值器检查。

可将已构造的角色绑定元组作为某一 context 的对象，再保留它的各角色投影，使一元概念索引对应多元关系外延。这是一个有条件的编码办法，不是 RCA 自动发明共享见证的证据；也不能全量展开无关的笛卡尔积。

### 7.3 成熟度

官方有可执行 JAR、Maven 发布及输入输出示例；仓库有 native 测试。所核 Java 发布 workflow 使用 -DskipTests，未发现完整 Java 语义单测目录。本轮没有运行 FCA4J。官方 -clean 还明确提示可能导致循环。

因此，它提供真实递归构造算法和可复现入口，尚不是我们已经验收的在线闭环。

## 8. Libra：联合发现关系结构与适用条件

论文：[Relational Query Synthesis ⋈ Decision Tree Learning](https://www.vldb.org/pvldb/vol17/p250-naik.pdf)，PVLDB 17(2)，2023／VLDB 2024。

作者仓库：[aadityanaik/libra @ 0f5e0d7d](https://github.com/aadityanaik/libra/tree/0f5e0d7dd6393566417d1f459958b35db5fc038a)，Scala。未核到根 LICENSE，不能把论文许可当作代码许可。本轮做源码阅读，未运行。

Select–Project–Join（选择—投影—连接，SPJ）综合同时处理：

- 连接哪些输入关系；
- 哪些角色必须相等；
- 哪些列是公开输出；
- 使用哪些类别或数值条件。

实际调用链是 Main 的 --dtgs 分支 → DTGS.solve → solveRelationNonRec → solveField → ProjectedDT 的条件学习。

其价值在于，关系连接和筛选条件相互影响，算法将二者交替搜索。结果是明确的查询结构，可以编译到共同关系表达。

### 8.1 具体迁移差距

| 具体问题 | 代码位置／当前逻辑 | 对我们会产生的后果 | 对应解决方式 |
| --- | --- | --- | --- |
| 数值值域不匹配 | [Condition.scala](https://github.com/aadityanaik/libra/blob/0f5e0d7dd6393566417d1f459958b35db5fc038a/src/main/scala/mustar/ProjectedDT/Condition.scala) 14、25–36 行删掉非数字字符再转 Double | 负位移和小数可能改变含义；这是迁移到我们值域时的风险 | Julia 的有类型数值解释负责运算，禁止这种字符串清洗 |
| 缺失不等于负例 | Problem.scala 存 inputRelations/outputRelations；DTGS 将 result - expected 当坏输出 | 部分观察会把未知误作否定 | 只对已完整观察的指定目标域构造负例，未知另存 |
| 有界代码不自动继承无限搜索保证 | DTGS.solveField 初始 bound=20，使用启发式条件树 | 未找到只能解释为本轮界内未发现 | 明示本轮语法、规模和计算预算 |
| 没有持久概念回灌 | 接收 schema、facts、expected，输出查询；没有我们的版本／证据库 | 一次综合后不能自然成为下一轮概念 | 将结构化查询登记为可求值定义，求值事实进入下一轮 |

论文的完备性与最小性结果有语言和搜索前提，整体复杂度并不低；实验是多表数据库任务，不是 ARC3。论文大基准数字不作为本项目增益保证。

### 8.2 与 E-Stitch 是互补关系

Libra 式候选生成从实例与目标构造“连接和条件”；E-Stitch 从这些表达中学习共享程序结构。前者增加候选定义，后者降低定义和后续搜索的重复成本。

二者都应输出或消费同一关系表达，不各自维护环境真值。无需把整个 Scala 项目加入运行架构，可以在明确许可及验证前提下研究其算法并实现对应构造步骤。

## 10. 真正统一的中间产物必须保存什么

Intermediate Representation（中间表示，IR）在这里应是“有角色接口的可求值关系定义”，不是一个没有含义的通用 JSON。

每个定义需要清楚表达：

- 公开角色：调用者得到哪些对象、事件或值。
- 内部角色：哪些变量只作为满足关系的见证。
- 构造主体：使用哪些关系、相等、合取、存在投影或明确扩展运算。
- 类型与读取时点：数值怎样解释；只读动作前信息还是依赖动作后响应。
- 展开依赖：引用的旧概念和宏怎样展开，采用哪个版本。
- 求值结果与来源：实例外延，以及每个实例的公共证据见证；未知和未完成不混入假。

例如“共同移动”可以有事件 e、支持 u/v 三个公开角色，位移 dx/dy 为内部角色。共享 dx/dy 是概念含义，不能在编译中变成两个独立存在位移。

定义不需要作为新的 Julia 源码执行；采用固定解释器及已核查运算，将学得定义作为数据。原有无 LLM、Julia 语义所有权和实际 Rust E-Stitch 的原则不变。

## 11. 如何接成真正能相互促进的发现回路

下面是本轮修订后的设计综合，不是任何单篇论文已经完成的功能。

~~~text
公共事件 → 有来源的像素／候选关系事实

根据重复结构、结果残差、当前目标选择有限的局部学习任务
    Relational Decomposition 式分解输出目标
    Libra 式联合提出角色连接与条件
    RCA 式沿已知关系提升既有概念
    所有候选都进入同一关系定义语言

Julia 按类型、公开角色、内部见证和读取时点求值
    保存实例与证据
    未知保持未知
    对同一公开元组去重，并保留多个来源见证

将可复用定义及解释程序提交真实 E-Stitch
    仅使用已核实等式
    得到宏定义与被重写的语料

Julia 检查宏展开、参数、类型、求值与来源
    合法定义进入同一概念库
    新定义的求值结果进入下一轮关系事实
    原子索引／偏序帮助选择和压缩相关描述

当前查询／预测／动作实际调用新定义
    成功留用当前经验版本
    反例定位到定义、条件、对象解释或视图
    更新依赖和下一消费者
~~~

重要的是只保留一套定义身份与语义。FCA4J、Libra、Paspailleur 是算法与对照来源；不意味着必须增加 Java、Scala、Python 的多个在线认知服务。

## 12. 必须检查的几个转换合同

### 12.1 编译后的求值不变

对输入定义 P、公共数据解释 G：

$$
\operatorname{Eval}_{Julia}(\operatorname{Compile}(P),G)
=
\operatorname{Meaning}(P,G).
$$

有限测试域中可以用独立枚举／关系运算进行差分检查；不能用同一个错误编译器生成预期结果。

### 12.2 宏压缩后展开不变

$$
\operatorname{Eval}_{Julia}(\operatorname{Expand}(M),G)
=
\operatorname{Eval}_{Julia}(M,G).
$$

有递归时需要另立语义；首个可执行片段可采用无环定义展开。E-Stitch 的程序等式不等于经验机制在全世界成立。

### 12.3 共享见证与存在投影保持

把两个模式拼接后求值，应与分别求匹配、在共享接口上连接相符。隐藏内部变量后对公开结果去重，内部来源仍可追溯。

### 12.4 概念索引不改变查询含义

把定义压缩为原子／闭包索引后，应能在声明查询上还原同样实例。当前数据上的外延等价不自动升格为全模型逻辑等价。

### 12.5 证据时间与控制使用相容

动作后发现的 CoMove 是效果描述；要用于选择动作，必须另学只读取动作前信息的条件和动作到效果的规律。否则“预测成功”可能仅是读取了结果。

上述合同提供具体检查点，但不是完整因果发现保证。动作—对象最小因果单元的闭合覆盖仍需公共交互证据。

## 13. 新方法的作用大小，按能补什么判断

| 能力缺口 | 最直接的方法 | 预期新增作用 | 当前证据强度 |
| --- | --- | --- | --- |
| 关系表达无法统一执行 | CCA 有限语义 + Catlab | 共享角色、隐藏、组合的统一含义 | 数学基础与实现方法存在；仍需项目编译差分 |
| 不知道该连接哪些对象、保留哪些条件 | Libra 式 SPJ＋条件联合综合 | 自动产生有区分力的关系定义 | 有源码与论文任务实验，ARC3 迁移未测 |
| 学到概念却不能继续生长 | FCA4J 式 RCA 递归属性 | 新概念成为下一轮描述材料 | 已有实际消费链；一般多角色需扩展 |
| 表达重复、跨事件无法共享 | 实际 E-Stitch | 参数化定义、程序库复用 | 固定源码和多轮学习测试存在 |
| 已有候选太多、闭包和比较成本大 | Paspailleur 式原子索引 | 减少描述重建、查询和筛选重复 | 源码及测试存在；性能取决于负载 |
| 需要新的构造套路 | TOIL/Möbius 的受限思想 | 元规则或递归结构提升 | 原型／artifact 边界较大 |
| 像素对象对应与隐藏状态不清 | 公共证据驱动的候选解释与实验 | 提高 grounding 和机制可辨识性 | 上述概念库软件没有替我们完成 |
| 希望可靠控制 | 概念定义＋前态条件＋动作语义＋控制检验 | 把关系规律变成可执行选择 | 需要真实消费和反例，不能从格闭包推出 |

不提供未经实测的“效果提高百分比”或笼统成熟度分数。增加多少能力，要看一个方法是否新增可表达／可发现的定义，或者以更小预算获得相同语义结果。

## 14. 怎样实质评估集成增益

不以概念节点数、压缩率或个别游戏成功波动单独判定进步。

可用同一公共事件序列、相同候选语言与预算做消融：

- 只有定义求值与原有 E-Stitch；
- 加入关系连接／条件候选；
- 再加入新定义回灌；
- 对描述规模成为瓶颈时，比较有无原子索引。

每组记录：

1. 能否从实例构造原先库中没有的关系定义；是哪条定义，来自哪些事件。
2. 定义能否在后续未参与构造的事件上求值，且角色和未知语义正确。
3. 新定义是否实际参与下一轮构造、预测或控制条件。
4. 产生的反例是否修改了相应定义，并影响下一次消费。
5. 等语义结果下的匹配数、临时物化规模、时间、内存及公共动作成本。
6. 未覆盖动作—对象—条件是否显式保留，不因压缩或稳定性过滤消失。

这是集成潜力的可验证落点。本轮只完成源代码与一个原型的有限执行核查，没有完成这些 ARC3 消融实验。
