### 4.3 M05 实际消费了学得定义

[scripts/motion.jl](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/scripts/motion.jl#L69) 从公共事件重建冻结语料，核对 Rust 回传，发布定义，展开其调用并读取位移。该定义值实际参与后续预测；不是仅把 definition ID 写进日志。

## 5. M05 究竟证明了什么

按[测试断言](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/tests/bench/check_motion.py#L86)和[控制器源码](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/julia/TddESCat/src/Controller.jl#L1)，已有执行记录对应以下过程：

1. 训练中观察到 ACTION1 的位移，E-Stitch 发现可复用关系结构。
2. 新场景提交 ACTION1 前，冻结位移预测 (2, 0)。
3. 公开反馈显示实际位移 (0, 0)，形成反例。
4. Julia 从公开画面候选中找到远端色块条件，产生新机制版本，旧判断缓存失效。
5. 新条件使 ACTION1 对当前位移规则不适用；控制器优先选择未知动作。
6. M05 的合法动作只有 1 和 5，因而选择唯一剩余的未知动作 ACTION5。
7. ACTION5 后公开画面满足新条件，再选 ACTION1，实际位移得到支持。

**已经成立：反例修订确实改变下一消费者和下一次公共动作。**

**尚未成立：控制器已经学会 ACTION5 的前条件和远端效果，并根据“它能建立通行条件”的预测主动选择 ACTION5。**

[Revision.jl 的反馈分支](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/julia/TddESCat/src/Revision.jl#L50) 只把当前声明所对应动作的样本加入该机制。ACTION5 的原始公开事件仍在 Evidence 中，但没有形成独立的辅助动作机制。这是覆盖探索带来的成功，不能升级成辅助条件因果链已经掌握。

训练和留出的范围也必须保持精确：

- 八个训练事件来自八个重新开始的公共会话，但场景配置是两个固定上下文各重复四次。
- 训练只用第一个训练种子。
- 位置留出改变主体、门和分隔墙的位置；颜色、形状及远端面板的绝对位置保持相同。
- 面板被裁掉时保留 unknown 是正确的保守行为。
- 这些结果不构成跨颜色、跨面板位置、多对象或完整动作域的高置信泛化证据。

依据：[训练构造](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/tests/bench/check_motion.py#L145)、[场景构造](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/python/src/tddesc_env/bench/build.py#L195)、[13实测记录](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/docs/changelog/2026-11-23-三语言框架与复杂移动实施计划/13-S1.06至S1.07单步机制修订实测.md)。

### 6.1 反馈恢复的最小修正算法

问题不要求新增另一套学习引擎。已有条件搜索应由完整反馈调度调用。下列伪代码说明控制顺序，名称不是要求照搬的新数据结构：

~~~text
收到公共动作结果：
    若结果未确认：
        按现有事务规则隔离或停止；不生成训练证据
    否则：
        保留该次完整公共事件
        对各效果查询记录：已支持、已反驳、未知、未完成
        找到读取了受影响证据、角色或条件的机制与待解释义务
        若存在新增有效证据或解释被细化：
            在冻结预算内重新求解参数和条件
            发布完整新版本，并使依赖旧版本的判断失效
        使用当前完整版本重新评估下一动作
~~~

“效果查询”表示这次希望预测和核对的量，例如主体位移、面板变化、资源变化或选中关系；“待解释义务”表示尚未被现有机制解释的动作效果与条件范围。它们必须保留原始事件引用，不能通过缩小条件把旧反例删除。

最小验证：先使现有条件语言无法区分支持和失败，得到不可行机制；随后经公开动作得到可由 RecentAction 区分的新支持。直接拟合能恢复时，真实反馈路径也必须恢复，并保留原来的未解释范围。

### 6.2 范畴复用目前到达什么位置

[CategoryBackend.jl](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/julia/TddESCat/src/CategoryBackend.jl) 已实际调用 Catlab 的图同态枚举与 pushout（推出，即沿共享接口把结构组合起来）。这不是仅写依赖名。

但匹配、推出与 glue_matches 的调用目前主要出现在语义合同测试；M05 控制链尚未靠这些运算完成多角色组合。glue_matches 还是直接遍历左右匹配对，没有统一预算和未完成状态传递。

下一步应让 M04 的“一个受控角色作用于另一个候选角色”通过共享接口组合，M06 的“位移与资源效果”通过同一事件关联。这样验证范畴运算是否被实际消费；只增加更多范畴 API 单测不能替代这一条路径。

### 6.3 Rust 资源改造应尊重既有不变量

已有逐赋值访问器去掉了完整笛卡尔乘积行表，但最终应用仍暂存 pending，受行数上限约束，尚未按实际内存计量。[cost.rs 的注释](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/third_party/egg-stitch/src/cost.rs#L690) 明确指出：随意在中间 union 会使自由变量和规范类分析陈旧。因此不能为了“分块”简单每若干行插一次 union；需要冻结匹配快照、处理规范化和 rebuild，并验证不同分块大小得到相同语义、成本与来源。

[matching.rs:28](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/third_party/egg-stitch/src/matching.rs#L28) 的组合计数仍为 usize 乘积。八个各 256 行的因子只存储 2,048 行，却有 2^64 个组合；这是静态数学边界，不是本轮已观测到的运行事故。先使所有计数算术显式检查溢出，超界不得声称 exact，再落实任意精度计数。

作业身份也应同时记录上游来源、本项目受控源码摘要及实际二进制摘要。目前只锁上游树、Cargo.lock 与工具链，不足以区分本项目的不同改造构建。

成本核验也应精确表述：[StitchBridge.jl:93](https://github.com/zdx3578/TddESCat/blob/8f4d2462274e3e61df5000fcc6678d5aab9c72c9/julia/TddESCat/src/StitchBridge.jl#L93) 已独立重算输入、输出、库成本、总成本和比值，但未独立核验 post_rewrite_baseline。该基线字段需提供提取表达与等价证明以核实成本；最优性另列为引擎保证，或者明确标为引擎报告值。不能由此否定已经完成的总成本复算。

## 10. 本轮参考计数复算方法

下列代码在固定提交仓库根目录运行，仅使用 Python 标准库及 build/reference；不执行官方引擎、HTTP 或学习器。instances 是选定种子下的场景变体数量；states 是每个实例按当前具体动作域可达的状态数之和；transitions 是每个可达状态中具体动作数量之和。

~~~sh
python -B - <<'PY'
import json
import sys
from pathlib import Path

root = Path.cwd()
sys.path.insert(0, str(root / "python/src"))
from tddesc_env.bench.build import read_plan, scenes
from tddesc_env.bench.reference import reachable, concrete_actions

plan = read_plan(root / "config/bench_scenarios.toml")
summary = {
    case: {"instances": 0, "states": 0, "transitions": 0}
    for case in plan["cases"]
}
selected_seeds = (plan["training_seeds"][0], plan["development_seeds"][0])
for seed in selected_seeds:
    for scene in scenes(plan, seed):
        states = list(reachable(scene))
        row = summary[scene.case]
        row["instances"] += 1
        row["states"] += len(states)
        row["transitions"] += sum(
            len(concrete_actions(scene, state)) for state in states
        )
totals = {
    field: sum(row[field] for row in summary.values())
    for field in ("instances", "states", "transitions")
}
print(json.dumps({
    "scope": "reference_only",
    "seeds": selected_seeds,
    "cases": summary,
    "totals": totals,
}, ensure_ascii=False, indent=2))
PY
~~~

本轮对固定源码缓存执行同一算法，结果为 instances=82、states=3718、transitions=22172。
