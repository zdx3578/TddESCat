# 阶段二：多步规划、关系表示优化与完整验收

日期：2026-11-23，台北时间。本文给出需要实现的算法和验收，不报告已实现能力。阶段一已经具备公开证据、有限类型语义、实际 E-Stitch 两批学习、定义消费、单步反馈与修订后，按本文接续。

## 1. 第二阶段到底新增什么

阶段一能回答“在当前已知条件下，某个具体动作预计产生哪些可观察变化；若不确定，该试哪个动作”。阶段二把这些可检查接口组合成带观察分支的有限程序，在每一步后重新核对条件与模型。

首先处理 04 中的组合场景：先获得或触发辅助条件再通行；推动物体影响另一区域；选中某个角色再执行动作；相同当前画面需要历史区分；动作虽然没有位移却消耗资源或改变状态。不能把这些组合简化为像素邻居是否同色。

本阶段只实现所需有限片段，不建全量概念格，不预设所有游戏确定或局部，不把概率估计作为必须先完成的门槛。用户真正关心的“可行动区域、墙、辅助条件”在 solver 内先表现为有证据的关系与条件；自然语言名称可以作为展示注释，不能决定机制真假。

## 3. 计划状态究竟含什么

只在当前查询真正需要的有限状态上规划。一个 ModelState 是派生解释，包含：

- observation_ref：用来构造它的已确认公开观测；
- role_binding：当前竞争角色映射，不能凭颜色合并身份；
- query_values：本次任务要保持的有限可观测查询值，如所选区域关系、公开进度、动作可用性；每项可为 unknown；
- history_summary：从已确认动作/反馈提取的有限历史摘要和其构造版本；
- model_version：用哪一冻结机制解释后继；
- completeness：哪些查询和后继已经求全，哪些仍有未展开候选。

belief（信念集合）保存仍与公共证据相容的多个 ModelState/模型解释。这里先使用集合，不捏造概率。原始帧相同但历史或作用对象解释不同，可以在 belief 中占不同分支；同一来源的两个表述不增加独立支持数。

不能将“训练中出现过的有限状态列表”直接当作所有未来状态。模型构造必须为没有定义完整转移的区域保留 unknown_successor。该标记不是一个已经验证的环境状态，而是阻止错误保证的明确缺口。

最终成功查询默认来自公开 state==WIN；levels_completed 的增长可以成为进度查询，不能自动替代最终目标。没有公开内部目标掩码时，探索子目标来自学得可观测关系和覆盖义务，不从测试 oracle 读终点。

## 4. Post 与 wlp 的可执行合同

Post（后像）和 Weakest Liberal Precondition（最弱自由前置条件，wlp）对有限关系 R⊆S×S 定义为：

$$
\operatorname{Post}_R(P)=\{s'\mid \exists s\in P:(s,s')\in R\},
\qquad
\operatorname{wlp}_R(Q)=\{s\mid \forall s':(s,s')\in R\Rightarrow s'\in Q\}.
$$

有限模型内必须穷举检查伴随式：

$$
\operatorname{Post}_R(P)\subseteq Q
\iff P\subseteq \operatorname{wlp}_R(Q).
$$

这项检查不证明 R 是真实环境。特别是没有后继的状态会空真地满足 wlp，所以实际执行门必须额外要求：

$$
\operatorname{SafePre}_a(Q)=
\operatorname{Enabled}_a\cap
\operatorname{DomKnown}_a\cap
\operatorname{NonemptySucc}_a\cap
\operatorname{CompleteSucc}_a\cap
\operatorname{wlp}_{R_a}(Q).
$$

这些集合分别表示动作公开可用、模型适用域已知、至少一个合法后继、相关后继与查询已求全、所有后继满足目标。这里的“安全前提”是当前模型和指定查询内的保证，不是对未知环境的无条件保证。

### 4.1 successors 返回值逐项说明

~~~text
successors(model, state, action, query_scope, budget)
  -> values, complete, stop_reason, domain_truth, dependencies
~~~

- values：已求出的有限后继解释集合；去重只按明示状态等价。
- complete：在当前有限模型和 query_scope 内是否完成枚举。
- stop_reason：正常穷尽、预算、未建模参数、角色歧义或不支持的片段。
- domain_truth：true/false/unknown，不能只靠 values 是否为空判断。
- dependencies：机制、查询、解释、证据和索引版本，供后续失效。

输入 guard=false 时，不能自动产生全状态不变后继；动作可能改变其它通道。只有另一个有证据且适用的效应分支才能给出这种后继。

### 4.2 最小确定性测试

令 S={0,1,2,3}，R={(0,1),(0,2),(1,3)}，Q={3}。应得到 wlp_R(Q)={1,2,3}，因为 2、3 无后继；若 Enabled 与 DomKnown 为 {0,1,2}，NonemptySucc={0,1}，且 complete=true，则 SafePre={1}。

测试必须断言：0 不能因为“存在通向 1 的分支”而判可保证到达 3；2 不能因为没有后继而获得执行许可。将从 0 的枚举截在第一个后继后，完整性必须为 false，即使该后继最终成功也不能声称保证。

compose_rel(Ra,Rb) 通过共享中间状态做关系连接和存在量化，返回中间见证；例如仅存 {(0,3)} 不能省略它经过 1 的证据。若任一阶段有未建模后继，复合完整性为 false。

## 5. 多步策略算法：有观察分支，逐步执行

实现有深度界的 AND–OR Search（与或搜索）：选择动作是“或”，该动作可能产生的每个可区分观测分支都能继续才是“与”。第一版不追求无限时域最优。

~~~text
solve_policy(belief B, goal Q, depth h, snapshot K, budget):
    if B为空：返回InconsistentBelief，交Revision处理；禁止空真成功
    if 全部 b∈B 的 Q(b) 已知为true:
        return GoalReached(依赖和见证)
    if h==0:
        return DepthIncomplete
    if budget耗尽:
        return ResourceIncomplete
    key = (规范化B, Q, h, K的所有依赖版本)
    若缓存命中且所有依赖仍有效，返回缓存

    actions = 当前所有分支共同公开可执行的具体动作
    按目标进展的已知代价、条件/覆盖需求、确定性次序排列
    for action a in actions:
        对每个b∈B和每个相容机制求successors
        若域未知、空后继或不完整:
            记录该a的缺口；它可转为实验请求，但不是保证计划
            continue
        按下一次可观察查询值将后继分成belief分支
        children = 每个分支递归solve_policy(h-1)
        若所有children均有有效策略:
            返回以a为根、公开观察为分支条件的策略
    记录穷尽了哪些有限动作/深度和哪些缺口
    return NoPolicyInCheckedScope 或 Incomplete
~~~

公开 confirmed 响应中的 WIN 可由 Controller 独立判定终止；不能用空 belief 的 all(true) 得出成功。

“没有策略”只能在明确有限模型、动作域和深度内解释，不能输出游戏全局无解。ACTION6 参数枚举如果只遍历一部分坐标，整体必须是 incomplete；不能只让搜索器看到偏好的几个点击点后声称穷尽。

控制循环每次只执行根动作：

~~~text
plan = solve_policy(当前belief, 当前目标, 配置深度)
若plan有可执行根：
    固定plan/库/机制版本、实际绑定、预测通道和参数
    提交一个公共动作
    保存并核对完整响应
    修订belief、机制、覆盖与依赖索引
    revalidate_suffix：重新求条件/绑定/动作可用性/查询完整性
    若失败或发生版本变化，撤回未执行后缀并重新规划
否则：
    调用ExperimentDesign产生有明确目的的区分或覆盖请求
    无可执行请求则报告阻塞原因，不暗中随机走另一引擎
~~~

动作在实际环境中失败是机制反例，不能通过计划器偷偷改写原预测消除。动作后的“只移动一次”不表示剩余程序仍正确。

### 5.1 程序可复用的条件

程序保存每步前置查询、效应接口、共享角色约束、资源/历史依赖及每个调用的概念版本。复用时重新做参数绑定与条件核对；不能因为源码片段可展开就自动扩大其经验适用地图和资源域。

将程序表达再交给 E-Stitch 发现可复用程序结构时，沿用同一 typed codec 与来源见证。不能在阶段二偷偷加入第二套“人工把两步命名为开门”的概念发现器。程序结构宏与动作机制的经验声明仍分开管理。

## 6. 主动实验：先计算差异，再执行区分

discriminate 的输入为竞争解释 H、当前 belief、合法具体动作、查询集合 Ω 和预算。H 可以是不同动作方向、作用角色、历史长度、阻挡条件、远程依赖或资源解释；必须由公开证据/通用候选产生，不能来自基准真值。

~~~text
对每个候选动作a：
    分别从各h∈H计算动作后的可观察查询预测集
    未建模或未求全的预测标为unknown，不能当作某个确定输出
    对已明确的h_i,h_j：
        若预测集合不相交 → 记录可区分对及区分查询
        若有交集 → 记录可能无法区分，不假定一次动作必成功
    估计达到a前提的公开动作成本、资源风险和剩余预算
    构成排序键：
        未解决覆盖义务优先级
        明确可区分的假设对数
        能形成新查询结果的确定信息量
        已知执行成本
        稳定动作/坐标次序
选择最优可执行请求；固定预测后发出一个动作
~~~

第一版用可审计字典序，不需要未经校准的概率或加权“置信度分数”。后续若引入概率电路，必须另定义样本权重、依赖结构和校准实验；不能把 adaptive 轨迹中的每个像素当独立样本。

当两种解释对当前一切可行动作都给出相同可观察预测时，返回 observationally_unresolved（当前观察下未可区分），并保存具体检查的动作/查询/历史域。不是自动宣告全局因果等价。

### 6.1 一个必须出现的历史修订例子

两次当前帧完全相同、同一 ACTION3，一次能通过，一次不能；读取 0 步历史无法区分。修订请求扩展到最近 1、2、4…步公共动作与反馈；若存在“先前某次公开反馈关系”为动作前可计算的区分项，可形成新条件。若达到 history_lengths 上限仍无法区分，保留竞争机制和 unknown。

禁止的修订是把 event_id、episode_id、未来颜色变化或“本次应成功”作为条件。保留测试必须包含同历史特征的另一个 episode 和颜色/位置扰动，检验是否只是记住一次事件。

## 7. 查询抽象怎样细化，怎样避免误合并

factor_query(alpha,q) 检查 q 是否在 alpha 的每个纤维上恒定。alpha 是从具体有限解释状态到抽象类的映射；q 是当前关心的公开查询。算法按抽象类分组，计算组内 q 的已知结果：

~~~text
对每个抽象类C：
    若有状态的q为unknown → 返回该类的unresolved，不声称已因子分解
    若出现两个不同结果 → 返回这两个状态及来源作为区分见证
若所有类均恒定：
    建立qbar(C)=该常值，并记录检查域和版本
~~~

refine_partition 先加入被反例区分的查询值，再按动作可用性、guard、资源/历史查询，以及相容模型下的后继类集合细分。重复直到当前有限域稳定或预算停止。不要加入所有可想象属性；每次拆分需要对应失败查询或控制用途。

check_causal_square 的有限模型检查为：先低层执行后抽象的结果集合，与先抽象后按抽象关系执行的结果集合一致；集合双方的完整性均为 true 才能判定。只检查一个实际后帧相同，不是该交换关系已成立。

具体测试：

- 同一颜色和外形、一个携带已观察资源一个没有；最终帧相同的合并在“能否继续通过”的查询上应被拆分。
- 相同局部窗口、远程公开机关不同；局部类在后继查询上被拆分或请求扩窗。
- 候选对象因相邻同色而合并、推动后分离；修订角色后，上层动作参数、guard、程序和负匹配缓存全部失效。
- 仅作坐标重命名且保持所有声明查询的两个表示，可以在所选查询内复用；不据此扩大到其它未检查通道。

## 8. 先定位关系瓶颈，再选 TDD

### 8.1 冻结比较输入

从实际 Rust 压力路径导出 relation_fixture/：原始程序、类型签名、规则、旧库、候选模式、局部关系、来源映射、域和值次序、成本配置、种子以及触发消费者。比较从同一局部关系构造开始，直到最优候选最终应用与输出结束。

不能把基线的“包括关系构造与最终应用”对比新后端的“已经编译好后的查询”。每份报告同时列冷构造、重复查询、最终应用和端到端值。

先实现一种结构明确的精确共享关系；本计划指定 Multi-valued Decision Diagram（多值决策图，MDD）作为易于独立验证的固定变量序基线。它不是新 TDD 重构定理的实现，也不被命名为 TDD。TDD 作为第二个对照候选，只有完成全部必要操作才可切为生产表示。

### 8.2 MDD 的具体构造

每个匹配槽有有限合法域 Dom(v)，例如本批允许的 e-class ID 集合；其原始 ID 通过固定字典映射到连续域值。值域包含类型和作用域检查，不把任何整数都当合法对象。

节点保存 variable（当前槽）、edges（值→子节点）、false 终端、true 终端；相同 variable 和相同子边表通过 hash-cons 共享。缺失边为 false。首版保留明确变量层，不因优化而隐式丢失需要计数的域。

从单个输入因子或算子孩子关系的已有有限行建立 trie，再合并相同后缀。只允许枚举本来就存在的局部因子；不能先对全部因子做笛卡尔积，再把结果导入 trie。

Join 用同步递归 Apply：对两个根和当前公共变量次序建立 memo；变量只在一侧出现时另一侧保持原根；共同变量逐个合法域值相交边。每次创建节点前检查预算，缓存相同根对的结果。Projection/Exists 对被消去变量的子图作 OR，并通过精确布尔 union 去重；不能把各分支计数直接相加来冒充存在投影。

Count 对保留域层逐层求和；成员检查逐层走边；选定见证按已计算子计数或代价下降，实际需要完整枚举才返回迭代器。由于状态数可能指数增长，每个操作仍有明确预算与 incomplete。

### 8.3 共同 RelationBackend 合同

| 操作 | 输入→输出 | 必须保持的意义 |
| --- | --- | --- |
| from_local_relation | 局部行/结构化约束、合法域→关系根 | 不要求先有整个联合绑定表 |
| restrict | 根、槽约束→根 | 精确筛选，不删除来源解释 |
| join | 两根、共享槽→根 | 与局部关系自然连接同义 |
| project / exists | 根、保留槽→根 | 集合存在量化，重复绑定合并规则明确 |
| contains / is_empty | 根、赋值/查询→判断 | 未完成构造不返回确定 false |
| count | 根、计数模式→精确值或 incomplete | 绑定集合数与 occurrence/抽样重数分开 |
| min_cost | 根、经批准代价分解→最优值与见证 | 只对已支持的分解作动态规划；通用非局部代价不能谎称线性可算 |
| witness | 根、查询、来源要求→一个/迭代见证 | 可追溯 program occurrence，不把 DAG 节点当事件身份 |
| enumerate | 根、预算→有序迭代器与完成标志 | 输出本身巨大时如实计入时间/内存 |
| stats / release | 根/arena→测量/回收 | 节点共享拥有期正确，不因一次迭代回收仍被候选引用的块 |

每个返回同时带 complete、stop_reason、budget_usage、domain_hash、order_or_tree_hash。空关系、尚未构造完成、类型错误、不支持操作分别返回不同状态。

成本分解先复用上游已核对的 size objective；如果某一代价依赖多个槽/共享 occurrence，必须作为明确联合代价因子纳入，或在有界精确枚举下求值并记录复杂度。不能把仅适用于逐槽加和的 min-sum DP 用在任意 DAG 成本上。

### 8.4 来源与抽样重数不能因布尔化丢失

布尔关系可以合并相同赋值，但 E-Stitch 的抽样、程序 occurrence 和成本可能仍区分产生它们的路径。固定上游 factor.rs 明确把行作为去重集合，Factor::new 会 sort/dedup；Expand 的 rebuild_factor 依赖生成唯一行的不变量，不是允许 bag。matching 的 num_substs 是每个根下因子行数乘积，跨根再求和；语料 occurrence 和 SMC 粒子重数是另两层。SMC 提议质量包含父粒子重数乘提议概率，不能用子关系去重后的 count 替代。后端分别保存集合成员、必要来源及粒子重数，逐消费者核对。

以下是来源/抽样适配的合同测试，不表示上游 Factor 接受重复行。一个小测试包含三条产生记录：两条都投影到 (x=1)，一条到 (x=2)。集合 count 是 2；按产生记录的重数是 3；若原抽样按三条记录均匀，x=1 的概率是 2/3。布尔化后均匀抽两个值改成 1/2 就是不等价。不能通过固定随机种子掩盖分布已经改变。

此处若是原始集合关系消费者，投影后的重复产生路径不得重新加入 num_substs；只有原语义本来具有权重的上层消费者才保留对应权重。

只要无法恢复原消费者需要的重数、来源或成本，后端不得切换为生产表示。测试 oracle 可小规模枚举全部行；生产路径不能用先全量物化恢复这些信息的方式声称消除了峰值。

### 8.5 TDD 需要先明确的内容

TDD 的变量来自已定义的有限匹配槽，不是“像素自然长出一棵变量树”。若用二进制编码槽域，域大小不是 2 的幂时必须加合法编码约束；否则 count、exists 和 min_cost 会计入无效绑定。

variable tree（变量树）首先选固定、可复现的结构：优先把同一原语的相关端口放近，再按共享接口组织；每次树变更记录 hash 和实际重构代价。选树是算法输入，不是论文自动替项目解决的语义发现。

适配 TiDiDi 时逐项核对当前固定版本的布尔运算、条件化、计数、存在量化、来源恢复与资源作用范围。其现有 restructure_to 的旋转路径不能作为新论文输出大小界算法的实现。论文给定的表示重构保证也不能直接变成整个 E-Stitch 进程峰值 RSS 上限。[T1][T2]

不要先承诺任意投影、任意因子连接和任意加权最优查询都可高效。只把已经实现并通过 RelationBackend 合同的运算接入实际 Expand / Reuse / final apply 路径。

## 9. 表示后端的确定性对照测试

在小域中用完整枚举 oracle；规模压力中用独立可计算约束、抽样成员核对和严格来源审计，不把“跑完”当语义一致。

| 测试 | 具体输入 | 必须满足 |
| --- | --- | --- |
| rel_join | R(x,y)={(0,0),(1,1)}，S(y,z)={(0,1),(1,0)} | 结果恰为 {(0,0,1),(1,1,0)} |
| rel_project | R(x,y)={(0,0),(0,1),(1,1)}，投影 x | 集合为 {0,1}、count=2；保留所需来源重数 |
| rel_empty_unknown | 空输入关系；另一个构造预算为 0 | 前者完成且 empty；后者 incomplete，二者不同 |
| rel_invalid_code | 域有 3 个值，使用 2 bits | 11 编码不能成为第四个值；count=3 |
| rel_type_reuse | 两槽整数编码相同，但类型/时间角色不允许共享 | Reuse 被拒绝，不能只比较整数 |
| rel_parity_free | x1 xor x2 xor x3=0，x4 独立 | 8 个赋值；独立因子 4×2；不得由成对独立性错误推出四变量全独立 |
| rel_occurrence_bag | §8.4 的 2+1 记录 | 集合、重数、抽样和来源各自正确 |
| rel_final_apply | 搜索小，但最终候选具有大量合法替换 | 最终应用也遵守预算；不在收尾物化全部乘积 |
| rel_dense_irreducible | 固定种子的高熵有限关系 | 允许表示很大；及时 incomplete，不伪报压缩保证 |
| rel_restructure | 输入/目标树与中间树明确 | 记录全部阶段峰值；不能仅测输入/输出节点 |

小域全枚举采用 1—4 个变量，每域 1—3 个值，运行固定种子的关系样本和边界关系。随机关系测试是确定种子的算法检查，不是统计证明所有规模正确。计数可使用 BigInt 或 checked integer，溢出显式失败，不截断为负值。

生产后端选择写入 config/relations.toml 并通过单一构造入口。选型报告要解释：消耗主要在建表示、join、计数、最优选择还是最终应用；即使 MDD/TDD 减小节点数却增加端到端延迟，也如实呈现。

## 10. 长链修订的执行顺序

维护依赖图：公开事件→角色解释→关系实例→定义使用见证→机制声明→计划前提→缓存/待执行动作。定义本身的展开等式和某次机制经验声明是不同节点；动作反例通常撤回后者，不应无理由销毁仍然正确的定义体。

~~~text
on_counterexample(event, frozen_prediction):
    记录不可变反例与它实际反驳的查询/绑定
    找到直接失效的机制声明或角色解释
    沿依赖反向索引收集受影响节点，拓扑顺序标记stale
    保留原证据、旧版本和原覆盖义务
    先重建低层解释和查询充分性，再重验条件/机制
    取消尚未发出的动作与旧策略后缀
    对负缓存和未命中索引执行同样版本失效
    发布新版本；下一次choose_next只允许消费有效依赖
~~~

固定测试链：区域 A、B 被误合并→学得宏仍可展开→“对共同角色执行动作”的机制预测失败→角色拆分→所有以旧角色为参数的机制和计划失效→下一消费者选择新绑定或明确 unknown。验收日志必须出现实际下一动作/不执行理由，不能停在“stale=true”。

异步压力测试：批次 watermark=100 时启动学习，事件 101 是反例；旧任务稍后返回。期望它不能把库/机制回滚到 100 的“无反例”状态。批次重基只改变派生发布，原101证据始终保留。

## 11. 验收运行和产物合同

阶段二配置需要写明 max_plan_depth、max_belief_states、max_relation_nodes、max_expansions、max_public_commands、wall_time 和 memory 范围。配置数值由首轮核心用例确定后冻结；遇到失败不得偷偷提高预算再与旧基线比较。

统一运行：

~~~sh
.venv/bin/python -m tddesc_tools.run --config config/acceptance/phase2.toml
.venv/bin/python -m tddesc_tools.run --config config/acceptance/relation_equivalence.toml
.venv/bin/python -m tddesc_tools.run --config config/acceptance/relation_stress.toml
~~~

这些是待创建命令。phase2.toml 依次调用有限语义单元、组合合成环境、固定公共夹具、真实公共交互、关系压力五组任务；独立输出状态，再决定阶段状态，不把某组跳过藏在总退出码里。

| 产物 | 必需内容 |
| --- | --- |
| manifest.json | 项目提交、三语言锁摘要、环境公开版本、实际配置与随机种子、平台资源 |
| events/、predictions/、decisions/ | 每次动作前冻结与动作后核对；保留完整帧 |
| learning/ | 输入语料、旧库、规则、来源、完整轮次、停止状态、实际新定义 |
| claims/、coverage/、revisions/ | 机制范围、支持/反例/未知、未完成因果单元及消费者变化 |
| plans/ | 具体动作、分支条件、后继完整性、依赖版本与失效原因 |
| relations/ | 冻结关系、各后端配置、等价核对、构造/查询/最终应用资源 |
| metrics.jsonl | 单调时钟 span、墙钟/CPU、各进程 RSS 与同一时刻整体内存、动作和有效反馈 |
| acceptance.json、report.md | 测试状态、实际证据链接、具体问题定位与未完成项 |

全系统峰值由同一时刻进程组或 cgroup 记录；各进程各自峰值之和只是上界估计，不能冒充实际同时峰值。首次 Julia 编译、环境启动、Rust 学习和循环推理分开，同时给出用户实际等待的全链路时间。比较冻结输入时保持机器/工具链/并发/预算相同，差异写进报告。

验收关注三个过程层面：语义与因果覆盖是否闭合；反馈到下一动作的有效处理速度；资源边界及异常恢复。普通游戏得分的上下浮动不作算法成败裁决；重复大规模跑分只在定位明确极端问题或验证改动时做。

## 12. 必须定位而不能绕过的失败

| 具体问题 | 代码位置 | 可能的当前错误逻辑 | 后果 | 规定解决方案 |
| --- | --- | --- | --- | --- |
| 单个后继成功被当全部成功 | Plan.jl::solve_policy | 任一分支可达就返回策略 | 非确定/多假设时错误控制 | AND 分支全通过；完整性入门 |
| 无后继获得许可 | RelationSemantics.jl::wlp / Plan.jl::precondition | 忽略空真 | 未建模动作被保证成功 | 加 enabled、已知域、非空与完成性 |
| 目标替未知位移赋值 | Mechanisms.jl 参数求解 | 为满足目标反推物理参数并当已知 | 看似规划成功，执行失配 | 参数只来自动作前证据/冻结候选；未知转实验 |
| 后继只有局部查询却默认为全局无变化 | Prediction / successors | 未建模通道补不变 | 错漏资源、远程和公共进度变化 | query_scope 显式；补查询或保持未知 |
| 条件收紧后宣称覆盖提升 | GuardRepair / Coverage | 删除被排除反例的义务 | 最小因果单元遗漏 | 反例继续留在原作用条件域，另找机制 |
| 布尔关系去重改变粒子采样 | relations / smc | count 代替重数 | 搜索分布、代价和结果改变 | 独立核对集合/重数/来源合同 |
| 搜索省内存但应用爆炸 | E-Stitch final apply | 最后一次构造全乘积 | 仍无法交付结果 | 消费者逐见证/分块，构造前预算 |
| 空匹配缓存永不失效 | CacheIndex.jl | 无见证所以无依赖 | 新关系出现仍判无解 | 记录被查询索引和其版本 |
| 晚到学习覆盖新反例 | Library / Revision | 无条件替换 current | 回到旧错误机制 | watermark 后补核 + compare-and-swap |

实际实现后的报告必须把表中“可能逻辑”替换为真实源码函数和观察到的行为。只看本计划或 changelog，不能称完成代码审查。
