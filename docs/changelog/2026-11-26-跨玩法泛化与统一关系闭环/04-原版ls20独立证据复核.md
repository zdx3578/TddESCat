## 3. 四项 PASS 的条件本身是什么

源码：`tests/bench/check_real_public.py::verify_autonomous_capture`。

| 验收项 | 当前判据 | 不包含的保证 |
|---|---|---|
| autonomous_public_win | 冷启动、单会话 WIN、逐关晋级、接触证据和跨关进度关系等均满足 | 不是任意机制家族的公共 WIN 通用判据；其语义审计与 contact 模型绑定 |
| autonomous_learned_task | 同一关、同一模型和目标先有缺失前提的 continue，后有 established；审计无错 | 不要求相对于完整既有规划器产生新任务顺序 |
| autonomous_goal_program | 有程序调用、改变普通排序、跨关重绑定、程序审计无错 | 不要求改变完整 baseline，也不要求新关系目标契约被使用 |
| autonomous_learned_policy | 至少一次策略 stopped，且审计无错 | 不要求正负与未知分支全覆盖，不要求多轮候选域缩小，不要求跨任务家族迁移 |

`tests/bench/policy_audit.py::PolicyAudit.verify` 会按当前候选数重新查发布正文，检验分支、定义可用时间、源语料、公共晋级和停止。它检查的是当前策略语言中的执行正确性；不能由其通过推出策略语言本身已经足以表达未知游戏。

此外，`autonomous_report` 的通过条件要求全部晋级事件出现在 contact_control/contact_samples，并要求有对比准入和进度关系迁移。建议将“公开成绩卡与回执确认真实 WIN”的环境事实验收独立出来；学习与覆盖验收按实际机制证据核对，不把任何新玩法的 WIN 都要求投影成旧接触家族。这个验收耦合不是本次 24 款求解失败的直接运行原因，应与求解器限制分开修正。

## 4. 动作对象因果覆盖仍不完整

本包有 479 条动作带定义引用，436 条所预测的局部查询全部 supported，其中 260 条仍保留非空的未解释变化 residual。覆盖资格统计为 467 条 predicted_queries_only、277 条 unresolved；定义引用与预测覆盖在新策略实现里不完全同口径，不应混作一个成功率。

仅 ACTION1–4 出现在该 ls20 会话中，分别 245、214、133、152 次。因此这个原版结果不能替代点击及其他动作家族的完整因果覆盖验收。该事实不是对 ls20 本身应执行无效动作的要求，而是跨玩法实验需要单独证明相应能力。

当前程序模式账本有 60 组 search_complete、89 组 unsubmitted。完成 WIN 并不意味着本局所有可学习模式已处理，也不意味着增加这些模式的定义数就能补足缺失的任务语义。

## 5. 与其余 24 款结论的边界

本次附件仅包含 ls20 原版运行包，没有 24 款原始逐动作证据或 paired-analysis.json。固定仓库的 16 号文档提供了逐款汇总，记录：

- 相同游戏版本、相同公共命令上限与同一搜索策略下，最终版总计 3,560 次实际动作；
- 7 款游戏有 53 次基于对象效果的后续实验；
- 事前晋级预测为 0；
- 合计仍只有 1 个小关，0 个整款 WIN，最终全部 GAME_OVER。

这些数字在本轮应标注为作者发布报告，不能写成已经由本上传包独立重算。本次可以结合当前源码分析“对象效果怎样进入选择、为什么不能形成目标关系”，但不能据缺少原始帧断言每款游戏的具体失败机制。

特别是，点击后画面变化比例上升，说明选中的干预更能改变可见状态；变化可能是目标相关效果，也可能是消耗、撤销、扰动或失败。该比例本身不是进展价值、信息增益或高置信因果模型的充分指标。相同命令上限下更少动作便 GAME_OVER，也不能单独解释为效率提升。

使用 Python 3.11 或更新版本；`--repo` 指向包含固定提交六个审计文件的源码根，`--evidence` 指向解压包根，`--output` 必须位于证据目录之外且文件未存在。脚本不使用环境变量。

```bash
python ls20-audit.py --repo /path/to/TddESCat --evidence /path/to/capture --config ls20-audit-config.json --output /path/to/review/compact-audit.json
```

脚本校验固定源文件摘要，在纯 Python 范围内重算四项验收并比较原报告，任何核查差异非零退出；禁止向证据包内部输出。它不提供完整 Julia 解释器的独立证明，数据结构内声明的源码、数量和机制语义仍需各自的审计责任。

可发布文件：`ls20-audit.py`、`ls20-audit-config.json`、`ls20-audit.json` 和本说明。源代码缓存、旧中间输出、历史对照轨迹和原始帧无需随本次审查重复提交。
