## 一、三处修复是真实修复，但只闭合了探索的一部分

1. **当前画面重新绑定对象已进入执行。** `OnlineSession.jl:703–707` 每个决策由当前公开帧和当前组件生成 `click_scene`；`InterventionLearning.jl:12–51` 取实际支持内部的代表点，实例身份包括位置、外观及当前数量特征。旧坐标队列的问题确实改变，不应继续指责“仍按初始坐标盲点”。
2. **点击位移不再建立无坐标移动主体。** `SpatialLearning.jl:146–157` 在尝试建立角色之前就拒绝 ACTION6。点击位移仍由局部效果解释器保留；不意味着点击效果被删掉。无坐标动作是必要的来源约束，仍不足以单独证明某个同时移动的对象就是受控主体；当前后续仍选最大唯一候选。
3. **公开回执确实影响下一轮探索。** `primitive_outcome` 区分未变、近似回退、新观测；`primitive_schedule` 调整复探时点。`object_effect_followup` 使用不同位置的同外观作用见证优先选择未试实例。53 次行为若原始记录与来源核对成立，可以称为“观察效果引导探索”，不能自动称为“已学任务策略”。

四联通同色组件是用户已接受的基础先验。本专项没有把这种起始分割批评为不允许的先验。需要改的是把起始分割过早当成唯一对象绑定，以及不能被当前效果语言解释的变化如何进入后续修订。

## 二、最重要的新发现：事前晋级预测为零有结构性原因

`InterventionLearning.jl::intervention_models` 第 62 行要求：

```julia
length(unique(row.level for row in positives)) >= 2 || return NamedTuple[]
```

第 63 行另要求至少一个未晋级样本；第 70–72 行对每个可复用特征值，又要求该值在至少两个不同关卡有晋级正例。候选特征仅为几何、颜色及三种数量。

所以，对本次所有最多推进一个小关的 public24 游戏，**点击晋级分支的事前预测为零，是代码准入条件的必然结果**。这不证明实现没有学习任何内容，但证明该分支不能帮助这些游戏首次突破：它需要先由别的机制推进至少两关，才能对晋级作事前判断。

跨关晋级需要较强证据是合理的。解决方式不应是把门槛改成一个正例、把一关观察伪称跨关规则。应在同一关系模型中区分当前绑定、同关适用域、跨关适用域：先允许被实际验证的局部作用建立中间关系任务，再逐步积累跨关晋级证据。未知仍是未知。

## 四、GAME_OVER 不能被误读

正常遇到 GAME_OVER 停止该局是正确的。不能把这一行简单叫程序错误，也不能直接把任何末步都认定为失败的唯一原因。

这里的系统缺口是：

1. `LocalEffects.observed_public_delta` 记录公共 state，投影也会保守处理公共状态变化，但 `evaluate_joint_trial` 仍只根据局部效果对原机制支持/反驳。
2. `InterventionLearning` 未把终态后果单独加入拟合，只有“推进/未推进”。因此局部改变的正确预测不能自动演变为任务安全性或失败条件。
3. `OnlineSession` 遇 GAME_OVER 立即结束；已有 RESET 是条带资源耗尽之前的专门通道，并检查同关恢复。
4. `evaluate_public24.py::evaluate_one` 每款只调用一次 `offline_capture`，没有外部保知识续局控制。

因此“24款全部GAME_OVER、实际动作更少”不能直接当作探索效率提升。点击发生变化的比例提高真实反映触达效果的能力，是否更接近任务完成需另外验证。

通用失败续学应在公开 RESET 可用的前提下实现。RESET 如果改变关卡、布局或会话，应按公开返回值建立新的实例域；保留可迁移规则，重新绑定当前对象；不能伪造原关卡仍在，也不能把已试坐标清单直接套到新实例。对失败归因保留候选链，采取可区分的下一次实验，不能把最后一个动作武断记成普遍有害。

## 五、复探调度的改进与边界

最终版已经不再无条件固定交替。回执未变或近似回退会延后原子动作，防止 su15 一类连续点击被反复打断，这一点应认可。

但 `choose_intervention` 仍有偶数步原子采样、每七步坐标覆盖的结构性节奏；`primitive_schedule` 延后幅度为二次函数，依据是画面距离和当前公开阶段，不是显式任务契约。

- 画面近似回退可能是合法撤销，也可能是建立新条件的一步。
- 画面未变可能表示阻塞，也可能是隐状态／延迟过程。
- 状态改变被归入新观测，包括终态改变，不能将“新观测”直接视为有益。
- 当前代码只将这些分类用于探索调度，不能错误说它已经把所有回退动作全局禁止。已确定计划仍可直接调用合法动作。

建议将复探对象改成“某个尚未区分的作用关系在当前上下文的实验义务”。执行一个有依据的连续任务时，不由单纯步数奇偶打断；新反馈若反驳任务前提则立即撤回。需要覆盖尚未知动作时，也应记录要消除哪一项不确定性，而不是把画面变化率当作统一探索收益。

`fallback_cursor` 在此只是坐标覆盖游标的变量名，承担合法公开坐标探索，不等于旧版兼容路径。不能只因为名称含 fallback 就将必要覆盖删去。

## 六、最小可实施接续

### 先形成同关作用任务与失败修订的闭环

复用 `PublicEffects`、`JointMechanism`、现有关系语义和公共回执，不另立三个互不一致的模型。

1. 在 `observe_intervention!` 中保留指向已存在效果记录的引用，携带被点角色、对应效果具体参数与作用域。保留公共晋级、WIN、GAME_OVER 等不同结果，不将“没有晋级”作为中间动作失败的同义词。
2. 同一作用契约提供：当前可预测什么、有哪些争议、在新实例还缺哪项验证。代表点探索、空间机制和程序消费均读取这一契约。
3. 将 `choose_intervention` 的候选改为同一决策入口的实验任务，不再在规划之后直接清除已有任务。连续步骤依据待完成关系保持，反馈负责撤回。
4. 公共终态保留反例义务；若能公开 RESET，开启新实例并保留合格知识，重绑定后执行修订实验。若公开条件不能恢复，则明确当前任务停止和未验证责任。
5. 同关局部作用能用于建立中间条件；晋级模型仍按声明适用域验证，跨关发布继续需要跨关证据。

这一交付首先应覆盖三个受控公开区分案例：同对象需重复动作但第一次无可见变化；同对象在远端条件改变后重新变得可操作；局部作用正确却造成失败，公开重置后修订条件能够改变下一次动作。每个案例同时保存预测、绑定、失败/未知与下一次选择。

### 再验证跨实例作用与多条件迁移

1. 点击平移、计数及远端改变不能只存效果类别；把操作对象和受影响对象的相对关系明确编码。
2. 相同外观不同作用、同作用不同外观、两个同形对象同时变化，都必须有区分任务和保留未知的路径。
3. 从同关任务轨迹增加条件和连续语料，再沿用 E-Stitch 发现共同定义与证明展开。没有被解释的作用不会仅靠增加搜索深度自动进入程序语言。
4. 最终在同版本公开输入上记录：哪些任务由已学关系生成、哪些调用依据仍不足、哪些失败被下一轮修订解决。public24需要全量过程证据验证，而不是用ls20的同路径WIN替代泛化。
